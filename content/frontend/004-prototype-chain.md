# 題目

JavaScript 的原型鏈是怎麼運作的？ES6 的 `class` 只是語法糖嗎？

## 核心答案

每個物件都有一個內部連結指向它的**原型物件**（可以用 `Object.getPrototypeOf` 取得）。存取屬性時，如果物件本身沒有，就沿著這條鏈往上找，直到 `Object.prototype`，再往上是 `null`。這條鏈就是**原型鏈**，它是 JavaScript 實現繼承的機制——不是複製屬性，而是**委派查找**。三個容易混淆的概念要分清楚：**`prototype`** 是函式才有的屬性，指向「用這個函式 `new` 出來的物件會使用的原型」；**`__proto__`**（正式做法是 `Object.getPrototypeOf`）是每個物件都有的，指向它實際的原型；**`constructor`** 是原型物件上指回函式的屬性。至於 `class`——它**大部分是語法糖，但不完全是**：它的方法不可枚舉、必須用 `new` 呼叫（直接呼叫會拋錯）、類別體內部強制嚴格模式、而且**不會被提升**（存在暫時死區）。這些差異讓 `class` 比 `function` 建構函式更嚴格也更安全。

## 詳細解析

**`new` 做了什麼**：建立一個新物件、把它的原型設為建構函式的 `prototype`、以這個物件為 `this` 執行建構函式、如果建構函式沒有回傳物件就回傳這個新物件。理解這四步就能解釋許多現象——為什麼建構函式回傳物件會覆蓋 `new` 的結果、為什麼箭頭函式不能 `new`（沒有 `prototype` 也沒有自己的 `this`）。

**屬性查找是委派而非複製**：所有實例共用原型上的同一份方法，這是原型繼承最大的效能優勢——一萬個實例只有一份方法。相對地，**在建構函式裡用 `this.method = function(){}` 定義的方法**會讓每個實例各有一份，記憶體開銷大很多。class 的類別欄位（`handleClick = () => {}`）也屬於後者，這是它綁定 `this` 的代價。

**修改原型會影響所有既有實例**：因為查找是即時的，不是建立時複製。這既是動態擴充的能力來源，也是危險所在——修改內建物件的原型（例如給 `Array.prototype` 加方法）會影響全域所有程式碼，可能和函式庫衝突或在未來與新的標準方法撞名，所以是普遍禁止的做法。

**`instanceof` 檢查的是原型鏈**：它沿著物件的原型鏈往上找，看有沒有出現指定建構函式的 `prototype`。這代表它在**跨執行環境**（iframe、Web Worker）時會失效，因為不同環境有各自的內建物件。更可靠的型別判斷是 `Object.prototype.toString.call(x)`（能區分陣列、日期、null），或針對陣列直接用 `Array.isArray`。

**class 的 `extends` 與 `super`**：`extends` 同時設定了兩條鏈——實例的原型鏈（子類別的 `prototype` 指向父類別的 `prototype`）與靜態方法的繼承（子類別本身指向父類別）。`super()` 必須在使用 `this` 之前呼叫，因為在 class 的語意中 `this` 是由父類別建構函式建立的。這也是為什麼子類別的建構函式如果不呼叫 `super()` 就存取 `this` 會拋錯——用 `function` 寫的建構函式沒有這個保護。

## 面試回答方式

先把原型鏈講成一句話——屬性查找沿著原型鏈往上委派，不是複製，這是理解一切的基礎。接著分清 `prototype`、`__proto__`、`constructor` 三者各自屬於誰，這是最常混淆的地方。`new` 的四個步驟要能講出來，因為很多現象都由它解釋。回答 class 是不是語法糖時，答案要精確：**大部分是，但有四個實質差異**（方法不可枚舉、必須用 `new`、強制嚴格模式、不提升），這比單純回答「是語法糖」有深度。加分點是說明原型上的方法為所有實例共用（效能優勢），以及 `instanceof` 在跨 iframe 時會失效、該用 `Array.isArray` 或 `toString.call`。

## 講稿

每個物件都有一個連結指向它的原型。存取屬性的時候，如果自己身上沒有，就沿著這條鏈往上找，一路找到 Object.prototype，再上去是 null。

我覺得最重要的一句話是，這是委派查找，不是複製。所有實例共用原型上的同一份方法，一萬個實例也只有一份，這是原型繼承最大的效能優勢。相對地，如果在建構函式裡寫 this 點某方法等於一個函式，那每個實例都會各有一份。

有三個名詞容易混。prototype 是函式才有的，指向用它 new 出來的物件會使用的原型。至於物件實際的原型，正式取得方式是 Object.getPrototypeOf。constructor 則是原型物件上指回函式的那個屬性。

new 做的事情有四步，建立新物件、把原型設成建構函式的 prototype、以它為 this 執行建構函式、然後回傳。很多現象用這四步都解釋得通。

至於 class 是不是語法糖，我會說大部分是，但有幾個實質差異。方法不可枚舉、必須用 new 呼叫、類別體內強制嚴格模式，而且不會被提升。所以它比 function 建構函式更嚴格也更安全。

## 常見追問

### 原型繼承和類別繼承有什麼本質差異？

**核心答案**：**類別繼承是「複製藍圖」，原型繼承是「連結到實際物件」**。傳統類別繼承中，類別是一份靜態的定義，實例化時依照定義建立物件。原型繼承中，物件直接連結到**另一個實際存在的物件**，沒有藍圖這一層，而且這個連結可以在執行期改變。這讓 JavaScript 的物件模型更動態，代價是更容易失控。

**詳細解析**：實務上的差異體現在幾個地方。**動態性**：可以在執行期修改原型讓所有實例立刻獲得新方法，這在類別語言中做不到。**組合優於繼承**更自然：JavaScript 可以用 `Object.assign` 把多個物件的方法混入一個原型，實現類似多重繼承的效果，而不需要複雜的類別階層。**沒有真正的私有**：直到 `#` 私有欄位出現前，慣例上用底線前綴表示私有，但沒有強制力。在面試中能指出「JavaScript 的 class 是建立在原型之上的一層語法，底層仍然是原型鏈」是關鍵——這解釋了為什麼理解原型仍然必要，即使你日常只寫 class。

**面試回答方式**：用「複製藍圖 vs 連結到實際物件」這一組對比講清本質差異。接著給三個實務體現：動態性、混入式組合、私有性的演變。加分點是強調 class 底層仍是原型鏈，所以理解原型不是歷史包袱而是必要的。

### 怎麼實現一個物件的深層複製？

**核心答案**：現代環境優先用 **`structuredClone`**——它是瀏覽器與 Node 內建的標準方法，支援循環參照、`Map`、`Set`、`Date`、`ArrayBuffer` 等結構。不支援時再考慮函式庫。**`JSON.parse(JSON.stringify(obj))` 是最常見但最有問題的做法**：它會丟失 `undefined` 與函式、把 `Date` 變成字串、無法處理循環參照（直接拋錯）、也會遺失原型（複製出來的是普通物件）。

**詳細解析**：手寫深拷貝的重點是三件事：**遞迴處理巢狀結構**、**用 `WeakMap` 記錄已複製的物件以處理循環參照**、以及**依型別分別處理**（陣列、`Map`、`Set`、`Date`、正規表達式各有建構方式）。要注意 `structuredClone` 也有限制——**無法複製函式、DOM 節點與原型鏈**，遇到函式會拋錯。所以選擇時要先問「這個物件裡有什麼」。實務上更值得問的是**真的需要深拷貝嗎**：多數情況下淺拷貝加上不可變的更新模式（每次修改都建立新的物件而不是就地修改）更有效率，也更符合現代前端的資料流設計。

**面試回答方式**：先推薦 `structuredClone` 並列出 JSON 方法的四個具體缺陷。接著給手寫時的三個要點（遞迴、WeakMap 處理循環、依型別處理）。加分點是指出 `structuredClone` 也無法處理函式與原型，以及反問「真的需要深拷貝嗎」，多數情況淺拷貝加不可變更新更好。

### `Object.create(null)` 和 `{}` 有什麼不同？

**核心答案**：`Object.create(null)` 建立的物件**沒有原型**，所以完全不繼承 `Object.prototype` 上的任何東西——沒有 `toString`、沒有 `hasOwnProperty`、也沒有 `__proto__` 這個存取器。`{}` 則以 `Object.prototype` 為原型。前者的價值在於當成**純粹的字典**使用：不會有任何鍵和繼承來的屬性名衝突，也不會有原型污染的風險。

**詳細解析**：實際的問題場景是**用物件當雜湊表時的鍵衝突**——如果使用者輸入的鍵剛好叫 `toString` 或 `constructor`，用 `{}` 時 `obj[key]` 會拿到繼承來的函式而不是 `undefined`，導致判斷「這個鍵存不存在」時出錯。更嚴重的是**原型污染攻擊**：如果程式碼會依使用者輸入設定巢狀屬性，攻擊者可以透過 `__proto__` 這個鍵修改 `Object.prototype`，影響整個應用程式。防禦方式包括用 `Object.create(null)`、或直接改用 **`Map`**——`Map` 的鍵可以是任意型別、沒有原型問題、而且有明確的 `size` 與迭代順序，是當代更推薦的做法。

**面試回答方式**：先講差別（有沒有原型）與它的用途（純粹字典）。用「鍵剛好叫 toString」這個具體場景說明問題。加分點是提到原型污染攻擊這個真實的安全議題，並指出改用 `Map` 是更好的現代做法。
