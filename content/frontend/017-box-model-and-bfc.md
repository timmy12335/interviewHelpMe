# 題目

`box-sizing` 的兩個值差在哪？什麼是 BFC，它解決什麼問題？

## 核心答案

盒模型的差別在於 **`width` 算到哪裡**。`content-box`（規範預設）的 `width` **只包含內容區**，`padding` 與 `border` 往外加，所以設定 `width: 200px` 加上左右各 20px 的 padding，實際佔用 240px。`border-box` 的 `width` **包含內容加 padding 加 border**，設 200px 就是 200px，內容區自動縮小。實務上幾乎所有專案都會全域設成 `border-box`，因為它符合直覺、也讓排版計算單純。**BFC（區塊格式化上下文）**是一個獨立的版面計算區域——**內部的元素不會影響外部，外部也不會影響內部**。它解決三個經典問題：**外邊距合併**（相鄰或父子元素的垂直外邊距會合併成一個，把其中一方變成 BFC 就不會）、**浮動塌陷**（父元素高度不含浮動子元素，父元素成為 BFC 後就會包含）、以及**文字環繞浮動元素**（讓相鄰區塊成為 BFC 就不會被浮動元素侵入）。觸發方式包括 `overflow` 不為 `visible`、`display: flow-root`（最乾淨、沒有副作用）、`float`、絕對定位、以及 flex 或 grid 容器的子項。

## 詳細解析

**外邊距合併的三種情況**：**相鄰兄弟元素**之間的上下外邊距合併成兩者的較大值；**父子元素**之間，如果父元素沒有 border、padding 或 BFC 隔開，子元素的上外邊距會「跑出去」變成父元素的；**空元素**自身的上下外邊距也會合併。第二種最常造成困惑——明明給子元素設了上邊距，結果整個父元素被推下來了。解法是給父元素加上 `display: flow-root`，或用 padding 取代 margin。

**display: flow-root 是現代的最佳解**：過去清除浮動用 `overflow: hidden`，但它有副作用——會裁切超出容器的內容（陰影、下拉選單都會被切掉）。`flow-root` 的唯一作用就是建立 BFC，沒有其他副作用，是專門為此設計的值。清除浮動的另一個老方法是偽元素加 `clear: both`，仍然可用但不如 `flow-root` 簡潔。

**flex 與 grid 讓 BFC 的重要性下降**：現代排版多半用 flex 或 grid，而 **flex 與 grid 的子項不會有外邊距合併問題**，浮動也基本上不再用於排版。所以 BFC 現在更多是**理解舊程式碼與排查怪異行為**時需要的知識，而不是日常主動使用的工具。面試中能點出這個演變，會顯示你的知識是有時序的。

**替代盒模型仍有邊界情況**：`border-box` 讓 `width` 包含 padding 與 border，但**不包含 `margin`**——外邊距永遠在盒子外面。所以「兩個 50% 寬的元素加上 margin 就換行了」這個經典問題，`border-box` 解決不了，要用 flex 的 `gap` 或 `calc` 處理。理解這條界線可以避免誤以為 `border-box` 是萬靈丹。

**尺寸的其他相關屬性**：`min-width` 與 `max-width` 的優先權高於 `width`；flex 子項有一個容易踩到的預設 `min-width: auto`，它會讓子項不能縮到比內容還小，導致「明明設了 `overflow: hidden` 還是被撐開」——解法是明確設 `min-width: 0`。這是實務上排查版面被撐爆時最常見的答案。

## 面試回答方式

盒模型用「**`width` 算到哪裡**」一句話講清，並說明實務上全域用 `border-box` 的理由。BFC 要用「**內部與外部互不影響的獨立版面區域**」來定義，然後直接連到它解決的三個問題（外邊距合併、浮動塌陷、文字環繞）。觸發方式優先講 **`display: flow-root`**，並說明它比 `overflow: hidden` 好在沒有裁切內容的副作用。加分點有三個：父子外邊距合併是最常造成困惑的情況；**flex 與 grid 的子項不會有外邊距合併**，所以 BFC 現在更多用於理解舊程式碼；以及 flex 子項的 `min-width: auto` 是版面被撐爆最常見的原因，解法是設 `min-width: 0`。

## 講稿

盒模型的差別就是 width 算到哪裡。content-box 只包含內容，padding 跟 border 往外加，所以設兩百加上左右各二十的 padding，實際佔兩百四。border-box 的 width 包含 padding 跟 border，設兩百就是兩百。我會全域設成 border-box，因為它符合直覺，排版計算單純很多。

BFC 是一個獨立的版面計算區域，內部的元素不會影響外部，外部也不會影響內部。

它解決三個經典問題。第一是外邊距合併，最容易困惑的是父子那種，明明給子元素設上邊距，結果整個父元素被推下來。第二是浮動塌陷，父元素高度不含浮動的子元素。第三是文字會環繞浮動元素。

觸發方式我會優先用 display 的 flow-root，因為它唯一的作用就是建立 BFC，沒有副作用。以前大家用 overflow hidden，但它會把超出容器的陰影或下拉選單裁掉。

不過我想補一句，現在排版多半用 flex 或 grid，而它們的子項本來就不會有外邊距合併，浮動也很少用了。所以 BFC 現在比較是拿來理解舊程式碼跟排查怪異行為。

## 常見追問

### 為什麼 flex 子項設了 overflow: hidden 還是被內容撐開？

**核心答案**：因為 flex 子項的 **`min-width` 預設是 `auto`**，意思是「不能縮到比內容的最小尺寸還小」。長字串或不換行的內容會撐出一個最小寬度，讓子項無法縮小，`overflow: hidden` 因此沒有作用（容器本身就變大了，沒有溢出可裁）。解法是明確設定 **`min-width: 0`**（垂直方向則是 `min-height: 0`）。

**詳細解析**：這是實務上最常見的版面被撐爆原因之一，典型場景是「側邊欄固定寬、主內容區自適應，但主內容裡有一段長 URL 或寬表格，結果整個版面被推爆」。同樣的問題也出現在 grid 中——grid 軌道的 `minmax` 預設下限是 `auto`，要用 `minmax(0, 1fr)` 而不是 `1fr` 才能真正允許縮小。除了設 `min-width: 0`，也可以在內容上加 `overflow-wrap: break-word` 讓長字串換行，兩者常常一起用。能一次講出 flex 與 grid 兩邊的對應寫法，會顯示這是你實際踩過的問題。

**面試回答方式**：直接給根因（`min-width: auto`）與解法（設 `min-width: 0`），並用側邊欄加長 URL 這個具體場景說明。加分點是給出 grid 的對應寫法 `minmax(0, 1fr)`，以及配合 `overflow-wrap` 讓長字串換行。

### overflow: hidden 清除浮動有什麼副作用？

**核心答案**：**它會裁切所有超出容器的內容**——`box-shadow`、`transform` 放大的元素、絕對定位的下拉選單或提示框，只要超出容器範圍就會被切掉。它建立 BFC 只是副產物，裁切才是它的本職。所以只是要建立 BFC 時應該用 **`display: flow-root`**，它專為此設計、沒有其他影響。

**詳細解析**：另一個較少被提到的副作用是**它會影響捲動行為**——`overflow: hidden` 的容器在某些情況下仍可透過程式或鍵盤捲動，而且會成為絕對定位子元素的捲動祖先，可能讓 `position: sticky` 的行為不如預期。實務上遇到「sticky 沒作用」時，檢查祖先鏈上有沒有 `overflow` 不為 `visible` 的容器是標準的排查步驟。至於瀏覽器支援，`flow-root` 在現代瀏覽器已普遍支援，除非要支援很舊的環境，否則沒有理由再用 `overflow: hidden` 來清除浮動。

**面試回答方式**：明確指出裁切才是它的本職、建立 BFC 只是副產物，並列出會被切掉的東西。加分點是提到它會成為捲動祖先，導致 `position: sticky` 失效——這是很有辨識度的實務經驗。

### content-box 還有什麼場合會用到？

**核心答案**：多數專案全域設 `border-box` 之後就很少用到，但仍有兩類情況。一是**需要精確控制內容區尺寸**——例如要讓內容區恰好等於某個圖片的原始尺寸，用 `content-box` 直接設就好，不必扣掉 padding 與 border。二是**與第三方元件整合**——某些函式庫的樣式假設了 `content-box`，全域覆蓋可能讓它們的版面錯亂，這時要針對那個範圍還原。

**詳細解析**：全域設定的標準寫法是把 `box-sizing: border-box` 設在根元素、再讓所有元素與偽元素繼承，這樣第三方元件若需要不同的值，只要在它的容器上覆寫就會連帶影響其子孫，比直接對所有元素硬設更好調整。另外要知道 **`box-sizing` 不影響 `margin`**，也不影響 `width: auto` 時的行為——區塊元素預設的自適應寬度本來就會扣掉 padding 與 border。理解這一點可以避免一個常見誤解：以為所有排版問題都能靠切換盒模型解決。

**面試回答方式**：給出兩類仍需要 `content-box` 的情況。加分點是說明全域設定應該用「根元素設定加繼承」的寫法，方便局部覆寫，以及澄清 `box-sizing` 不影響 margin 與 `width: auto` 的行為。
