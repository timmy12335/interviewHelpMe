# 題目

什麼時候用 Flexbox、什麼時候用 Grid？兩者可以混用嗎？

## 核心答案

判準是**一維還是二維**。**Flexbox 是一維的**——沿著單一主軸排列元素，適合工具列、按鈕組、導覽列、卡片內部的內容排列，以及任何「一排東西要分配空間」的情況。**Grid 是二維的**——同時定義行與列，適合整體頁面骨架、儀表板、圖片牆這類**列與欄都要對齊**的版面。第二個實用判準是**由內容決定還是由容器決定**：Flexbox 傾向讓**內容大小決定分配**（子項的尺寸影響最終排列），Grid 則是**先畫好格線再放內容**。所以「不確定有幾個項目、讓它們自己排」用 Flex；「版面結構是固定的，內容填進去」用 Grid。兩者**設計上就是要混用**——外層用 Grid 定骨架，每個區塊內部用 Flex 排內容，這是最常見也最合理的組合。

## 詳細解析

**flex: 1 到底代表什麼**：它是 `flex-grow: 1`、`flex-shrink: 1`、`flex-basis: 0%` 的縮寫。關鍵是 **`flex-basis: 0%`** ——它讓分配從零開始，所以多個 `flex: 1` 的子項會**等寬**。相對地 `flex: auto`（`flex-basis: auto`）是先依內容大小分配、再把剩餘空間平均分，所以內容長的會比較寬。這兩者的差異是實務上「為什麼我的欄位沒有等寬」最常見的答案。

**Grid 的 minmax 與自動填充**：`repeat(auto-fill, minmax(200px, 1fr))` 這個組合可以做出**不需要媒體查詢的響應式格線**——容器夠寬就放更多欄，不夠就自動減少。`auto-fill` 與 `auto-fit` 的差別在於沒有內容時是否保留空軌道，`auto-fit` 會摺疊空軌道讓現有項目撐滿。這是 Grid 相對 Flexbox 最有價值的能力之一。

**對齊屬性的兩套命名**：`justify-*` 處理**主軸**（Grid 中是列方向即水平），`align-*` 處理**交叉軸**。容易混淆的是 Flexbox 中主軸方向會隨 `flex-direction` 改變——設成 `column` 之後 `justify-content` 變成控制垂直方向。Grid 則固定：`justify` 是水平、`align` 是垂直，比較不容易搞錯。`place-items` 與 `place-content` 是兩者的簡寫。

**gap 取代了 margin 的間距處理**：以前用 margin 加上「最後一個不要」的選擇器來做間距，現在 `gap` 直接由容器控制，且**不會在邊緣產生多餘的間距**。它現在在 Flexbox 中也普遍支援，是應該優先使用的做法。

**什麼時候兩者都不適合**：**文字流動的排版**（文章中圖片環繞文字）仍然用 `float` 或 `shape-outside`；**元素重疊**（卡片上的標籤、覆蓋層）用絕對定位或 Grid 的重疊區域；**依內容多寡自動換行的標籤雲**用 Flexbox 加 `flex-wrap` 就好，用 Grid 反而綁手綁腳。認得出這些邊界，比會用兩者更能顯示判斷力。

## 面試回答方式

用「**一維還是二維**」這個判準開場，並立刻補上第二個判準——內容決定還是容器決定，這比只講維度更能指導實際選擇。明確表態**兩者本來就該混用**：外層 Grid 定骨架、內部 Flex 排內容。加分點有三個：講清楚 **`flex: 1` 與 `flex: auto` 的差別**（`flex-basis` 是 0 還是 auto），這是「為什麼沒有等寬」最常見的原因；介紹 `repeat(auto-fill, minmax(...))` 做出不用媒體查詢的響應式格線；以及主動說出**兩者都不適合的場景**（文字環繞、元素重疊），顯示你知道工具的邊界。

## 講稿

我的第一個判準是一維還是二維。Flexbox 是一維的，沿著單一主軸排列，適合工具列、按鈕組、卡片內部的內容。Grid 是二維的，同時定義行跟列，適合頁面骨架、儀表板這種列跟欄都要對齊的版面。

第二個判準是由內容決定還是由容器決定。Flexbox 傾向讓內容大小影響分配，Grid 是先畫好格線再把內容放進去。所以不確定有幾個項目、讓它們自己排，我用 Flex。版面結構固定、內容填進去，我用 Grid。

而且這兩個本來就是設計來混用的。外層用 Grid 定骨架，每個區塊裡面用 Flex 排內容，這是最常見的組合。

有個細節我想提，flex 設成一其實是 grow 一、shrink 一、basis 零。關鍵在 basis 是零，所以多個子項會等寬。如果寫 flex auto，basis 是 auto，會先依內容大小分配再分剩餘空間，內容長的就比較寬。這是為什麼我的欄位沒有等寬最常見的答案。

另外 Grid 有個很好用的組合，repeat 配 auto-fill 跟 minmax，可以做出不需要媒體查詢的響應式格線，容器夠寬就多放幾欄。

## 常見追問

### auto-fill 和 auto-fit 差在哪？

**核心答案**：差在**項目不足以填滿時的行為**。`auto-fill` 會**保留空軌道**——容器能放五欄但只有兩個項目時，仍然建立五個軌道，項目靠左排、右邊留三個空位。`auto-fit` 會**摺疊空軌道**，讓現有的兩個項目撐滿整個容器寬度。項目數量足以填滿時，兩者行為完全相同。

**詳細解析**：選擇取決於**你想要的視覺結果**。商品列表通常用 `auto-fill`，因為項目保持一致的寬度，不會因為某一列只有兩個就變得特別寬，視覺上比較穩定。而如果內容天生就少（例如首頁的三個特色區塊），`auto-fit` 讓它們撐滿看起來比較完整。要注意搭配 `minmax` 時，第二個值用 `1fr` 才有伸縮空間；如果寫成固定值，兩者的差別就看不出來。這題也常被拿來確認你是真的用過 Grid 還是只讀過語法，因為單看名稱很難分辨。

**面試回答方式**：用「項目不足時保留還是摺疊空軌道」一句話講清，並說明項目足夠時兩者相同。接著給選擇建議：商品列表用 `auto-fill` 保持寬度一致，內容天生少的用 `auto-fit` 撐滿。加分點是提醒必須搭配 `minmax` 的 `1fr` 才看得出差別。

### 要讓一個元素在容器中水平垂直置中，你會怎麼寫？

**核心答案**：最簡潔的是 **Grid 加 `place-items: center`** ——兩個屬性就完成，而且不受子元素數量影響。Flexbox 的版本是 `display: flex; justify-content: center; align-items: center`，同樣可靠。舊時代的絕對定位加 `transform: translate(-50%, -50%)` 仍然可用，主要價值在於**置中的元素要脫離文件流**（例如覆蓋整個畫面的對話框）時。

**詳細解析**：實務上要注意幾個邊界。**容器需要有高度**——如果容器高度由內容決定，垂直置中沒有意義（容器就是內容的高度）。要在整個視窗置中，容器要設 `min-height: 100vh`，而在行動裝置上更好的選擇是 `100dvh`（動態視窗高度），因為 `100vh` 在網址列收合時會造成跳動。另外**單行文字的垂直置中**可以直接用 `line-height` 等於容器高度，這在按鈕與標籤上仍然常用且成本最低。能依情境選出成本最低的做法，比背出四種置中方式更有價值。

**面試回答方式**：給 Grid 的 `place-items: center` 當首選並說明理由，再給 Flex 與絕對定位版本各自的適用時機。加分點是提到容器必須有高度、行動裝置上 `100dvh` 比 `100vh` 好，以及單行文字用 `line-height` 成本最低。

### 響應式版面現在還需要媒體查詢嗎？

**核心答案**：**需要，但比例大幅下降**。許多情況可以用**內在響應**的手段取代——`minmax` 加 `auto-fill` 的自動格線、`flex-wrap` 的自動換行、`clamp()` 讓字級與間距隨視窗平滑變化、`min()` 與 `max()` 限制尺寸。這些的優點是**依可用空間反應而非依視窗寬度**，所以元件放在側邊欄或主內容區都能正確表現。媒體查詢仍然需要的是**版面結構的根本改變**（側邊欄在手機上變成抽屜、導覽列變成漢堡選單）。

**詳細解析**：更根本的演進是**容器查詢**——讓元件依**自己所在容器的寬度**而非視窗寬度來調整樣式。這解決了元件化開發的核心痛點：同一個卡片元件放在寬的主內容區與窄的側邊欄應該有不同版面，但視窗寬度是一樣的，媒體查詢無能為力。容器查詢現在已在主流瀏覽器可用，是設計元件庫時應該優先考慮的工具。理解「**從視窗導向轉為元件導向**」這個趨勢，比記住斷點數值更能顯示你跟得上現況。

**面試回答方式**：明確說仍需要但比例下降，並列出取代它的內在響應手段與它們的優點（依可用空間而非視窗）。指出媒體查詢仍用於版面結構的根本改變。加分點是介紹容器查詢並說明它解決的元件化痛點，把趨勢總結為從視窗導向轉為元件導向。
