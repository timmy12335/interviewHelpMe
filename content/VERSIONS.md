# 版本對照表

**資料查核日期：2026-09-06。** 下面的版本會過期，這份表的用途是讓你知道題庫的敘述
是站在什麼位置上寫的，而不是拿來當作最新消息的來源。

## 題庫怎麼處理版本

**題目裡的版本號幾乎都是「這個東西什麼時候出現的」，那種敘述不會過期。**「JDK 21 引入
虛擬執行緒」「MySQL 5.5 之後 InnoDB 成為預設引擎」「Kafka 用 KRaft 取代 ZooKeeper」——
這些是歷史事實，寫死版本號反而是對的，讀者可以據此判斷自己的環境有沒有這個功能。

**會過期的是另一種句子：「目前最新」「現在的預設」「還是預覽功能」。** 這類敘述綁的是
撰寫當下的狀態。維護時要盯的是它們，而不是把所有版本號都往上改——把「JDK 21 引入虛擬
執行緒」改成 25 反而讓內容變錯。

## 幾個狀態會變、值得定期回頭確認的點

**Java 的預覽功能。** 預覽功能會轉正，轉正之後「這是預覽功能，不該用在生產」就變成錯的。
截至 2026-09：

- **作用域值（Scoped Values）已於 JDK 25 轉正**（[JEP 506](https://openjdk.org/jeps/506)）。
- **結構化併發到 JDK 26 仍是預覽**（[JEP 525](https://openjdk.org/jeps/525)，第六次預覽），
  且 API 換過形狀——`StructuredTaskScope.open(Joiner)` 取代了 JDK 21 的
  `ShutdownOnFailure` / `ShutdownOnSuccess` 子類別。

**Kubernetes 的功能成熟度。** alpha → beta → GA 的過程中，「有沒有預設開啟」會變。
原生 sidecar（`initContainers` 加 `restartPolicy: Always`）是 1.28 alpha、1.29 預設開啟、
**1.33 正式 GA**。

**預設值的變更。** 例如 Redis 的混合持久化（`aof-use-rdb-preamble`）在 4.0 引入時預設
關閉，**5.0 起才預設開啟**——「什麼時候有」與「什麼時候變成預設」是兩件事，題庫裡兩者
都會寫出來。
