# 題目

你怎麼看待從個人貢獻者轉成帶人的角色？

## 核心答案

這個轉換最大的挑戰是「成功的定義變了」——個人貢獻者的成就感來自自己交付的東西；而主管的產出是團隊的產出，而且回饋週期長得多、也模糊得多。沒有意識到這一點的人，會不自覺地繼續搶著自己做事，然後感到挫折。

**具體要放下的有三樣**：**「我做比較快」的誘惑**（那會讓團隊無法成長，也讓你成為瓶頸）、**對細節的完全掌控**（你會不知道很多事，那是正常的）、**以及即時的成就感。**

**具體要學會的有三樣**：**用問題而非答案引導**、把資訊在向上與向下之間翻譯、**以及處理人的問題**（那不是「軟技能」而是這個角色的核心工作）。

而在面試中被問到這題時，最重要的是說清楚你的動機——「因為想升遷」或者「因為資深工程師的下一步就是這個」是弱的；而「我發現自己在幫助別人變好時得到的滿足，比自己解決問題更大」是強的。

## 詳細解析

「我做比較快」是新手主管最常見的陷阱：短期確實是——但每次你搶著做，團隊就少一次成長的機會，而你的時間會被填滿到無法做只有你能做的事；而「只有你能做的事」（方向、優先順序、跨團隊的協調、人的發展）恰恰是不緊急但重要的。能說出「我學會了容忍別人用比我慢的方式做完，因為第三次他就比我快了」的候選人，展示的是真正的轉換。

「回饋週期變長」需要心理上的調整：寫程式碼幾分鐘就知道對不對——而一個人事決定或者一個方向的調整，可能六個月後才看得出結果；這會讓習慣即時回饋的人感到焦慮。應對的方式是建立中間的指標（團隊的交付節奏、成員的成長、離職率）而不是等最終的結果。

**「翻譯」是主管最被低估的工作**：把上層模糊的策略轉成團隊能執行的目標、把團隊的技術現實轉成上層能理解的取捨——這兩個方向的翻譯，決定了團隊是在做有意義的事還是在瞎忙；而做不好的主管，團隊會覺得指令莫名其妙，上層會覺得團隊很慢。

「這條路不是唯一的晉升路徑」值得說清楚：多數成熟的公司有平行的技術路線（資深、主任、首席工程師）——而選擇管理職應該是因為你想做那些事，而不是因為那是唯一往上的路；在面試中展現這個自覺，比表達「我想當主管」更成熟。

## 面試回答方式

先指出最大的挑戰是成功的定義變了，再給要放下的三樣與要學會的三樣。加分點有四個：**「我做比較快」的陷阱**與「容忍別人慢，因為第三次他就比我快了」這個具體的轉換；回饋週期變長需要建立中間指標；**翻譯是最被低估的工作**，而做不好會讓團隊覺得指令莫名其妙、上層覺得團隊很慢；以及**這條路不是唯一的晉升路徑**。最後強調動機的說明比意願的表達更重要。

## 講稿

我覺得最大的挑戰是成功的定義變了。個人貢獻者的成就感來自自己交付的東西，而主管的產出是團隊的產出，回饋週期長很多也模糊很多。

我自己在代理帶團隊的那半年，最難的是放下我做比較快這個念頭。短期確實是我做比較快，但每次我搶著做，那個人就少一次成長的機會，而我的時間會被填滿到沒辦法做只有我能做的事。

我後來的心得是要容忍別人用比我慢的方式做完。因為到第三次的時候，他通常就比我快了，而且那件事從此不需要我。

第二個我學到的是翻譯。把上層模糊的策略轉成團隊能執行的目標，還有把團隊的技術現實轉成上層能理解的取捨。做不好的話，團隊會覺得指令莫名其妙，上層會覺得團隊很慢。

至於為什麼想走這條路，我的理由是我發現幫助別人變好給我的滿足感，比自己解決問題更大。而不是因為那是唯一往上的路。

## 常見追問

### 如果發現自己不適合帶人呢？

**核心答案**：及早承認並轉回技術路線，那不是失敗。很多優秀的工程師試過管理後發現不喜歡——而在成熟的公司裡，這種轉換是被接受的；真正的問題是明知不適合卻因為面子或薪資而留在那個位置，因為那對團隊的傷害是持續的。

**詳細解析**：**「不適合的表現通常很明確」**：持續地逃避人的對話（績效、衝突、壞消息）、把大部分時間花在自己寫程式碼上、或者在做完管理工作後感到消耗而非充實——這些訊號如果持續半年以上，那值得認真考慮；而一個實用的檢查是「我這週最有成就感的事，是我自己做的還是團隊做的」。在多數公司裡，回到技術路線並不會損失太多——帶過人的技術專家反而更有價值，因為他理解組織如何運作；而這段經驗會讓你成為一個更好的協作者，即使你不再帶人。

**面試回答方式**：給明確的立場（**及早承認並轉回，那不是失敗**）並指出真正的問題是明知不適合卻留著。核心加分點是**不適合的表現通常很明確**並列出具體的訊號，以及一個實用的檢查（我這週最有成就感的事，是自己做的還是團隊做的）。收在正面的判斷：帶過人的技術專家反而更有價值，因為他理解組織如何運作。

### 帶人之後技術會不會退步？

**核心答案**：深度會，但廣度和判斷力會增加。你不會再有時間鑽研一個框架的細節——但你會接觸更多的系統、看到更多的決策後果、也更清楚什麼樣的技術選擇在組織裡真的能落地；而這種判斷力是純技術路線較難累積的。

**詳細解析**：「保持技術手感的可行做法」有幾種：**參與設計評審而非實作**（那需要理解但不需要大塊的時間）、**接一些非關鍵路徑的小任務**（不要接關鍵路徑，因為你的時間不可預測）、**以及認真做 code review**。而要避免的是「搶著做最有趣的技術工作」——那會讓團隊失去成長的機會，也讓你的時間被壓縮。一個更根本的心態是「你的技術能力現在的用途是判斷與指導，而不是產出」；理解這個轉變之後，「退步」的焦慮會小很多——因為你評估自己的標準也應該跟著改變。

**面試回答方式**：給誠實的答案（深度會退，但廣度與判斷力會增加）並說明後者的價值。核心加分點是**保持技術手感的可行做法**（設計評審、非關鍵路徑的小任務、認真做 code review）與要避免搶著做最有趣的技術工作。收在心態：你的技術能力現在的用途是判斷與指導而非產出——理解這個轉變之後，「退步」的焦慮會小很多。

### 沒有帶人經驗但想應徵這種職位怎麼辦？

**核心答案**：用「實質的領導經驗」取代「正式的頭銜」。主導過跨團隊專案、帶過實習生或新人、負責過某個領域的技術方向、或者在主管休假時代理過——**這些都是真實的證據**；而重點是說明「你做了什麼讓別人變得更有效」而非「你管過幾個人」。

**詳細解析**：「領導力在有頭銜之前就可以展示」：事實上多數公司在晉升時看的正是「你已經在做這件事了」而非「你有意願做」——所以想往這個方向走的人，正確的策略是先開始做：主動接下協調的工作、幫助新人上手、在團隊缺乏方向時提出一個計畫。這也回答了「先有雞還是先有蛋」的問題：你不需要等一個頭銜才能開始練習這些能力；而當機會出現時，已經在做的人是自然的人選。在面試中能舉出這類「沒有職權但實際在領導」的例子，比任何對領導力的抽象描述都有說服力——因為它證明了你的動機是真的，而不是為了升遷。

**面試回答方式**：給策略（用實質的領導經驗取代正式的頭銜）並列出可用的例子，強調重點是你做了什麼讓別人變得更有效。核心加分點是領導力在有頭銜之前就可以展示——多數公司晉升時看的正是「你已經在做這件事了」，並給出具體的起步方式。收在說服力：「沒有職權但實際在領導」的例子證明了你的動機是真的而不是為了升遷。
