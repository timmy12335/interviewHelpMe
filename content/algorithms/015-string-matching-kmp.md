# 題目

KMP 到底省掉了什麼？什麼情況下你會選滾動雜湊而不是 KMP？

## 核心答案

暴力比對的浪費在於匹配失敗後把主串的指針退回去重來。KMP 的核心洞察是：失敗前已經匹配成功的那一段，它自己的資訊就足以告訴你下一次該從模式串的哪裡繼續——具體來說，是找出「已匹配部分中最長的、既是前綴又是後綴的長度」，模式串跳到那個位置繼續，**主串指針永遠不回退**。這個資訊預先算成 `next` 陣列（也叫部分匹配表），預處理 O(m)、比對 O(n)，總共 O(n + m)。**滾動雜湊**（Rabin-Karp）走的是完全不同的路：把長度 m 的子串映射成一個數字，滑動視窗時用 O(1) 更新雜湊值，只在雜湊相同時才做一次真正的字元比對。它的優勢是**天然支援多模式串同時比對**與**二維擴展**，代價是有雜湊碰撞（需要二次驗證）且最壞可能退化。選型準則：單模式串精確匹配用 KMP，多模式串或需要快速比較大量子串用滾動雜湊，模式串很多且固定則用 AC 自動機。

## 詳細解析

**next 陣列的語意要講對**：`next[i]` 是「模式串前 i 個字元中，最長的相同前綴與後綴的長度」。它的意義是：如果匹配到第 i 個位置失敗，那麼主串中已經匹配的那 i 個字元的**後綴**，正好等於模式串的某個**前綴**，所以模式串可以直接滑到那個前綴的後面繼續，而不用整個重來。理解這句話比背程式碼重要得多——面試官問 KMP 時，真正在測的就是你能不能解釋這件事。

next 陣列自己也是用 KMP 的方式算出來的：計算 `next` 時是拿模式串跟自己比對，用已經算好的較短前綴資訊去推導較長的，是一個自我遞推的過程。這個「用自己匹配自己」的結構是 KMP 最漂亮也最難懂的部分。實作上的常見坑是 `next` 陣列的定義有多種變體（有的存長度、有的存下標、有的整體位移一格），不同教材混用會導致邊界差一格——**選定一種定義並貫徹**是唯一的解法。

滾動雜湊的更新公式與碰撞處理：把子串看成一個 base 進位的數字，視窗右移時「減掉最高位、整體乘以 base、加上新的最低位」，一次 O(1)。要選一個**大質數當模數**降低碰撞機率，並且**必須做二次驗證**——雜湊相同時再逐字元比對一次，因為碰撞會產生錯誤答案。有心人可以針對固定的 base 與模數構造碰撞，所以安全敏感的場景要隨機化參數。這也是滾動雜湊「期望 O(n)、最壞 O(nm)」的來源。

滾動雜湊真正不可替代的場景：一是**同時比對大量模式串**——把所有模式串的雜湊放進集合，主串滑動時每個位置只要查一次集合。二是**找最長重複子串**——配合二分答案，二分子串長度、用滾動雜湊檢查是否存在重複，總共 O(n log n)，這是 KMP 做不到的。三是**二維模式匹配**（在矩陣中找子矩陣），把每一行先做一次滾動雜湊，再對行的雜湊序列做一次，KMP 很難自然擴展到二維。

**實務上先問「標準庫夠不夠」**：真實工程裡幾乎沒有人手寫 KMP，語言內建的 `indexOf` 或 `find` 已經對常見情況優化（許多實作用的是 Boyer-Moore 或其變形，靠從右往左比對加上壞字元跳躍，在字符集大時平均比 KMP 更快）。面試中主動說明這一點，並補上「需要手寫的情況通常是要在比對過程中做額外處理、或要處理串流資料」，會讓回答顯得務實而不是為了炫技。

## 面試回答方式

先講暴力解錯在哪——主串指針回退是浪費，因為已匹配的部分自帶資訊。接著用一句話說明 KMP 的核心：找出已匹配部分中最長的相同前後綴，模式串跳過去、主串不回退。`next` 陣列的定義要講得精確，這是這題唯一的技術重點。複雜度給 O(n + m) 並說明預處理與比對各自的來源。然後主動提供第二條路線：滾動雜湊，並講清楚它的三個不可替代場景（多模式、最長重複子串配二分、二維匹配）與代價（碰撞需二次驗證）。加分點是坦白說實務上會先用標準庫，並說明什麼情況才需要自己實作。

## 講稿

暴力比對的浪費在哪，在於匹配失敗之後，主串的指針要退回去重來。

KMP 的核心洞察是，失敗之前已經匹配成功的那一段，它自己就帶著足夠的資訊。具體來說，我要找的是已匹配部分裡面最長的、既是前綴又是後綴的那一段長度。因為主串已匹配的後綴，正好等於模式串的某個前綴，所以模式串直接滑到那個前綴後面繼續就好，主串的指針永遠不回退。

這個資訊我會預先算成 next 陣列，預處理是 m、比對是 n，總共線性。

實作上有個很常見的坑，next 陣列的定義有好幾種變體，有的存長度、有的存下標、有的整體位移一格。混用不同教材就會差一格。我的做法是選定一種定義然後貫徹。

另外一條路線是滾動雜湊。把長度固定的子串映射成一個數字，視窗右移的時候常數時間更新。它的價值不在單模式，而在可以同時比對大量模式串，也可以配合二分答案找最長重複子串，甚至擴展到二維。代價是有碰撞，雜湊相同的時候必須再逐字元驗證一次。

## 常見追問

### 實務上要在一段文字裡找子字串，你會手寫 KMP 嗎？

**核心答案**：**不會**，優先用語言內建的 `indexOf` 或 `find`。主流實作對常見情況已經高度優化，許多用的是 Boyer-Moore 或其變形——從模式串**右端**開始比對，配合壞字元規則一次跳過多個位置，在字符集大（例如自然語言文字）時平均比 KMP 更快，因為它常常連看都不用看就跳過大段主串。需要手寫的情況只有三類：比對過程中要同時做額外處理、處理無法一次載入的串流資料、或面試官明確要求。

**詳細解析**：Boyer-Moore 與 KMP 的差別值得說清楚：KMP 的優勢是**最壞情況有保證**（永遠 O(n + m)），Boyer-Moore 是**平均極快但最壞可能退化**（原始版本最壞 O(nm)，加上 Galil 規則後可修正）。所以標準庫的選擇通常是混合的——短模式串直接暴力（常數最小），長模式串才啟用進階演算法。這種「按輸入規模切換策略」的模式和排序的 introsort 是同一個工程思路。面試中表達「我知道有哪些選擇、也知道標準庫已經做過這個取捨」，比堅持手寫更能顯示成熟度。

**面試回答方式**：明確表態用標準庫，並說明理由是實作已針對常見情況優化。接著比較 KMP 與 Boyer-Moore 的取捨（最壞保證 vs 平均速度）。加分點是點出標準庫會按模式串長度切換策略，並連結到排序的 introsort 是同一個工程思路。

### 滾動雜湊碰撞了怎麼辦？可以只靠雜湊不做驗證嗎？

**核心答案**：碰撞時**必須逐字元驗證**，否則會產生錯誤答案。不做驗證只有在「可以接受機率性正確」的場景才行——例如快速去重的前置過濾。要降低碰撞率有兩個手段：**選大質數當模數**，以及用兩組不同的 base 與模數做雙重雜湊，兩個都相同才視為匹配，碰撞機率降到可以忽略。

**詳細解析**：雙重雜湊在競賽中很常用，因為它讓「跳過驗證」變成實務上可接受的風險，特別是在需要把子串雜湊當作字典鍵的場景（例如「找出所有重複出現的長度 L 子串」，這時逐字元驗證會讓複雜度退回 O(nL)）。安全性上要注意：如果 base 與模數是固定且公開的，攻擊者可以構造大量碰撞讓系統退化，所以**執行期隨機化 base** 是必要的防禦，這和雜湊表用隨機種子防碰撞攻擊是同一個道理。另外模數運算要注意溢位——相乘前先轉成寬型別，減法後可能為負要補模數。

**面試回答方式**：先明確說必須驗證，並指出不驗證只適用於可接受機率性正確的場景。接著給兩個降低碰撞的手段（大質數模數、雙重雜湊）。加分點是提到固定參數會被構造碰撞、需要執行期隨機化，以及模運算的溢位與負數細節。

### 「找出最長重複子串」為什麼要配合二分答案？

**核心答案**：因為**答案長度具有單調性**——如果存在長度為 L 的重複子串，那麼長度 L−1 的重複子串必定也存在（取它的前綴即可）。所以可以對長度二分：每次用滾動雜湊把所有長度為 L 的子串雜湊放進集合，看有沒有重複，一次檢查 O(n)，總共 O(n log n)。直接枚舉所有長度是 O(n²) 起跳。

**詳細解析**：這題把兩個技巧疊在一起，是「二分答案」與「滾動雜湊」的經典組合，展示了演算法設計常常是工具的組合而非單一招式。實作上要注意：檢查函式回傳的不只是布林值，還要記下具體的起始位置，才能在二分結束後輸出答案本身。另一條路線是後綴陣列加最長公共前綴陣列，可以在 O(n log n) 或 O(n) 內解決且不依賴雜湊、沒有碰撞風險，但實作複雜得多。面試中先給二分加滾動雜湊（好寫、好解釋），再提一句後綴陣列是理論更優的方案，是很好的節奏。

**面試回答方式**：先論證單調性——長度 L 存在則 L−1 必然存在，這是二分成立的前提。接著給流程與複雜度。加分點是提到檢查函式要順便記下位置，以及後綴陣列是理論更優但實作複雜的替代方案。
