# 題目

什麼時候用位元表示狀態？狀態壓縮 DP 的適用條件是什麼？

## 核心答案

**核心條件是「集合的元素個數很小（通常 ≤ 20）而你需要枚舉子集或記錄哪些已被使用」**。**一個 n 位元的整數就是一個 n 元素集合的子集**——**於是 `dp[mask]` 表示「已經處理了 mask 這個子集」的最優解。**

**典型的訊號**：**題目給的 n 很小（10 到 20）而暴力枚舉是 n!**（旅行商、任務分配、集合覆蓋）；**或者「每一行的狀態只有有限種且只依賴上一行」**（棋盤上的放置問題）。

**常用的位元操作**：**`mask | (1 << i)`（加入元素 i）、`mask & ~(1 << i)`（移除）、`mask & (1 << i)`（檢查）、`__builtin_popcount(mask)`（數 1 的個數）、以及 `sub = (sub - 1) & mask`（枚舉 mask 的所有子集）。**

**而複雜度通常是 O(2^n × n) 或 O(3^n)**（後者是枚舉所有「子集的子集」）——**所以 n 的上限就是 20 左右。**

## 詳細解析

**「n 很小」本身就是最強的訊號**：多數演算法題的 n 是 10^5 或更大——**而一旦看到 n ≤ 20，那幾乎確定是狀態壓縮或者搜尋**；**因為 2^20 約一百萬，是可以接受的**。**所以「看到 n 的範圍先估算 2^n」應該是一個反射**——**它能在幾秒內排除或確認這個方向。**

**「枚舉子集的技巧」值得記住因為它不直觀**：`for (int sub = mask; sub; sub = (sub - 1) & mask)`——**它枚舉 mask 的所有非空子集**；**原理是「減一會把最低位的 1 變成 0 並把它後面的 0 全變成 1，再與 mask 取交集就跳到下一個子集」**。**而所有 mask 的所有子集加起來是 3^n（每個元素有「在 mask 中且在 sub 中」「在 mask 中但不在 sub 中」「不在 mask 中」三種狀態）**——**這個 3^n 的推導是一個經典的組合論證。**

**「旅行商問題」是最典型的應用**：`dp[mask][i]` 表示「已訪問 mask 中的城市且當前在 i」的最短路徑——**轉移是「從 i 走到一個未訪問的 j」**；**複雜度 O(2^n × n²)**。**它把 O(n!) 降到了 O(2^n × n²)**——**在 n = 20 時是一千萬對比天文數字**。**而理解「為什麼記錄『訪問過哪些』而非『訪問的順序』就夠」是關鍵**：**因為未來的決策只依賴「還有哪些沒訪問」與「現在在哪」，而不依賴之前的順序**——**這正是無後效性。**

**「行狀態壓縮」是另一類**：在棋盤問題中——**每一行的狀態（哪些格子被放了）用一個位元遮罩表示，而 dp 在「行」與「上一行的狀態」上進行**；**於是複雜度是 O(行數 × 2^列數 × 2^列數)**。**這要求列數很小（通常 ≤ 12），而它常見於「不能相鄰放置」這類約束的問題。**

## 面試回答方式

先給核心條件（**集合元素個數小、需要枚舉子集或記錄已使用**）與典型的訊號，再給常用的位元操作與複雜度上限。加分點有四個：**「n 很小」本身就是最強的訊號**——**看到 n ≤ 20 先估算 2^n 應該是一個反射**；**枚舉子集的技巧與它的原理**，**以及「所有子集的所有子集是 3^n」的組合論證**；**旅行商的狀態定義**與**為什麼記錄「訪問過哪些」而非順序就夠**（那正是無後效性）；以及**行狀態壓縮**這另一類應用與它的條件。

## 講稿

核心條件是集合的元素個數很小，通常不超過二十，而你需要枚舉子集或記錄哪些已被使用。一個 n 位元的整數就是一個 n 元素集合的子集。

而 n 很小本身就是最強的訊號。多數題目的規模是十萬以上，一旦看到二十以下，那幾乎確定是狀態壓縮或搜尋，因為二的二十次方大約一百萬，可以接受。所以看到範圍先估算二的 n 次方應該是一個反射。

最典型的應用是旅行商問題。狀態是已訪問哪些城市加上當前在哪，轉移是從當前走到一個未訪問的。它把階乘降到了二的 n 次方乘 n 平方，在二十個城市時是一千萬對比天文數字。

而理解為什麼記錄訪問過哪些而不是訪問的順序就夠，是關鍵。因為未來的決策只依賴還有哪些沒訪問跟現在在哪，不依賴之前的順序。這正是無後效性。

另外有一個枚舉子集的技巧值得記住因為它不直觀。從遮罩本身開始，每次減一再與遮罩取交集，就能枚舉所有非空子集。原理是減一會把最低位的一變成零並把後面的零全變成一。

## 常見追問

### 位元運算有哪些常用的技巧？

**核心答案**：**幾個高頻的**。**`x & (x-1)`**——**清除最低位的 1**；**用於數 1 的個數（Brian Kernighan 演算法）與判斷是否為 2 的冪（`x & (x-1) == 0`）**。**`x & (-x)`**——**取出最低位的 1**；**用於樹狀陣列與枚舉**。**`x ^ y`**——**找出不同的位元**；**經典應用是「陣列中只出現一次的數字」（全部異或，相同的抵消）**。**以及 `x >> 1` 與 `x << 1` 取代乘除二。**

**詳細解析**：**「異或的性質」是這類題目的核心而它值得被記住**：**`a ^ a = 0`、`a ^ 0 = a`、以及交換律與結合律**——**於是「一堆數字中只有一個出現奇數次」可以用「全部異或」在 O(n) 時間 O(1) 空間內解決**。**而進階的變體「有兩個只出現一次」需要多一步**：**全部異或的結果是那兩個數的異或（非零），取它的任一個 1 位元把所有數分成兩組，於是那兩個數必然分屬不同組，各組再異或**。**這個「用一個位元把集合分成兩半」的技巧很巧妙**——**而它也展示了「異或的結果攜帶了資訊」這個可以被利用的性質**。

**面試回答方式**：給幾個高頻技巧與各自的用途。核心加分點是**異或的性質**（自反、單位元、交換結合）**讓「只出現一次的數字」能 O(n) 時間 O(1) 空間解決**，並給出**兩個只出現一次的進階變體**：**用異或結果的任一個 1 位元把集合分成兩組**。收在洞察：**這個技巧展示了「異或的結果攜帶了資訊」這個可被利用的性質**。

### 狀態壓縮的空間怎麼優化？

**核心答案**：**用滾動陣列或者只保留必要的維度**。如果 `dp[mask][i]` 只依賴 `dp[mask'][j]` 且 `mask'` 是 `mask` 去掉一位——**那麼可以按 popcount 分層並只保留相鄰的兩層**；**而更常見的是「行狀態壓縮」中只保留上一行**。**另一個手段是「用 short 或 byte 而非 int」**（如果值的範圍允許）——**在 2^20 × 20 的表上那能省下大量記憶體。**

**詳細解析**：**「按 popcount 分層」是狀態壓縮特有的優化**：轉移總是從「少一個元素的集合」到「多一個元素的集合」——**於是所有的狀態可以按 1 的個數分成 n+1 層，而每層只依賴上一層**；**於是空間從 O(2^n × n) 降到「兩層的大小」**。**代價是需要按 popcount 排序或分組地遍歷狀態**——**而那本身有一點成本**。**這個優化在 n 接近上限（20 到 22）時可能是「能不能跑」的關鍵**——**而在 n 較小時不必要**。**所以它是一個「在極限情況下才需要」的技巧，值得知道但不必總是使用。**

**面試回答方式**：給兩個常見的手段（滾動陣列、更小的型別）。核心加分點是**按 popcount 分層**這個狀態壓縮特有的優化——**轉移總是從少一個元素到多一個，於是可以按 1 的個數分層且每層只依賴上一層**，並給出代價（需要按 popcount 分組遍歷）。收在判斷：**它在 n 接近上限時可能是「能不能跑」的關鍵，而 n 較小時不必要**。

### 面試中遇到狀態壓縮該怎麼開場？

**核心答案**：**先確認 n 的範圍並說出你的推理**。「n 最大是 15，所以 2^15 是三萬多，而每個狀態的轉移是 O(n)，總共約五十萬——這在時間限制內；所以我考慮用位元遮罩表示已選的集合」——**這個推理過程本身就是答案的一部分**；**它展示了「我是根據規模選擇方法」而非「我背過這一題」。**

**詳細解析**：**「用規模反推方法」是演算法面試中一個極有效的策略**：n ≤ 20 提示狀態壓縮或搜尋、n ≤ 100 提示 O(n³) 的 DP 或 Floyd、n ≤ 1000 提示 O(n²)、n ≤ 10^5 提示 O(n log n)、n ≤ 10^7 提示 O(n)——**這個對應表能在看完題目的三十秒內縮小方向**。**而在面試中把這個推理說出來，比直接跳到答案更能展示思路**——**因為它證明了「即使我沒見過這一題，我也有一個系統的方法找到方向」**。**這正是面試官真正想確認的能力**——**而它也是「刷題」與「有方法」的差別。**

**面試回答方式**：給具體的開場方式（**先確認 n 的範圍並說出推理**）並示範那段推理。核心加分點是**用規模反推方法**這個策略並給出對應表（n ≤ 20、100、1000、10^5、10^7 各提示什麼）。收在價值：**把推理說出來比直接跳到答案更能展示思路**——**它證明了「即使沒見過這一題，我也有系統的方法找到方向」，而那正是面試官想確認的，也是「刷題」與「有方法」的差別**。
