# 題目

隨機化在演算法中扮演什麼角色？有哪些常見的抽樣技巧？

## 核心答案

**隨機化主要有兩個作用。**

**避開最壞情況**——**快速排序選隨機的樞紐、快速選擇（找第 k 大）、跳表的層數**；**它們的最壞複雜度不變，但「壞輸入」不再由對手決定而是由骰子決定**，**於是期望複雜度就是實際的複雜度。**

**用機率換空間或時間**——**布隆過濾器、HyperLogLog、Miller-Rabin**；**接受一個可量化的小錯誤率，換取大幅的資源節省。**

**常見的抽樣技巧有三個**：**Fisher-Yates 洗牌**（O(n) 且每種排列等機率）；**蓄水池抽樣**（從未知長度的流中等機率抽 k 個，空間 O(k)）；**以及加權抽樣**（前綴和加二分，或者 Alias 方法做到 O(1)）。

## 詳細解析

**「隨機化把最壞情況從『對手可控』變成『機率極低』」是它最重要的價值**：確定性的快速排序在「已排序的輸入」上退化成 O(n²)——**而那樣的輸入在實務中很常見（甚至可能被惡意構造）**；**隨機樞紐讓退化的機率變成天文數字的小**。**這個「用隨機性防禦對手」的思路在安全領域同樣重要**——**雜湊表的 seed 隨機化正是為了防禦雜湊碰撞攻擊**；**在 2011 年多個 Web 框架因為固定的雜湊種子而遭受 DoS 攻擊後，隨機種子成為了標準做法。**

**「Fisher-Yates 的正確版本很容易寫錯」**：正確的做法是「從最後一個位置往前，每次和 `[0, i]` 中隨機一個位置交換」——**而常見的錯誤是「和 `[0, n-1]` 中的隨機位置交換」**；**後者產生 n^n 種等機率的過程但只有 n! 種排列，於是機率分布不均勻**。**這個錯誤很隱蔽（結果看起來仍然「很隨機」）而它在洗牌算法的實作中反覆出現**——**驗證的方法是對小的 n（例如 3）跑一百萬次並統計每種排列的頻率。**

**「蓄水池抽樣的證明很短」**：對第 i 個元素（i > k），以 `k/i` 的機率選中並隨機替換蓄水池中的一個——**用歸納法可證每個元素最終留下的機率都是 `k/n`**；**它的價值在於「不需要事先知道總數」與「只掃一遍」**，**這正是處理串流或超大檔案時的需求。**

**「加權抽樣的 Alias 方法」是一個少見但優雅的技巧**：預處理 O(n) 後，每次抽樣是 O(1)——**做法是把所有的機率縮放到平均值為 1 並用「大的補小的」構造 n 個桶，每個桶最多包含兩個結果**；**在需要大量抽樣時（例如模擬、推薦），它比前綴和加二分的 O(log n) 快得多。**

## 面試回答方式

先給隨機化的兩個作用（**避開最壞情況、用機率換資源**）與各自的例子，再給三個抽樣技巧。加分點有四個：**隨機化把最壞情況從「對手可控」變成「機率極低」**，**而雜湊表的 seed 隨機化正是防禦碰撞攻擊的標準做法**；**Fisher-Yates 的正確版本很容易寫錯**與錯誤的驗證方法；**蓄水池抽樣的價值在於不需事先知道總數且只掃一遍**；以及 **Alias 方法**把加權抽樣做到 O(1)。

## 講稿

隨機化主要有兩個作用。

第一個是避開最壞情況。確定性的快速排序在已排序的輸入上會退化成平方，而那樣的輸入在實務中很常見，甚至可能被惡意構造。隨機選樞紐讓退化的機率變成極小。關鍵是最壞情況不再由對手決定，而是由骰子決定。

這個用隨機性防禦對手的思路在安全上同樣重要。雜湊表的種子隨機化就是為了防禦碰撞攻擊。二零一一年有多個框架因為固定的種子被 DoS，之後隨機種子就成了標準做法。

第二個作用是用機率換空間或時間。布隆過濾器、HyperLogLog 都是這一類，接受一個可量化的小錯誤率換取大幅的資源節省。

抽樣方面常見的有三個。洗牌用 Fisher-Yates，從串流中抽樣用蓄水池抽樣，帶權重的抽樣用前綴和加二分或者 Alias 方法。

## 常見追問

### 快速選擇的期望複雜度為什麼是 O(n)？

**核心答案**：**因為每次分割後只需要遞迴一側，而問題規模期望減半**。於是總工作量是 `n + n/2 + n/4 + ... = 2n`——**這個幾何級數收斂到常數倍的 n**；**而快速排序需要遞迴兩側，於是是 `n log n`**。**最壞情況仍是 O(n²)（每次都選到極端的樞紐），但隨機樞紐讓它的機率極低。**

**詳細解析**：**「確定性的 O(n) 選擇演算法存在但實務中不用」是一個好的對比**：中位數的中位數（BFPRT）演算法保證最壞 O(n)——**但它的常數大得多（大約是隨機快速選擇的三到五倍）**；**於是在實務中，人們寧願接受一個機率極低的壞情況，換取平均快三倍**。**這是一個「理論的保證與實際的效能不一致」的經典例子**；**而 introselect（先用隨機快速選擇，若遞迴過深則切換到 BFPRT）是一個折衷**——**它拿到了兩者的好處，代價是實作複雜度**。**同樣的模式出現在 introsort（快速排序退化時切換到堆積排序）中，那正是多數標準函式庫的 sort 實作**。

**面試回答方式**：給幾何級數的論證並對比快速排序需要遞迴兩側。核心加分點是**確定性的 O(n) 選擇存在（BFPRT）但常數大三到五倍，實務中不用**——**人們寧願接受機率極低的壞情況**。收在折衷方案：**introselect 與 introsort 拿到兩者的好處**，**而後者正是多數標準函式庫的 sort 實作**。

### 蓄水池抽樣怎麼擴展到加權的情況？

**核心答案**：**用 A-Res 演算法**：對每個元素生成一個鍵 `u^(1/w)`，其中 u 是 [0,1] 的均勻隨機數、w 是權重——**然後保留鍵最大的 k 個（用一個大小 k 的最小堆積維護）**；**這樣每個元素被選中的機率正比於它的權重**。**空間仍是 O(k)，時間是 O(n log k)。**

**詳細解析**：**「這個鍵的形式看起來很神秘但推導不難」**：`P(u^(1/w) > t) = P(u > t^w) = 1 - t^w`——**於是權重越大的元素，它的鍵超過任何門檻的機率越高**；**而「保留最大的 k 個鍵」等價於按權重比例抽樣**。**這類「用一個巧妙的變換把加權問題轉成無權問題」的技巧在演算法中反覆出現**。**而在實務上，這個演算法讓「從一個巨大的日誌流中按重要性抽樣」變得可行**——**例如分散式追蹤中的尾部抽樣（保留慢的與出錯的請求，而非均勻抽樣）**；**理解它的機制，能讓你在設計抽樣策略時知道什麼是可以做到的。**

**面試回答方式**：給 A-Res 的鍵形式與維護方式，並給出複雜度。核心加分點是**推導那個鍵為什麼有效**（`P(u^(1/w) > t) = 1 - t^w`，權重越大鍵越可能超過門檻）。收在實務應用：**它讓「從巨大的日誌流中按重要性抽樣」可行**，**例如分散式追蹤的尾部抽樣**——**理解機制能讓你在設計抽樣策略時知道什麼做得到**。

### 隨機數的品質重要嗎？

**核心答案**：**看用途，差別很大**。**演算法中避開最壞情況**——**一般的偽隨機數就夠**；**模擬與統計**——**需要好的統計性質（週期長、無明顯相關性），Mersenne Twister 或 PCG**；**安全相關**（金鑰、token、鹽）——**必須用密碼學安全的來源**（`/dev/urandom`、`crypto.randomBytes`），**因為一般的 PRNG 從少量輸出就能被推出內部狀態。**

**詳細解析**：**「用錯隨機源是一個真實且反覆出現的漏洞類型」**：用 `Math.random()` 生成 session token、用時間戳作為種子、或者用一個可預測的計數器——**這些都導致過真實的入侵**；**而它們的共同點是「功能上完全正常」，所以不會在測試中被發現**。**防禦的方法是規則而非判斷力**：**任何會離開程式並被當作憑證的隨機值，一律用密碼學安全的來源**——**因為判斷「這個值需不需要安全」在當下常常出錯，而統一使用安全來源的成本幾乎為零**。**這是一個「把安全決策變成預設值而非每次的判斷」的例子**——**而那正是安全設計中最有效的一類做法。**

**面試回答方式**：分三種用途給出對應的隨機源要求。核心加分點是**用錯隨機源是真實且反覆出現的漏洞類型**，並指出它的隱蔽性（**功能上完全正常，不會在測試中被發現**）。收在防禦方法：**用規則而非判斷力**——**任何會被當作憑證的隨機值一律用安全來源**，**因為統一使用的成本幾乎為零**；**這是「把安全決策變成預設值」這類最有效的做法**。
