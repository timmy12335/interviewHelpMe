# 題目

什麼時候可以用貪心？面試官要你「證明貪心是對的」，你會怎麼回答？

## 核心答案

貪心可用的前提是**貪心選擇性質**加上**最優子結構**：每一步選當下最好的，不會讓最終結果變差；而且原問題的最優解包含子問題的最優解。動態規劃只需要後者，所以貪心的適用範圍比動態規劃窄，但快得多（通常 O(n log n) 對上 O(n²) 或更高）。證明貪心正確有兩個標準手法：**交換論證**——假設存在一個最優解不含你的貪心選擇，那麼把它裡面的某個選擇換成貪心選擇，證明結果不會變差，於是必定存在一個包含貪心選擇的最優解；以及**歸納法**——證明每一步之後「當前的部分解都能擴展成某個最優解」。面試中更實際的做法是**先試著構造反例**：花一分鐘想能不能舉出貪心失敗的例子，舉不出來再論證正確性；舉得出來就直接排除貪心、改用動態規劃。這個順序比硬要證明快得多，也更誠實。

## 詳細解析

**交換論證怎麼具體操作**：以活動選擇（在時間軸上選出最多的不重疊區間）為例，貪心策略是每次選**結束時間最早**的。論證是：設某個最優解的第一個活動是 X，而貪心選的是 Y（結束時間最早）。因為 Y 結束得不比 X 晚，把 X 換成 Y 之後，剩下的活動仍然都不會與 Y 衝突，所以替換後的解仍然合法且活動數相同——於是存在一個以 Y 開頭的最優解。對剩下的子問題重複同樣論證，歸納下去就完成證明。這個「把最優解改造成含貪心選擇的形式」是交換論證的固定套路。

反例通常出現在「局部最優被後續代價反噬」：零錢兌換用面額 1、3、4 湊 6，貪心先拿 4 剩 2 只能拿兩個 1，共三枚；最優是 3 加 3，兩枚。反例的結構是：貪心拿走的那個大值，讓剩下的部分變成一個更糟的子問題。找反例的技巧就是刻意構造「拿了大的反而剩下難湊」的資料。同樣的思路可以測試任何貪心策略——問自己「有沒有可能當下最好的選擇會讓後面付出更多代價」。

**排序往往是貪心的第一步**：多數貪心題的關鍵不在貪心本身，而在**按什麼排序**。活動選擇按結束時間、合併區間按起點、最少箭數射爆氣球按結束座標、分發餅乾按大小配對、任務排程按截止時間或處理時間。選錯排序鍵，貪心就是錯的——例如活動選擇如果按開始時間排會失敗（一個很早開始但很晚結束的活動會擋掉許多後續活動）。所以回答這類題時，**先講排序依據並解釋為什麼**，比講貪心流程更關鍵。

貪心與動態規劃可以組合使用：跳躍遊戲的第二版（求最少跳躍次數）可以用動態規劃 O(n²)，也可以用貪心 O(n)——維護「當前這一跳能到達的最遠邊界」，走到邊界時次數加一並更新邊界。這裡貪心之所以對，是因為「這一步能到達的範圍」單調遞增，範圍內的每個點都可達，所以取最遠是安全的。另一個例子是霍夫曼編碼，每次合併頻率最小的兩個節點，用堆積輔助，本質是貪心加上優先佇列。

面試中的實用策略是「先給動態規劃、再談貪心」：動態規劃通常更容易確保正確，而且推導過程機械可執行。先寫出一個正確的動態規劃解，再說「這題我懷疑可以用貪心優化到 O(n)，因為……」，是很穩健的節奏——你已經交付了正確答案，再往上加分。反過來一上來就衝貪心，如果策略有誤又證不出來，會浪費大量時間且沒有可交付成果。

## 面試回答方式

先講兩者的條件差異——貪心需要貪心選擇性質加最優子結構，動態規劃只需要後者，所以貪心範圍窄但快。證明部分主動給出**交換論證**這個標準手法，並用活動選擇現場示範一次（把最優解的第一個活動換成結束最早的那個，結果不變差）。接著給出更實際的態度：面試時我會**先花一分鐘找反例**，找得到就直接排除貪心。強調多數貪心題的關鍵在**排序依據**而不是貪心流程本身。加分點是說明你的答題節奏——先交付正確的動態規劃解，再提出貪心優化，確保任何時候都有可交付的答案。

## 講稿

貪心跟動態規劃的差別在條件。動態規劃只需要最優子結構，貪心還多要一個貪心選擇性質，也就是每一步選當下最好的不會讓最終結果變差。所以貪心的適用範圍比較窄，但快很多。

如果面試官要我證明貪心是對的，標準手法是交換論證。以活動選擇為例，策略是每次挑結束時間最早的。論證方式是，假設有個最優解的第一個活動不是我選的那個，因為我選的結束得更早或一樣早，把它換掉之後剩下的活動一樣不衝突，活動總數也沒變。所以一定存在一個包含我這個選擇的最優解，接著對剩下的子問題重複同樣的論證。

不過老實說，面試時我會先花一分鐘試著找反例，而不是急著證明。像零錢兌換，面額一、三、四要湊六，貪心先拿四剩下只能拿兩個一，總共三枚，但最優是兩個三。找得到反例就直接排除貪心。

還有一點我覺得很關鍵，多數貪心題真正的難處不在貪心流程，而在按什麼排序。活動選擇按結束時間、合併區間按起點，選錯排序鍵貪心就是錯的。

## 常見追問

### 活動選擇為什麼要按結束時間排序，按開始時間或按時長不行嗎？

**核心答案**：按**結束時間**排序才對，因為結束得越早，**留給後續活動的時間就越多**，這正是貪心選擇性質成立的原因。按開始時間會失敗——一個很早開始但持續很久的活動會擋掉後面一整串短活動。按時長也會失敗——一個很短但橫跨兩個活動交界處的活動，會同時擋掉左右兩個更好的選擇。

**詳細解析**：三種排序的反例都很容易構造，值得當場說出來。按開始時間的反例：活動 A 是 0 到 10，活動 B 是 1 到 2、C 是 3 到 4，選 A 只得 1 個，選 B 和 C 得 2 個。按時長的反例：A 是 0 到 5、B 是 4 到 6、C 是 5 到 10，B 最短但選它會同時排除 A 和 C。這種「**用具體反例排除錯誤策略**」的回答方式非常有力，因為它不需要抽象論證，面試官一聽就懂。順帶一提，同樣的排序準則也用在「最少箭數射爆氣球」與「無重疊區間需要移除幾個」，它們都是活動選擇的變裝。

**面試回答方式**：先給正確答案與理由（結束早等於留給後面的時間多），再各給一個具體反例排除另外兩種排序。加分點是指出這個準則在最少箭數、無重疊區間等題目中重複出現，說明你認得出題目的骨架。

### 有沒有「看起來像貪心其實是動態規劃」的常見陷阱題？

**核心答案**：有，最典型的是**最長遞增子序列**。直覺上會想「每次盡量接在能接的地方」，但這是錯的——當前選一個較大的元素可能讓後續無法接續，必須考慮所有可能的結尾。正確解是動態規劃 O(n²)，或用**貪心加二分**的 O(n log n) 版本，但後者的貪心維護的是「長度為 k 的遞增子序列中最小的結尾值」這個輔助陣列，而不是直接貪心地選元素——這個陣列本身並不是答案，只有長度是。

**詳細解析**：這題的教育意義在於展示「貪心加二分」的正確形態——它不是「每步選最好的元素」，而是「維護一組最有潛力的狀態」。輔助陣列裡的值不構成任何一個實際的遞增子序列，把它當成答案輸出是常見誤解，只有它的長度是正確的。另一個類似的陷阱是**跳躍遊戲**：第一版（能否到達終點）可以純貪心（維護最遠可達位置），第二版（最少跳幾次）也能貪心但策略不同（按層擴展），第三版加上代價之後就必須動態規劃。同一個題面加一點變化就跨過貪心的界線，是面試官很愛用的手法。

**面試回答方式**：舉最長遞增子序列並說明直覺貪心為什麼錯。重點澄清 O(n log n) 解法裡的輔助陣列不是答案本身、只有長度是，這是最容易誤解的地方。加分點是舉跳躍遊戲三個版本說明題面小改就會跨過貪心的界線，展現你對邊界的敏感。

### 面試時如果貪心策略證不出來，該怎麼辦？

**核心答案**：**改用動態規劃並說明理由**。誠實地說「我想到一個貪心策略，但我沒辦法快速說服自己它是對的，所以我先用動態規劃給一個確定正確的解，如果時間允許再回頭驗證貪心」——這個回答本身就是加分的，因為它展示了你把**正確性放在效能之前**，而這正是工程判斷的核心。

**詳細解析**：面試官在觀察的往往不是你是否想出最優解，而是**你怎麼處理不確定性**。硬套一個沒把握的貪心策略、寫完再被反例打臉，比一開始就選擇穩健方案糟糕得多。實務上也是同樣的道理：一個 O(n²) 但確定正確的實作，遠比一個 O(n) 但可能在特定輸入下出錯的實作有價值，尤其在正確性影響金額或安全的系統裡。另一個有用的做法是**寫個小的暴力解當對照**，用隨機資料驗證貪心策略——這在面試中不一定有時間做，但主動提出「我平常會這樣驗證」會顯示你有真實的工程習慣。

**面試回答方式**：直接示範這句話怎麼說（承認證不出來、先給動態規劃、時間允許再回頭）。點出這展現的是把正確性放在效能之前的判斷。加分點是提到實務上會寫暴力解對拍驗證貪心策略，讓面試官看到你的工程習慣而不只是解題技巧。
