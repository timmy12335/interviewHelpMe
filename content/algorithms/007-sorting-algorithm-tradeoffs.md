# 題目

快速排序、合併排序、堆積排序都是 O(n log n)，實務上要怎麼選？「穩定排序」為什麼重要？

## 核心答案

三者同階但特性完全不同。**快速排序**平均最快，因為它**原地**、常數小、記憶體存取連續（快取友善），代價是最壞 O(n²) 且**不穩定**。**合併排序**穩定且保證 O(n log n)，代價是需要 O(n) 額外空間；它是**外部排序**與**連結串列排序**的首選，因為合併只需要循序存取。**堆積排序**原地且保證 O(n log n)，但存取跳躍、快取不友善、也不穩定，實務上很少單獨用，主要當作快排的**保底**。**穩定性**指相等元素的相對順序在排序後保持不變，重要性在於**多鍵排序**——先按部門排、再按年資排，穩定性讓你可以分兩次排序達成，不必寫複合比較器；也在於資料呈現的一致性（重排後畫面不會無故跳動）。這就是為什麼 Java 對基本型別用雙樞紐快排（無所謂穩定，因為相等的 int 無法區分），對物件用 TimSort（必須穩定）。

## 詳細解析

混合式排序才是實務的標準答案：C++ 的 `std::sort` 用 introsort——先跑快排，當遞迴深度超過 `2 log n` 就切換成堆積排序把最壞情況壓回 O(n log n)，而區間小於某個門檻（常見是 16）改用插入排序，因為小規模時插入排序的常數最小且對近乎有序的資料極快。Java 的 `Arrays.sort` 對物件用 TimSort，它會先掃描出資料中天然存在的遞增或遞減區段（run），再用合併策略把這些區段併起來，對真實世界中「部分有序」的資料特別快。能講出混合策略，比背三種演算法的複雜度表有價值得多。

**快排的最壞情況怎麼避免**：最壞發生在每次樞紐都選到極值（例如對已排序陣列固定取第一個元素當樞紐），遞迴退化成 n 層。防禦方式有三種：**隨機選樞紐**、**三數取中**（取首、中、尾的中位數）、以及**三路劃分**（把等於樞紐的元素單獨分一堆）。三路劃分特別重要，因為它讓「大量重複元素」這個常見情況從 O(n²) 變成接近 O(n)——只用兩路劃分時，全部相同的陣列會退化。

**合併排序的不可取代之處**：資料量大到記憶體放不下時只能做外部排序——分批讀進記憶體排好寫回磁碟，再做多路合併，這個流程本質上就是合併排序，因為合併只需要**循序讀寫**，對磁碟極為友善。連結串列排序也一樣：快排在連結串列上難以隨機存取，而合併排序可以用快慢指針找中點、原地接指標，空間降到 O(log n) 的遞迴堆疊。

**穩定性的實際後果**：假設訂單列表先按金額排序，再按客戶名稱排序。如果第二次排序是穩定的，同一個客戶的訂單會保持金額順序；不穩定的話這個順序會被打亂，使用者會覺得畫面亂跳。在後端則常見於分頁——不穩定排序加上相等鍵，可能讓同一筆資料在第一頁和第二頁都出現、或都不出現。解法是在排序鍵裡加上唯一的決勝鍵（例如主鍵），讓順序完全確定，這在資料庫分頁查詢裡是標準做法。

**非比較排序的適用條件**：計數排序、基數排序、桶排序可以突破 O(n log n) 的比較下界，達到 O(n + k) 或 O(nk)，但前提很嚴格——鍵必須是有限範圍的整數或可分解成固定位數。當值域 k 遠大於 n（例如排序任意 64 位元整數）時計數排序完全不可行。面試中如果題目明確說「數值範圍在 0 到 1000」或「排序年齡」，那就是在提示你用計數排序。

## 面試回答方式

不要背複雜度表，直接講**三個維度的取捨**：是否原地、是否穩定、最壞情況是否有保證。用這三個維度把快排、合併、堆排定位清楚，再說明為什麼實務上是混合式的——introsort 用堆排保底、小區間用插入排序，Java 對物件用 TimSort。穩定性要講出實際後果而不只是定義，舉多鍵排序或分頁重複這種具體場景。加分點有三個：快排用三路劃分處理大量重複元素、合併排序在外部排序與連結串列上不可取代、以及非比較排序的適用條件（值域有限）。

## 講稿

這三個雖然同階，但特性差很多，我會從三個維度來看：是不是原地、穩不穩定、最壞情況有沒有保證。

快排原地、常數小、記憶體存取連續，所以平均最快，代價是最壞會退化成平方，而且不穩定。合併排序穩定，而且保證線性對數，但要額外的線性空間。堆排原地又有保證，可是存取跳躍、對快取不友善，所以很少單獨用，通常是拿來當快排的保底。

實務上大家用的其實是混合式的。像 introsort 就是先跑快排，遞迴太深就切成堆排把最壞情況壓回來，區間很小的時候改用插入排序。Java 對物件則是用 TimSort，它會先找出資料裡本來就有序的區段再合併。

穩定性我想多講一點，因為它常被當成小細節。它真正的價值在多鍵排序，先按金額排、再按客戶排，穩定的話同一個客戶底下還是照金額排列，不用寫複合比較器。在分頁查詢裡也很關鍵，排序鍵有相等值又不穩定，同一筆資料可能在兩頁都出現。解法是在排序鍵裡加一個唯一的決勝鍵。

## 常見追問

### 為什麼 Java 對基本型別和物件用不同的排序演算法？

**核心答案**：因為**穩定性只對物件有意義**。兩個相等的 `int` 完全無法區分，交換它們沒有任何可觀察的差異，所以基本型別可以放心用不穩定但更快的雙樞紐快排，而且原地排序省掉了 O(n) 的輔助空間。物件則不同——兩個「金額相等」的訂單仍是不同物件，順序被打亂使用者看得出來，所以必須用穩定的 TimSort。

**詳細解析**：這個決策還有第二層考量：**比較成本**。基本型別的比較是一條 CPU 指令，物件的比較要呼叫 `compareTo` 或比較器，成本高出好幾個數量級。TimSort 針對真實資料常常「部分有序」的特性做了優化，能大幅減少比較次數，這對比較昂貴的物件排序特別划算；對 int 排序則沒必要，因為比較根本不是瓶頸，反而是記憶體搬移。所以這不只是穩定性的取捨，也是「比較成本高低」的取捨。同樣的思路解釋了為什麼 `Arrays.sort` 對物件會多花 O(n) 空間也在所不惜。

**面試回答方式**：先給主因——相等的基本型別無法區分，所以穩定性沒有意義，可以選更快的不穩定演算法。接著補第二層：物件的比較成本高，TimSort 減少比較次數的優化對物件才划算。加分點是點出這是兩個因素共同決定的，不只是穩定性。

### 快速排序遇到大量重複元素為什麼會退化？怎麼解？

**核心答案**：用傳統兩路劃分時，等於樞紐的元素會被全部分到同一邊，導致每次劃分極度不平衡。極端情況是整個陣列都是同一個值，每次只切出一個元素，遞迴 n 層，退化成 O(n²)。解法是**三路劃分**：把陣列分成小於、等於、大於樞紐三段，等於的那一段**直接排除在遞迴之外**，相同元素越多反而越快。

**詳細解析**：三路劃分（也叫荷蘭國旗劃分）維護三個指針，一趟掃描就把元素歸位。它對重複率高的資料效果驚人——全部相同的陣列從 O(n²) 直接降到 O(n)，因為第一次劃分就結束了。實務上這個情況比想像中常見：對「狀態」「分類」「布林旗標」這種低基數欄位排序時，重複率極高。Java 的雙樞紐快排用兩個樞紐把陣列分成三段，也有類似的效果並且對部分有序的資料更友善。面試中能主動指出「大量重複」這個退化情境並給出三路劃分，通常比只講「隨機選樞紐」更有深度，因為隨機樞紐對全相同的陣列**完全沒有幫助**。

**面試回答方式**：先講清楚退化機制——等於樞紐的元素全歸一邊造成劃分不平衡。接著給三路劃分，並強調關鍵是等於的那段不進遞迴。加分點是點出隨機選樞紐解決不了這個問題，因為問題不在樞紐選得好不好，並舉低基數欄位排序這個真實場景。

### 資料量超過記憶體時要怎麼排序？

**核心答案**：做**外部排序**，本質是合併排序的兩階段。第一階段把資料切成能放進記憶體的區塊，逐塊讀入、在記憶體裡排好、寫回磁碟成為有序的暫存檔。第二階段做**多路合併**——同時開啟所有暫存檔，每個檔案留一個讀取緩衝區，用一個**最小堆積**每次取出當前最小的元素寫進輸出。整個過程只需要循序讀寫，對磁碟與網路儲存都友善。

**詳細解析**：關鍵設計參數是**合併的路數**。路數太少要合併很多輪、磁碟 I/O 次數變多；路數太多則每個檔案分到的緩衝區太小，讀取變得零碎、失去循序優勢。實務上會依可用記憶體推算最佳路數。這個模式在大數據處理裡到處都是：MapReduce 的 shuffle 階段、資料庫的 `ORDER BY` 在結果集超過工作記憶體時的落盤排序，走的都是同一套流程。面試中如果題目說「一億筆資料排序、記憶體只有 1GB」，考的就是這個，而不是問你哪種排序快。

**面試回答方式**：直接給兩階段流程：分塊排序落盤、再多路合併。強調用最小堆積挑出當前最小值，以及整個過程只需要循序 I/O。加分點是講合併路數的取捨（輪數與緩衝區大小之間），並連結到資料庫排序落盤與 MapReduce shuffle 這些真實系統。
