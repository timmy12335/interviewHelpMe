# 題目

什麼樣的題目可以用滑動視窗？固定長度和可變長度的寫法差在哪，為什麼可變長度的版本仍然是 O(n)？

## 核心答案

滑動視窗處理的是**連續子陣列或子字串**的問題，前提是**視窗的性質具有單調性**——視窗變大時某個量只增不減（或只減不增）。有了單調性，右邊界擴張到不合法時，就知道**左邊界只能往右走、不需要回頭**，所以左右指針各走一趟，總共 O(n)。骨架有兩種：**固定長度**是右指針每前進一格、左指針也跟著前進一格，維護視窗內的統計量（進來一個、出去一個）；**可變長度**是右指針無條件擴張，每擴張一次就用 `while` 把左邊界收縮到視窗重新合法為止，然後在合法狀態下更新答案。判斷能不能用的關鍵問句是：「如果目前這段不合法，把左邊界往右移有沒有可能讓它變合法？」答案是肯定的才能用——這也是為什麼**含負數的陣列不能用滑動視窗求和**。

## 詳細解析

**單調性是門檻，不是所有子陣列題都能用**：求「和大於等於 target 的最短子陣列」，在**全為正數**時可以用滑動視窗，因為擴張右邊界和只會變大、收縮左邊界和只會變小。一旦陣列含負數，收縮左邊界可能讓和變大，單調性斷掉，滑動視窗就不成立——這時要改用**前綴和加上單調佇列或有序集合**。面試官很常用「陣列含負數嗎」這句話來測你是不是只會套模板，這個界線一定要能講清楚。

**可變長度為什麼還是 O(n)**：因為內層 `while` 移動的是**左指針**，而左指針在整個過程中總共只會前進 n 次。外層迴圈跑 n 次、內層總共移動 n 次，加起來是 2n。把它誤判成 O(n²) 是常見錯誤——判斷巢狀迴圈複雜度不能只看層數，要看**內層的總移動次數**。這個論證跟攤還分析是同一個思路。

**兩種骨架的差別在收縮的時機**：固定長度是「每次都收縮一格」，所以不需要 `while`，通常寫成先填滿前 k 個、之後每步做一次「加右邊、減左邊」。可變長度是「不合法才收縮」，收縮條件由題目定義：求最短時是「合法就一直收縮並更新答案」，求最長時是「不合法就收縮直到合法，再更新答案」。這兩者的**更新答案位置不同**——最長題在收縮迴圈之後更新，最短題在收縮迴圈內部更新，寫反是最常見的錯誤。

**視窗內狀態的維護方式決定了難度**：簡單的題目維護一個和或計數就好。字串題通常要維護**字元頻率表**，例如「最長無重複字元子字串」維護一個集合、「包含所有目標字元的最短子字串」維護「還缺幾種字元」這個計數器。關鍵技巧是用一個 `valid` 計數器記錄「已經滿足條件的字元種類數」，而不是每次都重新比對整張表——否則每步 O(k) 的比對會讓整體變成 O(nk)。

**視窗不一定是「一段」**：有些題目要維護視窗內的最大值（例如視窗最大值序列），這時單靠計數不夠，要配合**單調佇列**——佇列裡只留「還有可能成為最大值」的候選，新元素進來時把比它小的從尾部彈掉。這是滑動視窗與單調佇列的經典組合，也是這個題型的難度上限。

## 面試回答方式

開場先講前提而不是寫法——滑動視窗要求視窗性質具有單調性，收縮左邊界必須有機會讓不合法變合法。緊接著主動提負數的反例，這一句話能立刻和只會套模板的人拉開差距。接著分清楚兩種骨架：固定長度是進一個出一個，可變長度是右邊界無條件擴張、用 while 收縮左邊界；並點出求最長與求最短時更新答案的位置不同。複雜度要主動論證：內層 while 移動的是左指針，總共只前進 n 次，所以是 O(n) 不是 O(n²)。加分點是提到字元頻率題用 valid 計數器避免每步重新比對，以及視窗最大值要配單調佇列。

## 講稿

滑動視窗處理的是連續子陣列或子字串的問題，但它有前提，就是視窗的性質要有單調性。

具體來說，我要能回答一個問題：如果現在這一段不合法，把左邊界往右移，有沒有可能讓它變合法。答案是肯定的才能用。所以求和大於某個值的最短子陣列，在全部是正數時可以用，一旦有負數就不行，因為收縮左邊界可能反而讓和變大，單調性就斷了。這時候要改成前綴和配單調佇列。

寫法有兩種。固定長度比較單純，右指針前進一格、左指針也前進一格，維護視窗裡的統計量，就是進來一個出去一個。可變長度是右指針無條件擴張，然後用一個 while 把左邊界收縮到視窗重新合法。這裡最容易寫錯的是更新答案的位置，求最長要在收縮完之後更新，求最短要在收縮的過程中更新。

複雜度我想特別說明一下。看起來有兩層迴圈，但內層移動的是左指針，左指針整趟只會前進 n 次，所以總共是線性的，不是平方。

## 常見追問

### 陣列含負數時，「和等於 k 的子陣列個數」該怎麼做？

**核心答案**：改用**前綴和加哈希表**。定義 `prefix[i]` 為前 i 個元素的和，那麼子陣列 `(j, i]` 的和等於 `prefix[i] - prefix[j]`。要找和等於 k 的子陣列，等價於對每個 i 去問「前面出現過幾次 `prefix[i] - k`」，用哈希表邊掃邊記錄前綴和出現次數，一趟 O(n) 就能算完，而且完全不依賴正負號。

**詳細解析**：這題是「滑動視窗不能用」的標準替代方案，面試官問它就是在確認你知道界線在哪。實作上有兩個坑：一是哈希表要**先放入 `prefix = 0` 出現一次**，代表空前綴，否則從頭開始的子陣列會被漏掉；二是要**先查詢再插入當前前綴和**，順序反了會把自己算進去（在 k 等於 0 時會多算）。這個模式可以推廣到「和能被 k 整除的子陣列」（改記錄前綴和的餘數）與「和為 0 的最長子陣列」（改記錄前綴和第一次出現的位置）。

**面試回答方式**：先明確說「這題不能用滑動視窗，因為有負數」，再給前綴和加哈希表的解法。把等價轉換講清楚——找和為 k 的區間就是找 `prefix[i] - k` 出現過幾次。加分點是主動提兩個實作陷阱（要預放 0、先查後插），以及推廣到餘數版本。

### 「包含目標字串所有字元的最短子字串」要怎麼判斷視窗合法？

**核心答案**：維護一張**需求表**（目標字串每個字元需要幾個）與一個 **`valid` 計數器**（已經滿足需求的**字元種類數**）。右指針納入字元時，若該字元的視窗內數量剛好等於需求量，`valid` 加一；當 `valid` 等於需求表的種類數，視窗就合法，開始收縮左指針並更新答案。收縮時若某字元數量從「剛好滿足」掉到不足，`valid` 減一。

**詳細解析**：關鍵在於**用 `valid` 取代每步的整表比對**。如果每次移動都掃一遍需求表確認是否全部滿足，複雜度會變成 O(n × k)，k 是字元種類數。用計數器則每步 O(1)，整體維持 O(n)。第二個關鍵是判斷條件必須是「**剛好等於**需求量時才動 `valid`」，寫成「大於等於」會重複累加，導致 `valid` 虛高、提早判定合法。這兩點是這題最常見的失分處，也是面試官真正在看的地方。

**面試回答方式**：直接給出 `valid` 計數器這個核心設計，並說明它取代了每步整表比對、把 O(nk) 降回 O(n)。接著強調判斷條件要用「剛好等於」而不是「大於等於」，並解釋寫錯會怎麼壞。加分點是提到收縮時要對稱地把 `valid` 減回去。

### 滑動視窗和雙指針是同一個東西嗎？

**核心答案**：滑動視窗是雙指針的**一種形態**，不是同義詞。雙指針涵蓋三種用法：**對撞指針**（左右向中間夾，關心兩端的組合）、**快慢指針**（同向不同速，關心位置關係）、**同向雙指針**（也就是滑動視窗，關心中間那一段區間）。差別在於「你關心的是指針指到的元素，還是它們之間的區間」。

**詳細解析**：這個分類的實際價值是**幫你在看到題目時選對工具**。題目說「找一對元素滿足某條件」而且陣列已排序，想對撞指針；說「連續的一段」，想滑動視窗；說「連結串列的第 k 個、中點、有沒有環」，想快慢指針。反過來，如果題目要的是**不連續的子序列**，滑動視窗就完全不適用——這是初學者最常見的誤用，看到「子」這個字就套視窗。子陣列與子字串是連續的，子序列不是，這個區分在面試中必須清楚。

**面試回答方式**：先給關係——滑動視窗是雙指針的一種形態，並用「關心元素還是關心區間」把三種形態分開。接著把它變成選型指引：已排序找一對用對撞、連續一段用視窗、連結串列位置關係用快慢。加分點是點出子陣列（連續）與子序列（不連續）的區別，後者不能用滑動視窗。
