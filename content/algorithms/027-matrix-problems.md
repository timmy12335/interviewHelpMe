# 題目

矩陣類的題目有哪些常見的模式？

## 核心答案

**四類，而它們的思路差異很大。**

**遍歷與模擬**——**螺旋矩陣、對角線遍歷、Z 字形**；核心是「用邊界變數而非複雜的條件判斷」：維護上下左右四個邊界，每走完一行或一列就收縮對應的邊界——**於是不需要 visited 陣列也不會重複。**

**原地變換**——旋轉 90 度（先轉置再翻轉每一行）、翻轉；關鍵是找到「用兩次簡單操作組合出目標」的分解。

**搜尋與連通性**——**島嶼數量、圍繞區域、最短路徑**；用 DFS 或 BFS，而矩陣天然就是一個圖（每個格子是節點、相鄰是邊）。

**以及利用矩陣的性質**——每行有序且每列有序的矩陣中搜尋：從右上角開始，比目標大就左移、比目標小就下移；**於是 O(m+n) 而非 O(mn)。**

## 詳細解析

「從右上角開始搜尋」的正確性論證是這類題目的關鍵：在右上角這個位置——左邊的都比它小、下面的都比它大；於是每一次比較都能排除一整行或一整列。而從左上角開始就不行（右邊與下面都比它大，無法決定往哪走）。這個「選對起點讓每一步都能排除一個維度」的思路，是「利用結構性質」類題目的典型——而能說出「為什麼是右上角而不是左上角」正是面試官想聽的。

「矩陣就是圖」這個視角能統一很多題目：島嶼數量就是「求連通分量的數量」、最短路徑就是「無權圖的 BFS」、以及各種「從邊界擴散」的問題就是「多源 BFS」——於是不需要為每一種發明新的做法，只要認出它是哪一種圖問題。而矩陣相對於一般圖的便利是「鄰居可以直接計算而不需要鄰接表」（上下左右四個方向的偏移量）。

「邊界檢查應該集中在一個地方」：分散的 `if (x >= 0 && x < m && y >= 0 && y < n)` 容易寫錯——而把它包成一個 `isValid(x, y)` 的輔助函數讓主邏輯清楚且不容易漏。這個小小的重構在矩陣題目中的收益很明顯——而它也讓「四個方向的迴圈」能被寫成一個乾淨的迴圈而非四段重複的程式碼。

「就地標記」是省空間的常見手法：DFS 走過的格子——可以直接改成一個特殊值（例如把 '1' 改成 '0'）而非維護一個 visited 陣列；於是空間從 O(mn) 降到 O(1)（不算遞迴堆疊）。**代價是「破壞了輸入」**——而如果不能破壞，可以在結束後還原（多一次遍歷）。

## 面試回答方式

先給四類模式與各自的思路，並在遍歷類中指出用邊界變數而非複雜的條件判斷。加分點有四個：**從右上角搜尋的正確性論證**——左邊都小、下面都大，於是每次比較排除一整行或一整列，而從左上角不行，能說出這個差別正是面試官想聽的；「矩陣就是圖」的視角能統一很多題目，而它相對於一般圖的便利是鄰居可以直接計算；邊界檢查應該集中在一個輔助函數中；以及**就地標記省空間**與它破壞輸入的代價。

## 講稿

矩陣題目有四類常見模式。遍歷與模擬、原地變換、搜尋與連通性、還有利用矩陣的性質。

遍歷類的核心是用邊界變數而不是複雜的條件判斷。維護上下左右四個邊界，每走完一行或一列就收縮對應的邊界，於是不需要走過標記也不會重複。

而利用性質這一類有一個很經典的題目，在每行有序且每列有序的矩陣中搜尋。做法是從右上角開始，比目標大就左移、比目標小就下移，於是複雜度是行加列而不是相乘。它的正確性論證是，在右上角這個位置，左邊的都比它小、下面的都比它大，所以每一次比較都能排除一整行或一整列。而從左上角開始就不行，因為右邊跟下面都比它大，無法決定往哪走。能說出為什麼是右上角而不是左上角，正是面試官想聽的。

還有一個視角能統一很多題目，矩陣就是圖。每個格子是節點、相鄰是邊。島嶼數量就是求連通分量、最短路徑就是無權圖的廣度優先。於是不需要為每一種發明新做法，只要認出它是哪一種圖問題。

## 常見追問

### 多源 BFS 什麼時候用？

**核心答案**：當「起點有多個且要求到最近起點的距離」時。例如「每個格子到最近的 0 的距離」或者「腐爛的橘子需要幾分鐘擴散完」——做法是「把所有起點一次全部放進佇列」再開始 BFS；於是第一次到達某個格子的距離，自然就是到最近起點的距離。

**詳細解析**：「一次放入所有起點」為什麼是對的：BFS 是按層擴散的——而多個起點同時開始，第 k 層就是「距離任一起點為 k 的所有格子」；於是第一次訪問到某個格子時，那個距離一定是最小的。而如果用「對每個起點各跑一次 BFS 再取最小」——複雜度是 O(起點數 × mn)，遠差於一次多源的 O(mn)。這個「把多個問題合併成一次遍歷」的思路在很多地方出現——而識別它的訊號是「要求到最近的某一類點的距離」。同樣的思路也適用於「從邊界開始的擴散」（例如「被包圍的區域」：從所有邊界的格子開始標記能到達的，剩下的就是被包圍的）。

**面試回答方式**：給適用場景（起點有多個且要求到最近起點的距離）與做法。核心加分點是說明為什麼一次放入所有起點是對的——BFS 按層擴散，第 k 層就是距離任一起點為 k 的所有格子，並比較複雜度（一次多源 vs 對每個起點各跑一次）。收在識別的訊號與同類應用：「要求到最近的某一類點的距離」，**以及從邊界開始的擴散問題**。

### 矩陣的 DFS 為什麼可能堆疊溢位？

**核心答案**：**因為遞迴的深度可能達到 mn**。一個 1000×1000 的全連通矩陣——**DFS 可能遞迴一百萬層**；而多數語言的預設堆疊放不下。解法是「改用迭代的 BFS（用佇列）」或者「迭代的 DFS（用明確的堆疊）」——它們的深度限制在堆積而非呼叫堆疊上。

**詳細解析**：「什麼時候該用 BFS 什麼時候該用 DFS」在矩陣題上有一個實用的判準：**求最短路徑（無權）必須用 BFS**（因為它按層擴散，第一次到達就是最短）；求連通性或者需要「走到底再回溯」的用 DFS（例如路徑列舉）。而在「只是要遍歷所有格子」的情況下兩者都行——這時 BFS 更安全（沒有堆疊深度的問題）而 DFS 的程式碼更短。所以在面試中「用 DFS 寫，但主動提到大矩陣可能堆疊溢位並說明怎麼改」是一個很好的表現——它展示了對實際限制的意識，而那正是「能寫程式」與「能寫可用的程式」的差別。

**面試回答方式**：給原因（遞迴深度可能達到 mn）與解法（改用迭代）。核心加分點是給出 **BFS 與 DFS 的選擇判準**（最短路徑必須 BFS、連通性或路徑列舉用 DFS、只是遍歷則兩者都行而 BFS 更安全）。收在面試技巧：用 DFS 寫但主動提到大矩陣可能溢位並說明怎麼改——它展示了對實際限制的意識，那是「能寫程式」與「能寫可用的程式」的差別。

### 稀疏矩陣該怎麼處理？

**核心答案**：**用「只儲存非零元素」的表示**。常見的是**座標列表（COO）**（一組 `(row, col, value)`）、**壓縮稀疏行（CSR）**（適合按行存取與矩陣乘法）、**或者「用 Map 以座標為鍵」**（最簡單，適合稀疏度極高且操作簡單的場景）。**於是空間從 O(mn) 降到 O(非零元素數)。**

**詳細解析**：「稀疏矩陣乘法」是一個經典的面試題而它的核心洞察很簡潔：直接三層迴圈是 O(mnk)——而如果 A 是稀疏的，那「A 中為零的元素對結果沒有貢獻」；於是只遍歷 A 的非零元素，對每個 `A[i][k] != 0`，累加到 `C[i][j] += A[i][k] * B[k][j]`。這把複雜度從「與矩陣大小相關」變成「與非零元素數相關」。而這個「跳過不影響結果的計算」的思路是稀疏優化的通用原則——它也出現在稀疏向量的內積、以及各種「大部分是預設值」的資料結構中。識別的訊號是「資料中有大量的零或預設值」，而那在真實的資料（推薦系統的評分矩陣、圖的鄰接矩陣）中極為常見。

**面試回答方式**：給三種表示與各自的適用場景，並指出空間的改善。核心加分點是**稀疏矩陣乘法的核心洞察**——A 中為零的元素對結果沒有貢獻，於是只遍歷非零元素，把複雜度從與矩陣大小相關變成與非零元素數相關。收在通用原則：「跳過不影響結果的計算」是稀疏優化的通用思路，而識別的訊號是資料中有大量零或預設值，那在真實資料中極為常見。
