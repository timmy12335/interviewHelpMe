# 題目

面試官要你分析一段程式的複雜度時，他到底想聽到什麼？攤還分析和平均複雜度差在哪裡？

## 核心答案

Big-O 回答的是**成長趨勢**，不是執行時間。它問的是「輸入放大之後，工作量放大多少倍」，所以常數與低階項會被捨去——當 n 夠大，`3n + 100` 和 `n` 的成長速度沒有差別，都是 O(n)。分析時看兩件事就夠：**迴圈的巢狀深度**（兩層掃同一個陣列是 O(n²)）與**遞迴每次把問題縮小多少**（每次砍一半是 O(log n)，切一半再合併是 O(n log n)）。**攤還分析**（amortized）處理的是另一種情況：單次操作偶爾很貴，但貴的次數隨規模變得稀疏，把成本分攤下來仍然便宜——動態陣列擴容單次是 O(n)，但因為每次容量翻倍，插入 n 個元素的總搬移量是 O(n)，所以每次 `add` 是**攤還 O(1)**。攤還與平均複雜度的差別在於：攤還是對任意操作序列都成立的保證，平均是**對輸入分布的假設**。

## 詳細解析

為什麼捨去常數是合理的，什麼時候不合理：Big-O 的目的是比較演算法，不是預測毫秒數。當你要在 O(n log n) 和 O(n²) 之間選，常數完全不重要。但當兩個演算法同階時，常數就是全部——同樣是 O(n) 的兩趟掃描與一趟掃描，在熱路徑上差一倍。面試裡如果你只會背階數、被問「這兩個都是 O(n)，你選哪個」就答不出來，是很常見的失分點。

**最壞、平均與最好情況**：Big-O 習慣上描述最壞情況，但很多演算法的價值在平均。快速排序最壞是 O(n²)（每次都選到極值當樞紐），平均是 O(n log n)，實務上大家還是用它，因為隨機化樞紐讓最壞情況機率極低，而且它的常數與快取行為都比合併排序好。哈希表的查找是平均 O(1)、最壞 O(n)——這個「最壞」在被惡意構造碰撞時會真的發生，所以 Java 8 之後 HashMap 的桶會在過長時轉成紅黑樹，把最壞拉回 O(log n)。

**攤還分析的三種算法**：最直覺的是**聚合法**——算出 n 次操作的總成本再除以 n。動態陣列從容量 1 開始翻倍，擴容的搬移總量是 1 + 2 + 4 + … + n，等比級數小於 2n，所以平均每次 O(1)。另外還有**記帳法**（每次便宜操作多存一點「代幣」，貴的操作用存下來的代幣付帳）與**位能法**。面試講聚合法就足夠，重點是說清楚「貴的操作為什麼會愈來愈稀疏」。

**空間複雜度容易被忽略**：遞迴的呼叫堆疊要算進空間成本。深度為 n 的遞迴就是 O(n) 空間，這是面試官問「能不能改成迭代」時真正在問的東西。另外要區分**額外空間**與**總空間**：原地排序說的是額外空間 O(1)，不是不佔記憶體。合併排序需要 O(n) 的輔助陣列，這正是它在記憶體受限時輸給快速排序的原因。

**遞迴式的快速判斷**：主定理（Master Theorem）可以不背，但要能對 `T(n) = 2T(n/2) + O(n)` 這種式子反應出 O(n log n)——切成兩半、每層合併成本 O(n)、共 log n 層。二分搜尋是 `T(n) = T(n/2) + O(1)`，每層只做常數工作，共 log n 層，所以 O(log n)。

## 面試回答方式

先定調——Big-O 描述的是成長趨勢而不是執行時間，這句話決定了後面所有的取捨。接著給你分析的**方法**而不是結論：看迴圈巢狀深度、看遞迴每次縮小多少。攤還分析要主動提，並用動態陣列擴容當例子，講清楚「擴容愈來愈稀疏」這個關鍵。加分點有兩個：一是點出攤還與平均的差別（一個是對任意序列的保證，一個是對輸入分布的假設）；二是主動補空間複雜度，特別是遞迴堆疊。如果面試官給的兩個方案同階，記得談常數與快取，不要只回「都是 O(n)」。

## 講稿

複雜度分析的重點不是背表格，而是問一句話：輸入變成兩倍，我要做的工作會變成幾倍。

Big-O 描述的是成長趨勢，不是執行時間。我們捨去常數跟低階項，因為當輸入夠大，那些項不影響趨勢。實際分析我只看兩件事，第一是迴圈的巢狀深度，第二是遞迴每次把問題縮小多少。二分搜尋每次砍一半，所以是對數級別，合併排序切一半再合併，就是 n 乘以 log n。

比較容易被追問的是攤還分析。動態陣列擴容那一次是 O(n)，但因為容量每次翻倍，擴容會愈來愈稀疏，把總搬移量分攤到每一次插入，平均還是常數。所以我們說 add 是攤還常數，而不是常數。

我想補一個很多人會漏掉的地方，就是空間。遞迴的呼叫堆疊要算進去，深度是 n 的遞迴就有 n 的空間成本。面試官問能不能改成迭代，問的其實就是這件事。

還有，如果兩個方案同階，那常數跟快取行為就是全部，這時候不能只回答都是 O(n)。

## 常見追問

### 攤還 O(1) 和平均 O(1) 有什麼不同？

**核心答案**：**攤還是保證，平均是假設**。攤還 O(1) 的意思是：不管你給什麼樣的操作序列，n 次操作的總成本都不會超過 O(n)——它對**最壞的序列**也成立。平均 O(1) 則建立在輸入分布的假設上，哈希表的平均 O(1) 假設鍵值均勻散布；如果有人刻意構造全部碰撞的鍵，平均就失效，退化成 O(n)。

**詳細解析**：這個差別在安全情境下會變成真實漏洞。曾有一輪針對多種語言的哈希碰撞阻斷攻擊，就是攻擊者送出大量碰撞鍵，讓伺服器的參數解析從 O(n) 變成 O(n²)。這類攻擊對「攤還 O(1)」的動態陣列無效，因為攤還的保證不依賴輸入長什麼樣子。防禦方式是隨機化哈希種子（讓攻擊者無法預先算出碰撞），或像 Java 8 那樣把過長的桶轉成樹結構，把最壞情況從 O(n) 收斂到 O(log n)。

**面試回答方式**：一句話定調——攤還是對任意序列的保證，平均是對輸入分布的假設。接著用哈希碰撞說明平均為什麼會失效，而攤還不會。加分點是提到哈希碰撞阻斷攻擊，以及隨機化種子與樹化桶這兩種防禦。

### 為什麼快速排序最壞是 O(n²)，實務上還是最常用？

**核心答案**：因為最壞情況在隨機化樞紐之後**機率低到可以忽略**，而它的**常數項與快取局部性**明顯優於同階的競爭者。快排是原地排序、只需 O(log n) 的遞迴堆疊，資料存取是連續的；合併排序雖然穩定保證 O(n log n)，卻要 O(n) 額外空間並且反覆在兩個陣列之間搬資料，快取不友善。

**詳細解析**：實務上的排序函式多半是混合式的。C++ 的 `std::sort` 用 introsort——先跑快排，遞迴深度超過門檻就切換成堆排序，把最壞情況壓回 O(n log n)，同時保留快排的平均效能；小區間則改用插入排序，因為在 n 很小時插入排序的常數最小。Java 對基本型別用雙樞紐快排，對物件用 TimSort（合併排序的變形），因為物件排序需要**穩定性**而基本型別不需要——這個差異常被追問，答得出來會加很多分。

**面試回答方式**：先講最壞情況為什麼可以接受（隨機化樞紐後機率極低），再講它真正的優勢是常數與快取。加分點是舉 introsort 這種混合策略，以及 Java 對基本型別與物件用不同排序演算法、原因是穩定性需求不同。

### 一段程式跑兩次 O(n) 的迴圈，複雜度是 O(2n) 還是 O(n)？

**核心答案**：是 **O(n)**，因為常數係數會被捨去，`O(2n)` 這個寫法本身就不符合慣例。但這不代表兩趟掃描和一趟掃描在實務上一樣快——在資料量大到超出快取的情況下，兩趟掃描要把資料從記憶體讀兩次，實測可能真的慢一倍。

**詳細解析**：這題在考你會不會把「同階」誤當成「一樣快」。面試官接著常會問：什麼時候你會刻意選兩趟掃描？答案是**可讀性與正確性**——例如先掃一趟算總和、再掃一趟算差值，比硬塞進一個迴圈清楚得多，而且大多數情況下這個差距根本量不出來。反過來，在熱路徑上（例如每秒百萬次的迴圈、或資料量遠大於快取）合併掃描才有意義。判斷原則是：先寫清楚的版本，量到瓶頸再合併，而不是預先優化。

**面試回答方式**：先給正確答案 O(n)，並說明常數被捨去是定義使然。緊接著補上「同階不等於一樣快」，講快取讀取次數的差異。加分點是講清楚取捨立場——預設寫清楚的版本，量到瓶頸才合併，避免給人過早優化的印象。
