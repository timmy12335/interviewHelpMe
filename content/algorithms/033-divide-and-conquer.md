# 題目

什麼樣的問題適合用分治？怎麼分析它的複雜度？

## 核心答案

分治適用的條件有三個，缺一不可。問題可以被拆成同類型的子問題、**子問題之間互相獨立**（有重疊就該用 DP 而非分治）、以及子問題的解可以被合併成原問題的解。

而「合併的成本」決定了整體的複雜度：歸併排序的合併是 O(n)，於是總複雜度是 O(n log n)；而二分搜尋沒有合併（只走一邊），於是是 O(log n)。

**分析用主定理**：`T(n) = a·T(n/b) + f(n)`——**比較 `f(n)` 與 `n^(log_b a)` 的大小**；前者大則合併主導、後者大則遞迴主導、相當則多一個 log 因子。而在面試中，畫出遞迴樹並「按層加總」往往比套公式更直觀也更不容易記錯。

**典型的分治題目**：歸併排序、快速排序、逆序對計數、最近點對、以及各種「在有序或半有序結構上二分」的問題。

## 詳細解析

「子問題獨立」是分治與 DP 的分界線：斐波那契的遞迴分解看起來是分治——**但 `F(n-1)` 與 `F(n-2)` 的子問題大量重疊**；於是純遞迴是指數級的，而加上記憶化就變成了 DP。所以判斷的方式是「畫出遞迴樹，看有沒有重複的節點」——有的話用 DP（記憶化或遞推），沒有的話分治是合適的。

「逆序對計數」是一個很好的分治範例：在歸併排序的合併過程中——當右半部的元素被取出時，左半部剩下的所有元素都與它構成逆序對；**於是「順便就數出來了」**。這展示了分治的一個常見用法：「在合併的步驟中順便計算跨越兩半的貢獻」——而「左半部內部的、右半部內部的、以及跨越的」這個三段式分解，在很多分治問題中都適用（例如最大子陣列和的分治解法）。

**「快速排序不是嚴格的分治」**：它沒有「合併」的步驟（分割之後兩半各自排好，整體就排好了）——**於是它的工作在「分」而非「治」**；而歸併排序相反（分很簡單，合併是主要工作）。**這個對比很有教學價值**——它說明了「分治」的工作可以落在任一端，而那決定了它的特性（快排是原地的但不穩定，歸併穩定但需要額外空間）。

「遞迴的深度是空間複雜度的來源」：分治的空間開銷至少是遞迴的深度——平衡分割時是 O(log n)，而最壞情況（快排每次分割極不均勻）是 O(n)；這在面試中被問到空間複雜度時經常被漏掉。

## 面試回答方式

先給三個適用條件（可拆成同類子問題、子問題獨立、解可合併）並強調**有重疊就該用 DP**，再說明合併的成本決定了整體複雜度與主定理，並建議畫遞迴樹按層加總比套公式更直觀。加分點有四個：子問題獨立是分治與 DP 的分界線——判斷的方式是畫遞迴樹看有沒有重複的節點；逆序對計數展示了「在合併時順便計算跨越兩半的貢獻」，而「左、右、跨越」的三段式在很多分治問題中適用；快速排序的工作在「分」而歸併在「合」，**這決定了它們的特性**；以及遞迴的深度是空間複雜度的來源，**在被問到空間時經常被漏掉**。

## 講稿

分治適用的條件有三個。問題可以被拆成同類型的子問題、子問題之間互相獨立、還有子問題的解可以被合併。

第二個條件是分治與動態規劃的分界線。斐波那契的遞迴分解看起來是分治，但子問題大量重疊，於是純遞迴是指數級的，而加上記憶化就變成動態規劃。所以判斷的方式是畫出遞迴樹看有沒有重複的節點。

而合併的成本決定了整體的複雜度。歸併排序的合併是線性的，於是總共是線性對數。而二分搜尋沒有合併只走一邊，於是是對數。分析我會畫遞迴樹按層加總，那比套主定理的公式更直觀也不容易記錯。

有一個很好的分治範例是逆序對計數。在歸併的合併過程中，當右半部的元素被取出時，左半部剩下的所有元素都與它構成逆序對，於是順便就數出來了。這展示了分治的一個常見用法，在合併的步驟中順便計算跨越兩半的貢獻。而左半部內部、右半部內部、跨越的這個三段式分解，在很多分治問題中都適用。

還有一個容易漏掉的，遞迴的深度是空間複雜度的來源。

## 常見追問

### 分治的並行化為什麼自然？

**核心答案**：**因為子問題獨立**。兩個子問題之間沒有資料依賴——於是可以在不同的執行緒或核心上同時進行；**而合併只需要等它們都完成**。這正是 Java 的 Fork/Join 框架與各種平行歸併排序的基礎。

**詳細解析**：「並行化的收益有一個明確的閾值」：對小的子問題，「建立任務與排程的開銷」超過了平行的收益——所以實務的做法是「當子問題小於某個閾值時改用串行的實作」（`if (size < THRESHOLD) return sequentialSort(...)`）。那個閾值通常靠實測決定，常見的量級是幾百到幾千個元素。這個「粗粒度並行、細粒度串行」的模式在所有的平行分治中都出現——而忘記它的話，平行版本可能比串行還慢（因為任務的數量爆炸而每個任務的工作極少）。而 Fork/Join 的「工作竊取」正是為了處理「子問題大小不均」的情況：閒置的執行緒從忙碌的那裡偷任務，於是負載自動均衡。

**面試回答方式**：給根本原因（**子問題獨立，沒有資料依賴**）與它作為 Fork/Join 基礎的角色。核心加分點是**並行化的收益有明確的閾值**——小的子問題中任務開銷超過收益，所以要在閾值以下改用串行，忘記它的話平行版本可能比串行還慢。收在工作竊取處理子問題大小不均——閒置的執行緒從忙碌的那裡偷任務，負載自動均衡。

### 最近點對問題怎麼分治？

**核心答案**：按 x 座標分成兩半、遞迴求兩半的最近距離 d、然後只檢查「跨越分界線且水平距離小於 d」的那條帶狀區域。關鍵的洞察是「在那條帶內，每個點只需要與 y 座標相鄰的常數個點比較」——因為如果超過那個數量，它們之間的距離就會小於 d，與遞迴的結果矛盾。**於是合併是 O(n) 而總複雜度是 O(n log n)。**

**詳細解析**：「每個點只需比較常數個」的論證是這題的精髓：在帶狀區域中，考慮一個點與它 y 座標之後的點——如果有超過 7 個點在它的 y 距離 d 之內，那麼由鴿籠原理，某兩個點的距離會小於 d；而那與「兩半各自的最小距離是 d」矛盾。所以最多檢查 7 個（有些版本說 6 或 8，取決於推導的細節）。這個「用矛盾證明常數上界」的論證方式，是分治複雜度分析中一個經典的技巧——而它也說明了為什麼「看起來是 O(n²) 的合併其實是 O(n)」。

**面試回答方式**：給分治的步驟並指出關鍵洞察是帶內每個點只需比較常數個。核心加分點是給出**那個論證**：如果超過 7 個點在 y 距離 d 之內，由鴿籠原理某兩個的距離會小於 d，與遞迴的結果矛盾。收在方法論：「用矛盾證明常數上界」是分治複雜度分析中的經典技巧，它說明了為什麼看起來 O(n²) 的合併其實是 O(n)。

### 分治與二分搜尋有什麼關係？

**核心答案**：二分搜尋是分治的一個退化形態——它「分」成兩半但只「治」其中一半，而且不需要合併；**於是複雜度是 `T(n) = T(n/2) + O(1) = O(log n)`**。而理解這個關係的價值在於：很多「二分答案」的問題本質上是「在一個單調的判定函數上做分治」——而識別出那個單調性正是解題的關鍵。

**詳細解析**：**「二分答案」的識別訊號很明確**：題目要求「最小的最大值」或者「最大的最小值」——而且存在一個「給定一個候選答案，能在多項式時間內判斷可行性」的函數；如果那個可行性關於候選答案是單調的（可行的都可行到某個界限），就能二分。**例如「分成 k 段使最大段和最小」**：給定一個上限 x，貪心地分段並數需要幾段——如果不超過 k 就可行；而 x 越大越容易可行，單調性成立。這個「把最優化問題轉換成判定問題再二分」的技巧極其實用——因為判定往往比直接求最優容易得多。而它也是分治思想的一個延伸應用。

**面試回答方式**：說明**二分搜尋是分治的退化形態**（只治一半、不需合併）並給複雜度推導。核心加分點是**「二分答案」的識別訊號**：求「最小的最大值」或「最大的最小值」加上一個單調的可行性判定，並給出具體例子（分成 k 段使最大段和最小）。收在技巧的價值：把最優化問題轉換成判定問題再二分——因為判定往往比直接求最優容易得多。
