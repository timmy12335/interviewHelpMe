# 題目

鄰接矩陣和鄰接表怎麼選？圖的 DFS 為什麼一定要有 visited，樹的 DFS 卻不用？

## 核心答案

選表示法看**稠密程度**：鄰接矩陣佔 O(V²) 空間、查詢兩點是否相鄰是 O(1)、但遍歷某點的鄰居要掃整列 O(V)；鄰接表佔 O(V + E) 空間、遍歷鄰居只走實際存在的邊。真實世界的圖幾乎都是**稀疏**的（E 遠小於 V²），所以**預設用鄰接表**，只有在圖很小或需要頻繁查詢「這兩點有沒有邊」時才用矩陣。`visited` 之所以必要，是因為**圖有環**——樹是無環的且每個節點只有一個父節點，走下去不會回到走過的地方；圖可以繞回起點，沒有 `visited` 就是無限迴圈。而且無向圖的每條邊都是雙向的，光是相鄰兩點就會互相來回。標記時機也是考點：**BFS 必須在入佇列時就標記**，不能等到出佇列——否則同一個節點會被多次推進佇列，退化成指數級。

## 詳細解析

**visited 標記的三種狀態**：無向圖的連通性問題用布林 `visited` 就夠。但**有向圖偵測環**需要三種狀態——未訪問、**正在遞迴堆疊中**、已完成。只有「指向仍在遞迴堆疊中的節點」的邊才是環（回邊）；指向已完成節點的邊只是重複路徑，不構成環。用兩種狀態去判有向圖的環是最常見的錯誤，會把「菱形結構」誤判成有環。

**BFS 的標記時機決定複雜度**：正確做法是「推進佇列的同時標記為已訪問」。如果等到出佇列才標記，一個節點可能被多個鄰居各推一次，佇列裡出現大量重複，最壞會爆炸。這個細節在面試白板上很容易寫錯，主動說出來是加分點。

**BFS 的分層是它獨有的能力**：在**無權圖**上，BFS 第一次到達某個節點時走的必定是最短路徑（邊數最少），因為它是一圈一圈往外擴散的。這使得「最少步數」「最短轉換序列」「最少幾次操作」這類題目天然屬於 BFS。實作上分層要用「每輪先記錄當前佇列長度、只處理這麼多個」的骨架。DFS 沒有這個保證——它可能繞一大圈才到達目標。

**雙向 BFS 能把搜尋空間開根號**：當起點與終點都已知、且分支因子較大時，從兩端同時擴散、在中間相遇，複雜度從 b^d 降到約 2·b^(d/2)。實作要點是每次擴展節點數較少的那一側，並用兩個 visited 集合，相遇即結束。單字接龍這類題目用它會有明顯的速度差距。

**連通分量與拓撲的關係**：無向圖數連通分量就是「對每個沒訪問過的點跑一次 DFS 或 BFS，跑幾次就有幾個分量」，也可以用併查集做。有向圖則要區分**弱連通**（忽略方向後連通）與**強連通**（任兩點互相可達），後者要用 Tarjan 或 Kosaraju 演算法。面試中如果題目說「島嶼數量」「省份數量」「朋友圈」，那都是無向連通分量的包裝，認出來就等於解完了。

**網格圖是圖的特例**：矩陣題（島嶼、腐爛的橘子、最短路徑）本質上是圖，只是邊是隱含的——每格與上下左右四格相鄰。不需要真的建鄰接表，用方向陣列 `{{0,1},{0,-1},{1,0},{-1,0}}` 迭代即可。這類題的標準優化是**直接在原矩陣上標記已訪問**（把走過的陸地改成水），省下 O(V) 的額外空間，但要先確認題目允許修改輸入。

## 面試回答方式

先給選型準則：稀疏用鄰接表、稠密或要頻繁查邊用矩陣，並補一句真實世界的圖幾乎都稀疏。`visited` 的必要性用「圖有環、樹沒有」一句話講清楚，然後主動加上兩個細節：BFS 要在**入佇列時**標記（否則重複入列），以及有向圖偵測環需要**三種狀態**而不是布林值。接著講 BFS 與 DFS 的分工——無權圖最短路徑只有 BFS 保證，需要子樹回報或路徑枚舉用 DFS。加分點是提到網格題其實是隱含圖、可以原地標記省空間，以及雙向 BFS 能把搜尋空間開根號。

## 講稿

表示法我看稠密程度。鄰接矩陣佔的是點數平方的空間，好處是查兩點有沒有邊是常數時間。鄰接表佔的是點數加邊數，遍歷鄰居只走實際存在的邊。真實世界的圖幾乎都是稀疏的，所以我預設用鄰接表。

visited 為什麼必要，因為圖有環。樹是無環的，每個節點只有一個父節點，走下去不會回到走過的地方。圖可以繞回起點，而且無向圖每條邊都是雙向的，光是相鄰兩點就會互相來回。

這裡有兩個細節我會特別注意。第一，BFS 要在推進佇列的當下就標記，不能等到出佇列才標記，不然同一個節點會被多個鄰居各推一次，佇列裡塞滿重複。第二，有向圖偵測環要用三種狀態，未訪問、正在遞迴堆疊裡、已完成。只有指向還在堆疊裡的節點才是環，指向已完成的節點只是重複路徑。用布林值判斷會把菱形結構誤判成有環。

至於選 BFS 還是 DFS，無權圖上要最短路徑只有 BFS 有保證，因為它是一圈一圈往外擴散的。需要枚舉路徑或者收集子樹資訊就用 DFS。

## 常見追問

### 為什麼無權圖的最短路徑用 BFS 就好，不用 Dijkstra？

**核心答案**：因為無權圖可以視為**所有邊的權重都是 1**，此時 BFS 的擴散順序天然就是按距離遞增的——第 k 輪訪問到的所有節點距離起點恰好都是 k。Dijkstra 用優先佇列維護「當前最短距離」，在權重全相同時這個排序完全是多餘的，只是白白付出 O(log V) 的堆積操作成本。BFS 是 O(V + E)，Dijkstra 是 O((V + E) log V)。

**詳細解析**：中間還有一個常被忽略的情況——**權重只有 0 和 1** 的圖，這時用**雙端佇列 BFS**（0-1 BFS）：走權重 0 的邊就把節點推到佇列**前端**，走權重 1 的邊推到**後端**，這樣佇列仍保持距離的單調性，複雜度維持 O(V + E)，不需要動用堆積。這類題目常包裝成「有些操作免費、有些要花一次代價」的形式。再往上，權重是小整數且範圍有限時可以用**桶佇列**。認得出這條「BFS → 0-1 BFS → Dijkstra」的階梯，比只會 Dijkstra 更能顯示你會依問題選工具。

**面試回答方式**：先講原因——無權等於權重全為 1，BFS 的擴散順序本身就是距離順序，Dijkstra 的優先佇列是多餘成本。給出兩者複雜度對比。加分點是主動介紹 0-1 BFS 這個中間層級，並說明它用雙端佇列維持單調性。

### 有向圖偵測環為什麼不能只用布林 visited？

**核心答案**：因為布林值分不清「這個節點在我當前的遞迴路徑上」和「這個節點之前已經完整走完了」。指向前者才是環（回邊），指向後者只是不同路徑匯聚到同一點。經典反例是菱形：A 指向 B 和 C，B 和 C 都指向 D。走完 A→B→D 之後 D 已訪問，回頭走 A→C→D 時若用布林判斷會誤報有環，但這張圖顯然無環。

**詳細解析**：正確做法是三種狀態：0 未訪問、1 在當前遞迴堆疊中、2 已完成。遇到狀態 1 的鄰居才回報有環；遇到狀態 2 直接跳過。等價的做法是維護 `visited` 與 `onStack` 兩個布林陣列。另一條完全不同的路線是**拓撲排序**——用 Kahn 演算法不斷移除入度為 0 的節點，如果最後還有節點沒被移除，那些節點就構成環。拓撲排序的版本在「課程表」這類題目中更自然，因為題目往往同時要求輸出一個合法順序。無向圖偵測環則簡單得多，只要在 DFS 時遇到「已訪問且不是父節點」的鄰居即可。

**面試回答方式**：直接用菱形反例說明布林值為什麼不夠，這比抽象解釋有力。接著給三狀態方案。加分點是提出拓撲排序這條替代路線，並指出無向圖的判環條件不同（已訪問且非父節點）。

### 圖很大、放不進記憶體時要怎麼遍歷？

**核心答案**：改用**外部儲存加分批處理**的思路。典型做法是把圖按頂點分片存在磁碟或分散到多台機器，遍歷時以**迭代的層級式 BFS** 取代遞迴——每一輪把「當前層的所有節點」批次讀入、產生下一層的候選集合、去重後寫回磁碟，再進入下一輪。這正是 Pregel 與 GraphX 這類圖計算框架的「以頂點為中心、逐輪迭代」模型。

**詳細解析**：關鍵挑戰有兩個。一是 **visited 集合本身可能放不下**，解法是把它也分片存放，或在容忍少量重複計算的前提下用布隆過濾器做前置過濾。二是**分片邊界上的邊**會產生大量跨機器通訊，所以分片策略很重要——按社群結構切割能大幅減少跨片邊，而隨機切割會讓通訊量爆炸。另外遞迴 DFS 在這種規模下完全不可行（堆疊深度可能是百萬級），必須改成顯式堆疊的迭代版本，這個轉換本身也是常見的面試要求。

**面試回答方式**：先給核心思路——分片儲存加逐輪迭代的層級式 BFS，並點名這是 Pregel 式的計算模型。接著講兩個挑戰：visited 放不下（分片或布隆過濾器）、跨片邊造成通訊（分片策略要照社群切）。加分點是提到遞迴 DFS 在這個規模必須改寫成顯式堆疊的迭代版本。
