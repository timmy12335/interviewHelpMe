# 題目

雙指針解法為什麼能把 O(n²) 降到 O(n)？看到什麼樣的題目你會想到它？

## 核心答案

雙指針省下一層迴圈的關鍵是**單調性**：移動指針時，你能證明被跳過的組合**不可能是答案**，所以不需要回頭。最典型的是**對撞指針**——在已排序陣列裡找兩數之和等於目標，左右各一個指針，和太小就左指針右移（因為左邊已經是最小值，配任何右邊都不夠），和太大就右指針左移。每一步都排除掉一整排候選，所以 n 步內結束。另一類是**快慢指針**，兩個指針同向但速度不同，用來找中點、找倒數第 k 個、或偵測環。第三類是**讀寫指針**（原地移除、原地去重），寫指針只在遇到要保留的元素時前進。看到「**已排序**」「**找一對元素**」「**原地修改**」「**連結串列的位置關係**」這四個訊號，就該想到雙指針。

## 詳細解析

**對撞指針的正確性論證**：這是面試官最想聽的部分。在已排序陣列裡找 `a + b = target`，當 `nums[l] + nums[r] < target` 時，`nums[l]` 配上任何小於等於 `nums[r]` 的元素都只會更小，所以**含 l 的所有組合都可以排除**，l 可以安全右移。反過來也一樣。每一次移動排除掉一整列或一整行，等於在 n×n 的候選矩陣裡走一條單調的路徑，所以是 O(n)。能講出這個論證，比講「用兩個指針掃」有價值得多。

**沒排序就先排序，划不划算**：排序是 O(n log n)，如果題目只要求找出「是否存在」一對數，用哈希表是 O(n) 時間、O(n) 空間，比排序快。但如果要求**輸出所有不重複的組合**（三數之和這類），排序後用雙指針處理去重非常自然，哈希表反而麻煩。判斷原則是：只問存在性用哈希，要枚舉並去重就排序加雙指針。

**快慢指針的兩個經典用途**：找中點時讓快指針一次走兩步、慢指針一次走一步，快指針到底時慢指針正好在中間，一趟掃完不需要先算長度。偵測環用同樣的走法，如果有環，快慢指針一定會相遇——因為進到環之後兩者的距離每一步縮小 1，不會跳過。相遇後把其中一個指針放回起點、兩者都改成一次一步，再次相遇的位置就是環的入口，這是 Floyd 判圈演算法的第二階段。

讀寫指針的心法是「寫指針指向下一個該放的位置」：原地移除某個值時，讀指針掃過全部元素，只有遇到要保留的元素才寫進寫指針的位置並前進。這種寫法的好處是**寫指針永遠不會超過讀指針**，所以覆蓋是安全的，不需要額外陣列。原地去重（已排序）也是同一個骨架，只是判斷條件換成「跟前一個保留的元素不同」。

**滑動視窗是雙指針的特例**：兩個指針同向、中間那一段有意義（子陣列或子字串），就是滑動視窗。差別在於滑動視窗關心的是「區間本身」，對撞指針關心的是「兩端的組合」。面試時把兩者說成同一個家族的不同用法，會顯得你理解的是原理而不是模板。

## 面試回答方式

不要只說「用兩個指針」，要說清楚**為什麼可以不回頭**——這是雙指針唯一的技術含量。用對撞指針舉例：和太小就左移，因為含 l 的所有組合都被排除了，這個論證講出來就到位了。接著把三種形態分清楚：對撞、快慢、讀寫，各給一個代表題型。加分點有兩個：一是講「沒排序時排序划不划算」的取捨（存在性用哈希、要去重枚舉才排序）；二是把滑動視窗歸進同一個家族，展現你看到的是原理不是模板。

## 講稿

雙指針能省下一層迴圈，靠的是單調性。移動指針的時候，我要能證明被跳過的那些組合不可能是答案，所以不必回頭。

最典型的是對撞指針。在已排序的陣列裡找兩數之和，左右各放一個指針。如果和太小，那我就把左指針右移，因為左邊那個數已經是最小的，配上任何右邊的數都不夠大，所以含它的組合全部可以排除。每一步排掉一整排候選，所以整體是線性的。

第二種形態是快慢指針，兩個指針同向但速度不同，拿來找中點、找倒數第 k 個，或者偵測環。第三種是讀寫指針，用在原地移除跟原地去重，寫指針只在遇到要保留的元素時才前進。

如果陣列沒排序，要不要先排序是個取捨。只問存不存在一對數，用哈希表是線性時間，比排序快。但如果要枚舉所有不重複的組合，排序之後用雙指針去重會自然很多。

最後補一點，滑動視窗其實是雙指針的特例，只是它關心中間那一段區間，而不是兩端的組合。

## 常見追問

### 三數之和為什麼要先排序？不排序可以做嗎？

**核心答案**：可以不排序，但**去重會變得很痛苦**。三數之和要求輸出所有不重複的三元組，排序之後可以固定第一個數、對剩下的區間跑對撞指針，重複元素會相鄰，跳過重複只要比較「跟前一個是不是一樣」。不排序而用哈希表，你會拿到大量順序不同但內容相同的三元組，得靠排序每個三元組再放進集合去重，反而更慢也更醜。

**詳細解析**：排序版的複雜度是 O(n log n) 排序加上 O(n²) 的雙層掃描，總共 O(n²)，排序的成本被完全吸收。去重有兩個位置要處理：外層固定的第一個數要跳過重複，內層找到一組答案後左右指針也要跳過重複，兩處都做才不會漏。實務上更容易寫錯的是內層——找到答案後只移動一邊的指針，會產生重複解。另外排序還帶來剪枝機會：當最小的數已經大於零（在求和為零的題型裡）就可以直接結束。

**面試回答方式**：先講重點是去重而不是效率——排序讓重複元素相鄰，跳過很便宜。接著說明複雜度上排序被 O(n²) 吸收，所以不虧。加分點是主動提兩個去重位置（外層與內層都要跳），以及排序帶來的提前結束剪枝。

### Floyd 判圈為什麼相遇後把指針放回起點就能找到環的入口？

**核心答案**：設起點到環入口是 a 步、入口到相遇點是 b 步、相遇點繞回入口是 c 步。快指針走的距離是慢指針的兩倍，可以推出 **a = c**（外加若干圈環長）。所以把一個指針放回起點、兩個都改成一次一步，一個走 a 步到入口、另一個走 c 步也剛好到入口，必定在入口相遇。

**詳細解析**：推導過程是：慢指針走了 a + b，快指針走了 a + b + k 圈環長，而快是慢的兩倍，所以 a + b 等於 k 圈環長，也就是 a = k 圈環長減 b，而環長等於 b + c，代入後得到 a = c 加上 (k−1) 圈。多繞的圈數不影響結論，因為繞完還是回到同一點。這個推導在面試中不一定要完整背出來，但要能說出「兩段距離相等」這個結論以及它從何而來。實務上這個技巧不只用在連結串列，也用在偵測狀態機的循環、或找重複數字（把陣列值當成指標的題型）。

**面試回答方式**：直接給結論——起點到入口的距離等於相遇點繞回入口的距離，所以兩個一次一步的指針會在入口相遇。接著簡短帶過推導：快是慢的兩倍，把式子列出來就會消掉。加分點是提到這個技巧可以用在「找陣列中重複數字」這種把值當指標的題型。

### 快慢指針找中點時，偶數長度會停在前面還是後面那個中點？

**核心答案**：取決於**迴圈條件**。用 `while (fast != null && fast.next != null)` 會停在**後半段的第一個**節點（偶數長度時是右中點）；用 `while (fast.next != null && fast.next.next != null)` 則會停在**左中點**。這不是細節而是常見的越界來源——合併排序連結串列時必須拿到左中點，否則遞迴切不開會無限迴圈。

**詳細解析**：以 1→2→3→4 為例，第一種寫法慢指針停在 3，第二種停在 2。連結串列的合併排序需要把串列切成兩半，如果拿到的是右中點，長度為 2 的串列會被切成空的一半加上原本的一半，遞迴永遠不會收斂。反過來，回文判斷或找「中間節點」的題目通常要右中點。所以面試時被問到這題，正確的回答不是背哪一種寫法，而是**先問清楚題目要哪一個中點**，再選對應的條件——這個反問本身就是加分。

**面試回答方式**：先點出答案取決於迴圈條件，並給出兩種寫法各自停在哪。接著用連結串列合併排序說明選錯會無限迴圈，讓對方看到你踩過這個坑。加分點是強調實務上應該先確認題目要左中點還是右中點，而不是背模板。
