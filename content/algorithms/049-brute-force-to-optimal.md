# 題目

拿到一道沒見過的題目，怎麼從暴力解一步步推到最優解？

## 核心答案

**一個五步的流程。**

**一、先寫出暴力解的思路**（不一定要寫程式碼）——**它建立了正確性的基準，也讓你看清問題的結構**；**「先確定我能解出來，再想怎麼更快」比一開始就追求最優可靠。**

**二、分析暴力解在做什麼重複的事**——**同一個和被算了很多次？同一個子問題被解了很多次？同一個查詢被重複執行？**；**重複的類型直接對應到優化的手段。**

**三、找一個能消除那個重複的結構**——**重複的求和用前綴和、重複的子問題用記憶化、重複的查詢用雜湊表或索引。**

**四、驗證新解法在小例子上和暴力解一致**——**這一步在面試中值得花一分鐘，因為優化最容易引入邊界錯誤。**

**五、如果還不夠快，回到第二步再問一次**——**優化常常是分階段的，O(n³) 到 O(n²) 到 O(n log n)。**

## 詳細解析

**「暴力解建立的不只是基準，還有理解」**：很多題目在寫出暴力解的過程中，你才真正看清「這個問題到底在問什麼」——**而在腦中直接跳到「這應該是 DP」往往是在猜而非在推導**；**猜對了很好，猜錯了會浪費大量時間且很難發現錯在哪。**

**「識別重複的類型」是整個流程的核心**：暴力解中的巢狀迴圈，內層在做什麼？——**如果內層是在求一段連續的和，那前綴和能消除它**；**如果內層是在找「最近的比它大的元素」，那單調堆疊能消除它**；**如果內層是在遍歷所有更小的子問題，那 DP 能消除它**。**這個「內層在做什麼 → 用什麼結構消除」的對應表，是可以被明確學習的**——**它比「多刷題培養直覺」更可教也更可靠。**

**「小例子驗證」的具體做法**：取一個 n = 4 或 5 的例子，手算暴力解的答案，再手動跑一遍優化後的邏輯——**特別注意空輸入、單一元素、全部相同、以及邊界值**；**在面試中做這一步會讓面試官對你的嚴謹度印象深刻**，**而它也真的能抓到錯誤。**

**「分階段優化是常態」**：三數之和從 O(n³)（三層迴圈）到 O(n²)（排序後雙指標）——**中間可能還有一個 O(n² log n) 的版本（雙層迴圈加二分）**；**每一步都是一個獨立的、可以被解釋的改進**。**在面試中展示這個階梯，比直接給出最優解更能證明你是推導出來的而非背過。**

## 面試回答方式

給五步的流程並強調**先確定能解出來再想怎麼更快**。加分點有四個：**暴力解建立的不只是基準還有理解**——**直接跳到「這應該是 DP」是在猜而非推導**；**識別重複的類型是核心**，給出「內層在做什麼 → 用什麼結構消除」的對應表，並指出**它可以被明確學習，比「多刷題培養直覺」更可教**；**小例子驗證的具體做法**與它在面試中的印象價值；以及**分階段優化是常態**，**展示階梯比直接給最優解更能證明你是推導出來的**。

## 講稿

我用一個五步的流程。

第一步先寫出暴力解的思路，不一定要寫程式碼。它建立了正確性的基準，也讓我看清問題的結構。很多題目其實是在寫暴力解的過程中，我才真正看清它在問什麼。直接在腦中跳到這應該是動態規劃，往往是在猜而不是在推導。

第二步是分析暴力解在做什麼重複的事。同一個和被算了很多次，還是同一個子問題被解了很多次。

第三步是找一個能消除那個重複的結構。重複求和用前綴和，重複的子問題用記憶化，重複查詢用雜湊表。這個內層在做什麼、用什麼結構消除的對應，是可以被明確學習的，比多刷題培養直覺更可靠。

第四步是拿一個小例子驗證新解法跟暴力解一致。這一步值得花一分鐘，因為優化最容易引入邊界錯誤。

第五步，如果還不夠快就回到第二步再問一次。優化常常是分階段的。

## 常見追問

### 如果連暴力解都想不出來呢？

**核心答案**：**縮小問題**。把 n 設成 1、2、3 手動求解——**看看答案有什麼規律，或者「n = 3 的答案能不能由 n = 2 的推出來」**；**這既可能直接發現遞推關係，也能讓你理解問題的結構**。**另一個手段是「先解一個更簡單的變體」**——**例如去掉某個約束、或者假設所有元素都不同。**

**詳細解析**：**「從小例子找規律」在兩種情況下特別有效**：一是答案有數學的封閉形式（爬樓梯就是費波那契、某些計數問題是卡特蘭數）——**列出前幾項後在腦中或紙上比對就能認出**；**二是遞推關係存在但不明顯**——**「n = 4 的答案是 n = 3 加 n = 2」這樣的觀察直接給出了 DP 的轉移**。**而在面試中把這個過程說出來（「讓我先看看 n = 1、2、3 的情況」）是完全正常且被鼓勵的**——**它展示了你有一個系統的方法應對陌生的問題，而不是靠記憶**；**面試官通常更在意這個，因為它預測了你在真實工作中遇到未知問題時的表現。**

**面試回答方式**：給兩個具體的手段（**縮小 n 手動求解**、**先解一個更簡單的變體**）。核心加分點是說明**從小例子找規律在兩種情況下特別有效**（數學封閉形式、不明顯的遞推關係）並各給例子。收在面試價值：**把這個過程說出來是完全正常且被鼓勵的**——**它展示了系統的方法而非記憶，而面試官更在意這個因為它預測了你遇到未知問題時的表現**。

### 怎麼知道自己的優化方向是對的？

**核心答案**：**看它有沒有真的消除了那個重複**。如果你加了一個資料結構但巢狀迴圈還在——**那複雜度沒有改變，只是換了一種寫法**；**明確地問「優化後，最內層的操作變成了幾次」是一個具體的檢查**。**另一個信號是「複雜度的表達式變簡單了」**——**從 O(n² log n) 到 O(n²) 到 O(n log n)。**

**詳細解析**：**「換了寫法但複雜度沒變」是一個很常見的自我欺騙**：例如把兩層迴圈改成遞迴、或者用了一個 map 但每次仍然遍歷它——**程式碼看起來「更進階」而效能完全相同**；**而在面試的壓力下，這個錯誤特別容易發生**。**防止它的方法是「每次優化後重新數一遍複雜度」而非憑感覺**——**具體地說出「外層 n 次、內層現在是 O(1) 的雜湊查詢、所以總共 O(n)」**。**這個習慣在真實的效能優化中同樣關鍵**：許多「優化」的提交實際上沒有改善任何東西——**而只有測量（或者嚴格的複雜度分析）能區分真的改善與感覺上的改善**；**這也是為什麼效能工作應該以基準測試開始而非以直覺開始。**

**面試回答方式**：給具體的檢查方法（**優化後最內層的操作變成了幾次**）與信號（複雜度表達式變簡單）。核心加分點是點出**「換了寫法但複雜度沒變」是很常見的自我欺騙**並給例子，防止的方法是**每次優化後重新數一遍複雜度而非憑感覺**。收在實務延伸：**許多「優化」的提交實際上沒有改善任何東西**，**而只有測量能區分真的改善與感覺上的改善**。

### 這個流程需要多少練習才能熟練？

**核心答案**：**比想像的少，如果練習的方式對**。**關鍵不是題目的數量而是「每一題都完整地走一遍流程並寫下識別到的重複類型」**——**三十到五十題有意識的練習，通常比三百題機械式的刷題效果更好**；**因為前者建立的是可遷移的模式而後者建立的是對特定題目的記憶。**

**詳細解析**：**「刻意練習的關鍵是在舒適區的邊緣並得到回饋」**：對演算法而言，那意味著「做略高於當前水準的題目」與「做完後對照更好的解法並問自己為什麼沒想到」——**後者是多數人省略的一步，而它恰恰是進步的來源**；**只做題不覆盤，等於重複已經會的東西**。**具體的做法是維護一個「我沒想到的洞察」的清單**——**每一條記錄「這題的關鍵一步是什麼、我當時卡在哪、下次遇到什麼訊號應該想到它」**；**這個清單會比任何題解都更有價值，因為它是針對你自己的盲點的**。**而我認為這個「記錄自己的盲點而非收集別人的答案」的習慣，是演算法準備中最被低估的一件事**。

**面試回答方式**：給明確的判斷（**關鍵不是數量而是每題完整走一遍流程**）並給出數字對比（三十到五十題有意識的練習 vs 三百題機械刷題）。核心加分點是**刻意練習的關鍵是在舒適區邊緣並得到回饋**，而**做完後問自己「為什麼沒想到」是多數人省略的一步且恰恰是進步的來源**。收在具體做法：**維護一個「我沒想到的洞察」的清單**，**它比任何題解都有價值因為它針對你自己的盲點**。
