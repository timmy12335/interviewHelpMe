# 題目

前綴和與差分陣列各自解決什麼問題？為什麼說它們互為逆運算？

## 核心答案

兩者都是用 **O(n) 的預處理換取 O(1) 的單次操作**，方向剛好相反。**前綴和**解決「**多次區間查詢、不修改**」：先算出 `prefix[i] = a[0] + … + a[i-1]`，之後任何區間和都是 `prefix[r+1] - prefix[l]`，一次減法。**差分陣列**解決「**多次區間修改、最後才查詢**」：把「區間 [l, r] 全部加 v」記成 `diff[l] += v` 與 `diff[r+1] -= v`，兩次寫入，全部修改做完後對 diff 求一次前綴和就還原出結果陣列。說它們互為逆運算，是因為**差分陣列的前綴和就是原陣列，原陣列的差分就是相鄰兩項的差**。判斷用哪個的關鍵是問：**修改和查詢誰多、誰先誰後**。查詢多用前綴和，修改多且能延後結算用差分，兩者都頻繁交錯就要換成樹狀陣列或線段樹。

## 詳細解析

**前綴和的邊界設計**：把 `prefix` 開成長度 n+1、`prefix[0] = 0`，是為了讓「從 0 開始的區間」不需要特判。如果開成長度 n 而 `prefix[i]` 代表前 i+1 項，查詢 `[0, r]` 就得寫成 `l == 0 ? prefix[r] : prefix[r] - prefix[l-1]`，多一個分支就多一個出錯機會。這種「多開一格換掉一個特判」的做法在面試中值得主動說出來，它顯示你在意的是不容易寫錯，而不只是能跑。

**前綴和加哈希表是另一個層次的用法**：單純的區間查詢只是入門。真正的高頻題型是「**和為 k 的子陣列個數**」——把區間和 `sum(j, i]` 改寫成 `prefix[i] - prefix[j]`，要找和為 k 就是找「前面出現過幾次 `prefix[i] - k`」，邊掃邊用哈希表記錄前綴和的出現次數，一趟 O(n)。同一個模式換個記錄對象就能解一整族題：記錄**餘數**解「和能被 k 整除」，記錄**第一次出現的位置**解「和為 0 的最長子陣列」，把 0 當成 −1 記錄則解「0 和 1 數量相等的最長子陣列」。

**二維前綴和與容斥**：矩陣的區域和用 `prefix[i][j]` 表示左上角到 (i, j) 的總和，查詢子矩形時要**加一次、減兩次、再加回一次**——減掉上方和左方之後，左上角那塊被減了兩次，要補回來。這是容斥原理最小的實例，畫個圖說明比背公式可靠。

**差分陣列的實務對應**：訂位系統、航班座位、行程重疊這類「大量區間加值、最後才問結果」的題目就是差分的主場。經典例子是航班預訂統計：上萬筆「第 l 到第 r 班機各加 v 個座位」的紀錄，逐筆展開是 O(n×m)，用差分是 O(n + m)。它也能推廣到二維——二維差分要在四個角落各做一次加減，最後對兩個維度分別求前綴和。

**什麼時候這兩個都不夠用**：前綴和的致命限制是**原陣列一改就要全部重算**，差分的限制是**過程中查不了值**。當修改與查詢交錯發生（改一次、查一次、再改一次），就必須換成支援 O(log n) 單點更新與區間查詢的結構——**樹狀陣列**（Binary Indexed Tree）寫起來短、常數小，**線段樹**功能更全（可以維護最大值、支援區間更新配懶標記）。面試中能點出這條升級路線，代表你知道模板的邊界在哪。

## 面試回答方式

先用一句話把兩者的分工講清楚——前綴和是查詢多不修改，差分是修改多延後查詢，兩者互為逆運算。接著主動講前綴和的真正價值不在區間求和，而在**配哈希表解子陣列計數**，並舉「和為 k 的子陣列」說明轉換過程。差分則用航班訂位這種實際場景說明，避免聽起來像純技巧。最後主動說出邊界：修改與查詢交錯時兩者都不夠，要升級到樹狀陣列或線段樹。加分點是提到 `prefix[0] = 0` 這個多開一格的設計消掉了特判。

## 講稿

前綴和跟差分都是用線性的預處理，換取每次操作常數時間，但方向相反。

前綴和處理的是查詢很多、但不修改的情況。先把前綴和算好，之後任何區間和就是兩個值相減。差分反過來，處理修改很多、最後才查詢的情況。要把一個區間整段加上某個值，我只要在左端加、在右端的下一格減，兩次寫入就好，全部改完再對差分求一次前綴和，就還原出結果。

它們互為逆運算，差分的前綴和就是原陣列。

前綴和真正有價值的用法其實不是區間求和，而是配哈希表。像求和等於 k 的子陣列個數，我把區間和改寫成兩個前綴和相減，問題就變成前面出現過幾次某個值，邊掃邊記錄，一趟就掃完。同一個骨架換個記錄對象，還可以解餘數版本跟最長子陣列。

要注意它們的邊界。前綴和一改原陣列就要全部重算，差分在過程中查不了值。如果修改跟查詢是交錯發生的，就要換成樹狀陣列或線段樹。

## 常見追問

### 為什麼差分陣列要在 r + 1 的位置減，而不是在 r？

**核心答案**：因為差分還原時用的是**前綴和**，而前綴和在位置 i 累加的是 `diff[0]` 到 `diff[i]`。要讓加值的效果**涵蓋到 r 為止、從 r+1 起消失**，抵銷就必須發生在 r 的**後一格**。如果減在 `r`，那麼位置 r 本身的加值會被當場抵銷掉，變成只有 `[l, r-1]` 被加到，區間右端漏一格。

**詳細解析**：實作上這代表 `diff` 陣列要開成長度 n+1，讓 `r == n-1` 時的 `diff[n] -= v` 有地方可寫，否則會越界——這是這個技巧最常見的執行期錯誤。同樣的「多開一格」思路和前綴和的 `prefix[0] = 0` 是同一種設計：用一格記憶體換掉一個邊界特判。推廣到二維差分時，四個角落分別是 `(r1, c1) += v`、`(r1, c2+1) -= v`、`(r2+1, c1) -= v`、`(r2+1, c2+1) += v`，右下角要加回來是因為它被減了兩次，和二維前綴和的容斥是同一件事的鏡像。

**面試回答方式**：先用還原機制解釋——還原靠前綴和累加，所以抵銷要落在區間結束的下一格，減在 r 會少加一格。接著主動提實作細節：差分陣列要多開一格避免越界。加分點是連結到二維差分的四角加減，並說明右下角加回來就是容斥。

### 前綴和陣列會不會溢位？實務上怎麼處理？

**核心答案**：會，而且比想像中容易。長度十萬、每個元素接近 `int` 上限的陣列，總和就會超過 32 位元。處理方式是**前綴和用更寬的型別**（Java 用 `long`、C++ 用 `long long`），或在題目允許時**改存餘數**。要注意的是即使原陣列是 `int`，累加過程中的中間值也會溢位，所以型別必須在**累加前**就轉寬，寫成 `long sum = (long) a[0] + a[1]` 而不是先用 int 加完再轉。

**詳細解析**：溢位在面試中不一定會被主動問，但**主動提出來會加分**，因為它顯示你有處理真實資料的意識。相關的一個陷阱是二分搜尋的中點計算 `(l + r) / 2`——當 l 和 r 都很大時 `l + r` 會溢位，正確寫法是 `l + (r - l) / 2`。這兩個都屬於「演算法正確但實作會炸」的類型，面試官在資深職缺上會特別看。另外在取餘數的題型裡，減法後可能是負數（例如 `(prefixR - prefixL + MOD) % MOD`），忘記補 MOD 也是常見錯誤。

**面試回答方式**：先確認會溢位並給出量級直覺（十萬個接近上限的 int 就爆了）。接著給處理方式：用寬型別、且要在累加前轉型。加分點是連結到二分搜尋中點的同類問題，以及取餘數時負數要補 MOD。

### 前綴和、樹狀陣列、線段樹三者怎麼選？

**核心答案**：看**修改與查詢的比例和交錯方式**。完全不修改就用**前綴和**（預處理 O(n)、查詢 O(1)，最快也最簡單）。有單點修改、要區間查詢，用**樹狀陣列**（兩者都 O(log n)，程式碼十行以內、常數小）。要**區間修改加區間查詢**，或要維護的不只是和（最大值、最小值、區間賦值），就用**線段樹**。

**詳細解析**：實務上樹狀陣列被低估——它能做的比一般人以為的多，透過維護差分陣列的樹狀陣列，可以做到區間修改加單點查詢，再開第二棵就能做到區間修改加區間查詢，程式碼仍遠短於線段樹。線段樹的真正優勢在於**可維護的資訊種類**：最大值、最小值、區間最大子段和這類不可逆的資訊，樹狀陣列做不到，因為它的結構依賴減法。面試中如果題目只是區間和，寫線段樹會顯得殺雞用牛刀，反而暴露你只會一招；能說出「這題樹狀陣列就夠，因為只需要和」才是對的判斷。

**面試回答方式**：用一條升級路線來講——不修改用前綴和、單點改用樹狀陣列、區間改或非和類資訊用線段樹。接著點出關鍵判準是「要維護的資訊可不可逆」，這決定了樹狀陣列能不能用。加分點是說明樹狀陣列配差分也能做區間修改，以及主動表達不會為了展示而寫線段樹。
