# 題目

什麼樣的題目「先排序」之後會變得容易？代價是什麼？

## 核心答案

排序的價值是「它建立了一個可以被利用的順序性質」——**而三類問題特別受益。**

**需要比較「相鄰」關係的**——排序後，最接近的元素一定相鄰；於是「找最小差值」從 O(n²) 的兩兩比較降到一次線性掃描。

**需要按某個維度貪心的**——區間排程按結束時間排序、活動選擇按某個代價排序；排序把「該先選哪個」這個判斷變成了「按順序取」。

**需要消除順序影響的**——判斷兩個字串是不是變位詞、或者把「組合」的問題正規化；排序讓「本質相同」的東西有了相同的表示。

**而代價有兩個**：**O(n log n) 的時間**（如果原本能做到 O(n)，那排序反而是瓶頸）**與「破壞了原本的順序」**（如果題目需要原始的索引，就要先記錄下來）。

## 詳細解析

「排序後相鄰即最接近」是最常被利用的性質：找「陣列中差值最小的兩個數」——**排序後只需要比較相鄰的 n-1 對**；因為「如果 a 與 c 不相鄰而 b 在中間，那麼 a 與 b 的差一定小於 a 與 c」。這個論證是排序類解法的正確性核心——而面試中能說出它，比寫出程式碼更重要。

「排序讓貪心變得可行」有一個明確的機制：貪心需要「一個明確的選擇順序」——**而排序正是建立那個順序**；於是「每一步都選當前最好的」變成「按排好的順序依次考慮」。而選擇「按什麼排序」正是這類題目的核心難點：區間排程按結束時間（而非開始時間或長度）——因為「結束得早的留下最多空間給後面」；這個選擇必須被論證，而不是試出來的。

「先排序再雙指針」是一個極常見的組合：兩數之和（在無序陣列上要用雜湊表，而在有序陣列上雙指針只需 O(1) 空間）、三數之和、以及各種「找滿足條件的組合」——排序建立了「往右變大、往左變小」的單調性，於是指針的移動方向有了依據。這個組合幾乎是「排序類題目」的預設解法框架。

「什麼時候不該排序」也要能判斷：如果只需要找一個極值（最大、最小、第 k 大）——排序是 O(n log n) 而堆積或快速選擇能做到 O(n) 或 O(n log k)；而如果原始順序本身是題目的一部分（例如「找出第一個重複的元素」），排序就破壞了題意。

## 面試回答方式

先給排序的價值（**建立可被利用的順序性質**）與三類受益的問題，再給兩個代價。加分點有四個：「排序後相鄰即最接近」的正確性論證——如果 a 與 c 不相鄰而 b 在中間，那 a 與 b 的差一定更小，而能說出這個比寫出程式碼更重要；**排序讓貪心可行的機制**與「按什麼排序」是核心難點且必須被論證；先排序再雙指針是極常見的組合，因為排序建立了單調性讓指針的移動有依據；以及**什麼時候不該排序**（只需要極值時、或原始順序是題意的一部分）。

## 講稿

排序的價值是它建立了一個可以被利用的順序性質，而有三類問題特別受益。

第一類是需要比較相鄰關係的。排序後最接近的元素一定相鄰，於是找最小差值從兩兩比較降到一次線性掃描。而這個解法的正確性論證是，如果兩個數不相鄰而中間有另一個數，那它們跟中間那個的差一定更小。面試中能說出這個論證比寫出程式碼更重要。

第二類是需要按某個維度貪心的。排序把該先選哪個這個判斷變成了按順序取。而選擇按什麼排序正是這類題目的核心難點。區間排程按結束時間而不是開始時間，因為結束得早的留下最多空間給後面。這個選擇必須被論證，不是試出來的。

第三類是需要消除順序影響的，比如判斷變位詞。

而代價有兩個。時間變成線性對數，如果原本能做到線性那排序反而是瓶頸。還有破壞了原本的順序，如果題目需要原始索引就要先記錄。

另外先排序再雙指針是一個極常見的組合，因為排序建立了單調性，於是指針的移動方向有了依據。

## 常見追問

### 自訂排序的比較器要注意什麼？

**核心答案**：**必須滿足嚴格弱序（strict weak ordering）**——否則排序的行為是未定義的，可能拋例外或者產生錯誤的結果。具體要求是：**反自反（a 不小於 a）**、**傳遞性（a<b 且 b<c 則 a<c）**、**以及「不可比的傳遞性」**。最常見的違反是「用相減實作比較器」（`a - b`）——在整數溢位時會給出錯誤的符號。

**詳細解析**：**「用相減比較造成的 bug 極其隱蔽」**：`Integer.MAX_VALUE - (-1)` 溢位成負數——於是「一個很大的數」被判斷成小於「一個很小的數」；而它只在特定的數值範圍下出現，一般的測試不會觸發。正確的做法是用 `Integer.compare(a, b)` 或者明確的比較。而另一個常見的錯誤是「比較器不一致」——例如「按分數排序，分數相同時按名字」而名字的比較又有隨機性（例如用了 hashCode）；於是同一份資料排兩次可能得到不同的結果。Java 的 `TimSort` 甚至會在偵測到不一致時拋出 `IllegalArgumentException`——那個錯誤訊息（`Comparison method violates its general contract`）正是這類問題的標誌。

**面試回答方式**：給嚴格弱序的要求與最常見的違反（用相減實作）。核心加分點是說明**用相減造成的 bug 極其隱蔽**——溢位讓大數被判斷成小於小數，且只在特定範圍出現，一般測試不會觸發。收在另一個常見錯誤：**比較器不一致**，而 Java 的 TimSort 會拋出特定的錯誤訊息，那正是這類問題的標誌。

### 部分排序或線上排序怎麼處理？

**核心答案**：**看你需要多少有序**。**只需要前 k 個**——**用堆積（O(n log k)）或者快速選擇（平均 O(n)）**；**不需要對全部排序**。**資料持續到來且要維持有序**——**用平衡樹或跳表（每次插入 O(log n)）**；**而不是每次來一個就重排**。**只需要「大致有序」**——桶排序或者按範圍分組可能就夠。

**詳細解析**：「快速選擇（quickselect）」是找第 k 大最優的方法而它值得被知道：它是快速排序的變體——每次分割後只遞迴進入包含目標的那一側；**於是平均複雜度是 O(n) 而非 O(n log n)**。代價是最壞情況 O(n²)（可以用中位數的中位數優化到最壞 O(n)，但常數大）與「它會改變原陣列」。而在面試中，「找第 k 大」的三種解法（排序、堆積、快速選擇）的複雜度比較是一個經典的討論——而能說出「如果 k 很小用堆積、如果 k 接近 n/2 用快速選擇」比只知道一種解法好得多。

**面試回答方式**：給三種情況與各自的做法。核心加分點是介紹**快速選擇**——只遞迴進入包含目標的那一側所以平均 O(n)，並給出它的代價（最壞 O(n²)、會改變原陣列）。收在比較：「找第 k 大」的三種解法的複雜度討論是經典的，而「k 很小用堆積、k 接近 n/2 用快速選擇」比只知道一種好得多。

### 穩定性什麼時候重要？

**核心答案**：當需要「多輪排序」保留前一輪的順序時。例如「先按分數排序，分數相同時按報名時間」——可以先按報名時間排一次，再用穩定的排序按分數排；於是分數相同的自然保持了報名時間的順序。而如果排序不穩定，就必須用一個複合的比較器一次排完。

**詳細解析**：「穩定性讓複雜的排序需求可以被分解」：一個「按三個維度排序」的需求——可以用三次穩定排序（從最次要的維度開始）取代一個複雜的三層比較器；而後者容易寫錯（尤其是升降序混合時）。這個技巧在處理表格資料時特別有用（使用者點了幾次不同的欄位排序，期待的正是這個行為）。而實作上要知道哪些排序是穩定的：合併排序穩定、TimSort（Java 的物件排序）穩定；**快速排序與堆積排序不穩定**；而 Java 對原生型別用的是不穩定的快排變體（因為原生型別沒有身份，穩定性沒有意義）——這個「對物件用穩定的、對原生型別用快的」的設計選擇很合理，而知道它能解釋一個常見的困惑。

**面試回答方式**：給穩定性的用途（多輪排序保留前一輪的順序）與具體例子。核心加分點是穩定性讓複雜的排序需求可以被分解——三次穩定排序取代一個容易寫錯的三層比較器，而這在表格資料的互動排序中正是使用者期待的行為。收在實作細節：**哪些排序穩定**，而 Java 對物件用穩定的、對原生型別用快的，因為原生型別沒有身份所以穩定性沒有意義。
