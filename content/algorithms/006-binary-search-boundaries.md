# 題目

二分搜尋為什麼那麼容易寫出無限迴圈或差一格？「二分答案」又是什麼樣的題型？

## 核心答案

二分搜尋難的不是概念而是**邊界一致性**：區間是開還是閉、`while` 條件用 `<` 還是 `<=`、更新時 `mid` 要不要被排除，這三者必須配套。最不容易錯的做法是**固定一種寫法**——用閉區間 `[l, r]`、條件 `l <= r`、更新時一定寫 `l = mid + 1` 或 `r = mid - 1`（**mid 必被排除**），這樣每輪區間至少縮小一格，不可能無限迴圈。找**左邊界**（第一個滿足條件的位置）時改用 `[l, r)`、條件 `l < r`、更新 `r = mid`（不減一，因為 mid 可能就是答案），這種寫法收斂到 `l == r` 就是答案。**二分答案**則是完全不同的題型：答案本身具有單調性（例如「最小的可行容量」——容量越大越可行），就對**答案的值域**二分，每次用一個 O(n) 的檢查函式判斷「這個值可不可行」，總複雜度 O(n log W)。看到「最小化最大值」「最大化最小值」「在 D 天內完成」這類敘述，就該想到二分答案。

## 詳細解析

**無限迴圈的根源是「mid 沒有被排除」**：當區間縮到剩兩個元素，`mid = l + (r - l) / 2` 會取到 `l`。如果這時寫 `l = mid`（沒有加一），區間完全沒縮小，下一輪還是同樣的 l 和 r，就卡死了。所以規則是：**只要更新後可能保留 mid，就必須確保另一邊在縮小**，或者把 mid 的取法改成向上取整。與其記住什麼時候要上取整，不如固定用「找左邊界時 `r = mid`、`l = mid + 1`」這一組，因為 l 那側永遠在前進。

**中點計算要防溢位**：`(l + r) / 2` 在 l 和 r 都接近型別上限時會溢位變成負數，導致索引越界。正確寫法是 `l + (r - l) / 2`。這是面試中「演算法對但實作會炸」的經典案例，主動說出來會加分，尤其在資深職缺。

**找左邊界與找右邊界不是同一段程式**：`lower_bound`（第一個大於等於 target 的位置）與 `upper_bound`（第一個大於 target 的位置）的差別只在比較符號，但用途完全不同——兩者相減就是 target 出現的次數，這是「在排序陣列中找元素的起訖位置」那類題的標準解。不要試著用一段程式加一堆特判涵蓋所有情況，寫兩個清楚的函式比寫一個聰明的函式安全得多。

**二分答案的三個要素**：一是**值域**（答案可能落在哪個範圍，例如最小容量介於「最大單件重量」與「總重量」之間）；二是**檢查函式** `check(x)`，回答「x 這個答案可不可行」，通常是一個貪心的模擬；三是**單調性論證**——必須說明「x 可行則所有大於 x 的也可行」，否則二分不成立。面試官最想聽的就是第三點，因為那決定了這個做法對不對。經典題型包括在 D 天內運完包裹的最小載重、分割陣列使最大子陣列和最小、製作 m 束花所需的最少天數。

**旋轉陣列這類「局部有序」的變形**：陣列被旋轉過之後整體不再有序，但**以 mid 切開必有一半是有序的**。判斷 target 是否落在那一半的範圍內，就能決定往哪邊走。有重複元素時 `nums[l] == nums[mid] == nums[r]` 會讓你判斷不出哪一半有序，此時只能把 l 往右縮一格，最壞退化成 O(n)——這個退化要能主動說明，它是這題的考點。

## 面試回答方式

不要一上來就寫程式，先講你的**邊界約定**：用閉區間還是半開、迴圈條件是什麼、更新時 mid 排不排除，並說明「固定一種寫法」是刻意的，因為二分的錯誤幾乎都來自不一致。接著區分兩件事：找確切值、找左右邊界，後者是實務上更常用的。二分答案要當成獨立題型講，強調三要素中的**單調性論證**——先說明為什麼「可行性」對答案是單調的，再談值域與檢查函式。加分點是主動提中點溢位的寫法，以及旋轉陣列有重複元素時會退化成 O(n)。

## 講稿

二分搜尋難的不是概念，是邊界的一致性。區間開閉、迴圈條件、更新時 mid 要不要排除，這三件事必須配套，錯一個就會無限迴圈或者差一格。

所以我的做法是固定一套寫法。找確切值的時候用閉區間，條件是 l 小於等於 r，更新一定寫成 mid 加一或 mid 減一，讓 mid 必定被排除，這樣每輪至少縮小一格，不可能卡住。找左邊界的時候換一套，用半開區間，更新時 r 等於 mid 不減一，因為 mid 本身可能就是答案，收斂到 l 等於 r 就是結果。

無限迴圈的根源其實只有一個，就是 mid 沒有被排除。區間剩兩個元素的時候 mid 會取到左端，這時候如果寫 l 等於 mid，區間就完全沒有縮小。

另外中點我會寫成 l 加上 r 減 l 除以二，避免相加溢位。

還有一類是二分答案。答案本身有單調性的時候，我就對答案的值域二分，每次用一個檢查函式判斷這個值可不可行。看到最小化最大值，或者在幾天內完成這種敘述，通常就是它。

## 常見追問

### 二分答案怎麼確認「單調性」真的成立？

**核心答案**：把檢查函式的語意寫成一句話，然後驗證它**單向成立**。例如「載重 x 能在 D 天內運完」——載重變大只會讓每天裝得更多、需要的天數更少或持平，所以 x 可行則 x+1 必可行，這就是單調性。反過來如果檢查函式的結果會隨 x 上下震盪（例如「恰好用完 x 個容器」），二分就不成立，因為你無法從一次檢查推論出整個半邊。

**詳細解析**：實務上判斷單調性的最快方式是問「**這個條件是不是越寬鬆越容易滿足**」。最小化最大值、最大化最小值這兩類敘述之所以是二分答案的標誌，正是因為它們天然單調。要小心的變形是**含等號的邊界**：檢查函式應該回答「小於等於 x 是否可行」還是「小於 x」，決定了最後收斂到的是左邊界還是右邊界，寫錯會差一格。另外檢查函式本身通常是貪心，貪心的正確性也要能論證——二分答案題實際上考的是兩層正確性，很多人只論證了外層。

**面試回答方式**：給出可操作的判準——把檢查函式寫成一句話，問它是不是「越寬鬆越容易滿足」。用載重運包裹舉例說明單調性。加分點是點出這類題有兩層正確性要論證：外層的單調性與內層貪心檢查函式的正確性，很多人只講前者。

### 在有重複元素的旋轉陣列裡搜尋，為什麼會退化成 O(n)？

**核心答案**：因為判斷「哪一半有序」依賴比較 `nums[l]`、`nums[mid]`、`nums[r]`，當三者相等時**無法區分**左半有序還是右半有序——例如 `[1,1,1,0,1]` 和 `[1,0,1,1,1]` 在這三個位置上完全一樣，但答案在不同邊。此時唯一安全的動作是把 l 往右移一格（或 r 往左移一格）縮小問題，最壞情況下每輪只縮一格，變成 O(n)。

**詳細解析**：這說明了二分搜尋的前提是**每次比較都要能排除一半**，一旦比較無法提供這個資訊，二分的優勢就消失。面試官問這題通常是想確認你不會硬套模板而忽略前提。實作上要注意：縮一格的動作只在「三者相等」時做，不能無條件執行，否則正常情況也退化。另外沒有重複元素的版本可以穩定 O(log n)，所以面試中先問清楚「陣列有沒有重複元素」是合理且加分的澄清問題。

**面試回答方式**：直接指出退化的原因是「比較無法排除一半」，用兩個長得一樣但答案不同的例子說明。接著強調這揭示了二分的前提。加分點是提到應該先問面試官陣列有沒有重複元素，以及縮一格的動作只能在三者相等時做。

### 什麼情況下線性掃描反而比二分搜尋快？

**核心答案**：**資料量小**、**資料存放不連續**、或**只查一次而資料還沒排序**這三種情況。小陣列（幾十個元素以內）的線性掃描因為快取友善、沒有分支預測失敗的成本，實測往往比二分快。連結串列上做二分毫無意義，因為找中點本身就是 O(n)。而如果資料未排序、只查一次，排序的 O(n log n) 遠超過直接掃一遍的 O(n)。

**詳細解析**：這題考的是**理論複雜度與實際效能的落差**。二分搜尋的存取模式是跳躍式的，每次跳到記憶體的不同位置，快取幾乎命中不了；線性掃描則是連續存取，硬體預取器能發揮作用。這也是為什麼許多標準函式庫的實作在區間縮小到某個門檻後會切換成線性掃描。相對地，如果同一份資料要查詢很多次，排序的成本被攤薄，二分就明顯划算——**判斷準則是查詢次數**：查一次用線性，查多次先排序再二分，資料會變動就改用平衡樹或雜湊表。

**面試回答方式**：列出三種情況並各給一句理由，重點放在快取友善這個實際因素，展現你分得清理論與實測。接著給判準：查詢次數決定要不要先排序。加分點是提到標準函式庫在小區間會切換成線性掃描這個實作細節。
