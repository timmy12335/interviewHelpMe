# 題目

回溯和一般的遞迴差在哪？寫回溯時你會先想清楚哪幾件事？

## 核心答案

回溯是**在決策樹上做深度優先搜尋，走過之後把狀態還原**。它和一般遞迴的差別在於**「撤銷」**這個動作——做了選擇、遞迴下去、回來之後要把選擇撤掉，讓兄弟分支從乾淨的狀態出發。寫之前一定要先定義三件事：**路徑**（已經做過的選擇）、**選擇清單**（當前還能做什麼）、**結束條件**（什麼時候把路徑收進答案）。骨架永遠是：到達結束條件就收集答案；否則遍歷選擇清單，做選擇、遞迴、撤銷選擇。複雜度由決策樹的規模決定——子集是 2ⁿ、排列是 n!、組合是 C(n, k)，所以**剪枝**不是優化而是必要：能提前判斷這條路一定不會有解就立刻返回。去重則靠**先排序、再跳過同一層中重複的選擇**，這是回溯題最常寫錯的地方。

## 詳細解析

**「撤銷」為什麼必要，什麼時候可以不寫**：如果路徑是用同一個可變物件（例如一個 `List`）在遞迴間共享，那麼加進去之後就必須移除，否則兄弟分支會看到不屬於自己的選擇。但如果每層都傳一份**新的不可變複本**（例如字串拼接、或每次 `new ArrayList<>(path)`），就不需要撤銷，因為每條路徑各自獨立。兩種寫法的取捨很清楚：共享加撤銷**省記憶體、快**，複製**不容易錯、但每層 O(n) 的複製成本會讓複雜度多乘一個 n**。面試中選共享加撤銷，但要能講出這個取捨。

**收集答案時務必複製**：`res.add(path)` 是回溯最經典的 bug——加進去的是**同一個物件的參考**，後續的撤銷會把它清空，最後得到一堆空清單。正確寫法是 `res.add(new ArrayList<>(path))`。這個錯誤在面試白板上寫出來，面試官通常會直接指出，屬於「知道就不會犯」的類型，值得主動說明。

**三種去重情境要分清楚**：第一種是**元素本身重複**（`[1, 2, 2]` 求子集），做法是先排序，然後在同一層迴圈中 `if (i > start && nums[i] == nums[i-1]) continue`——注意條件是 `i > start` 而不是 `i > 0`，因為跳過的是「同一層的重複選擇」，不是「不同層用到相同的值」。第二種是**同一個元素不能重複使用**，用 `used` 布林陣列或起始索引控制。第三種是**排列的去重**，除了跳過同層重複，還要加上 `!used[i-1]` 的條件，確保重複元素之間維持固定的相對使用順序。這三者混在一起是回溯題難的真正原因。

**剪枝的三個層次**：最基本的是**可行性剪枝**——當前狀態已經違反約束就返回（N 皇后判斷同列同對角線）。第二是**上界或下界剪枝**——剩下的元素全加起來也達不到目標，或已經超過目標（組合總和在排序後可以直接 `break` 而不是 `continue`）。第三是**對稱性剪枝**——利用問題的對稱結構只搜一半（N 皇后第一列只需搜前一半的位置）。面試中能主動加剪枝並說明它把搜尋空間砍掉多少，比只寫出正確的暴力搜尋強得多。

**遞迴深度與堆疊**：回溯的遞迴深度通常是 n（路徑長度），所以空間是 O(n) 加上答案本身的空間。真正要小心的是**用遞迴處理大規模線性結構**（例如對十萬節點的連結串列或退化成鏈狀的樹做遞迴），深度會直接撐爆堆疊。這時要改成迭代加顯式堆疊，或者確認語言支援尾遞迴優化——Java 和 Python 都不做尾遞迴優化，這點值得知道。

## 面試回答方式

先把框架講出來再動筆：路徑、選擇清單、結束條件，這三件事定義清楚，程式碼幾乎是照抄骨架。接著主動說明**撤銷的必要性**，以及「共享加撤銷」與「每層複製」的取捨，表示你知道為什麼這樣寫。收集答案要複製這件事主動提一句，避免面試官以為你不知道。複雜度直接用決策樹規模說（子集 2ⁿ、排列 n!），並強調**剪枝是必要而非優化**，各舉一個可行性剪枝與上界剪枝的例子。加分點是把去重的三種情境分清楚，特別是 `i > start` 而不是 `i > 0` 這個細節。

## 講稿

回溯就是在決策樹上做深度優先搜尋，差別在於走完一條路要把狀態還原。

我動筆之前一定先定義三件事，路徑是已經做過的選擇，選擇清單是現在還能做什麼，結束條件是什麼時候把路徑收進答案。這三個講清楚，程式碼幾乎是照著骨架抄，做選擇、遞迴、撤銷選擇。

撤銷為什麼必要，是因為路徑通常是共享的可變物件。如果不撤銷，兄弟分支會看到不屬於自己的選擇。另一種寫法是每層都傳一份新的複本，那就不用撤銷，但每層多一次複製，複雜度會多乘一個 n。我會選共享加撤銷。

這裡有個很經典的坑，收集答案的時候一定要複製一份再放進結果，直接放路徑本身的話，後面的撤銷會把它清空，最後拿到一堆空清單。

複雜度就看決策樹多大，子集是二的 n 次方，排列是 n 階乘。所以剪枝不是優化而是必要。像組合總和在排序之後，一旦超過目標就可以直接中斷，不只是跳過。

## 常見追問

### 子集、組合、排列這三種題型的骨架差在哪？

**核心答案**：差在**選擇清單怎麼縮**。**子集**每個元素只有選或不選，遞迴時傳 `i + 1` 讓後面的元素不再回頭看前面的，且**每一層都要收集答案**（不是只在葉節點）。**組合**是子集加上長度限制，結束條件變成「路徑長度等於 k」，並且可以剪枝——剩餘元素不足以湊滿 k 就提前返回。**排列**因為順序有意義，每層都要從**全部元素**中選，用 `used` 陣列標記哪些已經在路徑裡，所以決策樹是 n! 而不是 2ⁿ。

**詳細解析**：這三者的關係可以用一句話串起來：**傳起始索引就是不考慮順序（子集與組合），用 used 陣列就是考慮順序（排列）**。理解這一點之後，變形題就好處理了——「組合總和」允許元素重複使用，只要遞迴時傳 `i` 而不是 `i + 1`；「排列二」有重複元素，就在排列的骨架上加同層去重。另外子集在每層收集答案這件事常被忽略：如果只在遞迴到底時收集，會漏掉所有非葉節點的路徑，結果數量會從 2ⁿ 掉到很少。

**面試回答方式**：用「傳起始索引還是用 used 陣列」這一句話把三者串起來，這比分別背三個骨架有說服力。接著補上子集要在每層收集而不是只在葉節點。加分點是示範一個變形推導，例如允許重複使用元素只要把 `i + 1` 改成 `i`。

### 回溯題怎麼判斷該用「先排序再跳過」還是用 `used` 陣列去重？

**核心答案**：兩者處理的是**不同的重複**，通常要**一起用**。先排序再跳過同層重複，處理的是「**同一層選到值相同的元素**」導致的重複解；`used` 陣列處理的是「**同一個元素不能在一條路徑上用兩次**」。子集與組合類只需要前者（起始索引已經防止重用），排列類兩者都要。

**詳細解析**：排列去重的條件經常寫錯，正確的是 `if (i > 0 && nums[i] == nums[i-1] && !used[i-1]) continue`。關鍵在最後那個 `!used[i-1]`——它強制「相同的元素必須依索引順序被使用」，也就是只有在前一個相同元素**還沒被用**時才跳過（代表我們正在同一層嘗試第二個相同值，那是重複的分支）。如果寫成 `used[i-1]`，語意變成另一種同樣可行但方向相反的約定，容易和跳過條件搭配錯誤。實務建議是**固定記一種寫法並能解釋它的語意**，而不是試著臨場推導，因為這個條件很反直覺。

**面試回答方式**：先講清楚兩者處理不同的重複來源，並說明子集組合只需要前者、排列兩者都要。接著給出排列去重的完整條件，並解釋 `!used[i-1]` 的語意是「強制相同元素依序使用」。加分點是坦白說這個條件反直覺、你會固定一種寫法並確認能解釋它。

### 什麼時候該把回溯換成動態規劃？

**核心答案**：當**不同的決策路徑會走到相同的子問題**時。回溯是把整棵決策樹走完，如果樹上有大量重複的子問題，就有兩條路：加**記憶化**（把子問題結果快取起來，本質上是自頂向下的動態規劃），或改寫成自底向上的動態規劃。判斷訊號是「**問的是數量或最值，而不是要列出所有具體方案**」——要列出所有方案時必須真的走完每條路，動態規劃幫不上忙。

**詳細解析**：這條界線很實用。「有幾種爬樓梯方式」用動態規劃，因為只要數量；「列出所有爬樓梯的走法」只能回溯，因為答案數本身就是指數級。中間地帶是「求最值並回溯出一組方案」——先用動態規劃算出最值並記錄轉移來源，再從終點回推一條路徑，兼得效率與具體解。實作上從回溯升級到記憶化最省事：把遞迴函式的參數收斂成幾個關鍵狀態、確認同樣的狀態必定得到同樣的結果（無後效性），然後加一張快取表。這個「先寫回溯、確認正確、再加記憶化」的流程在面試中很好用，因為它讓你有階段性可交付的答案。

**面試回答方式**：給判準——重複子問題加上「只要數量或最值」就換成動態規劃，要列舉所有方案就只能回溯。接著描述升級路徑：先寫回溯確認正確，再把參數收斂成狀態、加記憶化。加分點是提到「動態規劃求最值再回推一組方案」這個折衷做法。
