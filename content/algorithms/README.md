# 演算法與資料結構面試題

InterviewHelpMe 第 13 個內容類別，共 24 題，取材自 [tech-interview-handbook](https://github.com/yangshun/tech-interview-handbook) 的演算法章節，涵蓋複雜度分析、陣列與字串技巧、連結串列、樹、圖、動態規劃與貪心。

## 這個類別的設計

這裡**不放單題 LeetCode 的解答**，放的是**題型與解題模式**。原因是面試官幾乎不會問「這一題怎麼解」，而是問「你看到這種題目會怎麼想」——同一個雙指針的想法可以解十幾道題，而背下十幾道題的解法卻推不出第十一題。所以每一題的核心都在回答兩個問題：**什麼訊號讓你想到這個工具**，以及**它為什麼是對的**。

因此每題都刻意包含**正確性論證**。雙指針那題要能說明「被跳過的組合為什麼不可能是答案」，單調堆疊要能說明「被彈掉的元素為什麼再也用不到」，貪心那題整篇都在講怎麼證明與怎麼找反例。這些論證正是面試中拉開差距的地方，也是純刷題練不出來的。

編號大致依難度與依賴關係遞增：001 到 009 是陣列與字串的基本技巧，010 到 015 是遞迴、樹與字串結構，016 到 019 是圖，020 到 023 是動態規劃與貪心，024 則是作答流程本身——它不是演算法題，但它決定了前面 23 題能不能在面試中發揮出來。

## 檔案格式

與其他類別相同：每題一個 `NNN-slug.md`，frontmatter 對應 [schema.sql](../../backend/sql/schema.sql) 的 `question` 表（`category: algorithms`，`source: original`）。正文含：題目、核心答案、詳細解析、面試回答方式、講稿、常見追問（3 題）、相關。

新增題目請用 `node scripts/new-question.mjs algorithms <slug> "<標題>"` 產生骨架，它會處理編號、frontmatter 與區塊結構。寫完跑 `npm test` 驗證結構與交叉連結，跑 `node scripts/check-scripts.mjs algorithms` 驗證講稿品質。
