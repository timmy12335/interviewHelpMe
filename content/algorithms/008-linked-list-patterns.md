# 題目

連結串列的題目為什麼特別容易寫錯？有哪些手法可以系統性地減少出錯？

## 核心答案

連結串列題的錯誤幾乎都集中在三處：**頭節點的特判**、**指標更新的順序**、**空指標與越界**。對應的三個手法是：第一，**虛擬頭節點**（dummy head）——在真正的頭前面掛一個假節點，讓「刪除頭節點」和「刪除中間節點」變成同一段程式，最後回傳 `dummy.next`，這一招消掉了大部分特判。第二，**改指標前先存好下一個**——反轉的標準骨架是「先記 next、再改當前節點的指標、然後兩個指針一起前進」，順序顛倒就會把後面整串弄丟。第三，**快慢指針**處理位置相關的需求（中點、倒數第 k 個、環偵測），一趟掃完不必先算長度。掌握這三個手法之後，反轉、合併、刪除、判環、重排這些題就都是同一批零件的組合。

## 詳細解析

**虛擬頭節點解決的是「前驅節點不存在」**：刪除節點需要拿到它的前驅，但頭節點沒有前驅，所以不加 dummy 就得寫一個 `if (head == target)` 的分支。這個分支本身不難，難的是它會在每一題重複出現、而且在遞迴或多次刪除時容易漏掉。加了 dummy 之後每個節點都有前驅，程式碼從兩條路變成一條路。除了刪除，合併兩個有序串列、分割串列、按值劃分這些「要建構新串列」的題也都該用 dummy，因為它讓「第一個節點」不需要特別處理。

**反轉的三行骨架**：`next = cur.next` 先把後路存起來，`cur.next = prev` 改向，`prev = cur; cur = next` 前進。這三行的順序不能動。常見的變形是**區間反轉**（反轉第 m 到第 n 個節點），做法是先走到 m 的前驅、記住它，反轉指定段落後再把三段接回去——關鍵是**接回去時要接兩個地方**：前驅接到新的頭，原本的頭接到剩下的部分，只接一邊是最常見的 bug。遞迴版的反轉更短但要能講清楚「回傳的是新的頭、而當前節點要變成它的下一個的下一個」，並且遞迴深度是 O(n)，資料大時有堆疊溢位風險。

**環的偵測與入口**：快指針一次兩步、慢指針一次一步，有環必相遇（進環後兩者距離每步縮小 1，不會跳過）。找入口則是相遇後把一個指針放回起點、兩者都改成一次一步，再次相遇處即入口，這來自「起點到入口的距離等於相遇點繞回入口的距離」這個推導。另一個方向是用雜湊集合記錄走過的節點，空間 O(n) 但邏輯直白——面試時可以先給雜湊解表示你有可行方案，再給 O(1) 空間的快慢指針解，這種「先給能動的、再給更優的」節奏本身就是好的答題策略。

**倒數第 k 個節點的一趟寫法**：讓快指針先走 k 步，然後兩個指針同速前進，快指針到底時慢指針正好在倒數第 k 個。要刪除它就讓慢指針停在它的**前驅**（配合 dummy 讓「刪除倒數第 n 個剛好是頭」不需要特判），這是虛擬頭節點價值最明顯的一題。邊界檢查是 k 大於長度時快指針會先變成 null，要主動處理。

**連結串列排序為什麼用合併排序**：快排在連結串列上很難做，因為它依賴隨機存取來劃分。合併排序則天生適合——用快慢指針找中點切開、遞迴排序、再合併兩個有序串列（合併只需要循序存取與改指標，不用搬資料）。要注意找中點時必須拿到**左中點**，否則長度為 2 的串列切不開會無限遞迴。空間是 O(log n) 的遞迴堆疊，可以再改成自底向上的迭代版本做到 O(1)。

## 面試回答方式

不要直接開始寫指標，先講你的**防錯策略**：加虛擬頭節點消掉頭節點特判、改指標前先存下一個、位置相關需求用快慢指針。這三句話講完，面試官就知道你寫過而不是背過。反轉題主動說出三行骨架的順序不能動，區間反轉則強調「接回去要接兩個地方」。判環先給雜湊解再給快慢指針解，展現你能先交付可行方案再優化。加分點是主動提遞迴版的堆疊深度風險，以及連結串列排序用合併排序的原因（合併只需循序存取）。

## 講稿

連結串列的錯幾乎都集中在三個地方，頭節點的特判、改指標的順序，還有空指標。所以我會先用三個手法把這些堵起來。

第一個是虛擬頭節點。在真正的頭前面掛一個假節點，這樣每個節點都有前驅，刪除頭節點跟刪除中間節點就變成同一段程式，最後回傳假節點的下一個就好。合併兩個串列、分割串列也都適用，因為第一個節點不用再特別處理。

第二個是改指標之前先把下一個存起來。反轉的骨架就三行，先記 next，再把當前節點指向前一個，然後兩個指針一起前進。順序顛倒就會把後面整串弄丟。

第三個是快慢指針，處理跟位置有關的需求。找中點、找倒數第 k 個、判斷有沒有環，都是一趟掃完，不用先算長度。

如果被問到判環，我會先給雜湊集合的解法，因為它直白而且一定對，再給快慢指針的版本把空間降到常數。先交付能動的，再優化，這樣比較安全。

## 常見追問

### 遞迴反轉連結串列和迭代版本，你在面試時會選哪個？

**核心答案**：**迭代版**。兩者時間都是 O(n)，但遞迴版的空間是 O(n)——每一層都佔一個堆疊框，十萬個節點就可能堆疊溢位。迭代版空間 O(1)，而且三行骨架寫熟之後比遞迴版更不容易錯。遞迴版的價值在於展示你對「回傳新頭」這個抽象的理解，可以當作補充說明，但不該是主要方案。

**詳細解析**：遞迴版的核心是兩行：`newHead = reverse(head.next)` 拿到反轉後的頭，然後 `head.next.next = head; head.next = null` 把當前節點掛到尾巴。難點在於理解 `head.next` 在遞迴回來之後**仍然指向原本的下一個節點**（那個節點現在是反轉後這一段的尾巴），所以可以透過它把自己接上去。最後一行 `head.next = null` 不能漏，否則會形成環。面試時如果面試官特別問「能不能用遞迴」，那是在考抽象思考，這時就寫遞迴並主動說明堆疊深度的限制，表示你知道代價。

**面試回答方式**：先表態選迭代，理由是空間 O(1) 且不會堆疊溢位。接著簡述遞迴版的關鍵（利用 `head.next` 仍指向反轉後那段的尾巴），並主動點出 `head.next = null` 漏掉會成環。加分點是說明如果對方指定遞迴，你會補一句深度限制，展現你在意實際可用性。

### 怎麼判斷兩個連結串列是否相交，並找出交點？

**核心答案**：用**雙指針走完兩條路**——指針 A 從串列一開始走，走到底轉去串列二的頭；指針 B 從串列二開始，走到底轉去串列一的頭。兩者各自走過的總長度相同（a + c + b 與 b + c + a），所以會**同時抵達交點**；如果不相交，兩者會同時變成 null 而結束。時間 O(m + n)、空間 O(1)。

**詳細解析**：另外兩種解法各有取捨。**長度差法**是先量兩條長度、讓長的先走差值步，再同步前進，思路直白但要掃三趟。**雜湊集合法**把一條串列的節點全放進集合、再掃另一條，空間 O(n)。雙指針換路法最漂亮，但要注意它比的是**節點的參考相同**而不是值相同——相交的定義是共用同一個節點物件，不是值一樣。這個澄清值得在面試中主動提出，因為題目描述有時模糊，而兩種理解會導出完全不同的解法。

**面試回答方式**：先講換路法的直覺——兩個指針走完兩條路的總長相同，所以會同時到交點。接著補上不相交時會同時變 null，這是這個寫法優雅的地方。加分點是主動澄清「相交指的是同一個節點物件而非值相同」，並簡述長度差法作為備案。

### 為什麼有些題目要用雙向連結串列，單向不夠嗎？

**核心答案**：當你需要**從某個節點 O(1) 地找到它的前驅**時，單向就不夠。最典型的是 **LRU 快取**——用雜湊表存「鍵到節點」的映射，命中時要把該節點從串列中間摘除並移到頭部，摘除需要前驅；單向串列找前驅要 O(n)，整個結構就退化了。雙向串列讓摘除變成 O(1)，配合雜湊表才能達成「查詢與更新都是 O(1)」。

**詳細解析**：LRU 是雙向串列價值最清楚的例子，實作上還有兩個細節值得提：一是**頭尾都放哨兵節點**，讓插入與刪除完全不需要判斷空串列或邊界；二是雜湊表存的是**節點參考**而不是值，這樣才能從鍵直接跳到串列中的位置。Java 的 `LinkedHashMap` 內建了這個結構，覆寫 `removeEldestEntry` 就能得到一個 LRU，面試中提到它會顯示你知道標準庫的能力邊界。反過來，只需要頭尾操作的場景（佇列、堆疊）單向就夠，多存一個指標是浪費。

**面試回答方式**：用「需不需要 O(1) 找前驅」當判準，並以 LRU 為例說明單向會讓摘除退化成 O(n)。接著補兩個實作細節：頭尾哨兵消掉邊界判斷、雜湊表存節點參考。加分點是提到 `LinkedHashMap` 已經內建這個結構。
