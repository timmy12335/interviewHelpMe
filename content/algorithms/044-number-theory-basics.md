# 題目

面試中的數學題常考哪些？質數篩、GCD 與模運算的關鍵點是什麼？

## 核心答案

**三個高頻的主題。**

**質數**——判斷單個數是否為質數只要試除到 √n，O(√n)；求 1 到 n 的所有質數用埃拉托斯特尼篩，O(n log log n)；而線性篩（歐拉篩）是 O(n)，代價是實作稍複雜。

**最大公因數**——**輾轉相除法 `gcd(a, b) = gcd(b, a % b)`，複雜度 O(log min(a, b))**；**而最小公倍數是 `a / gcd(a, b) * b`**（**先除再乘以避免溢出**，這是一個容易被忽略的細節）。

**模運算**——加減乘可以逐步取模，而除法不行；除法要用模逆元，前提是模數與除數互質。負數取模在多數語言中結果可能為負，需要 `((x % m) + m) % m` 修正。

這類題目的特點是「知道就會、不知道就卡住」——它們考的是知識的覆蓋面而非推理能力；所以準備的方式是「確保常見的幾個都熟」而非「臨場推導」。

## 詳細解析

「先除再乘」這個細節在最小公倍數中很典型：`a * b / gcd` 在 a 和 b 都接近 int 上限時會溢出——**而 `a / gcd * b` 不會（因為 gcd 整除 a）**；這類「數學上等價但數值上不同」的改寫，是實作數學題時的常見陷阱。同類的例子還有「求平均值用 `l + (r - l) / 2` 而非 `(l + r) / 2`」（二分搜尋中的經典溢出）。

**「埃氏篩的優化」值得知道**：內層迴圈從 `i * i` 開始而非 `2 * i`——因為小於 `i * i` 的倍數已經被更小的質因數篩掉了；**這個優化把常數降低不少**。而線性篩的核心是「每個合數只被它的最小質因數篩一次」——它需要維護一個質數列表並在 `i % prime == 0` 時跳出；那個跳出的條件正是保證「只被最小質因數篩到」的關鍵。

**「擴展歐幾里得的用途」**：它在求 gcd 的同時求出一組 `x, y` 使得 `ax + by = gcd(a, b)`——**於是能求模逆元**（當 gcd 為 1 時，x 就是 a 的模逆元）**與解線性同餘方程**。在模數不是質數時，這是求逆元的唯一辦法（費馬小定理要求模數是質數）。

「快速冪是這類題目的基礎工具」：`a^b mod m` 用二進位分解指數，O(log b)——它是模逆元（費馬小定理版本）、矩陣快速冪、以及很多加密演算法的基礎；而它的實作只有八行，應該做到不假思索地寫出。

## 面試回答方式

先給三個主題各自的核心方法與複雜度，並指出這類題目考的是知識的覆蓋面而非推理能力。加分點有四個：**先除再乘避免溢出**這個細節，與二分搜尋中同類的例子；**埃氏篩從 `i*i` 開始的優化**與線性篩「每個合數只被最小質因數篩一次」的關鍵；擴展歐幾里得在模數非質數時是求逆元的唯一辦法；以及快速冪是這類題目的基礎工具，**應該做到不假思索地寫出**。

## 講稿

有三個高頻主題。質數、最大公因數、還有模運算。

質數方面，判斷單個數只要試除到根號 n。求一個範圍內的所有質數用埃氏篩，而線性篩是 O n 但實作稍複雜。埃氏篩有一個優化，內層從 i 的平方開始而不是兩倍 i，因為更小的倍數已經被更小的質因數篩掉了。

最大公因數用輾轉相除。而最小公倍數要寫成先除以最大公因數再乘，不要先乘再除，否則在數字大的時候會溢出。這類數學上等價但數值上不同的改寫，是實作時的常見陷阱。同樣的例子是二分搜尋裡求中點要寫成左邊加上差的一半。

模運算方面，加減乘可以逐步取模，除法不行，要用模逆元。如果模數是質數可以用費馬小定理，不是質數就要用擴展歐幾里得。另外負數取模在多數語言裡結果可能是負的，要記得修正。

這類題目的特點是知道就會、不知道就卡住，考的是覆蓋面而不是推理。

## 常見追問

### 怎麼判斷一個很大的數是不是質數？

**核心答案**：**用機率性的測試**。**Miller-Rabin** 是最常用的——對隨機選的幾個底數做測試，每次通過就把「是合數」的機率降低到四分之一以下；**做二十輪後誤判的機率小於 10^-12**。而對 64 位元範圍內的數，有已知的一組固定底數能保證確定性正確（例如前 12 個質數）。試除法在數字達到 10^18 時需要 10^9 次操作，太慢。

**詳細解析**：「機率性演算法在實務中被廣泛接受」是一個值得理解的觀念：RSA 的金鑰生成就依賴 Miller-Rabin——而它的錯誤機率遠低於硬體出錯的機率；於是「確定性正確」在工程上並不總是必要的目標。**這個觀念延伸到很多地方**：布隆過濾器接受偽陽性、HyperLogLog 接受估計誤差、抽樣監控接受統計誤差——共同的模式是「用可量化且極小的錯誤機率換取巨大的效能或空間收益」。判斷它可不可接受的方法是「把錯誤率和系統中其他的錯誤來源比較」——如果它比硬體故障率還低，那它就不是瓶頸；這個比較的視角，比抽象地討論「正確性」更能得到合理的決定。

**面試回答方式**：給 Miller-Rabin 與它的錯誤機率，並指出 64 位元範圍內有確定性的固定底數。核心加分點是機率性演算法在實務中被廣泛接受（RSA 就依賴它，錯誤率遠低於硬體出錯），並列舉同一模式的其他例子（布隆過濾器、HyperLogLog）。收在判斷方法：把錯誤率和系統中其他的錯誤來源比較——如果比硬體故障率還低，它就不是瓶頸。

### 為什麼輾轉相除法是對數複雜度？

**核心答案**：**因為每兩步餘數至少減半**。若 `a > b`，則 `a % b < a / 2`——理由是若 `b ≤ a/2` 則餘數小於 b 也小於 a/2；若 `b > a/2` 則 `a % b = a - b < a/2`；於是每兩次遞迴數字至少減半，總步數是 O(log min(a, b))。而最壞的情況是連續的費波那契數——那時每一步只減少一個「費波那契的級別」。

**詳細解析**：「費波那契是最壞情況」這個結論很優雅：`gcd(F(n), F(n-1))` 需要恰好 n 步——**因為 `F(n) % F(n-1) = F(n-2)`**；於是輾轉相除法的步數上界與費波那契數的增長率（黃金比例）直接相關，這給出了一個精確的界：步數約為 `log_φ(min(a,b))` ≈ 4.785 × log₁₀(min(a,b))。這是 Lamé 定理，也是歷史上第一個演算法複雜度分析的結果（1844 年）。知道「最壞情況長什麼樣」不只是理論趣味——**它也是構造測試案例的方法**；在效能測試中，用最壞情況的輸入而非隨機輸入，才能得到有意義的上界。

**面試回答方式**：給減半的論證（分 `b ≤ a/2` 與 `b > a/2` 兩種情況）。核心加分點是最壞情況是連續的費波那契數與它的原因，給出 Lamé 定理這個精確的界，並提到它是歷史上第一個演算法複雜度分析的結果。收在實用價值：知道最壞情況長什麼樣也是構造測試案例的方法——效能測試用最壞輸入才能得到有意義的上界。

### 這些數學題在面試中頻率高嗎？

**核心答案**：**中等，而且分布不均**。GCD 與模運算的基本用法出現得相當頻繁（作為其他題目的一部分，例如「分數化簡」「循環節長度」）；而質數篩與數論的進階內容（中國剩餘定理、歐拉函數）在多數公司的面試中很少見——它們更多出現在競賽與少數重視演算法的團隊。

**詳細解析**：「作為其他題目的一部分」是這類知識最常見的出現方式：一道看起來是模擬或字串的題目中，中間需要求一個 GCD 或者做一次模逆元——如果那一步卡住，整題就完不成；**而那一步本身只有兩行**。所以準備的重點應該是「基礎的幾個要能立刻寫出來」而非「涵蓋所有的數論主題」——具體來說是 gcd、快速冪、以及取模的正確處理。這三個加起來不到三十行程式碼，而它們覆蓋了絕大多數的實際需求。這個「識別出高槓桿的小集合並把它練到自動化」的準備方式，比廣泛但淺薄的覆蓋有效得多——它適用於演算法準備，也適用於任何技能的學習。

**面試回答方式**：給誠實的頻率評估並區分基本用法（頻繁）與進階內容（少見）。核心加分點是指出這類知識最常見的出現方式是「作為其他題目的一部分」——那一步只有兩行但卡住就完不成整題，並給出高槓桿的小集合（gcd、快速冪、取模的正確處理，加起來不到三十行）。收在通則：識別出高槓桿的小集合並練到自動化，比廣泛但淺薄的覆蓋有效得多。
