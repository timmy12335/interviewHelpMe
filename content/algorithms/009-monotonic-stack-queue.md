# 題目

單調堆疊解決哪一類問題？為什麼每個元素進出各一次就能得到答案？

## 核心答案

單調堆疊處理的是「**對每個元素，找它左邊或右邊第一個比它大（或小）的元素**」這一類問題。核心觀察是：當新元素 x 進來時，堆疊裡所有**比 x 小**的元素，它們要找的「下一個更大元素」就是 x，可以當場結算並彈出；而且這些被彈掉的元素**永遠不會再成為後續元素的答案**，因為 x 比它們大又比它們靠後，任何後面的元素都會先碰到 x。正因為每個元素**最多進堆疊一次、出堆疊一次**，總操作是 2n，複雜度 O(n)——這是攤還分析的典型應用，看起來有巢狀迴圈但實際是線性。**單調佇列**是同一個想法用在滑動視窗上：維護一個遞減的雙端佇列，新元素從尾部把比它小的全部彈掉，隊首永遠是視窗最大值；視窗左移時若隊首已滑出範圍就從頭部彈掉。判斷訊號是「**下一個更大／更小**」「**左右第一個比它高的**」「**視窗最值**」。

## 詳細解析

**為什麼被彈掉的元素可以安全丟棄**：這是單調堆疊唯一的正確性論證。假設堆疊裡有 a，新來的 x 比 a 大。對於 x 之後的任何元素 y，如果 y 要找「左邊第一個比自己大的」，那麼在 a 和 x 之間它一定先碰到 x（x 更靠近且更大），所以 a 再也用不到了。這個「**被更大且更近的元素遮蔽**」的性質，就是可以彈掉的理由。面試中能講出這一句，比寫出程式碼更能證明你理解。

**遞增堆疊還是遞減堆疊，取決於你要找什麼**：要找「下一個更大元素」，堆疊維持**從底到頂遞減**，新元素比頂大就彈出結算。要找「下一個更小元素」，就維持遞增。實務上不要背，而是回到定義推：問自己「什麼樣的元素該被當場結算」，答案自然會給出彈出條件。另外要決定**存值還是存索引**——多數題目要存索引，因為結算時常需要距離（例如「幾天後會有更高的溫度」），存值就算不出來。

**接雨水與最大矩形是同一個模式的兩種變形**：接雨水用單調遞減堆疊，彈出一個元素時，它左邊的堆疊頂與右邊的當前元素構成一個「凹槽」，能接的水是兩側較低者減去凹底、乘以寬度。柱狀圖中最大矩形用單調遞增堆疊，彈出時該柱子的高度是矩形高，左右邊界分別是新的堆疊頂與當前位置。兩題的共同點是：**彈出的那一刻，左右邊界同時確定了**——左邊界是堆疊裡的下一個，右邊界是觸發彈出的當前元素。抓住這句話，這兩題就從「背解法」變成「推得出來」。

**環形陣列的處理**：「下一個更大元素」在環形陣列上的標準技巧是**掃兩遍**——把索引對長度取餘數，跑 2n 輪，第二輪只結算不入堆疊（或直接讓它自然運作）。這比實際把陣列複製一份更省空間。要點是結果陣列先初始化成 −1，掃完仍留在堆疊裡的元素就是「沒有更大元素」的。

**單調佇列與堆積的取捨**：滑動視窗最大值也可以用最大堆積做，但堆積裡會殘留已經滑出視窗的元素，需要延遲刪除（取出時檢查索引是否過期），複雜度是 O(n log n)。單調佇列是 O(n)，因為每個元素進出各一次。堆積的優勢是可以回答「第 k 大」而不只是最大值，單調佇列只能給極值。所以選型準則是：**只要極值用單調佇列，要第 k 大用堆積**。

## 面試回答方式

先講題型識別——看到「下一個更大／更小」「左右第一個比它高的」「視窗最值」就想單調結構。接著給正確性論證：新元素比堆疊頂大時，堆疊頂被一個更近且更大的元素遮蔽，永遠用不到了，所以可以彈掉並當場結算。複雜度要主動論證：每個元素進出各一次，總共 2n，所以是 O(n) 而不是看到雙層迴圈就說平方。實作細節主動提兩個：存索引而不是存值、以及遞增或遞減由「什麼元素該被結算」推導而不是背。加分點是把接雨水與最大矩形歸成同一個模式（彈出那一刻左右邊界同時確定），以及單調佇列與堆積的選型準則。

## 講稿

單調堆疊解決的是這一類問題，對每個元素找它左邊或右邊第一個比它大或比它小的元素。

它的關鍵觀察是這樣。新元素進來的時候，堆疊裡所有比它小的元素，要找的答案就是這個新元素，可以當場結算然後彈掉。更重要的是，這些被彈掉的元素以後再也用不到了，因為新元素又比它們大、又比它們近，後面任何元素都會先碰到新元素，它們被遮蔽了。

正因為每個元素最多進一次、出一次，總操作是兩倍的 n，所以是線性的。這裡很多人會看到雙層迴圈就說是平方，其實要看內層的總移動次數。

實作上我會存索引而不是存值，因為結算的時候常常需要距離。至於堆疊要遞增還是遞減，我不背，而是回到定義問自己，什麼樣的元素該被當場結算，答案就出來了。

接雨水跟柱狀圖最大矩形其實是同一個模式。彈出的那一刻，左邊界就是堆疊裡的下一個，右邊界就是觸發彈出的當前元素，兩邊同時確定。

滑動視窗最大值則換成單調佇列，維持遞減，隊首永遠是最大值。

## 常見追問

### 為什麼單調堆疊是 O(n)，明明有兩層迴圈？

**核心答案**：因為內層的 `while` 彈出的是**堆疊裡已有的元素**，而每個元素**一生只會被彈出一次**。外層迴圈跑 n 次負責入堆疊，內層所有輪次加起來最多彈出 n 次，總操作是 2n。判斷巢狀迴圈的複雜度不能只數層數，要看**內層在整個過程中的總執行次數**。

**詳細解析**：這正是攤還分析的思路——單次操作可能很貴（某一輪可能一口氣彈掉 n−1 個元素），但那是因為前面很多輪都很便宜（只入堆疊、沒彈出），把成本分攤下來每次仍是 O(1)。同樣的論證適用於滑動視窗的可變長度版本（內層移動的是左指針，總共只前進 n 次）與動態陣列擴容。面試中被問到複雜度時，如果你能主動說「這裡要用攤還的角度看」，而不是被問了才補救，會給人分析扎實的印象。

**面試回答方式**：直接指出關鍵——每個元素一生只被彈出一次，所以內層總次數是 n，加上外層共 2n。接著把它歸類為攤還分析，並舉滑動視窗與動態陣列擴容作為同類。加分點是主動說明「數迴圈層數判斷複雜度」是常見誤區。

### 滑動視窗最大值，單調佇列和最大堆積怎麼選？

**核心答案**：只要**最大值**就用單調佇列，O(n)；要**第 k 大**或需要同時維護多種統計就用堆積，O(n log n)。單調佇列快的原因是它敢直接丟掉「不可能成為最大值」的元素——新元素進來時，佇列尾部所有比它小的都可以永久刪除，因為它們比新元素小又比新元素早過期。堆積做不到這件事，只能保留所有元素、取出時再檢查是否過期。

**詳細解析**：堆積版的實作細節值得知道：因為無法從堆積中間刪除元素，標準做法是**延遲刪除**——堆積存「值與索引」的組合，每次取堆頂時檢查索引是否已滑出視窗，是就彈掉再取，直到堆頂有效。這樣堆積大小可能遠超過視窗長度，空間是 O(n) 而非 O(k)。另一個替代方案是用有序集合（如 TreeMap 計數），支援 O(log k) 的插入、刪除與查最大值，空間 O(k)，而且能同時回答最大與最小，在需要「視窗內最大減最小」的題目裡比單調佇列方便，因為單調佇列要開兩條。

**面試回答方式**：先給選型準則（只要極值用單調佇列、要第 k 大用堆積），並解釋單調佇列快在敢永久丟棄被遮蔽的元素。接著說明堆積版需要延遲刪除、空間會膨脹。加分點是提到有序集合方案，以及「視窗內最大減最小」這種需要兩條單調佇列的變形。

### 柱狀圖最大矩形為什麼要在陣列兩端補哨兵？

**核心答案**：為了**消掉兩個特判**。左端補一個高度 0（或 −1）的哨兵，讓堆疊永遠不會空，計算左邊界時不必判斷「堆疊是否為空」；右端補一個高度 0 的哨兵，強制把掃描結束時仍留在堆疊裡的所有柱子都彈出結算，不必在迴圈後再寫一段收尾邏輯。兩個哨兵各消掉一個容易寫錯的分支。

**詳細解析**：不補哨兵的版本要處理兩件事：堆疊為空時左邊界視為 −1，以及迴圈結束後把剩餘元素依序彈出、右邊界視為 n。這兩段邏輯本身不難，但它們與主迴圈的計算方式略有不同，很容易寫出不一致的邊界而差一格。哨兵的思路和連結串列的虛擬頭節點、前綴和的 `prefix[0] = 0` 完全一樣——**用一點額外空間換掉分支**，是降低出錯率的通用手法。這類「我為什麼這樣寫」的說明在面試中特別值錢，因為它展示的是工程習慣而不只是解題能力。

**面試回答方式**：說明兩個哨兵各自消掉哪個特判：左端讓堆疊不會空、右端強制清空堆疊。接著把它歸納成通用手法，和虛擬頭節點、前綴和多開一格並列。加分點是點出不補哨兵時收尾邏輯與主迴圈容易寫得不一致，這才是真正的出錯來源。
