# 題目

區間 DP 與樹形 DP 的狀態怎麼設計？它們和線性 DP 的差別在哪？

## 核心答案

**差別在於「子問題的結構」**。**線性 DP 的子問題是前綴（`dp[i]` 依賴 `dp[i-1]`）**；**區間 DP 的子問題是子區間（`dp[i][j]` 依賴更短的區間）**；**樹形 DP 的子問題是子樹（`dp[u]` 依賴它的所有子節點）。**

**區間 DP 的標準形式**：`dp[i][j]` 表示區間 `[i, j]` 的最優解——**轉移是枚舉一個分割點 k，把區間拆成 `[i, k]` 與 `[k+1, j]`**；**關鍵是「按區間長度由小到大遍歷」，因為長區間依賴短區間**。**複雜度通常是 O(n³)**（兩層區間端點加一層分割點）。**典型題目是矩陣連乘、石子合併、最長迴文子序列。**

**樹形 DP 的標準形式**：`dp[u][狀態]` 表示以 u 為根的子樹在某個狀態下的最優解——**用 DFS 後序遍歷，先算完所有子節點再合併到父節點**；**「狀態」常常是「u 自己選或不選」**（打家劫舍在樹上的版本）。**複雜度通常是 O(n × 狀態數)。**

## 詳細解析

**「按長度遍歷」是區間 DP 最容易寫錯的地方**：如果直接用 `for i` `for j` 的雙層迴圈——**在計算 `dp[i][j]` 時 `dp[i][k]` 可能還沒算**；**正確的寫法是最外層迴圈跑區間長度 `len` 從 2 到 n，內層跑起點 i，而 `j = i + len - 1`**。**另一個等價的寫法是「i 由大到小、j 由小到大」**——**因為 `dp[i][j]` 依賴 `dp[i+1][...]`（更大的 i）與 `dp[...][j-1]`（更小的 j）**。**記住「先確認依賴的方向再決定遍歷的順序」這個原則，比背模板可靠。**

**「區間 DP 的分割點含義要想清楚」**：在石子合併中，k 表示「最後一次合併的分界」——**於是 `dp[i][j] = min(dp[i][k] + dp[k+1][j]) + sum(i, j)`**；**而在矩陣連乘中 k 表示「最後一次相乘的位置」**。**這個「最後一步是什麼」的思考方式，是設計區間 DP 轉移的通用方法**——**它和線性 DP 中「最後一個元素選不選」是同一種思路。**

**「樹形 DP 的合併順序」**：處理節點 u 時要把所有子節點的結果合併——**如果狀態是簡單的（選/不選），合併就是累加或取最大**；**但如果狀態涉及「子樹中選了幾個」（樹上背包），合併就是一個背包的過程**，**而複雜度分析會出現一個經典的結論：樹上背包的樸素實作其實是 O(n²) 而非 O(n × k²)**——**因為每一對節點只會在它們的最近公共祖先處被合併一次。**

**「換根 DP」是樹形 DP 的一個進階變體**：當你需要「以每個節點為根時的答案」——**樸素做法是對每個根跑一次 DFS，O(n²)**；**換根 DP 先算出以某個節點為根的答案，再用一次 DFS 把答案「轉移」到相鄰節點，總複雜度 O(n)**。**它的核心是「父節點方向的貢獻」可以由父節點的答案減去自己的貢獻推出。**

## 面試回答方式

先給核心的差別（**子問題的結構：前綴、子區間、子樹**）並給出兩者的標準形式與複雜度。加分點有四個：**按長度遍歷是區間 DP 最容易寫錯的地方**，**而「先確認依賴的方向再決定遍歷順序」比背模板可靠**；**「最後一步是什麼」是設計區間 DP 轉移的通用方法**；**樹上背包的樸素實作其實是 O(n²)**——**因為每一對節點只在最近公共祖先處被合併一次**；以及**換根 DP** 把「以每個節點為根」從 O(n²) 降到 O(n)。

## 講稿

差別在子問題的結構。線性 DP 的子問題是前綴，區間 DP 的子問題是子區間，樹形 DP 的子問題是子樹。

區間 DP 的狀態是 dp i j 表示區間 i 到 j 的最優解，轉移是枚舉一個分割點把區間拆成兩半。而最容易寫錯的地方是遍歷的順序。如果直接用兩層端點迴圈，計算長區間時短區間可能還沒算好。正確的寫法是最外層跑區間長度。

我的原則是先確認依賴的方向再決定遍歷順序，這比背模板可靠。

設計轉移時，我會問最後一步是什麼。在石子合併裡分割點表示最後一次合併的分界，在矩陣連乘裡表示最後一次相乘的位置。這跟線性 DP 裡問最後一個元素選不選是同一種思路。

樹形 DP 是用後序遍歷，先算完子節點再合併到父節點。而有一個容易被算錯的結論值得知道，樹上背包的樸素實作其實是平方複雜度，因為每一對節點只會在它們的最近公共祖先處被合併一次。

## 常見追問

### 最長迴文子序列為什麼是區間 DP？

**核心答案**：**因為判斷「s[i..j] 是不是迴文」自然地依賴「s[i+1..j-1]」**——**這是一個子區間而非前綴**。**狀態 `dp[i][j]` 表示 `s[i..j]` 中最長迴文子序列的長度**；**轉移是「如果 s[i] == s[j] 則 `dp[i][j] = dp[i+1][j-1] + 2`，否則取 `max(dp[i+1][j], dp[i][j-1])`」。**

**詳細解析**：**「它有一個等價的轉換」值得知道**：**最長迴文子序列等於「s 與 reverse(s) 的最長公共子序列」**——**因為一個迴文正著讀反著讀相同**；**於是可以直接套用 LCS 的模板，複雜度同樣是 O(n²)**。**這個轉換展示了一個常見的解題技巧「把陌生的問題歸約到熟悉的問題」**——**而在面試中，如果你能同時給出兩種解法並說明它們等價，那比只給一種強得多**。**但要注意「最長迴文子串」（連續）與「子序列」（不連續）是不同的問題**——**子串有 O(n) 的 Manacher 演算法而子序列沒有**；**混淆這兩者是一個常見的錯誤。**

**面試回答方式**：說明**依賴的是子區間而非前綴**並給出狀態與轉移。核心加分點是**等價轉換：它等於 s 與 reverse(s) 的最長公共子序列**，並指出這展示了**「把陌生的問題歸約到熟悉的問題」**這個技巧。收在容易混淆處：**「最長迴文子串」（連續）與「子序列」是不同的問題**——**前者有 Manacher 而後者沒有**。

### 樹形 DP 怎麼避免遞迴太深？

**核心答案**：**改成迭代式的後序遍歷**，或者**在極端情況下增加執行緒的堆疊大小**。一條長度十萬的鏈——**遞迴會爆堆疊**；**而迭代式的做法是先用一次遍歷得到「後序的節點順序」，再按那個順序遞推**。**在多數語言中預設的堆疊深度是幾千到幾萬，而競賽與面試中的資料規模常常超過它。**

**詳細解析**：**「先算出遍歷順序再遞推」是一個通用的技巧**：對樹做一次 BFS 或迭代 DFS 得到節點的順序——**然後「反過來遍歷那個順序」就等價於後序**（因為 BFS 的順序保證父節點在子節點之前，反過來就是子節點在父節點之前）**。這個做法把遞迴完全消除，而程式碼並不比遞迴版本複雜多少**。**在面試中主動提到「如果樹很深，遞迴會有堆疊溢出的風險，我可以改成迭代版本」是一個好的加分點**——**它展示了你考慮過實際的限制而非只寫出「教科書上的解法」**。

**面試回答方式**：給兩個做法（迭代式後序、調整堆疊大小）並指出**預設的堆疊深度常常小於資料規模**。核心加分點是**「先算出遍歷順序再反過來遞推」**這個通用技巧——**BFS 的順序保證父在子前，反過來就是後序**。收在面試價值：**主動提到堆疊溢出的風險展示了你考慮過實際的限制**。

### 這兩類 DP 在面試中常見嗎？

**核心答案**：**樹形 DP 中等常見，區間 DP 較少見**。樹形 DP 出現在很多與樹相關的題目中（樹的直徑、樹上的打家劫舍、最近公共祖先的變體）——**而它的思路（後序遍歷加合併）比較自然**；**區間 DP 則多見於中高難度的題目，在多數公司的面試中不算高頻**。**但兩者的共同思路「先確認子問題的結構」在任何 DP 題中都用得上。**

**詳細解析**：**「準備的優先順序應該按頻率而非難度」**：如果時間有限——**先掌握線性 DP、背包、以及樹形 DP 中最基本的幾種，比鑽研區間 DP 的各種變體更划算**；**因為前者出現的機率高得多**。**而一個實用的策略是「對每一類 DP 掌握一到兩個代表題並理解它的狀態設計為什麼是那樣」**——**於是遇到變體時能推導而非回憶**。**這比「刷一百題但每一題都只記得答案」有效得多**——**因為面試中的題目常常是變體，而變體無法靠記憶應對**；**這個「理解狀態設計的理由」的準備方式，是我認為性價比最高的做法。**

**面試回答方式**：誠實給出頻率（樹形中等、區間較少）並指出**共同的思路在任何 DP 題中都用得上**。核心加分點是**準備的優先順序應該按頻率而非難度**，並給出具體的策略：**對每一類掌握一到兩個代表題並理解它的狀態設計為什麼是那樣**。收在理由：**面試中的題目常常是變體，而變體無法靠記憶應對**。
