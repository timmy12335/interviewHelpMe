# 題目

字串類的題目有哪些常見的解題模式？

## 核心答案

**五類，而它們對應不同的訊號。**

**計數與比較**——**變位詞、字元頻率**；用一個大小為字元集的陣列（而非 HashMap）通常更快也更簡潔。

**回文**——中心擴展（每個位置與每對相鄰位置各擴展一次，O(n²)）；而 Manacher 能做到 O(n) 但很少在面試中被要求。關鍵是認出「回文的判斷可以從中心往外」而非從兩端往內比較所有子串。

**分割與組合**——**分割回文串、復原 IP 位址**；這些是回溯，而剪枝的條件（剩餘長度是否足夠、當前片段是否合法）決定了效率。

**滑動視窗**——最長無重複子串、最小覆蓋子串；訊號是「連續的子串」加上「某個條件」。

**以及建構與模擬**——**字串壓縮、數字轉換、大數運算**；**重點是邊界情況而非演算法。**

## 詳細解析

「回文的中心擴展」有一個容易漏掉的細節：回文的長度可能是奇數（中心是一個字元）或偶數（中心是兩個字元之間）——於是需要對每個位置做兩次擴展；忘記偶數的情況是這類題目最常見的錯誤。而更根本的洞察是「從中心擴展避免了重複的比較」：判斷 `abcba` 是回文時，`bcb` 的判斷已經被包含在內；而從兩端往內逐個檢查所有子串會重複那些工作。

「用陣列取代 HashMap」在字元集有限時是明顯的優化：只有 26 個小寫字母——`int[26]` 比 `HashMap<Character, Integer>` 快得多（沒有雜湊計算、沒有裝箱、快取友善）；**而程式碼也更短**。這個「當鍵的範圍有限且已知時用陣列」的優化在很多地方適用——而它的前提是「範圍確實有限」，所以要先確認題目的字元集。

「分割類問題的剪枝」是效率的關鍵：復原 IP 位址時——如果剩下的字元數超過「剩餘段數 × 3」或者少於「剩餘段數」，那條路徑一定失敗；**提前返回能砍掉大量的搜尋**。而這類剪枝條件通常是「基於長度或範圍的簡單算術」——它們容易寫但收益巨大，是回溯類題目中最值得投入的部分。

**「字串的不可變性影響效能」**：在迴圈中用 `+=` 串接字串——每次都產生一個新物件，複雜度是 O(n²)；**用 `StringBuilder` 才是 O(n)**。這是一個在面試中應該主動提到的細節——它展示了對語言特性的理解，而且面試官經常會追問。

## 面試回答方式

先給五類模式與各自的訊號。加分點有四個：回文中心擴展要處理奇偶兩種情況，**忘記偶數是最常見的錯誤**，而更根本的洞察是它避免了重複比較；用陣列取代 HashMap 在字元集有限時明顯更快，而前提是先確認題目的字元集；分割類問題的剪枝是效率的關鍵——基於長度的簡單算術容易寫但收益巨大；以及字串的不可變性讓迴圈中的 `+=` 變成 O(n²)，**這是應該主動提到的細節**。

## 講稿

字串題目我會分五類。計數與比較、回文、分割與組合、滑動視窗、還有建構與模擬。

回文類的核心手法是中心擴展。從每個位置往外擴展，而關鍵的洞察是回文的判斷可以從中心往外，於是避免了重複的比較。判斷一個五個字元的回文時，中間三個字元的判斷已經被包含在內了。

這裡有一個容易漏掉的細節。回文的長度可能是奇數，中心是一個字元；也可能是偶數，中心在兩個字元之間。所以要對每個位置做兩次擴展。忘記偶數的情況是這類題目最常見的錯誤。

還有一個實用的優化。當字元集有限時用陣列取代雜湊表。只有二十六個小寫字母的話，一個長度二十六的整數陣列比雜湊表快得多，沒有雜湊計算、沒有裝箱、而且快取友善，程式碼也更短。前提是先確認題目的字元集。

最後一個我會主動提的細節，字串在多數語言中是不可變的。在迴圈中用加號串接，每次都產生新物件，複雜度變成平方。要用字串建造器才是線性。

## 常見追問

### 最小覆蓋子串這類題目怎麼想？

**核心答案**：可變長度的滑動視窗加上一個「是否滿足條件」的判斷。右指針擴展直到滿足——然後左指針收縮直到不再滿足，過程中記錄最小的長度；重複這個「擴展到滿足、收縮到剛好」的循環。**關鍵是「怎麼 O(1) 地判斷滿足」**——通常用一個計數器記錄「還缺幾種字元」而非每次重新比較整個頻率表。

**詳細解析**：「用一個計數器取代整表比較」是這類題目從 O(n × 字元集) 降到 O(n) 的關鍵：維護 `need`（還需要幾種字元達標）——當某個字元的計數從「不足」變成「剛好」時，`need` 減一；**於是判斷是否滿足只需要看 `need == 0`**。這個「維護一個增量的摘要而非每次重算」的思路，是滑動視窗類題目的通用優化——而它也是很多流式演算法的基礎。實作上最容易錯的是「計數的更新時機」：只有在「恰好從不足變成剛好」時才更新 need，而不是每次計數增加時——這個條件寫錯會導致答案錯誤且很難察覺。

**面試回答方式**：給「擴展到滿足、收縮到剛好」的循環框架，並指出**關鍵是怎麼 O(1) 地判斷滿足**。核心加分點是**用一個計數器取代整表比較**——當某字元從不足變成剛好時計數器減一，判斷只需看它是否為零，**這是從 O(n × 字元集) 降到 O(n) 的關鍵**，而這個「維護增量摘要」的思路是滑動視窗的通用優化。收在最容易錯的實作細節：只有在恰好從不足變成剛好時才更新，寫錯會導致答案錯誤且難察覺。

### 大數運算怎麼實作？

**核心答案**：**用陣列或字串逐位模擬**。加法——從低位到高位逐位相加並處理進位；**乘法——**「豎式乘法」，`num1[i] * num2[j]` 的結果貢獻到結果的第 `i+j` 與 `i+j+1` 位**。**關鍵的細節是「進位的處理」與「結果的前導零」**——**而後者是最常被漏掉的。

**詳細解析**：「乘法中位置的推導」值得能自己推而非記憶：`num1` 的第 i 位（從右數第 i 位，權重 10^i）乘以 `num2` 的第 j 位（權重 10^j）——**結果的權重是 10^(i+j)**；於是它貢獻到結果的第 i+j 位（以及可能的進位到 i+j+1）。而如果用「從左數的索引」，那個關係是「結果的索引 i+j+1」——兩種索引方式都對，但混用會錯。所以在寫之前明確「我用哪一種索引」是避免這類錯誤的方法。而更一般的建議是「大數題目先在紙上算一個小例子」——因為那些位置關係在腦中推容易錯，而在紙上一目了然。

**面試回答方式**：給加法與乘法的做法與關鍵細節（進位、前導零）。核心加分點是**乘法中位置關係的推導**（權重相乘所以是 10^(i+j)）並指出兩種索引方式都對但混用會錯，**所以要先明確用哪一種**。收在實用建議：大數題目先在紙上算一個小例子——位置關係在腦中推容易錯而在紙上一目了然。

### 字串比對除了 KMP 還有什麼？

**核心答案**：**三個實用的替代**。**滾動雜湊（Rabin-Karp）**——**用雜湊快速比較，平均 O(n+m)**；適合「多模式比對」與「找重複子串」。**Boyer-Moore**——從右往左比較並用「壞字元」與「好後綴」規則跳躍；在實務中往往比 KMP 快（很多標準函式庫用它的變體）。**以及 Aho-Corasick**——同時比對多個模式，用 Trie 加失敗指針。

**詳細解析**：「Boyer-Moore 在實務中比 KMP 快」的原因值得知道：KMP 保證 O(n+m) 但它掃描每個字元至少一次——而 Boyer-Moore 可以「跳過」大段字元（當壞字元不在模式中時，可以直接跳過整個模式的長度）；於是在模式較長且字元集較大時，它的平均效能明顯更好（可能是次線性的）。這是一個「最壞複雜度相同或更差，但平均表現更好」的例子——而實務的選擇往往看平均而非最壞。這個「理論最優不等於實務最快」的認知，在演算法的實際選擇中反覆出現（快速排序的最壞是 O(n²) 卻是最常用的排序）。

**面試回答方式**：給三個替代方案與各自的適用場景。核心加分點是解釋 **Boyer-Moore 在實務中比 KMP 快的原因**——它能跳過大段字元，在模式長且字元集大時平均效能明顯更好甚至次線性。收在認知：這是「最壞複雜度相同或更差但平均更好」的例子，而「理論最優不等於實務最快」在演算法的實際選擇中反覆出現，快速排序就是另一個例子。
