# 題目

面試官說「你能不能優化」時，有哪些通用的優化方向可以嘗試？

## 核心答案

**六個方向，按嘗試的順序排列。**

**用空間換時間**——加一個雜湊表記住已經算過的、已經看過的；這是最常見也最容易想到的一步（兩數之和從 O(n²) 到 O(n)）。

**利用有序性**——如果資料有序或者可以排序，雙指標或二分能把一層迴圈去掉（三數之和從 O(n³) 到 O(n²)）。

**避免重複計算**——前綴和、記憶化、或者發現子問題重疊而改用 DP。

**用更好的資料結構**——堆積取代排序（Top K）、單調堆疊取代暴力找下一個更大元素、並查集取代反覆的連通性檢查。

**減少維度**——發現某個狀態是冗餘的、或者兩層迴圈可以合併成一次掃描。

**改變問題的視角**——從「對每個元素找答案」改成「每個元素貢獻給誰」；這往往是最大的突破但也最難想到。

## 詳細解析

**「按順序嘗試」比「靈感」可靠**：面試中最糟的狀態是卡住而沒有方向——而有一個清單能讓你持續產生候選；即使某個方向不通，說出「我試了用雜湊表記住已見過的元素，但這裡的問題是……」也展示了你的思考過程。面試官評估的是過程而非只有結果——一個有方向的探索遠好過沉默。

「改變視角」值得展開因為它最有價值：計算「所有子陣列的和的總和」——**正面做是枚舉所有子陣列，O(n²)**；換個視角問「每個元素被多少個子陣列包含」，答案是 `(i+1) × (n-i)`，於是 O(n)。同樣的視角轉換出現在「貢獻法」「反向思考」「補集」中——共同點是「不直接計算目標，而是計算每個部分對目標的貢獻」。練習這個視角的方法是「遇到需要枚舉組合的題目時，主動問一次：能不能反過來算每個元素的貢獻」。

「先說出當前解法的瓶頸在哪」是優化的起點：「我現在是 O(n²)，因為對每個 i 都掃了一遍 j 找滿足條件的元素」——明確地指出瓶頸後，優化的方向自然浮現（「那我需要一個能快速找到滿足條件的元素的結構」）；而跳過這一步直接猜方法，命中率低得多。

**「知道下界能避免徒勞」**：如果問題需要讀完所有輸入，那 O(n) 就是下界——**比較排序的下界是 O(n log n)**；認出「這已經是最優」比繼續尋找不存在的優化更有價值。在面試中說「我認為 O(n log n) 是這裡的下界，因為……」是一個強的信號。

## 面試回答方式

給六個方向並強調它們是**按嘗試順序排列的清單**。加分點有四個：**按順序嘗試比靈感可靠**——即使方向不通，說出嘗試的過程也展示了思考；**改變視角**這個最有價值的方向，用「所有子陣列的和」這個具體例子展示它從 O(n²) 到 O(n)；**先說出當前解法的瓶頸在哪**是優化的起點；以及**知道下界能避免徒勞**，而說出「我認為這已經是下界」是一個強信號。

## 講稿

我會按順序試六個方向。

第一是用空間換時間，加一個雜湊表記住已經看過的。第二是利用有序性，排序後用雙指標或二分去掉一層迴圈。第三是避免重複計算，用前綴和或記憶化。第四是換更好的資料結構，比如用堆積取代排序。第五是減少維度。第六是改變問題的視角。

而在開始試之前，我會先說出當前解法的瓶頸在哪。比如我現在是平方，因為對每個位置都掃了一遍找滿足條件的元素。明確指出瓶頸之後，方向自然浮現，我需要一個能快速找到那種元素的結構。跳過這一步直接猜方法，命中率低得多。

最有價值的是改變視角這一個。舉個例子，計算所有子陣列的和的總和，正面做是枚舉所有子陣列，平方複雜度。但換個問法，每個元素被多少個子陣列包含，答案是一個乘積公式，於是變成線性。

另外知道下界能避免徒勞。如果已經是最優，認出這一點比繼續找不存在的優化更有價值。

## 常見追問

### 如果想不出優化怎麼辦？

**核心答案**：回到問題本身，尋找還沒被利用的條件。題目給的每一個條件通常都有用——「陣列已排序」「所有元素為正」「值域在 1 到 n 之間」「保證有解」；如果你的解法沒有用到某個條件，那往往就是優化的入口。主動盤點「我用了哪些條件、沒用哪些」是一個具體的方法。

**詳細解析**：「值域在 1 到 n 之間」是最典型的未被利用的條件：它暗示「可以把值當成索引」——於是「找重複的數字」可以用原地標記（把 `a[|x|]` 取負）在 O(n) 時間 O(1) 空間內完成；而不知道要用它的人會想到排序或雜湊表。同樣地，「所有元素為正」讓滑動窗口成為可能（因為和是單調的），而有負數時就不行。這個「盤點條件」的習慣在除錯與系統設計中同樣有用——當一個方案感覺笨拙時，常常是因為忽略了某個能簡化問題的約束；而明確地列出「我知道什麼」往往比繼續想「該怎麼做」更快找到出路。

**面試回答方式**：給具體的方法（**盤點用了哪些條件、沒用哪些**）並指出未被利用的條件往往是優化的入口。核心加分點是舉出**「值域在 1 到 n 之間」**這個最典型的例子及它帶來的原地標記解法，並補上「所有元素為正」讓滑動窗口成立這個對照。收在通用性：這個習慣在除錯與系統設計中同樣有用——明確列出「我知道什麼」往往比繼續想「該怎麼做」更快找到出路。

### 面試官說「還能更好」但你覺得已經最優了？

**核心答案**：**說出你的理由並問清楚**。「我認為 O(n) 是下界，因為我們至少要讀完所有輸入——你是指常數的優化，還是空間方面，或者我漏掉了什麼？」**這比繼續盲目地嘗試好**；而有時面試官指的是空間、或者是實作上的簡化，而非漸進複雜度。

**詳細解析**：「面試官的『還能更好』有幾種可能」值得分辨：真的有更優的解法、或者他指的是空間、或者是「你的實作有冗餘」、或者這是一個壓力測試看你會不會動搖。主動澄清能區分這幾種情況而不顯得防禦——關鍵在於語氣：陳述理由而非爭辯。而如果澄清後確認真的有更優解，那說「好，讓我再想想有沒有我沒利用到的條件」並回到盤點的方法。這個「有依據地堅持、但保持開放」的態度本身就是被評估的項目之一——因為在真實的工作中，能說出「我認為這是對的，理由是……，但如果你有不同的看法我想聽聽」的人，比容易被說服或者固執的人都更有價值。

**面試回答方式**：給具體的回應方式（說出理由並問清楚指的是哪方面）。核心加分點是分辨**「還能更好」的幾種可能**（真有更優、指的是空間、實作有冗餘、壓力測試），並指出關鍵在語氣：陳述理由而非爭辯。收在態度：「有依據地堅持、但保持開放」本身就是被評估的項目——真實工作中這樣的人比容易被說服或固執的人都更有價值。

### 優化到什麼程度就該停？

**核心答案**：達到問題的下界，或者達到題目給的規模所需的複雜度。如果 n 是 10^5 而你有 O(n log n)——那已經足夠，繼續追求 O(n) 通常不是面試的重點；**而如果 n 是 10^9，那 O(n) 也不夠，需要 O(log n) 或 O(1)**。用規模反推所需的複雜度，是判斷「夠不夠好」的客觀標準。

**詳細解析**：「先把一個可行解寫完整，再優化」是比追求最優更好的策略：一個寫完並通過測試的 O(n²) 解，遠好過一個寫到一半的 O(n log n) 解——因為面試官需要看到你能寫出正確的程式碼；而在時間允許時再優化，展示的是完整的能力。**這也是真實工程中的順序**：**先讓它對，再讓它快**——過早優化不只浪費時間，還常常優化了錯的地方。我的做法是在面試中明確說出這個順序：「我先寫一個直觀的版本確保正確，然後我們再看要不要優化」——這既管理了期待，也讓面試官知道你有意識地做了這個選擇而非只會笨方法。

**面試回答方式**：給客觀標準（**用規模反推所需的複雜度**）並舉例。核心加分點是**先把可行解寫完整再優化**這個策略——**寫完的 O(n²) 遠好過寫到一半的 O(n log n)**，並指出這也是真實工程的順序（**先讓它對，再讓它快**）。收在具體做法：**在面試中明確說出這個順序**，既管理了期待也讓面試官知道你是有意識地選擇而非只會笨方法。
