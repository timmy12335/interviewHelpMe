# 題目

「統計 1 到 N 之間滿足某個條件的數字有幾個」這類問題怎麼解？

## 核心答案

**用數位 DP：逐位地構造數字，並記錄「是否還被上界約束」這個狀態。**

**核心的狀態是三個**：**當前處理到第幾位**、**是否仍緊貼上界（tight）**、**以及題目所需的額外資訊**（例如已出現的數字集合、當前的數位和、前一位是什麼）。**「tight」是關鍵**——**如果前面的位都等於 N 的對應位，那這一位就只能取 0 到 N 的這一位；否則可以取 0 到 9。**

**實作上最清楚的寫法是「記憶化搜尋」**：一個遞迴函式 `f(pos, tight, extra)`——**當 tight 為 false 時的結果可以被記憶化（因為它與具體的前綴無關）**；**而 tight 為 true 的路徑只有一條，不需要記憶。**

**複雜度是 O(位數 × 狀態數 × 10)**——**對 10^18 級別的 N 也只有幾千次計算。**

## 詳細解析

**「為什麼 tight 為 true 時不記憶化」值得理解**：在 tight 路徑上，每一位的取值範圍都不同（受 N 的對應位限制）——**而記憶化的前提是「相同的狀態有相同的結果」**；**tight 為 true 的狀態實際上只會被訪問一次（因為只有一條路徑一直緊貼上界）**，**所以記憶它沒有收益且如果把 tight 忘記放進鍵裡還會產生錯誤**。**這是數位 DP 最經典的錯誤來源**——**忘記把 tight 放進記憶化的鍵，於是把「受限」的結果誤用到「不受限」的狀態上。**

**「前導零」是第二個容易出錯的地方**：如果題目關心「數字的位數」或「相鄰位的關係」——**那麼 00123 與 123 的處理必須不同**；**這需要一個額外的 leadingZero 狀態**。**例如「統計不含前導零且各位遞增的數」中，前導零階段不應該把 0 算作「已放置的位」**。**判斷要不要這個狀態的方法是「問自己：0 開頭的短數字會不會被錯誤地計入或排除」。**

**「求 [L, R] 區間的答案」用差分**：`f(R) - f(L - 1)`——**這幾乎總是比直接處理雙邊界簡單**；**而它要求 f 定義為「0 到 X 中滿足條件的個數」。**

**「計數問題不一定要 DP」**：有些條件可以直接用組合數學算——**例如「1 到 N 中有幾個數包含數字 7」可以用容斥（總數減去不含 7 的數）**；**而不含 7 的數可以逐位地用乘法原理算出**。**在面試中先想想「有沒有直接的組合公式」再考慮 DP，往往能得到更簡潔的解法。**

## 面試回答方式

先給方法名（**數位 DP：逐位構造並記錄 tight**）與三個核心狀態，說明 tight 的含義，再給實作方式（記憶化搜尋）與複雜度。加分點有四個：**為什麼 tight 為 true 時不記憶化**，**以及「忘記把 tight 放進鍵」是最經典的錯誤來源**；**前導零狀態**與**判斷要不要它的方法**；**用差分處理 [L, R] 區間**；以及**先想想有沒有直接的組合公式**（例如用容斥算「包含數字 7」）。

## 講稿

用數位 DP，逐位地構造數字，並記錄是否還緊貼上界這個狀態。

核心狀態是三個。當前處理到第幾位、是否仍緊貼上界、還有題目需要的額外資訊。緊貼上界這個狀態是關鍵，如果前面的位都等於上界的對應位，這一位就只能取到上界的這一位，否則可以取零到九。

實作上最清楚的寫法是記憶化搜尋。而這裡有一個最經典的錯誤，就是忘記把緊貼上界這個標記放進記憶化的鍵裡。因為受限狀態的結果不能被套用到不受限的狀態上。

第二個容易出錯的地方是前導零。如果題目關心位數或相鄰位的關係，那零零一二三跟一二三的處理必須不同。判斷要不要這個狀態的方法是問自己，零開頭的短數字會不會被錯誤地計入或排除。

求區間答案的話，用上界的答案減去下界減一的答案，這幾乎總是比直接處理雙邊界簡單。

## 常見追問

### 記憶化的狀態要不要包含 tight？

**核心答案**：**要包含，但更好的做法是「只在 tight 為 false 時查表與存表」**。因為 tight 為 true 的狀態只會被訪問一次——**存它沒有收益**；**而如果不加區分地共用一張表，就會把受限的結果錯誤地套用到不受限的狀態上，導致答案偏小。**

**詳細解析**：**「這個錯誤的症狀很典型」**：答案總是偏小且在 N 是 10 的冪時正確（因為那時沒有受限的中間狀態）——**認得這個症狀能省下大量除錯時間**。**而一個更安全的實作習慣是「把 tight 作為函式參數而非狀態的一部分，並在函式開頭寫 `if (!tight && memo[pos][extra] != -1) return memo[pos][extra];`」**——**這樣結構上就不可能弄錯**。**leadingZero 的處理方式相同**。**這類「用結構保證正確性而非靠記得檢查」的實作習慣，在任何容易出錯的演算法中都值得採用**——**它把一個需要記憶的規則變成了程式碼的形狀。**

**面試回答方式**：給明確的答案（**要區分，但更好的做法是只在 tight 為 false 時查表存表**）並解釋原因。核心加分點是**這個錯誤的症狀很典型**（答案偏小、N 是 10 的冪時正確），**認得症狀能省下除錯時間**，並給出**用結構保證正確性的實作習慣**。收在通則：**把一個需要記憶的規則變成程式碼的形狀**。

### 有哪些常見的計數題型？

**核心答案**：**四類**。**數位相關**（含某個數字、數位和、相鄰位的約束）；**排列組合**（滿足條件的排列數、不同的子集數）；**格路徑計數**（從左上到右下的路徑數、帶障礙的版本）；**以及卡特蘭數家族**（合法括號序列、二元樹的形態數、出棧序列）。

**詳細解析**：**「卡特蘭數值得認得」因為它出現得比預期頻繁**：n 對括號的合法序列數、n 個節點的二元樹形態數、n×n 格中不越過對角線的路徑數、凸多邊形的三角剖分數——**這些看起來不相關的問題答案都是第 n 個卡特蘭數**；**而它的遞推式是 `C(n) = Σ C(i) × C(n-1-i)`**，**那個形式本身就是「枚舉第一個配對的位置把問題拆成兩半」**。**在面試中認出「這是卡特蘭數」能立刻給出答案與 O(n) 的計算方式**——**而更重要的是那個遞推式的推導展示了一種通用的思路**：**在計數問題中枚舉一個「分界」把問題拆成獨立的兩部分**。

**面試回答方式**：給四類題型。核心加分點是**卡特蘭數值得認得因為它出現得比預期頻繁**，列出幾個看起來不相關但答案相同的問題，並給出遞推式與它的含義（**枚舉第一個配對的位置把問題拆成兩半**）。收在通用思路：**在計數問題中枚舉一個分界把問題拆成獨立的兩部分**。

### 計數結果很大要怎麼處理？

**核心答案**：**題目通常會要求「對 10^9 + 7 取模」**——**於是每一步的加法與乘法都要取模**；**而要注意「兩個接近 10^9 的數相乘會溢出 32 位元」，所以中間結果要用 64 位元**。**如果需要除法（例如組合數），要用模逆元而非直接除**。

**詳細解析**：**「為什麼是 10^9 + 7」有一個實際的理由**：它是質數（於是每個非零元素都有模逆元，除法可以做）——**而且它小於 2^30，於是兩個模後的數相乘不超過 2^60，在 64 位元整數內不會溢出**。**這兩個性質正是它被選中的原因**。**而模逆元的計算方式是費馬小定理 `a^(p-2) mod p`（用快速冪，O(log p)）或者擴展歐幾里得**；**如果需要大量的組合數，通常預處理階乘與階乘的逆元，於是每個組合數是 O(1)**。**知道「為什麼是這個模數」比只記得它，在遇到不同的模數（例如 998244353，它適合 NTT）時更有用。**

**面試回答方式**：給處理方式（每步取模、用 64 位元避免溢出、除法用模逆元）。核心加分點是**為什麼是 10^9 + 7**——**它是質數所以有模逆元，且小於 2^30 所以相乘不溢出 64 位元**。收在延伸：**模逆元用費馬小定理或擴展歐幾里得**，**大量組合數則預處理階乘與逆元**，**而知道理由在遇到不同模數時更有用**。
