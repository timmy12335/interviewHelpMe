# 題目

Java 的註解是什麼？元註解有哪些？`@Retention` 的三種保留策略有什麼差異？

## 核心答案

註解是一種「附加在程式碼元素（類別、方法、欄位等）上的元資料標記」，本身不改變程式邏輯，而是提供資訊給編譯器、工具或框架在編譯期或執行期讀取並據此處理。元註解是「用來定義註解的註解」，主要有四個：`@Retention`（保留策略）、`@Target`（可用位置）、`@Documented`（是否納入 Javadoc）、`@Inherited`（是否可被子類別繼承）。`@Retention` 有三種策略：`SOURCE`（只在原始碼、編譯後丟棄）、`CLASS`（保留到 class 檔但執行期不可見）、`RUNTIME`（保留到執行期、可透過反射讀取）。

## 詳細解析

**註解的本質**：註解是元資料——它不直接影響被標註程式碼的執行，而是「攜帶資訊」讓其他程式（編譯器、註解處理器、框架）讀取後做對應處理。例如 `@Override` 讓編譯器檢查是否真的覆寫了父類別方法，`@Autowired` 讓 Spring 知道要注入依賴。

**四個核心元註解**：

1. **`@Retention`**：決定註解保留到哪個階段（見下方三種策略）。
2. **`@Target`**：限定註解可以用在哪些程式元素上（`TYPE` 類別、`METHOD` 方法、`FIELD` 欄位、`PARAMETER` 參數等）。
3. **`@Documented`**：標註此註解是否要被納入 Javadoc 文件。
4. **`@Inherited`**：標註此註解是否能被子類別自動繼承（預設註解不會被繼承）。

**`@Retention` 的三種保留策略**：

- **`SOURCE`**：只在原始碼階段存在，編譯後就被丟棄，不會進入 class 檔。用於「只給編譯器或原始碼工具看」的註解，例如 `@Override`、`@SuppressWarnings`、Lombok 的註解（編譯期生成程式碼後就不需要了）。
- **`CLASS`**（預設）：保留到 class 檔案中，但 JVM 載入類別時不會讀入，執行期反射看不到。用於「編譯後的位元組碼工具」場景。
- **`RUNTIME`**：保留到執行期，JVM 載入類別時會保留，可以透過反射讀取。這是框架最常用的策略——Spring、JUnit、Jackson 等都需要在執行期用反射讀取註解來決定行為（如 `@Autowired`、`@Test`、`@JsonProperty`）。

## 面試回答方式

先講「註解是元資料標記，不改變邏輯而是攜帶資訊給編譯器/框架讀取」這個本質，並舉 `@Override`（給編譯器）和 `@Autowired`（給 Spring）兩個對比例子。接著列出四個元註解的作用。`@Retention` 的三種策略是這題的重點，一定要講清楚三者的差異與典型用途——尤其強調「框架靠 `RUNTIME` + 反射讀取註解來運作」，這連結到反射題（[[013-reflection-principle.md]]），能展現你理解註解如何真正發揮作用。

## 常見追問

### 自訂一個執行期註解並讓它生效，需要哪些步驟？

**核心答案**：三步——第一步用 `@interface` 定義註解，並標上 `@Retention(RUNTIME)`（保留到執行期）和 `@Target`（限定使用位置）；第二步在目標程式碼元素上使用這個註解（可帶參數）；第三步寫一段「處理邏輯」，透過反射在執行期讀取這個註解（`isAnnotationPresent()`、`getAnnotation()`）並根據註解的資訊做對應處理。註解本身只是標記，真正讓它「生效」的是第三步的處理邏輯。

**詳細解析**：很多人誤以為「加了註解就會自動生效」，但關鍵在於——註解本身不做任何事，它只是一個標記，必須有一段程式碼去「讀取這個標記並執行對應邏輯」才會產生效果。例如你自訂一個 `@LogExecutionTime` 註解，光是標在方法上什麼都不會發生；你需要配合一個 AOP 切面或攔截器，在執行期透過反射檢查方法上有沒有這個註解，有的話就在方法前後記錄時間。這就是為什麼框架的註解能生效——框架內部有大量「掃描註解 + 反射處理」的邏輯（例如 Spring 掃描 `@Component` 建立 Bean、掃描 `@Autowired` 注入依賴）。理解「註解是被動的標記，需要主動的處理器」是理解整個註解機制的關鍵。

**面試回答方式**：講出「定義（`@interface` + `RUNTIME` + `Target`）、使用、反射讀取處理」三步，並特別強調「註解只是標記，需要處理邏輯才會生效」這個常見誤區，展現你理解註解機制的本質而不只是會用現成的框架註解。這種「戳破魔法」的回答很能體現理解深度。

### @Inherited 為什麼預設情況下註解不會被繼承？

**核心答案**：預設情況下，父類別上的註解不會自動出現在子類別上——例如父類別標了某個自訂註解，用反射檢查子類別時預設查不到這個註解。只有當這個註解本身被 `@Inherited` 標註時，子類別才能繼承到父類別的這個註解。而且要注意 `@Inherited` 只對「類別繼承」有效，對「介面實作」和「方法覆寫」都無效。

**詳細解析**：這個設計是為了避免註解語意的混淆——如果所有註解預設都被繼承，可能導致很多意外情況（子類別「莫名其妙」帶上了父類別的所有標記）。所以 Java 選擇「預設不繼承，需要繼承時明確用 `@Inherited` 宣告」。而 `@Inherited` 的限制也值得注意：它只讓「子類別繼承父類別（extends）的類別級註解」，不會讓「實作類別繼承介面上的註解」，也不會讓「覆寫方法繼承被覆寫方法上的註解」。這也是為什麼 Spring 不完全依賴 `@Inherited`，而是自己實作了一套更強大的註解查找邏輯（`AnnotatedElementUtils`），能處理介面、元註解（註解上的註解）等更複雜的繼承場景。

**面試回答方式**：回答「預設不繼承是為了避免語意混淆，需要時用 `@Inherited` 明確宣告」，並補上重要限制「`@Inherited` 只對類別繼承有效，對介面和方法覆寫無效」，如果能提到「Spring 自己實作了更強的註解查找來彌補這個限制」會是加分點，展現你了解框架如何處理原生註解機制的不足。

### 註解可以有哪些型別的成員（屬性）？有什麼限制？

**核心答案**：註解的成員（屬性）型別被限制為——基本型別（int、boolean 等）、`String`、`Class`、列舉（enum）、其他註解、以及這些型別的陣列。不能用一般的物件型別（如 `Object`、自訂類別），也不能為 null（可以設預設值，但預設值不能是 null）。成員宣告的語法像方法（`String value();`），可以用 `default` 指定預設值。

**詳細解析**：這些限制是因為註解的成員值必須是「編譯期常數」——註解是編譯期就寫入 class 檔的元資料，它的屬性值必須在編譯時就能完全確定，所以只能用編譯期常數表達的型別（基本型別、字串、Class 引用、列舉、其他註解及其陣列）。不能用任意物件是因為物件是執行期才建立的，無法在編譯期固化進 class 檔。另外有個慣例——如果註解只有一個成員，通常把它命名為 `value`，這樣使用時可以省略成員名（`@MyAnnotation("x")` 而非 `@MyAnnotation(value = "x")`）。理解這些限制的根源（成員值必須是編譯期常數）能幫助你正確設計自訂註解。

**面試回答方式**：列出允許的型別（基本型別、String、Class、enum、註解、陣列），並點出根本原因——「成員值必須是編譯期常數，因為註解是編譯期寫入 class 檔的」，再補一句「單成員習慣命名為 value 可省略名稱」的實用慣例，展現你既知道規則又理解規則背後的原理。
