# 題目

介面的預設方法（default method）是什麼？為什麼要引入它？如果一個類別實作的多個介面有同名的預設方法會怎樣？

## 核心答案

預設方法（JDK 8 引入）是介面中帶有實作主體的方法，用 `default` 關鍵字修飾。引入它的主要動機是「介面的向後相容演進」——讓已有的介面能新增方法而不破壞所有現存的實作類別（否則舊的實作類別會因為沒實作新方法而編譯失敗）。如果一個類別實作的多個介面有同名的預設方法（「菱形衝突」），編譯器會強制要求該類別自己覆寫這個方法來明確解決衝突，否則編譯錯誤。

## 詳細解析

**為什麼引入預設方法**：JDK 8 要為 `Collection` 等既有介面新增 `stream()`、`forEach()` 等方法以支援 Lambda 和 Stream。但如果直接在介面中加抽象方法，所有實作了 `Collection` 的類別（包括無數第三方類別庫）都會因為「沒實作新方法」而編譯失敗。預設方法讓介面可以「帶著預設實作」新增方法——舊的實作類別自動繼承這個預設實作，不需要修改就能相容，實現了介面的平滑演進。

**預設方法的特點**：

- 用 `default` 修飾，有方法主體（實作）。
- 實作類別可以直接使用（繼承預設實作），也可以覆寫它。
- 介面因此可以同時包含抽象方法、預設方法、以及靜態方法（JDK 8 也允許介面有 static 方法）。

**多重繼承衝突（菱形問題）**：如果一個類別實作了兩個介面 A 和 B，而 A、B 都有一個同名同簽章的預設方法，就產生了「該繼承哪一個」的歧義。Java 的規則是——**編譯器強制該類別自己覆寫這個方法**來消除歧義，否則編譯報錯。在覆寫的方法中，可以用 `介面名.super.方法名()` 的語法明確呼叫某個特定介面的預設實作。

**衝突解決的優先規則**：

1. **類別優先於介面**：如果一個方法同時來自父類別和介面，父類別的實作優先。
2. **子介面優先於父介面**：如果一個介面繼承另一個介面且都有同名預設方法，更具體的子介面優先。
3. **無法自動判斷時**：由實作類別強制覆寫解決。

## 面試回答方式

先講「引入動機」——這是這題的核心考點：預設方法是為了「介面能向後相容地新增方法」（用 JDK 8 給 Collection 加 stream 的例子最有說服力）。接著講多重繼承衝突（菱形問題）的處理——「編譯器強制實作類別覆寫、可用 `介面名.super.方法名()` 指定」。如果能講出三條衝突解決優先規則（類別優先於介面、子介面優先於父介面、否則強制覆寫），展現你對這個機制的細節有完整掌握，而不只是知道「有預設方法這個東西」。

## 常見追問

### 有了預設方法，介面和抽象類別還有什麼區別？

**核心答案**：即使介面有了預設方法（能提供方法實作），它和抽象類別仍有本質區別——介面不能有「實例欄位（狀態）」（只能有 `public static final` 常數），抽象類別可以有實例欄位、建構子、各種存取修飾的成員；一個類別只能繼承一個抽象類別（單繼承），但可以實作多個介面（多實作）。核心差異是「介面描述『能做什麼』的能力契約、不持有狀態，抽象類別描述『是什麼』的部分實作、可以持有狀態」。

**詳細解析**：預設方法讓介面能提供行為的預設實作，模糊了介面和抽象類別的一部分界線，但兩者的定位仍然不同。介面的核心是「契約/能力」——它宣告一組能力（如 `Comparable` 表示「可比較」），一個類別可以同時具備多種能力（實作多個介面），且介面不應該持有狀態（沒有實例欄位）。抽象類別的核心是「部分實作的基礎類別」——它可以有實例欄位保存狀態、有建構子初始化、提供部分共用實作供子類別繼承，但受限於單繼承，一個類別只能有一個抽象父類別。選擇時的一般原則是：如果是「定義一組能力、可能被多種不相關的類別具備」用介面；如果是「一組緊密相關的類別共享狀態和部分實作」用抽象類別。

**面試回答方式**：抓住兩個本質區別——「介面不能有實例狀態、抽象類別可以」和「介面可多實作、抽象類別單繼承」，並用「介面是能力契約、抽象類別是部分實作的基礎類別」概括定位差異。能講出「預設方法模糊了界線但兩者定位仍不同」展現你理解這個演進帶來的變化以及不變的本質。

### 為什麼介面的預設方法不能覆寫 Object 的方法（如 equals、toString）？

**核心答案**：Java 明確禁止在介面中用預設方法覆寫 `Object` 的方法（如 `equals`、`hashCode`、`toString`）。原因是——每個類別都繼承自 `Object`，根據「類別優先於介面」的衝突解決規則，`Object` 的方法實作永遠會優先於介面的預設方法，所以介面就算提供了這些方法的預設實作也永遠不會被採用（會被 Object 的實作覆蓋），既然註定無效，Java 乾脆從語言層面禁止這種寫法以避免誤導。

**詳細解析**：這個限制是「類別優先於介面」規則的直接推論。假設允許介面提供 `default boolean equals(Object o)`，那麼任何實作這個介面的類別，它的 equals 到底用誰的？根據衝突規則，類別（包括繼承自 Object 的方法）優先於介面，所以永遠是 Object（或類別自己覆寫）的 equals 生效，介面的預設 equals 永遠是死程式碼。與其讓開發者寫出一個「看起來會生效但實際永遠不生效」的誤導性程式碼，Java 直接在編譯層面禁止它。這也反映了一個設計原則——如果某個寫法註定無效，不如明確禁止它，避免開發者誤以為它有作用而產生錯誤的預期。

**面試回答方式**：用「類別優先於介面的規則導致介面的 equals 等永遠被 Object 的實作覆蓋、註定無效，所以乾脆禁止」這個推理回答，展現你能把「衝突解決規則」應用到推導出這個限制的原因，而不只是記住「不能這樣寫」這條規則本身。

### 介面的 default、static、private 方法各自的用途是什麼？

**核心答案**：`default` 方法提供可被實作類別繼承或覆寫的預設實作（用於介面演進）；`static` 方法（JDK 8）是屬於介面本身的工具方法，透過「介面名.方法名」呼叫，常用於提供與該介面相關的工廠或輔助方法；`private` 方法（JDK 9）用於在介面內部封裝多個 default 方法之間共用的邏輯，不對外暴露，避免程式碼重複。

**詳細解析**：這三種方法反映了介面從 JDK 8 到 9 逐步增強的能力。`default` 是核心，解決介面演進的相容問題。`static` 方法讓介面可以承載「和這個介面概念相關、但不需要實例」的工具方法——例如 `Comparator.comparing(...)` 就是介面的靜態工廠方法，讓你方便地建立比較器。`private` 方法（含 private static）是 JDK 9 補上的——當一個介面有多個 default 方法共用某段邏輯時，以前只能把這段邏輯複製到每個 default 方法，或暴露成一個 public 的輔助方法（污染介面的公開契約）；private 方法讓這段共用邏輯可以封裝在介面內部、不對外暴露，讓 default 方法之間能乾淨地共用程式碼。這三者合起來讓介面幾乎可以像一個小型的功能模組一樣組織程式碼。

**面試回答方式**：分別講清楚三者用途——default（可繼承/覆寫的預設實作、用於演進）、static（介面層級的工具/工廠方法）、private（封裝 default 之間共用的內部邏輯）。能點出它們是 JDK 8→9 逐步增強的、以及各自解決的具體問題，展現你對介面能力演進的完整認識。
