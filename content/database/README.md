# 資料庫面試題（樣板類別）

InterviewHelpMe 第六個內容類別，共 50 題，涵蓋 MySQL/InnoDB 索引原理（B+ 樹、聚簇索引、聯合索引、索引失效、覆蓋索引、EXPLAIN）、交易與併發控制（ACID、隔離級別、MVCC、鎖類型、間隙鎖、樂觀鎖與悲觀鎖）、崩潰恢復與複製（redo log、binlog 與兩階段提交、讀寫分離與主從延遲）、效能優化（深分頁、慢查詢排查）、分散式資料庫工程（分庫分表、分散式 ID、正規化與反正規化、儲存引擎比較、連線池、SQL 注入防範），以及 LSM Tree 儲存引擎（與 B+ 樹形成寫入／讀取成本分配的對照）。

## 這個類別的設計

001 到 025 是最初的批次，覆蓋索引原理、交易與併發控制、崩潰恢復、以及分散式資料庫工程的高頻題。026 到 050 是後續補充的第二批，往四個方向延伸：**InnoDB 的內部機制**（undo log、Buffer Pool 的 LRU 分區、change buffer、統計資訊與最佳化器、JOIN 演算法、索引下推）、**維運與診斷**（死鎖排查、長交易治理、線上 DDL、複製格式、備份與時間點恢復、監控指標）、**schema 與寫入設計**（主鍵選擇、資料型別、字元集與定序、NULL 語意、約束的取捨、批次寫入、分區表），以及**選型判斷**（PostgreSQL 與 MySQL 的差異、NewSQL、容量與成本、什麼時候不該用關聯式資料庫）。

第二批的重心是**判準與失敗模式**：026 指出「MVCC 的多版本不是另外存資料，就是 undo log」並由此推出長交易的危害；034 提出「加索引可以減少死鎖」這個不直覺的洞見；044 用註冊流程的競態說明「應用層校驗在併發下不可靠」。050 是收束題，主張「預設應該是關聯式資料庫」並把理由講成靈活性而非保守。

## 檔案格式

與其他類別相同：每題一個 `NNN-slug.md`，frontmatter 對應 [schema.sql](../../backend/sql/schema.sql) 的 `question` 表（`category: database`）。正文含：題目、核心答案、詳細解析、面試回答方式、常見追問（3 題，各含核心答案／詳細解析／面試回答方式）、相關。部分題目透過 `[[../category/file.md]]` 交叉連結到 Java（HashMap 內部結構）、Java 併發（死鎖排查）、Spring（交易原理）、Redis（分散式鎖、主從複製、AOF 持久化、事務）等類別。
