# 題目

為什麼網路要分層？OSI 七層和 TCP/IP 四層的關係是什麼，實務上該記哪一套？

## 核心答案

分層解決的是**複雜度與可替換性**：每一層只依賴下一層提供的能力、只對上一層負責一組明確的服務，於是換掉任何一層都不需要動其他層——把 Wi-Fi 換成乙太網路，TCP 完全不用改；把 HTTP 換成 gRPC，IP 也完全不用改。**OSI 七層**是理論上的參考模型（實體、資料連結、網路、傳輸、會議、表達、應用），**TCP/IP 四層**是實際被實作出來的（網路介面、網路、傳輸、應用），它把 OSI 的上三層合併成應用層、下兩層合併成網路介面層。實務上要記的是 **TCP/IP 四層**，因為真實的協定堆疊長這樣；OSI 的價值在於**它提供了一套講清楚問題出在哪一層的共同語彙**。面試中最有用的不是背出七層名稱，而是能說出**每一層各自解決什麼問題**：網路層負責「跨網路找得到對方」（IP 定址與路由），傳輸層負責「找到對方機器上的哪個程式、以及要不要保證送達」（埠號與可靠性），應用層負責「這些位元組是什麼意思」。

## 詳細解析

**每一層的核心職責，用一句話記**：實體層傳位元；資料連結層在**同一個區域網路內**靠 MAC 位址把訊框送到隔壁；網路層靠 IP **跨網路**找到目標主機並選路；傳輸層靠**埠號**找到主機上的哪個程式，並決定要不要可靠傳輸；應用層定義**位元組的語意**。用「同網段用 MAC、跨網段用 IP、找程式用埠號」這條線串起來，比背名稱有用得多。

**封裝與解封裝**：資料往下走時每一層加上自己的標頭（應用資料 → 加 TCP 標頭成為段 → 加 IP 標頭成為封包 → 加乙太網路標頭成為訊框），到對端再逐層拆掉。這解釋了**為什麼有 MTU 限制與協定開銷**——每層標頭都佔用空間，也解釋了為什麼抓封包時看得到層層嵌套的結構。

**分層不是絕對的，實務上經常被打破**：HTTPS 的 TLS 嚴格說介於傳輸層與應用層之間；QUIC 把傳輸層功能搬到 UDP 之上的使用者空間實作；負載平衡器有「四層」（看 IP 與埠號轉發）與「七層」（看 HTTP 路徑與標頭轉發）之分，這個術語直接來自分層模型。能講出這些**跨層或違反分層的實例**，比純粹複誦模型更能顯示你理解它的用途與限制。

**四層與七層負載平衡的差別**是最常被追問的應用：四層只看傳輸層資訊，效能高、但無法依據 URL 或標頭做決策，也看不到加密內容；七層要解析應用層協定（通常也要終止 TLS），能做路徑路由、灰度發布、依 Cookie 做黏著，代價是效能與複雜度。

**分層的價值在排查時最明顯**：遇到「連不上」時，依層往上問——實體與連結層通不通（介面是否 up、同網段能不能 ping）、網路層通不通（跨網段 ping、路由與防火牆）、傳輸層通不通（埠號有沒有在聽、三次握手有沒有完成）、應用層對不對（協定、憑證、認證）。這條順序能把模糊的「壞掉了」收斂成一個具體的層。

## 面試回答方式

不要背七層名稱開場，先講**分層解決什麼問題**——複雜度與可替換性，並舉「換 Wi-Fi 不用改 TCP、換 HTTP 不用改 IP」這個具體例子。接著給兩套模型的關係，並明確表態實務上記 TCP/IP 四層。核心是用一句話說清每層職責：**同網段用 MAC、跨網段用 IP、找程式用埠號、應用層定義語意**。加分點有三個：封裝與解封裝解釋了 MTU 與協定開銷的來源；四層與七層負載平衡的術語直接來自這個模型，並說出兩者的取捨；以及分層在排查時是一條可操作的順序。

## 講稿

分層解決的是複雜度跟可替換性。每一層只依賴下一層提供的能力，只對上一層負責一組明確的服務。所以我把 Wi-Fi 換成有線網路，TCP 完全不用改，把 HTTP 換成 gRPC，IP 也不用改。

OSI 七層是理論上的參考模型，TCP/IP 四層才是真正被實作出來的。實務上我記四層，因為真實的協定堆疊長那樣。OSI 的價值在於它給了大家一套共同語彙，可以講清楚問題出在哪一層。

我記每層職責的方式是一條線。同一個網段裡用 MAC 位址送到隔壁，跨網段用 IP 找到目標主機並且選路，到了主機之後用埠號找到是哪一個程式，最後應用層決定這些位元組是什麼意思。

這套東西在排查的時候最有用。連不上的時候我會依層往上問，介面有沒有起來、同網段能不能通、跨網段的路由跟防火牆、埠號有沒有在聽、握手有沒有完成，最後才看應用層的協定跟憑證。這樣可以把壞掉了這種模糊描述收斂成一個具體的層。

另外像四層跟七層負載平衡這個講法，其實就是直接從這個模型來的。

## 常見追問

### 四層負載平衡和七層負載平衡怎麼選？

**核心答案**：**四層**只看 IP 與埠號做轉發，不解析應用層內容，因此**效能高、延遲低、也不需要終止 TLS**，適合純粹的流量分發與非 HTTP 協定（資料庫、遊戲、自訂 TCP 協定）。**七層**要解析 HTTP，能依**路徑、主機名稱、標頭、Cookie** 做路由，因此能做灰度發布、A/B 測試、依使用者黏著，代價是要終止 TLS、CPU 開銷高、也成為一個需要維運的複雜元件。

**詳細解析**：實務上常見的是**兩層併用**——外層用四層做跨機房或跨可用區的粗分流，內層用七層做細粒度的路由。要注意七層代理終止 TLS 之後，**後端到代理之間的流量是否加密**是一個要明確決定的安全問題（零信任架構會要求重新加密）。另一個容易忽略的是**來源 IP 的保留**：七層代理轉發時後端看到的是代理的 IP，要靠 X-Forwarded-For 這類標頭傳遞原始來源，而這個標頭是可以偽造的，所以只能信任由自己的代理層寫入的那一段。

**面試回答方式**：用「看不看得到應用層內容」把兩者分開，並各給適用場景。加分點是提到實務上兩層併用、TLS 終止後的後段加密決策、以及來源 IP 靠標頭傳遞但標頭可偽造，只能信任自己代理寫入的部分。

### 為什麼說 TLS 不好歸類在某一層？

**核心答案**：因為它**建立在傳輸層之上、又服務於應用層**，本身不屬於任何一層的職責。它使用 TCP 提供的可靠位元組流，在其上做握手、金鑰協商與加密，然後把加密後的通道交給 HTTP 這類應用協定使用。所以有人把它歸在傳輸層與應用層之間，OSI 模型裡則勉強對應到表達層。

**詳細解析**：這個歸類的模糊本身說明了**分層模型是描述性的而非規範性的**——真實協定是為了解決問題而設計，不是為了填進模型的格子。類似的例子還有 QUIC：它跑在 UDP 之上，卻在使用者空間實作了可靠傳輸、擁塞控制與加密，等於把傳輸層與安全層合併並移出核心，這樣做的好處是**升級不必等作業系統**。理解這些案例的價值在於，面試中被問「這個屬於第幾層」時，正確的回答往往是說明它做什麼、為什麼這樣設計，而不是硬塞進一個編號。

**面試回答方式**：說明它建立在 TCP 之上、服務於應用層，所以歸類模糊。把重點提升到「分層模型是描述性的而非規範性的」。加分點是舉 QUIC 為例，說明它把傳輸與加密合併並移到使用者空間，好處是升級不必等作業系統。

### 資料連結層的 MAC 位址和網路層的 IP 位址，為什麼兩個都需要？

**核心答案**：因為兩者解決**不同範圍**的問題。MAC 位址是**燒在網卡上的、扁平的**識別，只在**同一個區域網路內**有意義，用來把訊框送到隔壁機器。IP 位址是**分層的、可路由的**，帶有網段資訊，讓封包能跨越多個網路找到目標。跨網段通訊時，IP 位址從頭到尾不變（標示最終目的地），而 MAC 位址**每經過一個路由器就換一次**（標示下一跳）。

**詳細解析**：串起這兩者的是 **ARP**——主機要送封包給同網段的某個 IP 時，先廣播詢問「這個 IP 的 MAC 是多少」，拿到回應後才能組出訊框。這也是 ARP 欺騙攻擊的基礎：區域網路內的攻擊者可以偽造回應，把流量導向自己。如果目標不在同網段，主機會把封包送給預設閘道的 MAC，由路由器繼續往下轉發。理解「IP 不變、MAC 逐跳更換」這一點，能解釋很多排查現象，例如為什麼在中間路由器上抓包看到的來源 MAC 不是原始主機的。

**面試回答方式**：用「不同範圍」講清分工——MAC 是同網段的下一跳，IP 是端到端的最終目的地，並強調跨網段時 IP 不變、MAC 逐跳更換。加分點是講 ARP 如何把兩者連起來、以及 ARP 欺騙就是利用這個機制。
