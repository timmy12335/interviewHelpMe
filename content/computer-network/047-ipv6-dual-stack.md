# 題目

IPv6 除了位址變多還有什麼不同？雙協定堆疊有什麼要注意的？

## 核心答案

**除了 128 位元的位址，幾個實質的差異。**

**沒有 NAT（在設計上）**——**每個裝置有全球唯一的位址**；**於是「端到端可達」恢復了，而那簡化了很多協定（P2P、SIP）**。**代價是「NAT 曾經提供的隱式防火牆效果」不再存在，必須用真正的防火牆。**

**沒有廣播**——**用多播取代**；**而 ARP 被 NDP（鄰居發現協定）取代。**

**簡化的標頭與不分片**——**路由器不做分片，由來源端負責路徑 MTU 發現**；**於是「ICMPv6 被封鎖」會導致嚴重的連線問題（比 IPv4 更嚴重，因為沒有分片作為後備）。**

**位址自動設定**——**SLAAC 讓裝置能自己產生位址而不需要 DHCP。**

**雙協定堆疊的核心注意事項是「Happy Eyeballs」**——**同時嘗試 IPv6 與 IPv4，先連上的贏；沒有它的話，IPv6 不通的環境會讓每個連線都先等一次逾時。**

## 詳細解析

**「ICMPv6 不能被封鎖」是一個必須知道的運維規則**：IPv4 時代很多人習慣性地封鎖所有 ICMP——**而在 IPv6 中，ICMPv6 承擔了鄰居發現（相當於 ARP）與路徑 MTU 發現**；**封鎖它會讓網路根本無法運作或者出現「小封包通、大封包不通」的問題**。**而因為 IPv6 的路由器不做分片，路徑 MTU 發現失效的後果比 IPv4 更嚴重**——**IPv4 至少還有分片作為（低效的）後備。**

**「Happy Eyeballs 解決的是一個真實的體驗問題」**：早期的雙協定堆疊實作會「優先嘗試 IPv6，失敗才回退 IPv4」——**而如果 IPv6 的路徑有問題（設定錯誤、路由黑洞），使用者要等一次完整的連線逾時（可能幾十秒）才會回退**。**Happy Eyeballs 改成「並行嘗試，先成功的贏」（IPv6 有一點點先發優勢）**——**於是壞掉的 IPv6 只讓連線慢幾百毫秒而非幾十秒**。**這是一個「用少量的冗餘換取巨大的最壞情況改善」的設計，思路與對沖請求相同。**

**「應用層的相容性問題」是遷移中最容易踩的**：**位址被儲存在資料庫的 `VARCHAR(15)` 欄位中**（IPv4 的最大長度）——**IPv6 位址存不下**；**日誌的解析正則假設了點分十進位**；**以及「用位址判斷地理位置或做封鎖」的邏輯需要支援兩種格式**。**這些都不是網路問題而是應用問題**——**而它們往往在啟用 IPv6 之後才被發現。**

**「該不該支援 IPv6」的判斷**：**對面向公眾的服務，越來越應該**（**部分行動網路已經是 IPv6-only 加上 NAT64**）；**對內部服務，通常不急**（**內網位址不會不夠用**）。**而支援的成本主要在「測試與相容性」而非「網路設定」**——**因為雲端與 CDN 通常已經提供了 IPv6 的入口。**

## 面試回答方式

先給幾個實質差異（無 NAT、無廣播、不分片、自動設定）而非只說位址變多，再給雙協定堆疊的 **Happy Eyeballs**。加分點有四個：**ICMPv6 不能被封鎖**——**它承擔鄰居發現與路徑 MTU 發現**，**而因為路由器不分片，失效的後果比 IPv4 更嚴重**；**Happy Eyeballs 解決的真實體驗問題**——**從「等完整逾時才回退」變成「並行嘗試先成功的贏」**，**是「用少量冗餘換巨大的最壞情況改善」的設計**；**應用層的相容性問題最容易踩**（`VARCHAR(15)` 的欄位、假設點分十進位的正則、地理判斷邏輯）**且往往在啟用後才被發現**；以及**支援的成本主要在測試與相容性而非網路設定**。

## 講稿

除了位址變多，有幾個實質的差異。

第一是設計上沒有位址轉換，每個裝置有全球唯一的位址，端到端可達恢復了。代價是位址轉換曾經提供的隱式防火牆效果不再存在，必須用真正的防火牆。第二是沒有廣播，用多播取代，而位址解析協定被鄰居發現取代。第三是路由器不做分片，由來源端負責路徑探測。

第三點帶來一個必須知道的運維規則。不能封鎖控制訊息協定。很多人在舊版時代習慣性地封鎖所有這類訊息，而在新版中它承擔了鄰居發現跟路徑探測。封鎖會讓網路根本無法運作，或者出現小封包通、大封包不通的問題。而且因為不做分片，失效的後果比舊版更嚴重，舊版至少還有分片作為後備。

雙協定堆疊的核心是並行嘗試的機制。早期的實作會優先嘗試新版、失敗才回退，於是路徑有問題時使用者要等一次完整逾時才回退。改成並行嘗試、先成功的贏之後，壞掉的路徑只讓連線慢幾百毫秒而不是幾十秒。這是用少量冗餘換取巨大的最壞情況改善。

## 常見追問

### 為什麼 IPv6 普及這麼慢？

**核心答案**：**因為 NAT 太好用了**。IPv6 要解決的核心問題是「位址不夠」——**而 NAT 讓一個公網位址服務幾千台裝置，於是「不夠用」這個痛點被大幅推遲**。**加上升級需要整條路徑（ISP、企業網路、應用、設備）都支援**——**任何一環沒跟上就用不了**；**而每一方都缺乏單獨升級的動力（升級了也沒有立即的好處）**。**這是一個典型的協調失敗問題。**

**詳細解析**：**「協調失敗」在網路協定的演進中反覆出現**：每一方的最優選擇是「等別人先升級」——**於是大家一起停在原地**。**打破它的通常是「某一方有足夠的動力與規模」**：**行動營運商因為裝置數量爆炸而確實位址不夠，於是率先部署 IPv6**（**很多行動網路已經是 IPv6-only 加 NAT64 讓 IPv4 的服務仍可達**）；**而大型的內容提供者為了服務那些使用者而支援 IPv6**——**於是形成了一個正回饋**。**理解這個動力學能解釋「為什麼是行動網路先」以及「為什麼企業內網最慢」**（**內網位址永遠夠用，沒有動力**）。**這個「技術的採用取決於誰有痛點」的規律，比任何技術優勢的論述更能預測採用曲線。**

**面試回答方式**：給核心原因（**NAT 讓「位址不夠」這個痛點被推遲**）與**需要整條路徑都支援而每一方缺乏單獨升級的動力**。核心加分點是把它命名為**協調失敗**並說明打破它的方式：**行動營運商因裝置爆炸而確實不夠所以率先部署，大型內容提供者為服務那些使用者而跟進，形成正回饋**。收在規律：**這解釋了為什麼是行動網路先、企業內網最慢**，**而「技術的採用取決於誰有痛點」比任何技術優勢的論述更能預測採用曲線**。

### 應用要怎麼正確處理兩種位址？

**核心答案**：**四件事**。**用支援兩種的資料類型**（`INET` 型別，或者至少 `VARCHAR(45)`）。**用系統的解析與格式化函式而非自己寫正則**。**綁定監聽時用雙協定的 socket**（`::` 加上 `IPV6_V6ONLY=0`，在多數系統上同時接受兩種）。**以及「不要在程式碼中假設位址的格式」**——**尤其是日誌解析、地理判斷、與封鎖清單。**

**詳細解析**：**「IPv4-mapped IPv6 位址」是一個容易混淆的細節**：在雙協定的 socket 上，IPv4 的連線會以 `::ffff:1.2.3.4` 的形式出現——**於是「來源位址」的字串不是你預期的點分十進位**。**如果程式碼直接把它拿去比對白名單或存進資料庫，就會出問題**。**正確的處理是「用函式判斷它是不是 mapped 位址並正規化」**——**多數語言的網路函式庫都提供這個能力**。**這類「同一個東西有多種表示形式」的問題在 IPv6 中特別多**（**位址的縮寫形式、大小寫、以及 mapped 位址**）——**所以「永遠正規化之後再比較或儲存」是處理 IP 位址的基本紀律**。

**面試回答方式**：給四件事並強調**不要在程式碼中假設位址的格式**。核心加分點是 **IPv4-mapped IPv6 位址**這個容易混淆的細節——**雙協定 socket 上 IPv4 連線會以 `::ffff:` 的形式出現，直接拿去比對白名單就會出問題**。收在紀律：**IPv6 中「同一個東西有多種表示形式」的問題特別多**（縮寫、大小寫、mapped），**所以「永遠正規化之後再比較或儲存」是處理 IP 位址的基本紀律**。

### IPv6 對安全有什麼影響？

**核心答案**：**攻擊面的變化多於增減**。**沒有 NAT 意味著內部裝置直接暴露**——**必須依賴真正的防火牆規則而非「NAT 順便擋住了」**。**位址空間巨大讓「掃描整個網段」變得不可行**——**這是一個防禦上的優勢**；**但也讓「基於位址的封鎖」變得困難（攻擊者有大量位址可用）**。**而雙協定堆疊本身增加了攻擊面**——**兩套規則都要正確，而「IPv4 擋了但 IPv6 沒擋」是一個真實的漏洞來源。**

**詳細解析**：**「IPv4 擋了但 IPv6 沒擋」是雙協定環境中最常見的安全漏洞**：防火牆規則、安全群組、以及應用層的存取控制——**如果只針對 IPv4 設定，那麼一旦服務也監聽 IPv6，那條路徑就是完全開放的**。**而它很難被發現，因為測試通常用 IPv4**。**所以「啟用 IPv6 時必須逐條檢視所有的存取控制規則」**——**而更安全的做法是「預設拒絕」的規則模型（兩種協定都是）而非「列舉要封鎖的」**。**這再次體現了「白名單優於黑名單」**——**而在雙協定的環境中，黑名單的遺漏機率加倍**。

**面試回答方式**：給攻擊面的三個變化（無 NAT 的暴露、掃描不可行是優勢但基於位址的封鎖變難、雙堆疊本身增加攻擊面）。核心加分點是 **「IPv4 擋了但 IPv6 沒擋」是最常見的漏洞**——**只針對 IPv4 設定的規則在服務也監聽 IPv6 時完全開放，而它很難被發現因為測試通常用 IPv4**。收在原則：**啟用時必須逐條檢視所有存取控制規則**，**而「預設拒絕」優於「列舉要封鎖的」**——**在雙協定環境中黑名單的遺漏機率加倍**。
