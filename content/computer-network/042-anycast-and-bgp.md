# 題目

Anycast 是什麼？CDN 怎麼把使用者導向最近的節點？

## 核心答案

Anycast 是「同一個 IP 位址在多個地點被宣告」——而網際網路的路由協定（BGP）會自動把封包送到「路由上最近的那一個」。於是使用者不需要做任何選擇，路由層就完成了就近接入。

**它與 DNS 導流的關鍵差別有三個**。**生效速度**——Anycast 的故障轉移在路由收斂的時間內完成（秒到分鐘），而且不受客戶端快取影響；**DNS 則受制於 TTL 與各層快取**。**精確度**——Anycast 基於實際的網路拓撲，而 DNS 基於解析器的位置（可能不是使用者的位置）。**以及透明度**——Anycast 對應用完全透明，不需要任何客戶端支援。

代價是「你需要自己的 IP 位址段與 BGP 宣告能力」——這需要成為一個自治系統（AS）並與多家 ISP 建立對等連接，**門檻很高**；所以多數團隊是透過 CDN 或雲端服務間接使用它。

## 詳細解析

「BGP 選的是『路由上最近』而非『延遲最低』」是一個重要的區別：BGP 的決策主要看 AS 路徑長度與各種策略屬性——而那與實際的延遲只有粗略的相關性。於是「Anycast 導向的節點未必是延遲最低的」——一個經過三個 AS 但都是高速骨幹的路徑，可能比經過兩個 AS 但其中一段擁塞的路徑快。大型 CDN 因此會結合 Anycast 與其他手段（即時的效能量測、DNS 的微調）來修正。理解這個限制，能解釋「為什麼有時候你被導向一個地理上更遠的節點」。

**「Anycast 對 TCP 的挑戰」曾經是一個顧慮**：如果路由在連線中途改變——後續的封包可能到達另一個節點，而那個節點沒有這條連線的狀態，於是連線斷開。實務上這很少發生（BGP 路由在正常情況下相當穩定），而且短連線受影響的機率更低；**但在路由波動時確實會出現**。QUIC 的連線遷移某種程度上緩解了這個問題（**連線由 ID 識別而非五元組**）——但仍需要新節點能存取連線狀態。

「BGP 的信任模型是一個根本的問題」：BGP 本身沒有驗證機制——**任何 AS 都可以宣告任何前綴**；於是「BGP 劫持」（有意或誤設）能把大量流量導向錯誤的地方。歷史上有多次事故（一個 ISP 誤宣告了 YouTube 的前綴讓全球流量中斷）。RPKI 提供了「這個前綴應該由哪個 AS 宣告」的加密驗證——部署率在近年快速上升，但仍未普及。這是「網際網路的核心協定建立在相互信任之上」的一個具體例子。

「怎麼利用而不自建」是多數團隊的實際答案：CDN、雲端的全球負載平衡器、以及託管的 DNS 都建立在 Anycast 之上——於是你透過它們獲得了 Anycast 的好處而不需要自己的 AS。**理解它的原理仍然有價值**——因為它解釋了那些服務的行為特性（為什麼故障轉移快、為什麼導向的節點有時不是最近的）。

## 面試回答方式

先給 Anycast 的定義（同一個 IP 在多個地點宣告，BGP 自動送到路由上最近的）與**它與 DNS 導流的三個差別**（生效速度、精確度、透明度），指出**代價是需要自己的 IP 段與 BGP 能力**。加分點有四個：BGP 選的是「路由上最近」而非「延遲最低」——**兩者只有粗略的相關性**，這解釋了為什麼有時被導向地理上更遠的節點；**Anycast 對 TCP 的挑戰**（路由中途改變導致連線斷）**與它實務上的罕見性**；**BGP 沒有驗證機制**——任何 AS 都能宣告任何前綴，歷史上有多次劫持事故，而 RPKI 提供了加密驗證但仍未普及；以及多數團隊透過 CDN 與雲端服務間接使用它，而理解原理仍能解釋那些服務的行為特性。

## 講稿

任播是同一個位址在多個地點被宣告，而網際網路的路由協定會自動把封包送到路由上最近的那一個。於是使用者不需要做任何選擇，路由層就完成了就近接入。

它跟用名稱解析導流有三個關鍵差別。生效速度，任播的故障轉移在路由收斂時間內完成，不受客戶端快取影響。精確度，它基於實際的網路拓撲，而不是解析器的位置。還有透明度，對應用完全透明。

但有一個重要的區別要說清楚。路由協定選的是路由上最近，不是延遲最低。它的決策主要看路徑長度跟各種策略屬性，而那跟實際延遲只有粗略的相關性。於是被導向的節點未必是延遲最低的。大型內容分發網路因此會結合即時的效能量測來修正。

還有一個根本的問題，路由協定本身沒有驗證機制，任何自治系統都可以宣告任何位址前綴。歷史上有多次事故，一個服務商誤宣告了某個大網站的前綴，讓全球流量中斷。近年有加密驗證的機制在推廣但仍未普及。這是網際網路的核心協定建立在相互信任之上的一個具體例子。

## 常見追問

### 全球負載平衡有哪些做法？

**核心答案**：**四種，可以組合使用**。**Anycast**——路由層自動就近，最透明但精確度有限。**DNS 地理導流**——根據解析器位置回傳不同 IP，靈活但受 TTL 與解析器位置影響。**HTTP 重導向**——先到一個入口再重導向到最近的區域，精確但多一次往返。**以及客戶端 SDK 的主動探測**——最精確（客戶端實測各節點延遲）但需要客戶端支援。

**詳細解析**：「精確度與透明度是對立的」是這四種方法的共同規律：越透明的（Anycast）越不需要客戶端配合但精確度越差——越精確的（客戶端探測）越需要整合但能基於實測選擇。所以選擇取決於「你能控制客戶端嗎」：**瀏覽器（不能控制）用 Anycast 加 DNS**；自己的行動應用（能控制）可以做主動探測與智慧選路。這也解釋了為什麼「大型應用的 App 往往有自己的調度邏輯」——因為它們能控制客戶端，於是可以突破前兩種方法的精確度上限。能把「技術選擇」連結到「控制範圍」，是這類架構判斷的核心。

**面試回答方式**：給四種做法與各自的取捨。核心加分點是提煉規律：**精確度與透明度是對立的**——越透明越不需要客戶端配合但越不準，越精確越需要整合，所以選擇取決於「你能控制客戶端嗎」。收在推論：大型應用的 App 往往有自己的調度邏輯，因為它們能控制客戶端從而突破精確度上限，而把技術選擇連結到控制範圍是這類判斷的核心。

### 什麼是 BGP 劫持？怎麼防？

**核心答案**：**一個 AS 宣告了不屬於它的 IP 前綴**——於是部分網際網路的流量被導向它。可能是惡意的（竊聽、釣魚、竊取加密貨幣）也可能是誤設（設定錯誤導致的意外）。**防護分兩側**：作為前綴的擁有者——發布 RPKI 的 ROA（宣告哪個 AS 有權宣告你的前綴）；作為 ISP——驗證收到的宣告（RPKI 驗證加上前綴過濾）。

**詳細解析**：「更具體的前綴優先」是劫持有效的機制原因：BGP 的路由選擇偏好更長的前綴——**於是宣告一個 /24 能蓋過合法的 /16**。這讓劫持者不需要「贏過」原擁有者，只需要宣告一個更具體的段。防護的一個實用手段是「自己也宣告最具體的前綴」（**把 /16 拆成多個 /24 宣告**）——於是劫持者必須宣告更長的，而多數 ISP 不接受長於 /24 的宣告。這是一個「用協定的規則保護自己」的技巧。而在應用層面，「假設網路可能被劫持」的防護是 TLS——因為即使流量被導向錯誤的伺服器，攻擊者也無法提供有效的憑證（除非同時攻破憑證體系，而憑證透明度日誌讓那變得可被偵測）。所以「端到端加密」是應對網路層信任問題的根本手段。

**面試回答方式**：給定義與兩側的防護。核心加分點是「更具體的前綴優先」是劫持有效的機制原因——宣告一個 /24 能蓋過合法的 /16，所以劫持者不需要贏過原擁有者，並給出**自己宣告最具體前綴**這個「用協定規則保護自己」的技巧。收在應用層的根本防護：**TLS 讓被劫持的流量無法被冒充**，而憑證透明度讓憑證的濫發可被偵測，所以端到端加密是應對網路層信任問題的根本手段。

### 這些對應用開發者有什麼實際意義？

**核心答案**：**三件事**。知道「網路層有自己的故障模式」——當你的服務在某個地區突然不可達而其他地區正常，可能是路由問題而非你的問題。知道「就近接入是由基礎設施提供的」——選擇 CDN 或雲端區域時，它們的網路品質與對等連接是一個真實的差異點。以及「端到端加密是不可協商的」——因為你無法信任路徑上的任何一跳。

**詳細解析**：「某個地區不可達」的排查是應用開發者最可能遇到的網路層問題：症狀是「一部分使用者連不上，而你在自己的網路上測試一切正常」——這時常規的應用排查完全無效。有用的工具是「從多個地點測試」（**各種線上的全球 ping 與 traceroute 服務**）——它能立刻顯示問題是全球性的還是區域性的。而如果是區域性的，進一步的線索是 traceroute 在哪一跳中斷——如果在你的網路之外，那就是路由或 ISP 的問題，你能做的有限（聯絡供應商、或者透過 CDN 繞過）。這個「先確認問題在誰的範圍內」的步驟，能避免大量在自己的服務上徒勞的排查——而它正是分層排查思路在網路層的應用。

**面試回答方式**：給三件實際意義。核心加分點是展開**「某個地區不可達」的排查**——症狀是一部分使用者連不上而你測試一切正常，常規的應用排查完全無效，有用的是從多個地點測試以確認是全球還是區域性的。收在方法與原則：進一步看 traceroute 在哪一跳中斷，在你的網路之外就是路由或 ISP 的問題，而「先確認問題在誰的範圍內」能避免大量徒勞的排查。
