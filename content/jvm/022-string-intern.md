# 題目

`String.intern()` 做什麼？`new String("a")` 建立幾個物件？intern 在 JDK 6 和 JDK 7+ 的行為有什麼不同？

## 核心答案

`String.intern()` 的作用是——如果字串常數池中已經有一個內容相等的字串,就返回池中那個字串的引用;如果沒有,就把當前字串加入池中(JDK 7+ 是放引用,JDK 6 是複製)並返回。`new String("a")` 通常建立「兩個」物件——一個是字串字面量 "a"(在編譯期就放入字串池),一個是 `new` 在堆上建立的新 String 物件(如果 "a" 之前沒出現過)。JDK 6 的字串池在永久代、intern 沒有時會「複製」字串到池;JDK 7 字串池移到堆後、intern 沒有時直接把「堆中已存在字串的引用」放入池(不複製),更省記憶體。

## 詳細解析

**字串常數池**:JVM 維護的一塊存放字串的區域(JDK 7 起在堆中),用於重複使用相同內容的字串以節省記憶體。字串字面量(如 `"a"`)在編譯期/類別載入時就會被放入池中。

**`new String("a")` 建立幾個物件**:

- 字面量 `"a"` 本身:如果這是程式中第一次出現 "a",編譯期會在字串池中建立一個 "a"(1 個)。
- `new String(...)`:在堆上建立一個新的 String 物件(1 個),它的內容複製自池中的 "a"。
- 所以 `new String("a")` 通常涉及 2 個物件(池中的字面量 + 堆上 new 的)。這也是為什麼 `new String("a") == "a"` 為 false(一個是堆上 new 的,一個是池中的,引用不同)。

**intern() 的行為與 JDK 版本差異**:

- **JDK 6 及之前**:字串池在永久代。呼叫 intern 時,如果池中沒有這個字串,會把字串「複製」一份放進永久代的池,返回這個複製的引用。
- **JDK 7 及之後**:字串池移到堆中。呼叫 intern 時,如果池中沒有這個字串,不再複製,而是直接把「當前這個(堆中已存在的)字串物件的引用」放入池,返回這個引用。這樣更省記憶體(不用複製),但也導致一些經典的 `==` 判斷結果在 JDK 6 和 7 不同的陷阱題。

**經典陷阱題**:

```java
String s = new String("1") + new String("1"); // 堆上得到 "11",此時池中還沒有 "11"
boolean b = s.intern() == s;
// JDK 7+: true(intern 時池中沒有 "11",直接把 s 的引用放入池,所以 s.intern() 返回的就是 s)
// JDK 6:  false(intern 複製了一份 "11" 到永久代池,返回的是複製品,不等於 s)
```

## 面試回答方式

先講 intern 的作用(池中有就返回池中的、沒有就加入)。`new String("a")` 建立幾個物件是高頻考點——講清楚「字面量在池 + new 在堆 = 通常 2 個」並用 `new String("a") == "a"` 為 false 佐證。JDK 6 vs 7 的 intern 行為差異是這題最容易深挖的陷阱——講清楚「JDK 6 複製到永久代池、JDK 7 放堆中已存在的引用」,並能分析那個經典的 `s.intern() == s` 在不同版本結果不同的題。能完整分析這個陷阱,展現你對字串池和版本演進的精確掌握。

## 常見追問

### 為什麼 String s = new String("11") + new String("11") 這個 intern 陷阱在 JDK 6 和 7 結果不同?

**核心答案**:因為 JDK 6 和 7 的 intern 實現不同。這段程式碼中,`new String("1") + new String("1")` 在堆上產生一個內容為 "11" 的 String 物件 s,此時字串池中還沒有 "11"。JDK 7+ 呼叫 `s.intern()` 時,發現池中沒有 "11",就「直接把 s 的引用放入池」,所以 `s.intern()` 返回的就是 s 本身,`s.intern() == s` 為 true。JDK 6 呼叫 intern 時,發現池中沒有,會「複製一份 "11" 到永久代的池」,返回的是這個複製品(位於永久代,和堆上的 s 是兩個物件),所以 `s.intern() == s` 為 false。

**詳細解析**:這個陷阱題完美展示了 intern 版本差異的實際後果。關鍵在於「intern 發現池中沒有這個字串時,是複製(JDK 6)還是放引用(JDK 7+)」。JDK 7 把字串池從永久代移到堆之後,就有條件做這個優化——既然池和 s 都在堆裡,intern 時何必複製?直接把 s 的引用登記到池裡就好,省了一次複製。於是 `s.intern()` 返回的引用就是 s 自己。而 JDK 6 池在永久代、s 在堆,兩者在不同區域,intern 只能把 s 的內容複製一份到永久代池,返回的是永久代裡的複製品,自然不等於堆裡的 s。要注意如果把程式碼改成先出現過字面量 "11"(如 `String x = "11"`),那池裡早就有 "11" 了,intern 直接返回池中那個早有的 "11",結果又不同。這類題的分析要點永遠是——「執行到 intern 這一刻,池裡到底有沒有這個字串?intern 的行為(複製 or 放引用)是什麼?」

**面試回答方式**:完整分析——「s 是堆上 new 出來的 "11"、此時池中無 "11"、JDK 7 的 intern 把 s 引用放入池所以返回 s(true)、JDK 6 複製到永久代所以返回複製品(false)」。強調分析要點「看執行到 intern 時池裡有沒有、intern 是複製還是放引用」,展現你能系統地分析這類陷阱而非死記答案。

### 大量使用 intern() 有什麼風險?

**核心答案**:主要風險是——如果 intern 大量「內容各不相同」的字串(例如把海量的、幾乎不重複的動態字串都 intern),字串池會急劇膨脹,佔用大量記憶體(JDK 6 是撐爆永久代、JDK 7+ 是佔用堆),反而得不償失;而且字串池底層是一個固定大小的雜湊表,存太多字串會導致雜湊衝突加劇、intern 操作變慢。所以 intern 只適合「有大量重複的字串」場景(靠重複使用池中同一份來省記憶體),對「基本不重複」的字串用 intern 是負優化。

**詳細解析**:intern 的價值前提是「重複」——如果很多地方會用到相同內容的字串,把它們 intern 讓大家共享池中的同一份,能節省記憶體(不用每個地方都存一份相同內容)。但如果字串內容基本不重複(如每個使用者的唯一 ID、每個請求的隨機 token),intern 它們不僅省不了記憶體(因為沒有重複可共享),反而把這些一次性的字串都塞進了字串池、讓它們的生命週期被池延長(池化的字串更難被回收),白白撐大字串池。此外,字串池底層是一個 hash table(`StringTable`),它的大小(bucket 數)預設有限(可用 `-XX:StringTableSize` 調),塞入過多字串會導致每個 bucket 的鏈變長、intern 的查找變慢。所以 intern 是一把雙刃劍——用對場景(高重複)能省記憶體,用錯場景(低重複、海量)會撐爆池、拖慢效能。理解這個「取決於重複率」的判斷,展現你知道 intern 該用在哪、不該用在哪。

**面試回答方式**:講出風險「intern 海量不重複的字串會撐大字串池、佔記憶體、且 StringTable 雜湊衝突加劇拖慢 intern」,並點出核心判斷——「intern 只適合高重複場景、低重複時是負優化」。能提到 `-XX:StringTableSize` 這個細節,展現你對 intern 的適用邊界和底層實現都有掌握。

### 字串拼接 "a" + "b" 和變數拼接在物件建立上有什麼不同?

**核心答案**:純字面量的拼接(如 `"a" + "b"`)會被編譯器在「編譯期」直接摺疊成一個字面量 "ab" 放入字串池,執行期不產生任何拼接動作和中間物件;而涉及變數的拼接(如 `s + "b"`,s 是變數)無法在編譯期確定結果,會在「執行期」透過 `StringBuilder`(或 `StringConcatFactory`,JDK 9+)動態拼接,產生 StringBuilder 物件和最終的 String 物件。所以前者零執行期開銷、後者有物件建立開銷。

**詳細解析**:這題連結到 Java 核心的字串題([[../java/003-string-immutability-pool.md]])。核心是「編譯期常數摺疊」——編譯器對於能在編譯時確定結果的純字面量運算,會直接算出結果,`"a" + "b"` 在編譯後就是一個 "ab" 字面量,和你直接寫 `"ab"` 完全一樣,執行期沒有任何拼接。但只要拼接中有一個執行期才能確定的變數,編譯器就無能為力,只能生成執行期的動態拼接程式碼——JDK 8 及之前是 `new StringBuilder().append(...).append(...).toString()`,JDK 9+ 改用 `invokedynamic` + `StringConcatFactory`(更靈活高效)。這也是「迴圈中用 + 拼接字串效能差」的原因——迴圈內每次拼接(含變數)都執行期建立 StringBuilder,應改為迴圈外一個 StringBuilder。理解編譯期摺疊 vs 執行期拼接的區別,能幫你答對「這段拼接建立幾個物件」的題,也指導實務中的字串拼接優化。

**面試回答方式**:講出「純字面量拼接編譯期摺疊成一個字面量、零執行期開銷;含變數拼接執行期用 StringBuilder(JDK 9+ 是 StringConcatFactory)動態拼接、有物件開銷」。能連結到「迴圈中拼接該用 StringBuilder」的實務建議,展現你把編譯器優化和實際效能實踐串起來理解。
