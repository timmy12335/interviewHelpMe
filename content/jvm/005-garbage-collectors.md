# 題目

JVM 有哪些主要的垃圾收集器？它們的演進脈絡和適用場景是什麼？

## 核心答案

主要收集器按演進：Serial（單執行緒、STW，適合小型應用）→ Parallel Scavenge/Parallel Old（多執行緒並行，追求吞吐量，JDK 8 預設）→ CMS（Concurrent Mark Sweep，追求低停頓、並發標記，但有碎片問題，已被淘汰）→ G1（Garbage First，把堆分成 Region、可預測停頓時間，JDK 9+ 預設）→ ZGC/Shenandoah（追求亞毫秒級停頓，適合超大堆）。演進的主線是「從高吞吐量逐步轉向低延遲（短停頓）」以應對越來越大的堆和越來越嚴格的延遲要求。

## 詳細解析

**Serial / Serial Old**：單執行緒收集，收集時完全 STW。簡單高效（沒有執行緒切換開銷），適合單核心、小記憶體的環境（如客戶端應用）。是最古老的收集器。

**Parallel Scavenge / Parallel Old**：多執行緒並行收集（多個 GC 執行緒同時工作縮短 STW），目標是「吞吐量」（應用運行時間 / 總時間）。適合後台運算型、對停頓不太敏感但要求高吞吐的批次處理。JDK 8 的預設收集器。

**CMS（Concurrent Mark Sweep）**：第一個真正意義的並發收集器，目標是「最短停頓」。它讓「並發標記」和「並發清除」與應用執行緒同時進行，只在「初始標記」和「重新標記」做短暫 STW。缺點是——用標記清除演算法會產生碎片、並發階段佔用 CPU 降低吞吐、且有「並發模式失敗」退化成 Full GC 的風險。JDK 9 起被標記為 deprecated、JDK 14 移除。

**G1（Garbage First）**：JDK 9 起的預設收集器。它打破了傳統的連續分代——把堆劃分成許多大小相等的 Region，每個 Region 可以扮演 Eden、Survivor 或 Old 的角色。G1 會優先回收「垃圾最多、回收性價比最高」的 Region（Garbage First 的由來），並能根據使用者設定的「目標停頓時間（`-XX:MaxGCPauseMillis`）」來控制每次回收的 Region 數量，實現「可預測的停頓時間」。兼顧了吞吐和低延遲，適合大堆（幾 GB 到幾十 GB）。

**ZGC / Shenandoah**：追求極致低延遲的新一代收集器，透過「著色指標（colored pointers）」、「讀屏障」、「並發整理」等技術，把 STW 停頓壓到亞毫秒級（不隨堆大小增長），適合超大堆（TB 級）和對延遲極度敏感的服務。ZGC 在 JDK 15 轉正、JDK 21 支援分代。

## 面試回答方式

用「演進脈絡」串起所有收集器最能展現理解——從 Serial（單執行緒）到 Parallel（多執行緒高吞吐）到 CMS（並發低停頓）到 G1（Region 化、可預測停頓）到 ZGC（亞毫秒級）。核心要抓住這條主線——「從追求吞吐量逐步轉向追求低延遲，以應對越來越大的堆」。每個收集器點出它的關鍵特徵和適用場景即可，不用鉅細靡遺。特別要能講清楚 G1 的創新（Region 化、Garbage First、可設定目標停頓），因為它是現在的預設收集器，最常被深入追問。

## 常見追問

### CMS 為什麼被淘汰？G1 相比它有什麼改進？

**核心答案**：CMS 被淘汰主要因為三個問題——用標記清除演算法會產生記憶體碎片（碎片累積到無法分配大物件時會退化成一次 STW 很長的 Full GC）、並發階段佔用 CPU 降低應用吞吐、以及「並發模式失敗（concurrent mode failure）」的風險（老年代在並發回收完成前就被填滿，被迫退化成 Serial Old 的 STW Full GC）。G1 的改進是——用 Region 化 + 標記整理式的回收消除了碎片問題、能設定可預測的目標停頓時間、且回收策略更智慧（優先回收垃圾最多的 Region）。

**詳細解析**：CMS 的核心矛盾是「為了低停頓用了並發標記清除，但標記清除的碎片和並發的不確定性反而帶來新問題」。碎片問題導致它必須偶爾做一次代價高昂的整理式 Full GC，這次 Full GC 的長停頓抵銷了平時低停頓的優勢。並發模式失敗則是因為 CMS 並發回收老年代的同時應用還在往老年代放物件，如果回收速度跟不上分配速度，老年代滿了就只能緊急 STW。G1 用完全不同的架構解決這些——Region 化讓它可以「部分回收」（每次只回收一部分 Region 而非整個老年代），回收時把存活物件複製到空 Region 實現了整理（消除碎片），並透過統計每個 Region 的回收價值和成本來在「目標停頓時間」內選擇回收哪些 Region，讓停頓可控可預測。所以 G1 既避免了 CMS 的碎片和 Full GC 退化，又保持了低停頓，成為新的預設。

**面試回答方式**：列出 CMS 的三個問題（碎片、佔 CPU、並發模式失敗），並對應說明 G1 如何用 Region 化和可預測停頓來改進。能講出「CMS 的碎片問題導致它偶爾要做長停頓 Full GC、反而抵銷低停頓優勢」這個核心矛盾，展現你理解 CMS 為何被取代的深層原因。

### G1 的 Region 化設計帶來哪些好處？

**核心答案**：Region 化把堆劃分成許多大小相等的小區塊（每塊可扮演 Eden/Survivor/Old 角色），帶來幾個好處——一是實現「可預測的停頓時間」（可以只回收一部分 Region，用回收 Region 的數量來控制單次 GC 的停頓長度）；二是「優先回收價值最高的 Region」（統計每個 Region 的垃圾比例，優先回收垃圾多的，用最小的代價回收最多的垃圾）；三是回收時把存活物件複製到其他空 Region，天然實現了整理、消除碎片；四是打破了傳統分代必須是連續大塊記憶體的限制，管理更靈活。

**詳細解析**：傳統收集器把新生代、老年代作為連續的大塊記憶體整體處理，導致 GC 要嘛回收整個新生代、要嘛回收整個老年代，停頓時間難以控制（堆越大停頓越長）。G1 的 Region 化把堆拆成幾千個小區塊後，GC 可以「挑選」要回收哪些 Region——它維護每個 Region 的回收成本和能回收的垃圾量，然後在使用者設定的目標停頓時間預算內，貪心地選出「性價比最高」的一組 Region 來回收（這就是 Garbage First 的字面意思：優先回收垃圾最多的）。這種「可挑選、可部分回收」的能力，讓 G1 能把單次停頓控制在目標範圍內，代價是需要額外的資料結構（如 Remembered Set 記錄跨 Region 引用）和一些吞吐開銷。理解 Region 化是理解 G1「可預測停頓」這個核心賣點的關鍵。

**面試回答方式**：講出 Region 化的幾個好處（可預測停頓、優先回收高價值 Region、複製消除碎片、管理靈活），並解釋核心機制——「把堆拆成小塊後可以挑選性價比最高的一部分來回收，用回收數量控制停頓」。能點出 Garbage First 的字面含義（優先回收垃圾最多的），展現你真正理解這個收集器名字背後的設計思想。

### ZGC 是怎麼做到停頓時間不隨堆大小增長的？

**核心答案**：ZGC 透過「著色指標（colored pointers）」和「讀屏障（load barrier）」等技術，把幾乎所有的 GC 工作（包括最耗時的並發標記和並發整理/轉移物件）都做成與應用執行緒並發進行，只在少數幾個必須的同步點做極短暫的 STW（這些 STW 只做固定的、與堆大小無關的少量工作，如掃描 GC Roots）。因為耗時的部分都並發化了、STW 的部分又是固定的少量工作，所以停頓時間能穩定在亞毫秒級、不隨堆變大而增長。

**詳細解析**：傳統收集器的停頓時間往往和堆大小、存活物件數量正相關（要掃描/移動的東西越多、停頓越長）。ZGC 的突破在於把「標記」和「物件轉移（整理）」這兩個最耗時、傳統上需要 STW 的階段都做成並發的。實現這一點的關鍵是「著色指標」——它在 64 位元指標的高位元中存入幾個標記位元（記錄物件的 GC 狀態），配合「讀屏障」（應用每次讀取物件引用時執行一小段檢查程式碼），讓 GC 能在應用讀取到一個「正在被移動的物件」時，即時把引用修正到物件的新位址（這叫「指標自癒」）。這樣物件的移動就能和應用並發進行而不出錯。因為這些機制，ZGC 的 STW 只剩下「掃描 GC Roots」等少量固定工作，停頓時間與堆大小解耦，能穩定在亞毫秒級，代價是讀屏障帶來的一些吞吐開銷和著色指標佔用的位址空間。

**面試回答方式**：講出核心技術（著色指標 + 讀屏障實現並發標記和並發轉移物件），並解釋為什麼停頓不隨堆增長（耗時部分並發化、STW 只剩固定的少量工作）。能提到「指標自癒（讀屏障修正被移動物件的引用）」這個關鍵機制，展現你對這個新一代收集器的原理有超越「它很快」的深入理解，是很強的加分回答。
