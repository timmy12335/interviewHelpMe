# 題目

一個類別從被載入到可以使用，經歷哪些階段？各階段做什麼？

## 核心答案

類別的生命週期包括：載入（Loading）、連結（Linking，又分驗證 Verification、準備 Preparation、解析 Resolution）、初始化（Initialization），之後才是使用和卸載。載入是把類別的位元組碼讀入並生成 Class 物件；驗證檢查位元組碼的合法性；準備為靜態變數分配記憶體並設為預設值（零值）；解析把符號引用轉為直接引用；初始化執行類別建構器 `<clinit>`（給靜態變數賦真正的值、執行靜態程式碼區塊）。

## 詳細解析

**1. 載入（Loading）**：透過類別的全限定名取得定義它的位元組碼（可以來自 class 檔、jar、網路、動態生成等），把位元組碼載入到方法區，並在堆中生成一個代表這個類別的 `java.lang.Class` 物件，作為存取這個類別各種資訊的入口。

**2. 連結（Linking）**：

- **驗證（Verification）**：確保載入的位元組碼符合 JVM 規範、不會危害虛擬機器安全（如檢查魔數、版本號、常數池、位元組碼指令的合法性等）。這是保證安全的重要環節。
- **準備（Preparation）**：為類別的**靜態變數**在方法區分配記憶體，並設定為**預設零值**（int 為 0、引用為 null、boolean 為 false）。注意——這裡設的是零值，不是程式碼中寫的初始值。例如 `static int x = 10`，準備階段 x 是 0，賦值為 10 是在初始化階段。（`static final` 常數例外，準備階段就直接賦值。）
- **解析（Resolution）**：把常數池中的「符號引用」（用符號描述的引用，如類別名、方法名字串）替換成「直接引用」（指向記憶體位址的指標）。

**3. 初始化（Initialization）**：執行類別建構器 `<clinit>()` 方法——這是編譯器自動收集類別中所有靜態變數的賦值動作和靜態程式碼區塊，合併生成的方法。到這一步，靜態變數才被賦予程式碼中寫的真正初始值，靜態程式碼區塊才被執行。JVM 保證 `<clinit>()` 在多執行緒下只會被執行一次且執行緒安全（靠類別載入鎖）。

**觸發初始化的時機（主動引用）**：new 一個實例、存取或設定靜態變數（非 final 常數）、呼叫靜態方法、反射呼叫、初始化子類別時先初始化父類別、作為程式入口的主類別等。

## 面試回答方式

按「載入 → 連結（驗證/準備/解析）→ 初始化」的順序講，這是這題的骨架。每個階段講清楚做什麼——重點是「準備階段設零值、初始化階段才賦真正的值」這個容易考的細節（可以用 `static int x = 10` 在準備階段是 0 來佐證）。以及「`<clinit>` 由編譯器收集靜態賦值和靜態區塊生成、JVM 保證只執行一次且執行緒安全」，這個連結到單例模式的靜態內部類別寫法（見 Java 核心 DCL 題）。能講出這些細節而非只列階段名稱，展現你真正理解每個階段的作用。

## 常見追問

### 準備階段和初始化階段對靜態變數的處理有什麼區別？

**核心答案**：準備階段為靜態變數分配記憶體並設定「零值」（如 `static int x = 10` 此時 x 是 0，`static String s = "hi"` 此時 s 是 null）；初始化階段執行 `<clinit>()`，才把靜態變數賦予程式碼中寫的「真正初始值」（x 變成 10、s 變成 "hi"）。例外是 `static final` 修飾的編譯期常數，在準備階段就直接被賦予最終值（因為它是編譯期就能確定的常數）。

**詳細解析**：這個區別是類別載入很愛考的細節。理解它的關鍵是——準備階段只負責「分配空間、給一個安全的預設值」，這是為了保證變數在被賦真正的值之前有一個確定的初始狀態（不會是隨機的髒資料）；真正的賦值邏輯（可能涉及方法呼叫、運算）留到初始化階段的 `<clinit>` 執行。`static final` 常數的例外是因為——編譯期常數（如 `static final int X = 10`）的值在編譯時就確定並被放入常數池，準備階段可以直接用這個確定的值，不需要等到初始化。但如果是 `static final` 但值要執行期才能確定（如 `static final int X = compute()`），那它仍然要到初始化階段才賦值。理解這個區別能幫你答對「某個靜態變數在某個時刻的值是什麼」這類陷阱題。

**面試回答方式**：用「準備設零值、初始化賦真值」的對比回答，並用 `static int x = 10` 在準備階段是 0 這個具體例子佐證，再補上「static final 編譯期常數在準備階段就賦值」的例外，展現你對這個常考細節的精確掌握。

### 什麼情況會觸發類別的初始化？什麼情況不會？

**核心答案**：會觸發初始化的「主動引用」包括——new 實例、存取/設定非 final 的靜態變數、呼叫靜態方法、反射（如 `Class.forName`）、初始化子類別會先觸發父類別初始化、JVM 啟動時的主類別。不會觸發初始化的「被動引用」包括——透過子類別存取父類別的靜態變數（只初始化父類別）、定義類別陣列（`new SomeClass[10]` 不初始化 SomeClass）、存取類別的 `static final` 編譯期常數（因為常數在編譯期已放入呼叫方的常數池，不需要初始化定義它的類別）。

**詳細解析**：區分「主動引用（觸發初始化）」和「被動引用（不觸發）」是理解類別載入時機的關鍵。核心原則是——只有「真正需要用到類別的初始化結果（靜態變數的真值、靜態區塊的副作用）」時才會觸發初始化。幾個經典的被動引用陷阱：一是 `static final` 常數，例如 `System.out.println(SomeClass.CONST)`，如果 CONST 是編譯期常數，編譯時這個值就被直接內聯到呼叫方的位元組碼裡了，執行時根本不會用到 SomeClass，自然不初始化它；二是類別陣列 `new SomeClass[10]` 只是建立了一個陣列物件（型別是 `[LSomeClass`），並沒有用到 SomeClass 本身，所以不初始化；三是子類別存取繼承來的父類別靜態變數，只會初始化真正定義該變數的父類別，不初始化子類別。這些陷阱常出現在筆試的「輸出什麼」題目中。

**面試回答方式**：分別列出主動引用（觸發）和被動引用（不觸發）的情況，並重點講幾個被動引用陷阱（static final 常數內聯、類別陣列、子類別存取父類別靜態變數）。能舉出這些具體陷阱，展現你對類別初始化時機的理解足以應對筆試的輸出陷阱題。

### `<clinit>()` 和 `<init>()` 有什麼區別？

**核心答案**：`<clinit>()` 是「類別建構器」——由編譯器收集類別中所有靜態變數的賦值動作和靜態程式碼區塊合併而成，在類別初始化階段執行、每個類別只執行一次、由 JVM 保證執行緒安全。`<init>()` 是「實例建構器」——對應類別的建構子，在每次 new 一個實例時執行、每建立一個物件執行一次、負責實例變數的初始化和建構子邏輯。簡言之——`<clinit>` 初始化「類別層級的靜態狀態」（一次），`<init>` 初始化「每個物件的實例狀態」（多次）。

**詳細解析**：兩者名字相似但層級不同。`<clinit>`（class init）是類別級的，處理 static 的東西，在類別第一次被主動使用時觸發一次，JVM 用類別載入鎖保證即使多執行緒同時觸發也只執行一次——這正是「靜態內部類別持有者模式」實現執行緒安全單例的底層依據（見 Java 核心 [[022-double-checked-locking-singleton.md]]）。`<init>`（instance init）是實例級的，對應建構子，每次 new 都執行，它會先呼叫父類別的 `<init>`、再執行實例變數初始化和實例程式碼區塊、最後執行建構子本體。執行順序上——一個類別首次使用時，先執行 `<clinit>`（且父類別的 `<clinit>` 先於子類別）；之後每次 new 實例執行 `<init>`。理解這兩者的區別和執行順序，能幫你答對「靜態區塊、實例區塊、建構子的執行順序」這類經典題。

**面試回答方式**：用「類別級 vs 實例級」「一次 vs 多次」的對比清楚區分兩者，並點出 `<clinit>` 的執行緒安全保證是靜態內部類別單例的依據、`<init>` 涉及父類別建構子和實例初始化的順序。能連結到「靜態區塊/實例區塊/建構子執行順序」這個經典考點，展現你把類別載入和物件建立的知識串起來了。
