# 題目

Redis 有哪些基本資料類型？各自的特點和典型應用場景是什麼？

## 核心答案

Redis 有五種基本資料類型：**String**（字串，最基礎可存文字/數字/二進位，用於快取、計數器、分散式鎖（Distributed Lock））、**Hash**（雜湊，欄位-值的映射，適合存物件）、**List**（列表，有序可重複，用於訊息佇列（Message Queue）、最新列表）、**Set**（集合，無序不重複，用於去重、共同好友等交併差集運算）、**ZSet/Sorted Set**（有序集合，每個元素關聯一個分數並按分數排序，用於排行榜、延遲佇列）。此外還有一些進階類型——Bitmap（位圖，用於簽到/布林統計）、HyperLogLog（基數統計，估算大量元素的去重數量）、Geo（地理位置）、Stream（訊息佇列）。

## 詳細解析

**String（字串）**：

- 最基本的類型，一個 key 對應一個 value，value 可以是文字、數字、或二進位資料（最大 512MB）。
- 應用——快取（存序列化的物件/頁面）、計數器（`INCR`/`DECR` 原子地加減，用於瀏覽量、庫存）、分散式鎖（`SET key value NX EX`）、分散式 session。

**Hash（雜湊）**：

- 一個 key 對應多個「欄位-值」對，類似一個小的 map。
- 應用——存物件（如一個使用者的多個屬性用一個 Hash，比用多個 String key 更省記憶體、也能單獨讀寫某個欄位）。

**List（列表）**：

- 有序、可重複的字串列表，可以從兩端 push/pop。
- 應用——簡單的訊息佇列（`LPUSH` + `BRPOP` 阻塞消費）、最新列表（如最新的 N 條動態，`LPUSH` 加新的、`LTRIM` 保留前 N 個）、堆疊/佇列。

**Set（集合）**：

- 無序、不重複的字串集合，支援交集、併集、差集運算。
- 應用——去重（如記錄不重複的 UV）、標籤、共同好友（兩個使用者好友集合的交集）、抽獎（`SRANDMEMBER` 隨機取）。

**ZSet（有序集合）**：

- 每個元素關聯一個「分數（score）」，元素按分數排序，既不重複又有序。
- 應用——排行榜（分數是積分/銷量，按分數排序取 top N）、延遲佇列（分數是執行時間戳、取到期的）、範圍查詢（按分數區間取元素）。

## 面試回答方式

按五種類型逐一講——每種說清楚「特點 + 典型應用場景」，這是這題的關鍵（光說類型名沒用，要能對應到實際用途）。重點記住幾個經典對應——String 做計數器/分散式鎖、Hash 存物件、List 做訊息佇列/最新列表、Set 做去重/共同好友、ZSet 做排行榜。能主動提幾個進階類型（Bitmap 簽到、HyperLogLog 基數統計、Geo 地理位置、Stream 訊息佇列）是加分。能為每種類型舉出恰當的應用場景，展現你不只知道有哪些類型，還知道實際怎麼用。

## 常見追問

### 為什麼 ZSet（有序集合）特別適合做排行榜？

**核心答案**：因為 ZSet 天生就是「按分數排序的集合」——每個元素關聯一個分數（score），Redis 內部自動維護元素按分數的有序性，這完美契合排行榜「按某個指標（積分、銷量、時間）排序、取前 N 名」的需求。用 ZSet 做排行榜——`ZADD` 更新某個成員的分數（如玩家得分）、`ZREVRANGE key 0 9 WITHSCORES` 直接取分數最高的前 10 名及其分數、`ZREVRANK` 查某個成員的排名，這些操作都是 Redis 內建的、高效的（底層跳躍表 + 雜湊表，見 [[022-skiplist.md]]），不用自己排序。

**詳細解析**：排行榜的核心需求是「維護一組『成員 + 分數』、能按分數排序、能高效地取排名靠前的、能查某成員的排名、能更新某成員的分數」——ZSet 對這些需求全都有直接、高效的原生支援。用其他方式做排行榜會很麻煩——用資料庫 `ORDER BY` 排序在資料量大、更新頻繁時效能差且有壓力；自己在應用層維護排序又複雜。ZSet 則把「有序」這件事交給 Redis 底層處理（跳躍表保證了插入、刪除、範圍查詢都是 O(log n)，雜湊表保證按成員查分數是 O(1)），你只需簡單的命令就能完成排行榜的所有操作。典型的即時排行榜——遊戲積分榜、電商銷量榜、熱門文章榜——都用 ZSet 實現，`ZADD` 更新分數（如玩家每次得分後更新）、`ZREVRANGE` 取榜單、`ZINCRBY` 增量更新分數。理解 ZSet 為什麼適合排行榜（有序性是內建的、操作都是原生高效的），展現你理解資料結構和應用場景的匹配。

**面試回答方式**：講出「ZSet 天生按分數排序、契合排行榜『按指標排序取 top N』的需求」，並列出關鍵操作（ZADD 更新分數、ZREVRANGE 取前 N、ZREVRANK 查排名）。能點出「底層跳躍表+雜湊表保證這些操作高效」，展現你理解資料結構和場景的匹配。

### 用 Hash 存物件和用多個 String key 存物件的各個欄位，有什麼區別？

**核心答案**：用 Hash 存物件（一個 key、多個欄位）相比用多個 String key（每個欄位一個 key）——優點是：（1）更省記憶體（Hash 在欄位少時用緊湊的編碼、且省去了多個 key 的開銷）；（2）更好管理（一個物件就一個 key，能整體操作、整體設過期、整體刪除）；（3）能單獨讀寫某個欄位（`HGET`/`HSET`）也能一次取全部（`HGETALL`）。缺點是——Hash 不能給「單個欄位」單獨設過期時間（過期只能設在整個 key 上），而多個 String key 可以各自設不同的過期。所以——欄位屬於同一個物件、要整體管理、想省記憶體，用 Hash；如果各欄位需要獨立的過期時間，才考慮多個 String。

**詳細解析**：這是一個實務中常見的資料結構選型問題。假設要存一個使用者物件（有 name、age、email 等欄位）——方案 A 用一個 Hash（key 是 `user:1001`，欄位是 name/age/email）；方案 B 用多個 String（`user:1001:name`、`user:1001:age`、`user:1001:email`）。Hash 的優勢——記憶體上，Redis 對欄位不多的 Hash 用 ziplist/listpack 這種緊湊編碼，比多個獨立 String key（每個 key 都有自己的字典項、過期字典項等開銷）省很多記憶體；管理上，一個物件就一個 key，`DEL user:1001` 就刪掉整個物件、`EXPIRE user:1001` 給整個物件設過期，而多個 String 要一個個處理；操作上`HGET user:1001 name` 取單欄位、`HGETALL user:1001` 取全部都很方便。多個 String 的唯一優勢是「每個欄位能有獨立的過期時間」（因為過期是 key 級別的、Hash 的欄位共用一個 key 的過期）——但這種需求較少見。所以絕大多數「存物件」的場景，Hash 是更好的選擇。理解這個選型，展現你能根據需求（記憶體、管理、過期粒度）選對資料結構。

**面試回答方式**：講出「Hash 存物件的優勢——省記憶體（緊湊編碼、省 key 開銷）、好管理（一個 key 整體操作/過期/刪除）、能單獨或整體讀寫欄位；缺點是不能給單個欄位設獨立過期」。給出選型準則——「同一物件整體管理用 Hash、各欄位需獨立過期才用多個 String」。展現你能根據需求選對資料結構。

### Redis 的 String 類型底層一定是簡單的字串嗎？

**核心答案**：不是。Redis 的 String 底層根據內容用不同的編碼——如果 value 是「能用 long 表示的整數」，會用 `int` 編碼（直接存整數，省空間且便於 INCR 等數字操作）；如果是「較短的字串」（44 位元組以內），用 `embstr` 編碼（嵌入式字串，一次記憶體分配，適合短字串）；如果是「較長的字串」，用 `raw` 編碼（獨立分配的 SDS 結構）。而且 Redis 的字串不是 C 語言的原生字串，而是自己實現的 SDS（Simple Dynamic String，簡單動態字串），有記錄長度、預分配空間、二進位安全等優點。

**詳細解析**：這題揭示了「Redis 的 String 遠比表面複雜」。首先，Redis 不用 C 的原生字串（以 `\0` 結尾的字元陣列），而是自己實現了 SDS——它額外記錄了字串長度（`len`）和已分配空間（`alloc`），帶來幾個好處：獲取長度是 O(1)（不用像 C 那樣遍歷到 `\0`）、二進位安全（能存包含 `\0` 的二進位資料如圖片，因為靠 len 判斷結束而非 `\0`）、且透過預分配和惰性釋放減少了頻繁修改字串時的記憶體重新分配。其次，String 的編碼會根據內容自動選擇——純整數用 int 編碼（`SET n 123` 底層存的是整數 123 而非字串 "123"，這也是為什麼能對它 `INCR`）、短字串用 embstr（結構和字串內容在一塊連續記憶體，分配和釋放各只要一次）、長字串用 raw（結構和內容分開分配）。這些底層優化讓 String 既省記憶體又高效。理解 String 底層的 SDS 和多種編碼，展現你對 Redis 資料結構的理解深入到了實現層面（也連結到下一題的底層編碼）。

**面試回答方式**：講出「String 底層不是 C 原生字串、而是 SDS（記錄長度、二進位安全、預分配）」，並說明編碼會按內容自動選（整數用 int、短字串用 embstr、長字串用 raw）。能點出「int 編碼讓 INCR 高效、SDS 讓取長度 O(1) 且二進位安全能存圖片」，展現你對 String 底層實現的深入理解，自然銜接到底層編碼的話題。
