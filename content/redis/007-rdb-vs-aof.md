# 題目

RDB 和 AOF 有什麼區別？該怎麼選？什麼是混合持久化？

## 核心答案

RDB 是「全量資料的二進位快照」（定期生成）、AOF 是「寫命令的日誌」（持續追加）。核心區別——RDB 檔案緊湊、恢復快、對效能影響小，但會丟失兩次快照之間的資料；AOF 資料安全性高（最多丟 1 秒）、但檔案大、恢復慢。選擇——對資料安全要求高用 AOF、追求恢復速度和備份用 RDB、大多數生產環境「兩者都開」（互補）。「混合持久化」（Redis 4.0+）是兩者的結合——AOF 重寫時，把「當前資料的 RDB 快照」作為新 AOF 的前半部分（緊湊、恢復快）、之後的增量寫命令以 AOF 格式追加（資料安全），兼得 RDB 的恢復速度和 AOF 的資料安全，是現在推薦的方式。

## 詳細解析

**RDB vs AOF 對比**：

| 面向 | RDB | AOF |
|------|-----|-----|
| 內容 | 全量資料的二進位快照 | 寫命令的日誌 |
| 檔案大小 | 緊湊、小 | 較大（記錄每個寫命令） |
| 恢復速度 | 快（直接載入快照） | 慢（重放所有命令） |
| 資料安全 | 會丟（兩次快照之間） | 高（最多丟 1 秒，everysec） |
| 對效能影響 | fork 時短暫卡頓 | 每個寫命令要記錄，且 fsync 有開銷 |
| 適合 | 備份、災難恢復 | 資料完整性要求高 |

**該怎麼選**：

- **只用 RDB**——能接受丟失幾分鐘資料、追求恢復速度和備份便利（如純快取場景）。
- **只用 AOF**——對資料安全要求高、不能丟太多資料。
- **兩者都開（推薦）**——生產環境常同時啟用：AOF 保證資料安全（恢復時優先用 AOF，因為它更完整）、RDB 作為備份和快速恢復的手段。

**混合持久化（Redis 4.0+，推薦）**：

- 動機——RDB 恢復快但丟資料多、AOF 安全但恢復慢，能不能兼得？
- 做法——開啟 `aof-use-rdb-preamble yes`（Redis 5.0+ 預設開啟）後，AOF 重寫時生成的新 AOF 檔案是「混合格式」：檔案的「前半部分」是「重寫那一刻的全量資料的 RDB 格式快照」（緊湊、恢復快）、「後半部分」是「重寫之後產生的增量寫命令的 AOF 格式」（保證後續資料的安全）。
- 好處——恢復時，先快速載入前半的 RDB 快照（快）、再重放後半的少量增量命令（安全），兼得了 RDB 的恢復速度和 AOF 的資料安全。這是現在推薦的持久化方式。

## 面試回答方式

先用對比表講清 RDB 和 AOF 的核心區別（快照 vs 命令日誌、緊湊快 vs 安全、丟資料多 vs 少）。選型講「純快取可只 RDB、要安全用 AOF、生產常兩者都開」。混合持久化是這題的加分重點——講清「動機是兼得 RDB 恢復快和 AOF 安全、做法是 AOF 重寫時前半用 RDB 快照後半用 AOF 增量、恢復時先載入 RDB 再重放少量增量」，並點出「這是 Redis 5.0+ 預設、現在推薦的方式」。能講出混合持久化如何取兩者之長，展現你了解 Redis 持久化的現代最佳實踐。

## 常見追問

### 如果 RDB 和 AOF 同時開啟，Redis 重啟時用哪個恢復？

**核心答案**：如果同時開啟了 RDB 和 AOF，Redis 重啟時「優先使用 AOF」來恢復資料。原因是——AOF 通常比 RDB 更完整、更新（AOF 持續記錄每個寫命令、最多丟 1 秒；RDB 是定期快照、可能丟幾分鐘），所以用 AOF 恢復能得到更完整的資料。只有在「沒有開啟 AOF」或「AOF 檔案不存在」時，才用 RDB 恢復。所以同時開啟時，RDB 主要作為「備份和快速的災難恢復手段」，日常重啟的恢復由 AOF 負責（保證資料完整）。

**詳細解析**：這個「優先 AOF」的規則體現了「恢復時優先選資料最完整的來源」。理解它的關鍵是回顧兩者的資料完整性——AOF（everysec）最多丟 1 秒資料、且是持續記錄的，所以任何時刻的 AOF 都反映了「幾乎最新」的資料狀態；RDB 是定期快照,兩次快照之間可能有幾分鐘的資料還沒進 RDB。所以宕機重啟時,AOF 裡的資料比 RDB 新、比 RDB 全,用 AOF 恢復自然能得到更完整的結果。Redis 因此設計成「同時開啟時優先用 AOF」——它啟動時檢查:如果 AOF 開啟且 AOF 檔案存在,就用 AOF 恢復;否則才用 RDB。這也回答了「既然優先用 AOF、那還要 RDB 幹嘛」——RDB 的價值在「備份」(定期的 RDB 快照可以異地備份,作為災難恢復的最後防線,且 RDB 檔案小便於傳輸和保存)和「快速恢復的備選」。而如果啟用了混合持久化(前面講的),那 AOF 檔案本身前半就是 RDB 格式,恢復時既快又全,是最優的。理解「優先 AOF」的規則和背後「選最完整來源」的邏輯,展現你理解兩者協同工作的方式。

**面試回答方式**：講出「同時開啟時優先用 AOF 恢復,因為 AOF 更完整更新(最多丟 1 秒 vs RDB 丟幾分鐘)、只有沒 AOF 時才用 RDB」。說明「RDB 此時主要作為備份和災難恢復手段」。能連結到「混合持久化讓 AOF 前半是 RDB 格式、恢復既快又全」,展現你理解兩者協同的方式。

### 純快取場景(資料都能從資料庫重建)還需要持久化嗎?

**核心答案**：要看具體需求,不是絕對。純快取場景(Redis 只存能從資料庫重建的快取資料)理論上可以「不開持久化」——因為即使 Redis 資料全丟,也能從資料庫重新載入,不會真的丟失資料。但實務中通常仍建議「至少開 RDB」,原因是——如果完全不持久化,Redis 重啟後是「空的」,所有請求會瞬間穿透到資料庫(快取雪崩（Cache Avalanche）,見 [[012-cache-avalanche.md]]),可能把資料庫壓垮;而有 RDB 快照,重啟時能快速載入一個「較新的快取狀態」,避免了冷啟動時的快取雪崩。所以純快取場景——如果能承受重啟後的冷啟動壓力(資料庫扛得住),可以不持久化;如果承受不了(資料庫會被穿透壓垮),至少開 RDB 讓重啟後有快取墊底。

**詳細解析**：這題考的是「持久化的價值不只是防止資料丟失、還包括避免冷啟動的雪崩」。純快取場景下,持久化「防止資料丟失」的價值確實不大(資料能從 DB 重建),但它還有一個容易被忽略的價值——「避免重啟後的冷啟動快取雪崩」。想像一個高流量服務,Redis 快取扛著大部分讀請求、資料庫只處理快取未命中的少量請求;如果 Redis 重啟後是空的(沒持久化),那麼重啟瞬間所有請求都快取未命中、全部穿透到資料庫,資料庫瞬間承受平時幾十倍的壓力,很可能被壓垮(這就是快取雪崩的一種)。而如果開了 RDB,重啟時載入最近的快照,快取裡立刻就有大量熱資料,大部分請求還是能命中快取、不穿透到資料庫,平滑度過重啟。所以決策取決於——「資料庫能不能扛住冷啟動時的穿透壓力」:能扛(低流量、或資料庫很強)就可以不持久化省點開銷;扛不住(高流量)就至少開 RDB 讓重啟後有快取墊底。這也提醒——持久化的考量不只是「資料會不會丟」,還要考慮「重啟/故障恢復時的系統穩定性」。理解這個更全面的視角,展現你考慮問題的周全。

**面試回答方式**：講出「純快取理論上可不持久化(資料能從 DB 重建)、但實務常建議至少開 RDB——因為不持久化時重啟後 Redis 是空的、請求全穿透到資料庫可能壓垮它(冷啟動雪崩)、RDB 讓重啟後有快取墊底」。給出決策依據——「資料庫扛得住冷啟動穿透就可不持久化、扛不住就開 RDB」。展現你考慮到「持久化不只防丟資料、還關乎恢復時的系統穩定性」的全面視角。

### 為什麼 AOF 恢復比 RDB 慢?

**核心答案**：因為兩者的恢復方式本質不同——RDB 恢復是「直接載入一個二進位資料快照」,把快照裡的資料結構直接讀進記憶體重建,是一個相對直接、快速的過程;AOF 恢復是「重新執行 AOF 檔案裡的所有寫命令」,相當於把 Redis 從空的狀態、一條條命令重放、一步步還原到最終狀態——如果 AOF 記錄了幾百萬條命令,恢復時就要重新執行這幾百萬條命令(每條都要解析、執行),自然比「直接載入一個快照」慢得多。這也是混合持久化的價值——用 RDB 格式做 AOF 的前半部分,恢復時前半直接載入快照(快)、只重放後半的少量增量命令,大幅加快了 AOF 的恢復。

**詳細解析**：這個速度差異源於「載入結果」vs「重演過程」的本質區別。RDB 記錄的是「資料的最終狀態(快照)」——恢復時 Redis 直接把這個狀態讀進記憶體、重建資料結構,是「一步到位」載入結果。AOF 記錄的是「產生資料的過程(所有寫命令)」——恢復時 Redis 要「重演」整個過程,從空開始把每條命令重新執行一遍,才能得到最終狀態。打個比方——RDB 像「直接給你一張畫好的畫」,AOF 像「給你畫這張畫的所有筆觸步驟、你要重新畫一遍」。當命令數量巨大時(一個運行很久的 Redis 的 AOF 可能有海量命令),重演所有命令的耗時遠超直接載入一個快照。這正是混合持久化解決的問題——它讓 AOF 的前半部分用 RDB 快照格式(恢復時「直接載入畫」),只有後半的少量增量用命令格式(「重演最後幾筆」),這樣恢復時大部分靠快速的快照載入、只重放少量增量命令,兼得了 AOF 的資料安全和接近 RDB 的恢復速度。理解「載入結果 vs 重演過程」的區別,展現你理解兩種持久化恢復機制的本質差異。

**面試回答方式**：講出「RDB 恢復是直接載入資料快照(一步到位載入結果)、AOF 恢復是重放所有寫命令(從空開始重演整個過程、命令多時很慢)」,用「給你畫好的畫 vs 給你所有筆觸讓你重畫」的比喻。能點出「混合持久化用 RDB 做前半、只重放後半少量增量、大幅加快 AOF 恢復」,展現你理解恢復機制的本質差異和混合持久化的價值。
