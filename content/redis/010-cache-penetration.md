# 題目

什麼是快取穿透？怎麼解決？

## 核心答案

快取穿透是指——查詢一個「快取和資料庫中都不存在」的資料，導致每次請求都「穿透」快取、直接打到資料庫。因為資料庫裡也沒有，所以永遠不會被快取（快取只快取查到的結果），於是每次這種查詢都要查一次資料庫。如果有人惡意用大量「不存在的 key」發起請求（如查詢 id=-1、id=999999999 這種不存在的），這些請求全部穿透到資料庫，可能把資料庫壓垮。解決方法主要有兩個——（1）**快取空值**：即使查不到，也把「空結果」快取起來（設一個較短的過期時間），下次同樣的查詢就命中快取的空值、不再查資料庫；（2）**布隆過濾器**：在快取前加一個布隆過濾器，先判斷「這個 key 是否可能存在」，不存在就直接拒絕、不查資料庫。

## 詳細解析

**快取穿透的成因**：正常的快取流程是「先查快取、命中就返回、未命中就查資料庫、把結果寫入快取」。這個流程對「不存在的資料」失效了——因為資料庫裡也沒有,查詢返回空,而空結果通常不會被寫入快取,所以下次同樣的查詢還是「快取未命中→查資料庫→還是空」,每次都穿透到資料庫。如果攻擊者故意用大量不存在的 key 猛發請求,這些請求全部繞過快取直達資料庫,資料庫承受巨大壓力可能崩潰。

**解決方法一：快取空值(Cache Null)**：

- 做法——當查詢資料庫發現「不存在」時,也把這個「空結果」(如一個特殊的空標記)寫入快取,並設一個「較短的過期時間」(如幾分鐘)。這樣下次查同一個 key,快取命中(命中的是空值),直接返回、不再查資料庫。
- 優點——實現簡單。
- 缺點——如果攻擊者用「大量不同的不存在 key」攻擊,會快取大量空值、佔用記憶體(所以空值要設較短過期);且如果這個 key 之後真的有了資料,要注意空值快取的過期/更新(否則短時間內查不到新資料)。

**解決方法二：布隆過濾器(Bloom Filter)**：

- 做法——在快取層前面加一個布隆過濾器,裡面預先存入「所有存在的 key」。查詢時先問布隆過濾器「這個 key 可能存在嗎」——如果布隆過濾器説「不存在」,那就一定不存在,直接返回、不查快取和資料庫;如果説「可能存在」,才繼續走正常的快取/資料庫查詢。
- 優點——能擋住「查詢根本不存在的 key」的請求(尤其對大量不同的不存在 key 的攻擊很有效),且布隆過濾器記憶體效率高。
- 缺點——布隆過濾器有「假陽性」(可能誤判一個不存在的 key 為「可能存在」,但不會把存在的誤判為不存在),所以不能 100% 擋住;且要維護布隆過濾器(把所有存在的 key 加進去、新增資料時同步加入)。

**兩者常結合使用**——布隆過濾器擋住大部分不存在的 key,快取空值處理漏過的少數(布隆過濾器假陽性放進來的)。

## 面試回答方式

先講清楚「快取穿透是什麼」——查詢快取和資料庫都不存在的資料、每次都穿透到資料庫、惡意攻擊可壓垮資料庫。這個定義和「為什麼會穿透」(不存在的結果不會被快取)是關鍵。兩個解法都要講——快取空值(簡單但可能被大量不同 key 攻擊、佔記憶體)、布隆過濾器(能擋大量不存在 key、但有假陽性)。能點出「兩者常結合」以及各自的缺點(空值佔記憶體、布隆有假陽性),展現你不只知道解法還理解它們的權衡。這題和快取擊穿、雪崩容易混淆,要能清楚區分(穿透=查不存在的資料)。

## 常見追問

### 布隆過濾器的原理是什麼？為什麼有假陽性但沒有假陰性？

**核心答案**：布隆過濾器用「一個位元陣列 + 多個雜湊函式」來判斷「一個元素是否可能在集合中」。加入一個元素時——用多個(如 k 個)不同的雜湊函式對這個元素計算出 k 個位置,把位元陣列的這 k 個位置都設為 1。查詢一個元素時——同樣算出 k 個位置,檢查這 k 個位置是否「都為 1」:如果有任何一個是 0,説明這個元素「一定不在集合中」(因為如果加入過,這 k 位都會是 1);如果 k 個都是 1,説明「可能在集合中」(但也可能是其他元素把這些位都設成 1 了、恰好碰上——這就是假陽性)。所以——「都為 1」不能保證一定存在(可能假陽性),但「有 0」一定保證不存在(不會假陰性)。假陰性不可能是因為:一個真的加入過的元素,它的 k 個位置一定都被設為 1 了,查詢時一定都是 1、絕不會漏判。

**詳細解析**：理解布隆過濾器的「有假陽性、無假陰性」是理解它為什麼適合防快取穿透的關鍵。機制上——位元陣列初始全 0,加入元素就把該元素雜湊到的 k 個位置設為 1。查詢時檢查這 k 個位置:全 1 才説「可能存在」、有 0 就説「一定不存在」。為什麼「有 0 就一定不存在」(無假陰性)——因為如果這個元素真的被加入過,它雜湊到的那 k 個位置在加入時「一定都被設成了 1」,不可能後來變回 0(布隆過濾器只加不刪、位只從 0 變 1),所以查詢時這 k 位一定都是 1;反過來,如果查詢時發現有一位是 0,就説明「這個元素從沒被加入過」(否則那位早就是 1 了),所以一定不存在——絕不會把「真的存在的」誤判為「不存在」。為什麼「全 1 也可能不存在」(有假陽性)——因為一個沒被加入的元素,它雜湊到的 k 個位置,可能「恰好都被其他加入過的元素設成了 1」(不同元素的雜湊位置可能重疊),於是查詢它時 k 位都是 1、被誤判為「可能存在」。假陽性率取決於位元陣列大小、雜湊函式個數、已加入元素數量,可以透過調整這些參數控制在很低的水準。這個「無假陰性」特性正是它適合防穿透的原因——它能「確定地擋掉一定不存在的 key」(有 0 就直接拒絕),而它的假陽性(把少數不存在的誤判為可能存在、放進來查一次)只是「漏擋了少數」,不影響正確性(這少數會走正常查詢、查不到就完了,可配合快取空值)。理解這個原理,展現你理解布隆過濾器為什麼是防穿透的利器。

**面試回答方式**：講出原理——「位元陣列 + 多個雜湊函式:加入時把元素雜湊到的 k 個位置設 1、查詢時檢查這 k 位、全 1 説可能存在、有 0 説一定不存在」。解釋「無假陰性(加入過的元素 k 位一定都是 1、絕不漏判)、有假陽性(沒加入的元素可能恰好 k 位都被別人設成 1、誤判為可能存在)」。能點出「無假陰性正是它適合防穿透的原因——能確定擋掉一定不存在的 key」,展現你理解布隆過濾器的原理和適用性。

### 布隆過濾器不能刪除元素，這在防快取穿透時是問題嗎？怎麼辦？

**核心答案**：標準的布隆過濾器確實不能刪除元素(因為一個位可能被多個元素共用、直接把某元素的位清零可能誤刪其他元素),這在「資料會被刪除」的場景是個問題——如果一個 key 對應的資料被刪了,但布隆過濾器裡還留著它(刪不掉),那麼查詢這個已刪除的 key 時,布隆過濾器仍説「可能存在」、放它去查資料庫,失去了攔截作用(但不會出錯,只是這個特定 key 的穿透沒被擋)。解決辦法——(1)用「計數布隆過濾器(Counting Bloom Filter)」,把每個位從「1 bit」擴成「一個計數器」,加入時計數 +1、刪除時 -1,計數為 0 才算不存在,這樣支援刪除(代價是記憶體增大);(2)定期「重建」布隆過濾器(根據當前所有存在的 key 重新構建);(3)如果刪除不頻繁,可以容忍(已刪除的 key 偶爾穿透一下、配合快取空值兜底)。

**詳細解析**：這題考的是布隆過濾器的一個實際限制及應對。標準布隆過濾器「只能加不能刪」的原因是——多個不同的元素可能雜湊到「部分相同的位置」(位共用),如果要刪除元素 A、把 A 雜湊到的位都清零,可能會誤把「元素 B 也用到的位」清零了,導致之後查詢 B 時發現那位是 0、誤判 B「不存在」(產生了假陰性!這破壞了布隆過濾器「無假陰性」的核心保證,是不能接受的)。所以標準布隆過濾器乾脆不支援刪除。在防快取穿透時,如果資料會被刪除,就有前面説的問題——刪掉的 key 在布隆過濾器裡還在、失去對它的攔截。應對——「計數布隆過濾器」是最直接的解法:每個位置不再是 1 bit,而是一個小計數器,加入元素時對應位置 +1、刪除時 -1,查詢時檢查是否「都大於 0」;因為用計數,刪除 A 時只把 A 的位置 -1,不會影響 B(B 的位置計數還大於 0),所以支援刪除且不破壞正確性,代價是記憶體變大(每個位置從 1 bit 變成幾 bit 的計數器)。其他方案——定期根據當前實際存在的所有 key 重建布隆過濾器(適合可以接受週期性重建的場景)、或如果刪除很少就容忍(反正配合快取空值,漏擋的少數已刪 key 穿透一次會被快取空值擋住後續)。理解這個限制和應對,展現你了解布隆過濾器的實務細節。

**面試回答方式**：講出「標準布隆過濾器不能刪除(位共用、清零會誤傷其他元素、破壞無假陰性),在資料會刪除的場景會導致已刪 key 仍被判為可能存在、失去攔截(但不出錯)」。給出解法——「計數布隆過濾器(位改成計數器、支援 +1/-1 刪除、代價是記憶體大)、定期重建、或刪除少時容忍(配合快取空值)」。展現你了解布隆過濾器的實務限制和應對。

### 快取空值時，如果這個 key 之後真的有資料了怎麼辦？

**核心答案**：這是快取空值的一個要注意的點——如果快取了某個 key 的空值(表示「不存在」),但之後這個 key 對應的資料真的被建立了(如一個使用者剛註冊、或一個商品剛上架),那麼在「空值快取還沒過期」的這段時間裡,查詢這個 key 會命中快取的空值、返回「不存在」,查不到剛建立的新資料(資料不一致)。解決辦法——(1)給空值設「較短的過期時間」(如幾分鐘),讓它很快過期、之後就能查到真實資料(用短過期把不一致的時間窗控制得很小);(2)在「建立這個 key 對應的資料」時,主動「刪除或更新這個 key 的空值快取」(如註冊使用者後,主動刪掉之前可能快取的該使用者的空值),讓下次查詢直接查資料庫拿到新資料。實務中常結合——空值設短過期(兜底)+ 資料建立時主動清除空值(及時)。

**詳細解析**：這個問題本質是「快取空值」和「資料後來存在了」之間的一致性問題,和一般的快取一致性問題(見 [[013-cache-consistency.md]])是相通的。快取空值的假設是「這個 key 不存在」,但這個假設可能「後來變了」(key 對應的資料被建立了)。如果不處理,在空值快取的有效期內,新資料查不到(被空值擋住)。兩個解法——「短過期」是「被動兜底」:給空值設一個較短的 TTL(如 5 分鐘),即使不主動處理,最多 5 分鐘後空值過期、就能查到新資料了,把不一致的時間窗限制在可接受範圍。這是最簡單、最基本的保障。「主動清除」是「及時處理」:在「建立該 key 資料」的業務邏輯裡,主動刪掉這個 key 可能存在的空值快取(如 `DEL` 這個 key 的快取),這樣下次查詢就會 miss、去查資料庫、拿到並快取真實的新資料,實現了「資料一建立、空值快取就失效」的及時性。實務中通常「兩者結合」——短過期作為兜底(防止主動清除有遺漏或失敗)、主動清除保證及時性(不用等過期)。這也體現了快取設計的一個通用原則——「用過期做被動兜底 + 用主動失效保及時,雙保險」。理解這個問題和解法,展現你考慮到了快取空值的一致性細節。

**面試回答方式**：講出問題——「快取了空值後、key 對應的資料真的被建立了、在空值快取過期前查詢會命中空值返回不存在、查不到新資料」。給出解法——「空值設短過期(被動兜底、限制不一致窗)+ 建立資料時主動刪除空值快取(及時)、實務兩者結合」。能點出「這是快取一致性問題的一種、用過期兜底+主動失效保及時的通用原則」,展現你考慮到了快取空值的一致性細節。
