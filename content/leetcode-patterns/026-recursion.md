# 題目

用 Java 寫出遞迴的通用寫法（定義、終止條件、遞推關係），示範用「哨兵回傳值」在一次遞迴中同時傳遞兩種資訊，以及用遞迴改寫連結串列結構，並說明它們對應哪些 LeetCode 題目。

## 核心答案

寫遞迴前先確定**三要素**：一是**函式的定義**，用一句話說清楚它接收什麼、回傳什麼；二是**終止條件**，最小的輸入直接回傳；三是**遞推關係**，假設比較小的輸入已經算好，怎麼組出目前的答案。最關鍵的心態是**相信遞迴**：不要在腦中展開每一層，只要定義對、終止條件對、遞推對，結果就是對的。兩個實用技巧：**哨兵回傳值**，用 `-1` 之類不可能出現的值表示「已經失敗」，讓一次後序遞迴同時回傳高度與是否平衡；**遞迴改寫結構**，函式回傳「處理好之後的新頭」，讓上一層把它接上。

## 詳細解析

**範式一，三要素**：以「兩兩交換串列節點」為例。定義：`swapPairs(head)` 回傳交換後的新頭。終止：少於兩個節點就原樣回傳。遞推：交換前兩個，第一個接上「後面已經交換好的部分」。

```java
ListNode swapPairs(ListNode head) {
    if (head == null || head.next == null) return head;   // 終止條件
    ListNode second = head.next;
    head.next = swapPairs(second.next);                    // 相信後面已經處理好
    second.next = head;
    return second;                                         // 新的頭
}
```

**範式二，哨兵回傳值**：判斷平衡二元樹。`height` 回傳子樹高度，但只要任何子樹不平衡就回傳 `-1`，一路往上傳，整體 O(n)。

```java
boolean isBalanced(TreeNode root) { return height(root) != -1; }

private int height(TreeNode node) {
    if (node == null) return 0;
    int l = height(node.left);
    if (l == -1) return -1;                                // 提早結束
    int r = height(node.right);
    if (r == -1 || Math.abs(l - r) > 1) return -1;
    return 1 + Math.max(l, r);
}
```

**範式三，遞迴的記憶化**：遞迴最常見的效能問題是重複計算。爬樓梯的樸素遞迴 `f(n) = f(n-1) + f(n-2)` 是指數時間，加上一個陣列記住算過的答案就變成 O(n)。這是遞迴走向動態規劃的橋梁。

```java
int climbStairs(int n) { return ways(n, new int[n + 1]); }

private int ways(int n, int[] memo) {
    if (n <= 2) return n;
    if (memo[n] != 0) return memo[n];
    return memo[n] = ways(n - 1, memo) + ways(n - 2, memo);
}
```

**快速冪**：`x^n` 也是三要素的好例子，定義、終止（`n == 0` 回傳 1）、遞推（一半的平方），完整寫法見分治頁面。

**複雜度**：遞迴的時間是「呼叫次數乘上每次的工作量」，空間是最大遞迴深度。兩兩交換與平衡樹都是 O(n) 時間、O(n) 或 O(h) 空間；記憶化後的爬樓梯是 O(n)。

**常見錯誤**：一是忘了終止條件或終止條件寫不全（例如只檢查 `head == null`，沒檢查 `head.next`），造成空指標或無限遞迴。二是在遞迴裡重複呼叫同一個子問題，例如平衡樹在每個節點都另外呼叫一次 `height`，變成 O(n²)。三是遞迴深度太大造成 `StackOverflowError`，串列或退化樹長度上萬時要考慮改成迭代。

## 面試回答方式

寫遞迴前，先口頭說出三要素，特別是函式定義那一句。寫完後不要逐層展開追蹤，而是用最小的輸入（空、一個元素、兩個元素）驗證終止條件與遞推。被問到效能時，主動分析是否有重複子問題，以及遞迴深度帶來的堆疊風險。

## 講稿

寫遞迴之前，我會先講清楚三件事。第一是函式的定義，用一句話說它收什麼、回傳什麼。第二是終止條件，最小的輸入直接回傳。第三是遞推關係，假設比較小的問題已經解好了，我怎麼用它組出現在的答案。

最重要的是相信遞迴，不要在腦中一層一層展開。像兩兩交換串列的節點，我定義函式回傳交換後的新頭，少於兩個節點就原樣回傳。否則就交換前兩個，第一個接上後面已經交換好的部分，回傳第二個節點。

還有一個實用的技巧是用不可能出現的值當哨兵。像判斷平衡二元樹，函式回傳高度，但只要有子樹不平衡，就回傳負一一路往上傳，這樣一次走訪就同時知道高度和是否平衡，是線性時間。

另外要注意重複計算，像爬樓梯的遞迴，加上記憶化之後就從指數時間變成線性。

## 常見追問

### 遞迴一定可以改成迭代嗎？

**核心答案**：可以，任何遞迴都能用顯式堆疊模擬呼叫堆疊。尾遞迴（遞迴呼叫是函式最後一個動作）可以直接改成迴圈，不需要堆疊。

**詳細解析**：Java 的 JVM 不做尾呼叫優化，所以即使是尾遞迴，深度太大仍會溢位，需要手動改成迴圈。非尾遞迴（例如後序計算）改迭代需要記錄每一層的狀態，程式會複雜不少，面試中說明思路即可。

**面試回答方式**：說出顯式堆疊與尾遞迴兩種情況，並提到 Java 不做尾呼叫優化。

### 怎麼分析遞迴的時間複雜度？

**核心答案**：畫出遞迴樹，總時間等於所有節點的工作量總和。每層工作量相同就是「層數乘每層工作」；分治型可以套主定理；有重複子問題時，記憶化後的時間等於「不同子問題數乘上每個的工作量」。

**詳細解析**：樸素費氏遞迴的樹有約 φ^n 個節點，所以是指數；記憶化後只有 n 個不同子問題，每個 O(1)，所以是 O(n)。平衡樹的哨兵寫法每個節點只呼叫一次，所以是 O(n)；在每個節點另外算高度則是 O(n log n) 到 O(n²)。

**面試回答方式**：用遞迴樹的觀點說明，並以費氏數列對比記憶化前後。

### 什麼時候用全域變數、什麼時候用回傳值？

**核心答案**：答案可以由子問題的回傳值直接組出時，用回傳值，函式是純粹的、易於推理；回傳值和最終答案不同（例如二元樹直徑）時，用一個欄位記錄全域答案，並在入口重設。

**詳細解析**：也可以用長度為 1 的陣列或一個小物件傳進遞迴，代替類別欄位，避免多次呼叫之間殘留狀態。回傳多個值時，Java 可以回傳 `int[]` 或自訂 `record`。

**面試回答方式**：給出判斷原則，並提到全域變數要在入口重設。
