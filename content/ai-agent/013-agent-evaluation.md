# 題目

評估一個 Agent 系統的整體表現，為什麼會比評估一個單純的問答式大型語言模型**更加困難、更加複雜**？實務上可以從哪幾個不同的面向，去設計一套相對完整的 Agent 評估方法論？

## 核心答案

評估一個 Agent 系統之所以**比評估單純的問答式模型更加困難**，核心原因在於——延續前面（見 [[001-agent-fundamentals.md]]）已經深入討論過的核心特徵——**Agent 涉及一個持續、多輪、且動態的執行過程**，而**不是**像單純的問答式互動那樣只需要評估**單一次回應的品質**。這種**評估對象本身的多維度、多階段性**，讓 Agent 評估需要同時考量幾個**單純問答評估不需要特別考量**的面向——**(1) 最終結果是否正確達成**（這相對較接近傳統問答評估的思路，判斷這個任務最終是否被妥善完成）；**(2) 達成這個結果的『過程』是否合理、有效率**（即使最終結果恰好正確，如果這個過程本身是透過**大量不必要的冗餘步驟、甚至帶有危險的中間嘗試**才僥倖得到這個正確結果，這依然**不是一個值得被稱許的良好表現**）；**(3) 是否具備足夠的穩健性和可靠性**（同樣的任務在**些微不同的情境變化**下是否依然能夠穩定地被妥善完成，而不是**只在某些特定的、剛好被測試到的情境下**才能恰好成功）。實務上設計一套相對完整的 Agent 評估方法論需要**同時涵蓋**這些**不同層次**的評估面向，而不能只單純地聚焦在**「最終結果是否正確」**這**單一個相對表面**的評估指標上。

## 詳細解析

**過程評估——不只是「結果對不對」，還要「過程合不合理」**：這是 Agent 評估相較於傳統問答評估最核心的一個額外面向——因為 Agent 涉及**多輪的決策和行動過程**，評估**這個過程本身的品質**是一個**不能被忽略**的重要面向——具體來說，**過程評估**需要考量幾個具體議題——**是否出現了明顯不必要、多餘的行動步驟**（例如重複地執行相同的查詢、或者繞了一大圈冤枉路才得到一個其實可以更直接取得的結果）；**是否正確地識別、運用了恰當的工具**（如果一個任務明明有一個更恰當的工具可以被直接使用，但 Agent 卻選擇用一個較迂迴、效率較低的替代方式去達成相同的結果，即使最終結果依然正確，這種**過程本身的不理想**也是一個值得被重視的評估面向）；**是否在過程中做出了某些即使最終沒有造成實際負面後果、但本質上屬於高風險、不夠審慎的行動**（這某種程度上呼應了前面（見 [[010-sandbox-code-execution-security.md]]、[[011-human-in-the-loop.md]]）已經深入討論過的安全性考量——即使一個 Agent 這一次恰好僥倖地沒有因為某個高風險行動而造成實際的損害，這種**『恰好僥倖沒出事』**並**不等同於**這個 Agent 的行為模式本身是**值得被信賴、可以被安心持續採用**的）。

**穩健性評估——透過系統性地測試多樣化的情境變化，而不是只依賴單一次的測試結果**：延續前面（見 [[003-planning-task-decomposition.md]]）已經反覆強調的核心認知——**Agent 面對的任務執行路徑本身經常存在不確定性**——這意味著**單純地只測試一種特定的、固定的情境**並**不足以**充分地證明這個 Agent 在**各種不同的、可能遭遇到的實際情境變化**下都能**同樣穩健、可靠地**完成任務。實務上一套完整的 Agent 評估方法論需要**系統性地設計、涵蓋多樣化的測試情境**，包括——**正常的、預期內的典型情境**；**邊界情況**（例如輸入的資料恰好是某種極端、罕見的邊界值）；**故意注入的異常或錯誤情境**（例如前面（見 [[../ai-llm/022-function-calling.md]]）已經討論過的『某一次工具呼叫執行失敗』這種情況，故意去測試這個 Agent 是否能夠**妥善地因應這種非預期的異常**，而不是只測試那些**一切都順利無誤**的理想情境）。只有透過**大量、多樣化的測試情境**去全面地檢視這個 Agent 的表現，才能更加可靠地判斷這個 Agent 系統是否真的具備**足夠的整體穩健性**，而不是只因為它**恰好在某幾個被實際測試到的特定情境下**表現良好，就貿然地斷定它**在所有情境下**都值得被信賴。

**評估 Agent 表現的實務難題——「這個結果到底算不算成功」本身經常不是一個非黑即白的簡單判斷**：一個特別值得被重視的實務難題是——相較於很多傳統的軟體功能測試（通常存在一個相對明確、可以被客觀地做是非判斷的『預期結果』），很多 Agent 需要處理的**真實世界任務**，它的**「最終結果是否算成功」**這件事本身經常**帶有一定程度的模糊性和主觀判斷成分**（例如一個 Agent 被要求去撰寫一份市場分析報告，這份報告寫得『好不好』並沒有一個簡單、明確、可以被直接程式化判定的『正確答案』）。這種**「評估標準本身存在模糊性」**的難題，讓 Agent 評估某種程度上**比評估那些擁有明確、客觀的『對錯』標準**的任務（例如前面（見 [[009-self-correction-reflection.md]]）已經討論過的『執行程式碼是否通過測試』這種相對客觀可驗證的任務）**更加棘手**。實務上因應這種難題的常見做法包括——**針對那些確實存在某種客觀可驗證標準**的任務（例如程式碼是否能通過既定測試）優先採用這種**客觀、可驗證**的評估方式（這呼應了前面（見 [[009-self-correction-reflection.md]]）已經深入討論過的核心原則——重視客觀、可驗證的結果，而非只依靠主觀判斷）；而對於那些**本質上確實帶有主觀判斷成分**的任務，則可能需要依靠**人類評審**（或者運用一個額外的模型作為評審，這某種程度上呼應了前面（見 [[../ai-llm/016-perplexity-evaluation-metrics.md]]）已經討論過的 LLM-as-a-Judge 這類評估手段），依照一套**事先明確定義好的評分準則**去做相對一致、有結構的評分判斷。

## 面試回答方式

先給出Agent評估比單純問答評估更困難的核心原因——「Agent涉及一個持續、多輪、且動態的執行過程，而不是像單純問答互動那樣只需評估單一次回應的品質，這種評估對象本身的多維度、多階段性，讓Agent評估需要同時考量最終結果是否正確達成、達成這個結果的過程是否合理有效率、以及是否具備足夠的穩健性和可靠性這幾個不同層次的面向」。詳細說明過程評估這個核心額外面向——「不只是結果對不對，還要過程合不合理，包括是否出現明顯不必要多餘的行動步驟、是否正確識別運用了恰當工具、是否在過程中做出某些即使最終沒造成負面後果但本質上屬於高風險不夠審慎的行動」。可以補充穩健性評估的重要性——「需要系統性地設計涵蓋多樣化的測試情境，包括正常預期內情境、邊界情況、以及故意注入的異常錯誤情境，才能更可靠判斷這個Agent是否真的具備足夠整體穩健性，而不是只因為它在某幾個特定情境下表現良好就貿然斷定」。可以延伸提到評估標準本身的模糊性難題——「很多Agent需要處理的真實世界任務，最終結果是否算成功這件事本身經常帶有一定程度的模糊性和主觀判斷成分，因應做法是針對確實存在客觀可驗證標準的任務優先採用客觀驗證方式，而對本質上帶有主觀判斷成分的任務則依靠人類評審或LLM-as-a-Judge這類評估手段，依照事先明確定義好的評分準則做相對一致的評分判斷」，展現你對Agent評估這個相對困難議題的多個面向，有系統且深入的理解。

## 常見追問

### 如果一個 Agent 在測試環境裡表現得非常好，但部署到真實的生產環境後表現卻明顯不如測試時，這可能是什麼原因造成的？

**核心答案**：**這種現象經常是因為「測試環境和真實環境之間存在某種重要的分佈落差（Distribution Shift）」**所導致的——具體可能的原因包括——**(1) 測試情境的多樣性不足**：如果前面（見核心答案和詳細解析）已經深入討論過的**穩健性測試**本身並沒有**充分涵蓋到真實世界實際上會遭遇到的多樣化情境**（例如測試時使用的資料可能都是一些相對乾淨、規整的範例，但真實世界的使用者實際輸入的內容可能遠比這些測試範例**更加混亂、模糊、不合常規**），這種**測試涵蓋範圍不足**的問題會導致 Agent 在測試階段看起來表現良好，但一旦進入真實環境面對**測試階段沒有充分考量到的各種意外情境**，表現就會**明顯下滑**；**(2) 真實環境裡的外部工具或資料來源行為和測試環境不一致**：如果 Agent 在測試階段是**依靠一個模擬的、或者經過特別設計的測試版本的外部工具或資料來源**去進行測試，而這個**測試版本**的行為和**真實生產環境裡實際上會被呼叫到的正式版本工具或資料來源**存在某種程度的**行為差異**（例如正式環境的某個 API 實際的回應速度或回傳格式和測試環境略有不同），這種**環境本身的不一致**也可能導致 Agent 在測試和真實環境之間表現出現落差。

**詳細解析**：這題把 Agent 評估這個議題延伸到一個在**機器學習和軟體工程領域**都相當經典、且反覆出現的核心概念——**「測試表現和真實部署表現之間存在落差」**這個現象，考察是否能夠把前面已經建立的 Agent 評估核心認知套用到這個**更加貼近實際部署經驗**的具體問題情境。理解這個問題的核心在於回顧前面已經深入討論過的**「穩健性評估需要涵蓋多樣化情境」**這個核心原則——**測試環境的表現之所以能夠被信任作為這個 Agent 系統真實表現的可靠預測依據**，前提是——**這個測試環境所涵蓋的情境多樣性需要充分地代表、涵蓋真實世界實際上會出現的各種情境分佈**。如果這個**前提不成立**（測試涵蓋的情境只是真實世界實際情境分佈裡的一個**不夠具有代表性、過於狹隘或理想化**的子集合），這種**「測試環境和真實環境之間存在分佈落差」**的現象就**幾乎必然**會導致**在測試環境裡看起來相當亮眼的表現沒有辦法被直接套用、等同於**這個系統在**真實生產環境同樣會展現出相同水準**的表現。這種認知帶來一個相當重要的實務啟示——**在設計 Agent 的測試和評估流程時，應該特別審慎地去思考『我目前所設計的這些測試情境，是否真的充分且具備代表性地涵蓋了真實世界實際上會遭遇到的各種情境』**，而不是只滿足於**在一組可能過於理想化、狹隘的測試情境集合裡**看到**亮眼的評估結果**就貿然地**過度信任、樂觀地判斷**這個系統**在真實世界的實際表現**也會同樣優異。實務上緩解這種落差的常見做法包括——**盡可能運用真實世界實際發生過的（可能經過妥善的資料去識別化處理）歷史資料作為測試素材**（而不是只依靠人工刻意設計出來的、可能不夠貼近真實情況的模擬範例）；以及**在正式大規模部署之前，先透過一個範圍受限、風險可控的『先導測試（Pilot）』階段**，讓這個 Agent 系統先在**一小部分真實（但風險相對可控）的實際場景**下運作，觀察它在**真實情境**下是否真的維持著和測試階段相近的表現水準，才逐步地擴大部署的範圍。理解「這種現象經常是因為測試環境和真實環境之間存在某種重要的分佈落差，具體可能原因包括測試情境的多樣性不足(測試涵蓋的情境只是真實世界實際情境分佈裡一個不夠具有代表性的狹隘子集合，例如測試資料相對乾淨規整，但真實使用者實際輸入遠比測試範例更混亂模糊)、以及真實環境裡的外部工具或資料來源行為和測試環境不一致，這呼應了穩健性評估需要涵蓋多樣化情境這個核心原則——測試環境的表現之所以能被信任作為真實表現的可靠預測依據，前提是測試涵蓋的情境多樣性需要充分代表真實世界實際情境分佈，如果這個前提不成立，測試表現亮眼並不能直接等同於真實生產環境同樣會有相同水準表現，緩解做法包括盡可能運用真實世界實際發生過的歷史資料作為測試素材、以及在正式大規模部署前先透過範圍受限的先導測試階段觀察真實情境下的表現」，展現你能把之前建立的穩健性評估核心原則，連結到測試與真實部署表現落差這個機器學習和軟體工程領域經典且實務的問題情境。

**面試回答方式**：先給出核心答案——「這種現象經常是因為測試環境和真實環境之間存在某種重要的分佈落差，具體可能原因包括測試情境的多樣性不足(測試涵蓋範圍只是真實世界實際情境分佈裡一個不夠具代表性的狹隘子集合)、以及真實環境裡的外部工具或資料來源行為和測試環境不一致」。連結到之前建立的核心原則——「這呼應了穩健性評估需要涵蓋多樣化情境這個核心原則，測試環境表現之所以能被信任作為真實表現的可靠預測依據，前提是測試涵蓋的情境多樣性需要充分代表真實世界實際情境分佈，如果這個前提不成立，測試表現亮眼並不能直接等同於真實生產環境會有相同水準表現」。給出實務緩解做法——「盡可能運用真實世界實際發生過的歷史資料作為測試素材，而不只依靠人工刻意設計出來的可能不夠貼近真實情況的模擬範例;以及在正式大規模部署前，先透過一個範圍受限、風險可控的先導測試階段，觀察在真實情境下是否維持相近的表現水準，才逐步擴大部署範圍」。

### 如果用另一個模型作為「評審」去評估一個 Agent 的表現（前面提到的 LLM-as-a-Judge 這類做法），這個評審模型本身的判斷可靠嗎？有沒有什麼需要特別注意的地方？

**核心答案**：**評審模型本身的判斷並不能被視為絕對可靠、無需質疑的『黃金標準』**——延續前面（見 [[009-self-correction-reflection.md]]）已經深入討論過的核心洞察，任何一個模型（不管是被評估的 Agent 自己、還是額外引入的評審模型）都**同樣可能帶有它自己本身固有的系統性偏誤或盲點**，因此**用一個模型去評審、判斷另一個 Agent 的表現**這件事情本身**並不會自動地就比被評審的那個 Agent 本身的判斷更加絕對可靠**。需要特別注意的地方包括——**(1) 評審模型本身可能存在的偏誤會系統性地影響評分結果**（例如如果評審模型本身就帶有某種固有的偏好，如前面（見 [[../ai-llm/019-rlhf.md]]）已經深入討論過的獎勵駭客情境裡提到的『偏好較長的回答』這類偏誤，這種偏誤可能會系統性地扭曲最終的評分結果）；**(2) 需要額外地去驗證這個評審模型的判斷本身是否和人類的實際判斷具備足夠高的一致性**（透過抽樣比對評審模型的評分和真正的人類評審的評分是否具備足夠的一致性，來驗證這個評審模型是否真的值得被信賴、用來取代大規模的人工評審工作）。

**詳細解析**：這題要求把前面（見 [[009-self-correction-reflection.md]]）已經深入討論過的**「自我審查天生存在系統性盲點」**這個核心洞察**進一步延伸應用到『用另一個獨立的模型去評審』**這個看起來似乎已經**引入了某種獨立性**的做法上，考察是否能夠理解即使**評審者和被評審者是兩個不同的獨立模型**，這種**「用模型去評審模型」**的做法依然**沒有辦法完全消除**前面已經反覆強調的核心風險——**「任何一個依靠模型本身做出的判斷，都可能帶有這個模型自身固有的系統性偏誤」**。理解這個問題的核心在於重新釐清前面（見 [[009-self-correction-reflection.md]] 的常見追問）已經建立的核心區分——真正關鍵的問題**不是『評審者和被評審者是否是同一個模型』**，而是**『這個負責評審的角色（不管是同一個模型、還是不同的模型）本身是否真正具備足夠可靠的判斷能力』**——如果一個被用來作為評審的模型**本身同樣是一個（和其他大多數模型一樣）透過類似的訓練資料和訓練過程所訓練出來的大型語言模型**，這個評審模型**很可能也同樣帶有**某些**普遍存在於這一類模型裡的系統性偏誤或盲點**（例如前面（見 [[../ai-llm/019-rlhf.md]]）已經深入討論過的**傾向偏好較長回答**這類可能普遍地存在於很多透過類似方式訓練出來的模型裡的共通偏誤）——這種**共通、普遍存在**的系統性偏誤**並不會因為換了一個不同的模型來擔任評審**就自動地消失。因此**「引入一個不同的模型作為評審」**這個做法**雖然確實比讓同一個 Agent 自己審查自己**多提供了**一定程度的獨立視角**，但**並不能被視為一個能夠完全消除所有系統性偏誤風險的完美解方**。因應這種侷限，實務上一個相當重要的做法是——**必須額外地投入精力去驗證這個被選定作為評審的模型，它的判斷結果是否真的和真正的人類判斷標準具備足夠高的一致性**（例如抽樣一批樣本，同時讓這個評審模型和真正的人類評審員各自獨立地去評分，再比對這兩組評分結果之間的一致性程度）。只有經過這種**額外的驗證**，確認這個評審模型的判斷標準確實**和人類的實際判斷標準有著足夠高的一致性**，才能**相對放心地**把這個評審模型實際運用在**大規模、需要快速取得評估結果**的場景裡（而不是天真地假設**只要是用模型去評審，就自動地等同於取得了一個客觀、可靠的評估標準**）。理解「評審模型本身的判斷並不能被視為絕對可靠、無需質疑的黃金標準，任何一個模型不管是被評估的Agent自己還是額外引入的評審模型，都同樣可能帶有它自己固有的系統性偏誤或盲點，用一個模型去評審另一個Agent這件事本身並不會自動比被評審Agent本身的判斷更絕對可靠，真正關鍵的問題不是評審者和被評審者是否是同一個模型，而是這個負責評審的角色本身是否真正具備足夠可靠的判斷能力，如果評審模型本身同樣是透過類似訓練資料訓練出來的模型，很可能也同樣帶有普遍存在於這類模型裡的系統性偏誤(如偏好較長回答)，這種共通偏誤不會因為換了不同模型擔任評審就自動消失，因應這種侷限，實務上必須額外投入精力去驗證評審模型的判斷結果是否真的和真正的人類判斷標準具備足夠高的一致性，才能相對放心把評審模型運用在大規模需要快速取得評估結果的場景裡」，展現你能把之前建立的自我審查系統性盲點這個核心洞察，進一步延伸應用到用另一個模型評審這個看似已引入獨立性、但實際上仍可能繼承類似侷限的做法上。

**面試回答方式**：先明確給出核心答案——「評審模型本身的判斷並不能被視為絕對可靠無需質疑的黃金標準，任何一個模型都可能帶有它自己固有的系統性偏誤或盲點，用一個模型去評審另一個Agent，並不會自動就比被評審Agent本身的判斷更絕對可靠」。給出核心區分——「真正關鍵的問題不是評審者和被評審者是否是同一個模型，而是這個評審角色本身是否真正具備足夠可靠的判斷能力，如果評審模型是透過類似訓練資料訓練出來的，很可能也同樣帶有普遍存在於這類模型裡的系統性偏誤，例如偏好較長回答這類共通偏誤，不會因為換了不同模型就自動消失」。給出實務因應做法——「必須額外投入精力去驗證這個評審模型的判斷結果，是否真的和真正的人類判斷標準具備足夠高的一致性，例如抽樣讓評審模型和真正的人類評審員各自獨立評分再比對一致性程度，只有經過這種驗證，才能相對放心把評審模型運用在大規模評估場景裡」。

### 如果一個 Agent 系統涉及多個不同的子 Agent 協作完成任務（前面已經討論過的多代理系統（Multi-Agent System）），評估這個整體系統的表現時，是不是只需要評估最終的整體結果就足夠了？還是也需要評估每一個個別子 Agent 各自的表現？

**核心答案**：**只評估最終的整體結果並不足夠，也需要額外地評估每一個個別子 Agent 各自的表現**——核心原因在於，延續前面（見 [[005-multi-agent-systems.md]]）已經深入討論過的核心洞察——**多代理系統裡，錯誤可能跨越不同 Agent 的邊界層層傳播、放大**——如果**只關注最終的整體結果**，即使發現這個最終結果**不如預期**，光看這個籠統的整體結果也**沒有辦法**判斷究竟是**哪一個具體的子 Agent** 在**哪一個具體環節**出了問題，導致最終整體結果受到影響；只有**額外地針對每一個個別子 Agent 各自的表現**做**獨立、細緻的評估**，才能**精準地定位**問題究竟源自於哪裡。這種**「整體結果評估」和「個別子 Agent 表現評估」需要同時並行**的思路，某種程度上也呼應了前面（見 [[012-observability-tracing.md]]）已經深入討論過的核心概念——**「因果鏈的完整重建」**，只是把這個概念從**「事後除錯」**這個場景延伸到**「事前的系統性評估」**這個場景。

**詳細解析**：這題要求把前面（見 [[005-multi-agent-systems.md]]、[[012-observability-tracing.md]]）已經分別建立的兩個核心概念——**『多代理系統裡錯誤可能層層傳播放大』**以及**『需要完整重建因果鏈才能有效除錯』**——**整合連結**，具體應用到**「應該如何設計一套適用於多代理系統的評估方法論」**這個問題上，考察是否能夠把這些先前已經建立的核心洞察**融會貫通地運用到一個新的、更加複雜的具體評估情境**。理解這個問題的核心在於認識到——**「只看最終的整體結果」**這種評估方式某種程度上**類似於一種『黑盒（Black-box）』式的評估**——它能夠告訴你**這個系統（不管內部是由多少個子 Agent 協作構成）最終產出的結果是否符合預期**，但**沒有辦法**告訴你**這個系統內部具體是怎麼運作、又是哪一個具體環節出了問題**這種**更加細膩的內部診斷資訊**——這種**黑盒式評估**某種程度上**足夠**用來判斷**「這個系統整體而言值不值得被信賴採用」**這個較為籠統的判斷；但**不足夠**用來支援**「這個系統如果表現不如預期，具體應該如何被改進、優化」**這個**更加需要細緻診斷資訊**的判斷。因此一個**真正完整的多代理系統評估方法論**需要**同時涵蓋****「整體黑盒評估」**和**「個別子 Agent 的白盒（White-box）式細緻評估」**這兩個**層次**——前者回答**「這個系統整體好不好」**；後者回答**「如果不好，具體是哪裡出了問題、應該如何針對性地去改進」**。這種**「整體和個別兩個層次並重」**的評估思路也呼應了這篇文章反覆強調的一個核心原則——**「面對一個由多個獨立元件組合而成的複雜系統，光評估這個系統整體的單一籠統指標通常是不夠的，還需要深入到這個系統內部每一個個別組成元件的層次去做更加細緻的個別評估，才能真正全面、深入地理解這個系統的實際表現，以及具體可以如何被改進」**。理解「只評估最終整體結果並不足夠，也需要額外評估每一個個別子Agent各自的表現，核心原因在於多代理系統裡錯誤可能跨越不同Agent邊界層層傳播放大，如果只關注最終整體結果，即使發現結果不如預期，光看這個籠統整體結果沒辦法判斷究竟是哪個具體子Agent在哪個具體環節出了問題，只有額外針對每個個別子Agent做獨立細緻評估，才能精準定位問題源頭，只看整體結果類似一種黑盒式評估，足夠判斷系統整體值不值得信賴，但不足夠支援系統如果表現不如預期具體應該如何被改進優化這個更需要細緻診斷資訊的判斷，一個真正完整的多代理系統評估方法論需要同時涵蓋整體黑盒評估和個別子Agent的白盒式細緻評估這兩個層次」，展現你能把之前建立的多代理系統錯誤傳播、以及因果鏈完整重建這兩個核心概念，融會貫通應用到多代理系統評估方法論這個新的具體問題上。

**面試回答方式**：先明確給出核心答案——「只評估最終整體結果並不足夠，也需要額外評估每一個個別子Agent各自的表現」。解釋核心原因並連結之前的洞察——「這呼應了之前討論過的多代理系統裡錯誤可能跨越不同Agent邊界層層傳播放大這個核心洞察，如果只關注最終整體結果，即使發現結果不如預期，光看這個籠統結果沒辦法判斷究竟是哪個子Agent在哪個環節出了問題，只有額外針對每個個別子Agent做獨立評估，才能精準定位問題源頭」。用黑盒白盒的比喻做總結——「只看整體結果類似一種黑盒式評估，足夠判斷系統整體值不值得信賴，但不足夠支援具體應該如何改進這個需要細緻診斷資訊的判斷，一個真正完整的評估方法論需要同時涵蓋整體黑盒評估和個別子Agent的白盒式細緻評估這兩個層次」。
