# 題目

在 Agent 的情境裡，「自我修正（Self-Correction）」與「Reflection（反思）」具體指的是什麼樣的機制？它是如何讓一個 Agent 具備**在沒有任何外部人工介入的情況下，自己發現並修正先前錯誤**這種能力的？

## 核心答案

在 Agent 的情境裡，**自我修正**與 **Reflection** 指的是一種讓 Agent **在完成、或者執行到某個階段之後，額外地回過頭來用一種批判性的視角重新檢視、評估自己先前已經產出的結果或已經採取的行動，判斷這些結果或行動是否存在可以被改進的問題；如果發現問題，就依照這個發現重新調整、修正自己接下來的行為**的機制。它之所以能夠讓 Agent 具備**不需要外部人工介入就能自己發現、修正錯誤**的能力，核心原理在於——**這本質上是運用前面（見 [[003-planning-task-decomposition.md]] 的常見追問）已經深入討論過的『生成和審查／驗證是兩種性質不完全相同的認知任務』這個核心洞察**——Agent 一開始**生成**一個結果或採取一個行動時，可能因為任務本身的複雜度而出現一些疏漏；但當 Agent **額外地切換到一個『審查者』的角色**重新去**檢視這個已經產出的具體結果**時，這是一個**相對更聚焦、更容易被妥善處理**的任務，因此**同一個 Agent（甚至是同一個模型）**在扮演『審查／批評自己先前產出』這個角色時**有相當不錯的機率**能夠發現一些它在一開始**生成**這個結果時沒有注意到的問題。這種**「先生成、再切換角色自我審查、再依照審查發現修正」**的循環機制，正是讓 Agent 具備**自我修正**能力的核心運作原理。

## 詳細解析

**Reflection 的典型運作循環——生成、自我批評、修正**：一個典型的 Reflection 機制通常包含幾個核心步驟——**(1) 生成（Generate）**：Agent 針對被賦予的任務產出一個初步的結果或行動；**(2) 自我批評（Self-Critique）**：Agent **額外地切換到一個批判性審查者的視角**，針對這個剛剛產出的初步結果進行仔細的檢視，判斷是否存在**邏輯上的錯誤、遺漏的考量、或者可以被進一步優化的地方**，並把這些發現的問題**明確地用文字表達出來**；**(3) 修正（Revise）**：Agent 依照前一步自我批評所發現的具體問題**重新調整、修正**先前的結果，產出一個**經過改進的新版本**。這個「生成－批評－修正」的循環**可以被反覆地執行多輪**——每執行完一輪修正之後，可以再回到**自我批評**這個步驟，針對這個**已經被修正過的新版本**再次進行審查，判斷是否還存在其他可以被進一步改進的問題，直到這個結果被判斷為已經達到令人滿意的品質水準，或者達到某個事先設定好的反覆次數上限。

**為什麼「自我批評」這個步驟需要額外地切換一個不同的視角或角色**：Reflection 機制設計裡一個值得特別留意的細節是——**自我批評**這個步驟通常不會只是簡單地要求模型用**和最初生成那個結果時完全相同的視角和心態**去回頭檢視自己的產出，而是會**明確地透過提示的設計**（見 [[../ai-llm/006-prompt-engineering.md]] 已經深入討論過的相關技巧）**要求模型切換到一個明確不同的角色定位**——例如明確地指示模型扮演**『一個經驗豐富、以嚴格挑剔著稱的審查者』**去**專門尋找這份產出裡的問題和缺陷**（而不是延續一開始那種『努力試圖產出一個好結果』的生成者心態）。這種**明確地切換角色定位**的設計，某種程度上是為了**避免模型因為延續著剛才生成這個結果時的思維慣性和立場，而出現一種類似人類常見的『對自己剛產出的東西抱持一定程度的辯護心理，不容易客觀、挑剔地審視自己作品裡的問題』這種偏誤**——透過**明確地要求切換到一個不同、且帶有明確批判性導向**的角色，能夠某種程度上**促使模型更加客觀、更加願意主動地去挑出自己先前產出裡可能存在的問題**，而不是習慣性地傾向對自己剛剛產出的內容給予過度寬容、缺乏批判力道的評價。

**Reflection 機制的核心侷限——模型自我批評的能力終究受限於模型本身的能力上限**：需要誠實地承認的是——Reflection 這種自我修正機制雖然能帶來一定程度的品質提升，但它**終究不是一種能夠讓 Agent 憑空超越自己本身模型能力上限的魔法**——如果一個**特定類型的錯誤或問題**本質上**超出了這個模型自身所具備的知識或推理能力範疇**（換句話說，如果這個模型即使切換到『審查者』角色，依然**根本不具備識別出這一類特定問題**所需要的知識或能力），那不管讓這個模型執行多少輪的「自我批評－修正」循環，都**很難指望它能夠自己發現、修正這一類超出自身能力範疇的問題**（這某種程度上呼應了一個相當直觀的道理——**如果一個人本身就不具備判斷某件事情對錯所需要的知識，讓他反覆地重新檢視自己的判斷好幾次，也沒有辦法讓他憑空獲得原本不具備的那種知識或判斷能力**）。因此 Reflection 機制真正擅長處理的是**那些模型本身其實已經具備識別出問題所需要的知識和能力，只是在第一次生成的當下因為某些原因（例如過於倉促、或者注意力被分散在其他更急迫的考量上）而沒有被充分注意到的疏漏**，而**不是**一種能夠**彌補模型本身知識或能力根本缺口**的萬用解方。這也呼應了一個在評估任何『自我修正／自我改進』類型的機制時都值得反覆提醒自己的核心界限——**「重新檢視自己」能捕捉到『粗心導致的疏漏』，但沒有辦法捕捉到『能力本身就不具備』所導致的問題**。

## 面試回答方式

先給出自我修正和Reflection的核心定義——「讓Agent在完成或執行到某個階段之後，額外地回過頭來用批判性視角重新檢視評估自己先前已經產出的結果或行動，判斷是否存在可以被改進的問題，如果發現問題就依照這個發現重新調整修正接下來的行為」。解釋核心運作原理並連結之前的洞察——「這本質上是運用之前規劃審查機制章節已經討論過的核心洞察——生成和審查驗證是兩種性質不完全相同的認知任務，Agent一開始生成一個結果時可能因為任務複雜度而出現疏漏，但當它額外切換到一個審查者角色重新檢視這個已經產出的具體結果時，是一個相對更聚焦、更容易被妥善處理的任務，因此有相當不錯的機率能發現一開始生成時沒注意到的問題」。可以說明典型的三步驟循環——「生成初步結果、自我批評(切換到批判性審查者視角找出問題)、修正(依照發現的問題產出改進版本)，這個循環可以被反覆執行多輪」。可以補充為什麼需要明確切換角色——「明確要求切換到一個帶有批判性導向的不同角色，是為了避免模型延續生成時的思維慣性，出現類似人類對自己作品抱持辯護心理、不容易客觀挑剔審視的偏誤」。一定要誠實補充核心侷限——「Reflection終究不是能讓Agent憑空超越自身能力上限的魔法，如果一個錯誤本質上超出模型自身具備的知識或推理能力範疇，不管執行多少輪自我批評修正循環，都很難指望它能自己發現修正這類超出能力範疇的問題，重新檢視自己能捕捉到粗心導致的疏漏，但沒辦法捕捉到能力本身就不具備所導致的問題」，展現你對Reflection機制的運作原理和核心侷限有完整且誠實的理解。

## 常見追問

### 如果讓同一個模型同時扮演「生成者」和「審查者」這兩個角色，會不會存在某種「自己審查自己難免有所偏袒」的系統性風險？即使明確地要求它切換角色，這個風險是否能被完全消除？

**核心答案**：**這種系統性風險確實存在，且無法被完全消除**——即使透過明確的提示設計要求模型切換到一個帶有批判性導向的審查者角色，這終究**只是同一個模型（甚至很可能是同一次對話脈絡下）被要求扮演一個不同的角色**，而**不是**一個真正獨立、擁有完全不同訓練背景或視角的**外部第三方**。因此這種『自我審查』的機制**天生就存在一定程度的『系統性盲點』風險**——如果模型本身在某一類特定的判斷上就帶有某種**系統性的偏誤或盲點**（例如某種它在訓練過程中普遍形成的固有傾向），這種偏誤**很可能會同時體現在它扮演『生成者』角色時、以及它扮演『審查者』角色時這兩者身上**——換句話說，**如果模型本身的某個系統性盲點導致它一開始生成時就犯了某種特定類型的錯誤**，這個**同樣的系統性盲點**很可能也會讓它在切換到審查者角色時**依然沒有辦法識別出這個屬於它自己固有盲點範疇內的問題**（因為這並不是一個單純的『注意力分散、一時疏忽』所導致的錯誤，而是**這個模型本身在這一類判斷上就欠缺正確判斷所需要的能力或視角**）。因應這種自我審查固有的系統性侷限，一個更穩健的做法是**引入真正獨立的外部審查機制**——不管是讓**一個不同的、獨立的模型**來扮演審查者角色（而不是同一個模型自己切換角色），還是在關鍵的環節引入**真正的人類審查**。這種**真正獨立**的審查來源因為**不會天然地共享同一套系統性盲點**，才能夠更可靠地去捕捉到那些單靠『同一個模型自我審查』這種機制天生就難以觸及的問題類型。

**詳細解析**：這題要求對前面已經簡要提到的『Reflection 的核心侷限』做更深入、更精確的挖掘，考察是否能夠區分**「模型一時的疏忽大意」**和**「模型本身系統性固有的盲點或偏誤」**這**兩種性質不完全相同的問題來源**，並理解 Reflection 機制**能夠有效地處理前者，但對後者效果相對有限**這個更加細緻的核心界限。理解這個問題的核心需要回顧——Reflection 機制之所以能夠帶來效益，關鍵在於**『審查一個已經存在的產出』這件事相較於『從零生成這個產出』是一個性質不同、認知負擔較低的任務**，這讓**同一個模型**即使是扮演不同角色，也能在這種**任務性質切換**中某種程度上重新用一個更聚焦的視角去發現一些**原本因為需要同時兼顧太多考量而被忽略的疏漏**；但這種效益**有一個隱含的前提**——**這個模型本身其實是具備識別出這類問題所需要的知識和判斷能力**，只是因為一開始**生成**的當下注意力或認知資源被分散在太多其他考量上，而**沒有充分地運用到它其實已經具備的這種能力**。然而如果一個問題的根源**不是**這種『注意力分散而一時忽略』，而是**這個模型本身在這一類判斷上就欠缺足夠的知識或能力**（不管是因為訓練資料本身的某種偏差，還是模型架構或訓練過程本身固有的某種限制），這種情況下**單純地要求這個同一個模型切換一個角色標籤（從生成者換成審查者）****並不能改變**這個模型**本身實際具備的知識和能力**這個更根本的事實——它在扮演審查者角色時依然是**用和扮演生成者角色時同樣的那套（可能帶有系統性盲點的）知識、判斷力和世界觀**去進行審查。因此這種**「模型本身固有系統性盲點」**這類問題**很難指望單純地透過讓同一個模型切換角色就被自己發現、糾正**。這種洞察帶來一個相當重要的實務啟示——**「自我審查」和「獨立的外部審查」扮演的角色是互補、而非互相取代**的——自我審查（Reflection）適合作為**快速、低成本捕捉一時疏忽性錯誤**的第一道防線；但對於那些**更加根本、可能涉及模型本身系統性侷限**的問題，終究需要**引入真正獨立**（一個訓練背景、資料來源不同的獨立模型；或者直接引入人類專家）的審查角色，才能提供**真正有效**的補充和糾正。理解「自我審查天生存在系統性盲點風險且無法被完全消除，因為即使明確要求切換角色，終究只是同一個模型被要求扮演不同角色，而非真正獨立擁有不同訓練背景視角的外部第三方，如果模型本身在某類判斷上帶有系統性偏誤，這個偏誤很可能同時體現在生成者和審查者這兩個角色身上，關鍵在於區分模型一時疏忽大意和模型本身系統性固有盲點這兩種性質不同的問題來源，Reflection機制能有效處理前者(因為生成時注意力被分散而沒充分運用已具備的能力)，但對後者(模型本身欠缺足夠知識或能力)效果相對有限，因應這種侷限，更穩健的做法是引入真正獨立的審查機制，不管是不同的獨立模型還是人類專家，自我審查和獨立外部審查扮演的角色是互補而非互相取代」，展現你能對Reflection機制的核心侷限，做出比表面認知更精確、更深入的區分和挖掘。

**面試回答方式**：先明確給出核心答案——「這種系統性風險確實存在，且無法被完全消除，因為即使明確要求切換角色，終究只是同一個模型被要求扮演不同角色，而不是一個真正獨立、擁有完全不同訓練背景或視角的外部第三方」。給出精確的問題區分——「關鍵在於區分模型一時疏忽大意和模型本身系統性固有盲點這兩種性質不同的問題來源，Reflection機制擅長處理前者——因為模型其實已經具備識別問題所需要的知識能力，只是生成當下注意力被分散而沒有充分運用;但對後者效果相對有限——如果模型本身在某類判斷上就欠缺足夠知識或能力，單純要求它切換角色標籤，並不能改變它實際具備的知識能力這個更根本的事實」。給出更穩健的因應做法——「自我審查和真正獨立的外部審查扮演的角色是互補而非互相取代，自我審查適合作為快速低成本捕捉一時疏忽性錯誤的第一道防線，但對於更根本、可能涉及模型系統性侷限的問題，終究需要引入真正獨立的模型或人類專家審查，才能提供真正有效的補充」。

### Reflection 機制和前面 AI 大模型類別討論過的 RLHF 訓練流程，兩者都涉及「評估、批評模型的產出」這件事，兩者是同一回事嗎？

**核心答案**：**不是同一回事，兩者處於完全不同的層次——一個是訓練階段的機制；另一個是推理階段（執行任務時）的機制**——**RLHF**（見 [[../ai-llm/019-rlhf.md]]）是一個**訓練階段**的機制——它透過蒐集人類對模型不同回答的偏好評價訓練出一個獎勵模型，再用強化學習**永久性地調整、更新模型本身的參數**，這個過程**只發生一次（或者說只發生在訓練這個模型的過程中）**，一旦訓練完成，這個**被調整過的模型參數**就會被**固定下來**成為這個已經訓練好的模型；而 **Reflection** 則是一個**推理階段**的機制——它**不會改變模型本身的任何參數**，而是在**每一次實際執行一個具體任務的過程中**額外地多執行幾輪**額外的推理呼叫**（生成、批評、修正），這個過程是**針對這一次具體任務**臨時性地發生，**不會對這個模型本身未來執行其他任何任務時的行為造成任何永久性的改變**。兩者雖然都涉及某種形式的『評估、批評』，但**運作的層次、發生的時機，以及產生的效果都是完全不同的**。

**詳細解析**：這題延續這篇文章反覆練習過的核心分析框架——**當兩個概念都涉及類似的字眼（這裡是『評估／批評模型的產出』），仔細地去釐清它們各自具體發生在哪一個階段、運作的機制和產生的效果是否真的相同**——考察是否能夠精確地區分 **RLHF** 和 **Reflection** 這兩個容易因為都涉及『評估』這個共通字眼而被混為一談的概念。理解這兩者的核心差異需要先回顧——**RLHF**（見 [[../ai-llm/019-rlhf.md]]）本質上是**訓練流程**的一部分——它發生在這個模型**還沒有被正式訓練完成、部署出來讓使用者實際使用**的階段，透過這個訓練過程**永久性地**調整這個模型內部的參數權重，讓這個模型**未來在處理任何新的、不同的任務時**都**天然地傾向**展現出更符合人類偏好的行為模式（這種改變是**內化到模型參數本身**的，一旦訓練完成，這種改變就會**持續地體現在這個模型未來所有的行為表現裡，而不需要每一次使用這個模型時都額外地重新執行一次 RLHF**）；而 **Reflection** 則完全是**另一個層次**的機制——它**不涉及任何對模型參數本身的修改**，這個模型的參數**從頭到尾都維持不變**，Reflection 所做的事情只是**在使用這個（參數完全不變的）模型去執行一個具體任務的當下，額外地多呼叫這個模型幾次，讓它用不同的角色設定（生成者、審查者）針對這一次具體任務的產出進行反覆的檢視、修正**，這個過程**只影響這一次具體任務最終產出的結果品質，完全不會**讓這個模型本身出現任何**下一次執行完全不同的另一個任務時也會自動地變得更好**這種**跨任務的永久性改變**（如果希望讓模型未來在**面對所有任務**時都能天然地表現得更好，那需要做的是 **RLHF 這類訓練階段的工作**，而**不是**單純地在**每一次使用時**額外套用 Reflection 這種推理階段的臨時性機制）。理解了這個**「訓練階段的永久性參數改變」對比「推理階段針對單一次具體任務的臨時性反覆檢視」**這個核心區別，就能清楚地看出 **RLHF 和 Reflection** 雖然都涉及『評估』這件事，但兩者**完全不是同一回事**，也**完全不能被互相取代**——一個即使經過了非常完整、有效的 RLHF 訓練的模型，在執行**一個具體、複雜的任務**時依然可能因為這個任務本身的複雜度而需要額外地套用 Reflection 機制來進一步提升**這一次具體任務**的產出品質；反過來，單純地只依靠 Reflection 這種推理階段的臨時性機制，也**沒有辦法取代** RLHF 這種能夠**永久性地全面提升模型未來在所有任務上的普遍行為表現**的訓練階段工作。理解「RLHF和Reflection不是同一回事，兩者處於完全不同的層次，RLHF是訓練階段的機制，透過人類偏好評價訓練出獎勵模型，再用強化學習永久性調整模型本身的參數，這個過程只發生在訓練這個模型的過程中，一旦訓練完成就固定下來;而Reflection是推理階段的機制，不會改變模型本身的任何參數，只是在每一次執行具體任務的過程中額外多執行幾輪推理呼叫，這個過程只影響這一次具體任務最終產出的結果品質，完全不會讓模型出現下一次執行完全不同任務時也自動變好這種跨任務的永久性改變，兩者運作的層次、發生時機、產生效果都完全不同，也完全不能互相取代」，展現你能精確區分訓練階段機制和推理階段機制這兩個容易被表面字眼混淆的不同概念層次。

**面試回答方式**：先明確給出核心答案——「不是同一回事，兩者處於完全不同的層次，RLHF是訓練階段的機制，而Reflection是推理階段的機制」。詳細解釋RLHF的性質——「RLHF透過人類偏好評價訓練出獎勵模型，再用強化學習永久性地調整模型本身的參數，這個過程只發生在訓練這個模型的過程中，一旦訓練完成，這種改變就會持續體現在模型未來所有的行為表現裡」。詳細解釋Reflection的性質——「Reflection完全不涉及對模型參數本身的任何修改，模型參數從頭到尾維持不變，它只是在執行一個具體任務的當下，額外多呼叫模型幾次，用不同角色設定針對這一次任務的產出進行反覆檢視修正，這個過程只影響這一次具體任務的結果品質，不會讓模型下次執行完全不同任務時也自動變好」。給出結論——「兩者完全不能互相取代，即使經過完整RLHF訓練的模型，在執行複雜任務時依然可能需要額外套用Reflection來進一步提升這一次任務的產出品質;反過來單純依靠Reflection也沒辦法取代RLHF這種能永久性全面提升模型未來所有任務普遍表現的訓練階段工作」。

### 除了讓 Agent 自己（或另一個模型）進行文字層面的自我批評，還有沒有其他更客觀、更可驗證的方式去判斷一個 Agent 的產出是否真的需要被修正？

**核心答案**：有，一個相當重要、且比單純的『文字層面自我批評』更客觀、更可驗證的做法，是**盡可能地運用可以被客觀執行、驗證的具體檢驗手段**——例如如果 Agent 產出的是一段程式碼，與其只是讓模型用文字去『評論』這段程式碼看起來是否正確，更穩健的做法是**實際地去執行這段程式碼（或者執行對應的測試案例）**，依照**這個實際執行後得到的客觀結果（程式是否真的能成功執行、測試是否真的通過）**來判斷這段程式碼是否需要被修正。這種**「用客觀、可執行的驗證手段取代或補充單純主觀的文字評論」**的做法，某種程度上呼應了前面（見 [[002-react-pattern.md]] 的常見追問）已經深入討論過的核心告誡——**「不應該只因為展開的文字（不管是思考過程、還是自我批評的評論）讀起來合理通順，就過度地信任它一定準確地反映了真實的情況，應該更加重視客觀、可驗證的實際執行結果」**。

**詳細解析**：這題把前面（見 [[002-react-pattern.md]]）已經建立的核心告誡——**「重視客觀執行結果，而非只信任主觀展開的文字」**——進一步具體地延伸應用到**「如何讓自我修正機制變得更加可靠」**這個具體議題上，考察是否能夠把這個核心原則融會貫通地應用到一個新的、更加實務導向的問題情境。理解這個問題的核心在於認識到——單純的**『文字層面自我批評』**（前面已經深入討論的核心 Reflection 機制）終究是**依靠模型自己用文字去表達它對自己先前產出的評價**，這種做法**同樣繼承了**前面已經反覆討論過的**『展開的文字評論未必完全忠實地反映真實情況』**這個潛在風險——模型可能**生成一段聽起來言之成理的自我批評，但這段批評本身是否真的準確地指出了一個真實存在的問題**，這件事本身某種程度上也需要被**進一步地驗證**；相較之下，**如果這個任務本身的性質恰好允許某種客觀、可執行的驗證方式**（這並不是對所有類型的任務都適用——例如一段撰寫得好不好的行銷文案，就較難用一種類似『執行程式碼』那樣客觀、明確的方式去驗證），這種**客觀驗證**的效力**遠比單純的文字自我評論更加可靠**——**執行程式碼得到一個明確的『成功／失敗』或『通過／不通過測試』的結果**，這種結果是**不需要依靠模型自己的主觀判斷去詮釋**的客觀事實。這種**用客觀、可執行的手段取代或補充主觀的文字評論**的核心思路，實務上帶來一個相當重要的設計啟示——**在設計一個 Agent 系統的自我修正機制時，應該優先考量這個任務的性質是否允許某種客觀、可驗證的檢驗手段（例如執行測試、對照一個明確的、可以被程式化檢查的規格要求），如果存在這種客觀驗證的可能性，應該優先採用這種客觀驗證來作為判斷是否需要修正的主要依據**；而**只有**在任務本身的性質**確實不允許**這種客觀、可執行的驗證方式時（例如前面提到的行銷文案撰寫品質這類本質上帶有一定主觀性判斷成分的任務），才**退而求其次**依靠前面已經討論過的『文字層面自我批評』這種相對**較不那麼可靠**、但依然能帶來一定程度效益的機制。理解「除了文字層面自我批評，還有更客觀可驗證的方式，是盡可能運用可以被客觀執行驗證的具體檢驗手段，例如如果Agent產出的是程式碼，與其只讓模型用文字評論看起來是否正確，更穩健的做法是實際執行這段程式碼或對應測試案例，依照實際執行後得到的客觀結果來判斷是否需要修正，這呼應了之前已經建立的核心告誡——不應該只因展開的文字讀起來合理就過度信任，應該更重視客觀可驗證的實際執行結果，實務上的設計啟示是在設計自我修正機制時，應該優先考量任務性質是否允許客觀可驗證的檢驗手段，如果存在就應該優先採用，只有任務本身確實不允許這種客觀驗證方式時(如帶有主觀性判斷成分的任務)，才退而求其次依靠文字層面自我批評這種相對較不可靠的機制」，展現你能把之前建立的核心告誡(重視客觀執行結果而非只信任主觀文字)融會貫通地應用到自我修正機制可靠性這個新的實務問題上。

**面試回答方式**：先給出核心答案並舉例——「有一個更客觀可驗證的做法，是盡可能運用可以被客觀執行驗證的具體檢驗手段，例如如果Agent產出的是程式碼，與其只讓模型用文字評論看起來是否正確，更穩健的做法是實際執行這段程式碼或對應測試案例，依照實際執行後得到的客觀結果來判斷是否需要修正」。連結到之前的核心告誡——「這呼應了之前ReAct章節已經討論過的核心告誡——不應該只因展開的文字讀起來合理通順就過度信任，而應該更重視客觀可驗證的實際執行結果，單純的文字層面自我批評同樣繼承了展開文字未必完全忠實反映真實情況這個潛在風險」。給出實務設計啟示——「設計Agent系統的自我修正機制時，應該優先考量任務性質是否允許客觀可驗證的檢驗手段，如果存在就應該優先採用，只有任務本身確實不允許這種客觀驗證方式時(例如帶有主觀判斷成分的行銷文案撰寫)，才退而求其次依靠文字層面自我批評這種相對較不可靠的機制」。
