# 題目

Agent 系統的「自主性」，是不是一種**只有『全自動』和『需要人類逐步操作』這兩個極端**的二選一選項？實務上應該如何理解 Agent 自主性這個概念所涵蓋的完整光譜？

## 核心答案

Agent 系統的自主性**並不是**一種只有**『完全自動、不需要任何人類介入』**和**『每一步都需要人類親自操作』**這兩個極端選項的二選一，而是一個**連續的光譜**——在這個光譜的一端是**傳統的、完全依靠人類親自執行每一個步驟**的工作方式（這裡 AI 可能只是作為一個被動的工具，回答人類主動提出的具體問題）；沿著這個光譜逐步往另一端移動，會依序經過——**AI 能夠針對單一個具體的子任務自主地執行，但每一個較大的步驟都需要人類明確地確認才能繼續**；**AI 能夠自主地規劃、執行一整串涉及多個步驟的子任務，只有在遭遇特別高風險或高度不確定性的關鍵節點才需要人類介入**（這正是前面（見 [[011-human-in-the-loop.md]]）已經深入討論過的 Human-in-the-Loop 設計）；一直到光譜最末端的**完全自主——Agent 自己獨立地規劃、執行、甚至自己判斷任務是否已經妥善完成，人類只需要事後審視最終結果**。理解自主性是一個**連續的光譜、而非二元選項**這件事情帶來一個相當重要的實務啟示——**在設計、部署一個實際的 Agent 系統時，並不需要一律追求『達到光譜最末端的完全自主』這個目標**，而應該**依照這個具體任務本身的風險程度、以及目前這個系統的可靠性已經得到多充分的驗證**，去選擇**恰當的、落在這個光譜某一個合適位置**的自主性程度。

## 詳細解析

**Agent 自主性光譜的具體階層——一個常見的參考框架**：業界實務上經常會用**類似於自駕車領域裡用來描述自動駕駛能力等級**的分級思路去描述 Agent 系統的自主性層級，大致可以被理解成幾個漸進的階段——**(1) 輔助階段**：AI 只是扮演一個**被動的建議者**，針對人類提出的具體問題或請求提供回答或建議，但**所有的實際行動都需要人類自己去執行**（這某種程度上就是前面（見 [[001-agent-fundamentals.md]]）已經深入討論過的『單純的一次性問答互動』，還稱不上是一個真正的 Agent）；**(2) 半自主階段**：AI 能夠**自主地執行某些具體的行動**（例如運用前面（見 [[../ai-llm/022-function-calling.md]]）已經深入討論過的 Function Calling 能力），但在**每一個較關鍵的節點**都需要明確的人類確認才能繼續；**(3) 條件式自主階段**：AI 能夠**自主地完成一整段涉及多個步驟的任務**，只有在遭遇**特別高風險、或者 AI 自己對判斷結果信心度較低**的情境下才主動地暫停、尋求人類的協助或確認（這正是前面（見 [[011-human-in-the-loop.md]]）已經深入討論過的 Human-in-the-Loop 機制所對應的自主性層級）；**(4) 完全自主階段**：AI **在絕大多數情況下**都能夠獨立地完成整個任務，人類主要只是**事後審視最終的結果**、或者**設定一些高層次的整體目標和限制**，而不需要介入任何具體的執行細節。

**判斷應該選用哪一種自主性層級的核心考量——任務的風險程度，以及系統可靠性已經得到多充分的驗證**：實務上決定一個具體的 Agent 應用應該被設定在這個光譜的哪一個位置，主要取決於幾個核心考量——**(1) 這個任務本身的風險程度**：這直接呼應了前面（見 [[../ai-llm/023-prompt-injection.md]]、[[011-human-in-the-loop.md]]）已經反覆深入討論過的核心原則——**任務本身涉及越高的風險（如金錢交易、刪除重要資料），就越應該被設定在光譜裡越靠近『需要較多人類介入』的那一端**；而**風險相對較低、或是即使出錯也容易被復原修正**的任務（例如單純的資訊查詢彙整）則可以考慮被設定在**更加靠近自主的那一端**；**(2) 這個系統的可靠性已經得到多充分的實際驗證**：這呼應了前面（見 [[013-agent-evaluation.md]]）已經深入討論過的評估方法論——一個**剛被建構出來、還沒有經過長期、大量實際運作驗證**的新 Agent 系統，即使它處理的任務本身風險相對不算太高，在**初期導入**的階段依然適合**保守地被設定在光譜裡相對較需要人類介入的位置**，只有隨著這個系統經過**足夠長時間、足夠大量的實際運作驗證**證實它確實能夠**穩定、可靠地**勝任，才逐步地**朝著更加自主的方向往光譜的另一端移動**。

**「動態調整自主性層級」——不是一次性決定，而是可以隨著情境持續調整**：一個值得被特別強調的重要認知是——**一個具體的 Agent 應用被設定的自主性層級並不是一個一旦決定就永久固定不變**的靜態設定，而是**可以（也應該）依照實際的執行情境動態地被調整**——這某種程度上呼應了前面（見 [[003-planning-task-decomposition.md]]）已經深入討論過的核心概念——即使一個 Agent 系統**平時**被設定為**相對較自主**的運作模式，一旦它在執行過程中**偵測到某個特別異常、高度不確定、或者超乎預期的情況**，它依然應該**具備主動地暫時降低自己的自主程度、額外地尋求人類介入**的能力（而不是僵化地堅持**固守一開始被設定好的那個固定自主性層級**，即使遭遇到明顯超出它正常能力範圍的異常情況，也依然堅持**完全自主地硬著頭皮繼續往下執行**）。這種**「自主性層級本身也可以動態調整」**的設計思路，讓一個 Agent 系統能夠**同時兼顧『在正常情況下盡可能地發揮自動化效率』**和**『在異常情況下依然保有恰當的安全把關機制』**這兩個同樣重要的目標。

## 面試回答方式

先明確否定二選一這個誤解——「並不是只有完全自動和需要人類逐步操作這兩個極端選項的二選一，而是一個連續的光譜」。清楚描繪這個光譜——「從人類親自執行每個步驟的傳統工作方式，到AI能自主執行單一子任務但每個較大步驟都需要人類確認，再到AI能自主規劃執行一整串多步驟任務、只在特別高風險或高度不確定的關鍵節點才需要人類介入(這正是之前討論過的Human-in-the-Loop設計)，一直到光譜末端的完全自主、人類只需事後審視最終結果」。可以補充判斷應該選用哪個層級的核心考量——「主要取決於這個任務本身的風險程度，風險越高就應該被設定在越靠近需要較多人類介入的一端;以及這個系統的可靠性已經得到多充分的實際驗證，一個剛建構出來還沒經過長期驗證的新系統，即使任務風險不算太高，在初期導入階段也適合保守地設定在較需要人類介入的位置」。一定要提到動態調整這個重要認知——「自主性層級並不是一次性決定、永久固定不變的靜態設定，而是可以依照實際執行情境動態調整，即使平時被設定為相對自主的運作模式，一旦偵測到特別異常或高度不確定的情況，依然應該具備主動暫時降低自主程度、額外尋求人類介入的能力」，展現你對Agent自主性這個概念，有超越二元對立、更加細緻和動態的理解。

## 常見追問

### 如果一個 Agent 系統一開始被設定在相對較為保守、需要較多人類介入的自主性層級，隨著時間累積越來越多成功的實際運作經驗，是不是就應該自動地持續朝著更加自主的方向調整？

**核心答案**：**不應該是一種『自動、無條件』地持續朝向更自主方向調整的機制**——雖然前面已經建立的核心認知是**隨著系統的可靠性得到越充分的驗證，確實可以考慮逐步地朝向更加自主的方向調整**，但這種調整**應該是一個經過審慎評估、且仍然保有人類最終決策權**的過程，而**不應該被設計成一種完全自動化、只要累積到某個成功次數的門檻就自動地觸發自主性層級提升**這樣的機制——核心原因在於——**過去的成功經驗再多，也沒有辦法保證未來一定不會遭遇到先前累積的所有經驗裡都從未出現過的全新情境或風險**；如果**自主性層級的提升**本身是一個**完全不需要人類再次審慎評估、只是機械式地依照某個數字門檻**就自動觸發的過程，這某種程度上**反而會削弱人類對這整個自主性調整過程本身所應該保有的審慎監督和把關**。

**詳細解析**：這題考察是否能避免把「隨著可靠性驗證的累積，可以考慮調整自主性層級」這個核心認知**誤解、簡化成一種可以被完全自動化執行的機制**，而能夠理解**「自主性層級本身的調整決策」**某種程度上**也屬於一種需要人類保有最終把關權力**的**元層次（Meta-level）**決策。理解這個問題的核心在於回顧前面（見 [[013-agent-evaluation.md]]）已經深入討論過的核心洞察——**「測試環境（或者這裡是過去已經累積的實際運作經驗）和真實情況（未來可能遭遇到的全新情境）之間可能存在分佈落差」**——**「過去已經發生過的 N 次成功經驗」****終究**是**基於過去已經實際發生過的具體情境**所累積而來的證據，這種證據**確實能夠提供一定程度的信心**去支持『這個系統具備一定程度的可靠性』這個判斷，但這種證據**並不能被用來做出一個絕對保證未來不會遭遇到任何全新意外情況**的宣稱——如果**「自主性層級的提升」**被設計成**一個只要累積到某個預先設定的成功次數門檻，就自動地、不再需要人類額外審視判斷**就會觸發的機械式流程，這種設計某種程度上**隱含地假設****『過去的成功經驗本身已經足夠充分地代表和涵蓋了未來可能遭遇到的所有情境』**這個**未必成立**的前提。一個**更加審慎、負責任**的做法應該是**把『是否要調整這個 Agent 系統的自主性層級』這個決策本身也視為一個需要人類主動地去進行審慎評估、綜合考量（不只是單純看過去成功次數這個單一指標，還需要額外考量這個任務本身的風險性質是否有所改變、外部環境是否出現新的變化等等更全面的因素）**的重要決策，而不是把這個**攸關整個系統安全性的關鍵決策****完全交由一個單純依照過去成功次數這個單一量化指標**就自動地去決定的機械式流程。理解「不應該是一種自動、無條件地持續朝向更自主方向調整的機制，雖然隨著系統可靠性得到越充分驗證，確實可以考慮逐步朝向更自主的方向調整，但這種調整應該是一個經過審慎評估、且仍然保有人類最終決策權的過程，核心原因在於過去的成功經驗再多，也沒辦法保證未來一定不會遭遇到先前累積的所有經驗裡都從未出現過的全新情境或風險，這呼應了測試環境和真實情況之間可能存在分佈落差這個核心洞察，如果自主性層級的提升被設計成只要累積到某個成功次數門檻就自動觸發的機械式流程，這種設計隱含地假設過去成功經驗本身已經足夠充分代表和涵蓋未來可能遭遇的所有情境，這個前提未必成立，更審慎負責任的做法是把是否調整自主性層級這個決策本身也視為一個需要人類主動進行審慎評估、綜合考量多個因素的重要決策，而不是完全交由單純依照過去成功次數這個單一量化指標就自動決定的機械式流程」，展現你能把之前已經建立的測試與真實情況分佈落差這個核心洞察，遷移應用到自主性層級調整這個更高層次的元決策上。

**面試回答方式**：先明確給出核心答案——「不應該是一種自動、無條件地持續朝向更自主方向調整的機制，雖然隨著系統可靠性得到充分驗證確實可以考慮逐步調整，但這種調整應該是一個經過審慎評估、且仍然保有人類最終決策權的過程」。解釋核心原因並連結之前的洞察——「過去的成功經驗再多，也沒辦法保證未來一定不會遭遇到先前累積經驗裡都從未出現過的全新情境或風險，這呼應了測試環境和真實情況之間可能存在分佈落差這個核心洞察，如果自主性層級提升被設計成只要累積到某個成功次數門檻就自動觸發，這隱含假設過去成功經驗已經足夠代表未來所有情境，這個前提未必成立」。給出更審慎的做法——「更負責任的做法是把是否調整自主性層級這個決策本身，也視為一個需要人類主動進行審慎評估、綜合考量任務風險性質變化、外部環境變化等多個因素的重要決策，而不是完全交由單一量化指標自動決定」。

### 不同的任務、或者不同的使用者，是不是可以分別被設定不同的自主性層級？還是一個 Agent 系統整體只能有單一的自主性設定？

**核心答案**：**完全可以，且實務上通常也應該依照不同的任務性質、或者不同的使用者情境，分別設定不同的自主性層級**，而**不是**讓一個 Agent 系統整體只套用**單一固定不變**的自主性設定——這某種程度上直接呼應了前面（見核心答案和詳細解析）已經建立的核心判準——**「應該依照這個具體任務本身的風險程度去決定恰當的自主性層級」**——既然**不同的具體任務**本來就可能涉及**截然不同的風險程度**，讓這些**風險程度顯著不同**的任務都被**強制套用同一套固定的自主性設定**本身就**不夠合理**。一個**更加細緻、恰當的做法**是**依照每一個具體的任務類型（甚至可以進一步地依照不同的使用者、或者不同的使用情境）各自獨立地設定最適合那個具體情境的自主性層級**。

**詳細解析**：這題把前面已經建立的『自主性是一個光譜』這個核心概念進一步延伸，考察是否理解這個**光譜上的具體定位****不應該是一個套用在整個 Agent 系統的單一全域設定**，而是**應該能夠被更加細緻地依照不同的具體情境做各自獨立的客製化設定**。理解這個問題的核心在於回顧前面已經反覆強調的核心原則——**「不同性質的任務本來就可能涉及截然不同的風險程度」**——這個核心原則本身就**隱含著****「不同性質的任務理應對應不同的自主性設定」**這個推論——舉例來說，同一個 Agent 系統如果同時被賦予**「幫使用者查詢、彙整一些公開的參考資訊」**、以及**「幫使用者執行一筆實際的金錢交易」**這**兩種風險程度天差地遠**的不同任務類型，**理應針對這兩種不同性質的任務****各自獨立地設定截然不同的自主性層級**（前者可能適合被設定在光譜裡**相對較自主**的位置；而後者則**理應**被設定在光譜裡**相對較需要人工介入確認**的位置）。如果**強制要求**這**兩種風險程度截然不同的任務**都**必須套用同一套固定的自主性設定**，這**要嘛**會導致**那個風險相對較低的任務**被**不必要地過度設限**（明明風險不高，卻也被要求每一步都需要繁瑣的人工確認）；**要嘛**會導致**那個風險相對較高的任務**被**危險地過度放寬**（明明涉及重大的風險，卻因為需要遷就另一個較低風險任務所適用的自主性設定，而也被允許用相對較自主、缺乏足夠人工把關的方式去執行）——這兩種情況都**不是理想的架構設計**。因此一個**更加成熟、精細的 Agent 系統架構**應該具備**「依照不同任務類型（甚至不同使用者情境）各自獨立地設定對應自主性層級」**這種**更加細緻、可配置**的能力，而不是**只能用單一個全域、不加區分**的自主性設定去涵蓋這個系統可能需要處理的**所有不同性質的任務**。這種**「依照具體情境做細緻的差異化配置」**的思路某種程度上也呼應了這篇文章反覆強調的一個核心工程智慧——**「一體適用的單一標準很少是最理想的架構選擇，恰如其分地依照不同情境的實際需求做差異化的客製設計，通常才是更加成熟、細緻的做法」**。理解「完全可以且實務上通常也應該依照不同任務性質或不同使用者情境分別設定不同的自主性層級，這直接呼應了應該依照任務本身風險程度決定恰當自主性層級這個核心判準，既然不同具體任務本來就可能涉及截然不同的風險程度，強制套用同一套固定自主性設定並不合理，如果強制要求風險程度截然不同的任務都套用同一套設定，要嘛會導致風險較低的任務被不必要過度設限，要嘛會導致風險較高的任務被危險地過度放寬，一個更成熟精細的Agent系統架構應該具備依照不同任務類型甚至不同使用者情境各自獨立設定對應自主性層級的細緻可配置能力，這呼應了一體適用的單一標準很少是最理想架構選擇、恰如其分地依照不同情境實際需求做差異化客製設計通常才是更成熟做法這個核心工程智慧」，展現你能把自主性光譜這個核心概念，延伸應用到系統架構的細緻化差異配置設計，而非把它當成一個套用在整個系統的單一全域設定。

**面試回答方式**：先明確給出核心答案——「完全可以，且實務上通常也應該依照不同任務性質或不同使用者情境，分別設定不同的自主性層級，而不是讓整個系統套用單一固定不變的設定」。用具體例子解釋為什麼——「同一個Agent系統如果同時被賦予查詢彙整公開參考資訊、以及執行實際金錢交易這兩種風險程度天差地遠的任務類型，理應針對這兩種不同性質的任務各自獨立設定截然不同的自主性層級」。指出強制統一設定的問題——「如果強制要求都套用同一套固定設定，要嘛會導致風險較低的任務被不必要過度設限，要嘛會導致風險較高的任務被危險地過度放寬，這兩種情況都不是理想的架構設計」。給出結論——「一個更成熟精細的Agent系統架構應該具備依照不同任務類型甚至不同使用者情境各自獨立設定對應自主性層級的細緻可配置能力，這呼應了恰如其分地依照不同情境做差異化客製設計，通常才是更成熟做法這個核心工程智慧」。

### 「自主性層級越高」是不是就代表這個 Agent 系統能力越強、越先進？應該以「盡量追求更高的自主性層級」作為設計 Agent 系統的目標嗎？

**核心答案**：**不應該，這是一個相當常見、但需要被明確糾正的誤解**——**「自主性層級」**和**「Agent 系統本身的能力是否先進、強大」**是**兩個不完全相關**的不同面向——一個被**恰當地設定在較保守自主性層級**的 Agent 系統，它**背後運用的模型和技術依然可以是最先進、最強大**的；反過來，一個被設定在**極端自主**層級的系統也**不必然**代表它背後的技術特別先進（甚至可能是一種**魯莽、缺乏審慎考量**的設計決策）——**自主性層級真正應該被決定的依據**是前面（見核心答案和詳細解析）已經深入討論過的**「任務本身的風險程度，以及系統的可靠性已經得到多充分的驗證」**，而**不是**一個用來**炫耀技術先進程度**的指標。因此**「盡量追求更高的自主性層級」****不應該**被當成設計 Agent 系統時的一個**理所當然的目標**，恰當的目標應該是**「讓自主性層級恰如其分地對應到這個任務實際的風險程度和系統可靠性現況」**。

**詳細解析**：這題要求明確地**破除**一種在實務上相當常見的**認知誤區**——把**「Agent 的自主性層級」**錯誤地等同於**「這個 Agent 系統的整體能力或先進程度」**，考察是否能夠理解**這兩個概念實際上是處於不同的評估維度**，而不是**單一、可以被互相替代**的同一件事。理解這個問題的核心在於重新釐清——**「自主性層級」**衡量的是**「這個系統在多大程度上被允許不需要人類介入而獨立地做決策」**這件事本身，這是一個**關於『系統設計者選擇把多少決策權賦予這個系統』**的**設計選擇**，而**不是**一個**衡量這個系統本身實際具備多強大能力**的指標——一個**背後運用著最先進、最強大的大型語言模型**的 Agent 系統，完全可以**基於審慎的風險考量**而被**刻意地設計成只具備相對保守的自主性層級**（例如即使這個模型本身的能力已經強大到理論上完全有能力去自主地完成某個複雜任務，但因為這個具體任務涉及著相當高的風險（如前面已經反覆討論的金錢交易或刪除資料），設計者依然**審慎地選擇**保留人工的最終確認關卡）——這種**「明明有能力可以更自主，但出於審慎考量刻意選擇保留人工把關」**的設計決策某種程度上**恰恰反映了一種更加成熟、負責任的工程判斷**，而**不是**一種**能力不足的表現**；反過來，如果一個 Agent 系統**不論任務的實際風險程度如何**都**一律追求儘可能提升自主性層級**，這種**不加區分、一味追求自主**的做法某種程度上**反而可能是**一種**忽略了前面（見 [[../ai-llm/023-prompt-injection.md]]）已經深入討論過的安全性考量、魯莽而非真正成熟**的設計決策。這種認知的釐清帶來一個相當重要的實務啟示——在**評估、或者設計一個 Agent 系統**時**不應該**把**「這個系統的自主性層級設定得多高」**當作一個**值得被追求、拿來炫耀的正面指標**，而應該把**「這個系統的自主性層級設定是否真的恰如其分地對應了這個具體任務的實際風險程度、以及系統目前可靠性已經得到驗證的程度」**作為**評判這個自主性設定是否合理、負責任**的**真正核心標準**。理解「不應該，這是一個常見但需要被糾正的誤解，自主性層級和Agent系統本身能力是否先進強大，是兩個不完全相關的不同面向，一個被恰當設定在較保守自主性層級的系統，它背後運用的模型和技術依然可以是最先進強大的，自主性層級真正應該被決定的依據是任務本身的風險程度以及系統可靠性已經得到多充分的驗證，而不是一個用來炫耀技術先進程度的指標，盡量追求更高自主性層級不應該被當成設計目標，恰當的目標應該是讓自主性層級恰如其分地對應到這個任務實際的風險程度和系統可靠性現況，一個明明有能力可以更自主但出於審慎考量刻意選擇保留人工把關的設計決策，恰恰反映了一種更成熟負責任的工程判斷，而不是能力不足的表現;反過來不論任務實際風險程度如何都一律追求儘可能提升自主性層級，反而可能是一種忽略安全性考量、魯莽而非真正成熟的設計決策」，展現你能明確破除自主性層級和系統能力先進程度混為一談這個常見認知誤區。

**面試回答方式**：先明確給出核心答案並破除誤解——「不應該，這是一個常見但需要被糾正的誤解，自主性層級和Agent系統本身能力是否先進強大，是兩個不完全相關的不同面向」。給出具體說明——「一個被恰當設定在較保守自主性層級的系統，它背後運用的模型和技術依然可以是最先進的，自主性層級真正應該依據的是任務本身的風險程度以及系統可靠性已經得到多充分驗證，而不是一個用來炫耀技術先進程度的指標」。給出更深刻的洞察——「一個明明有能力可以更自主、但出於審慎考量刻意選擇保留人工把關的設計決策，恰恰反映了一種更成熟負責任的工程判斷，而不是能力不足的表現;反過來不論任務風險程度如何都一律追求提升自主性層級，反而可能是忽略安全性考量、魯莽而非真正成熟的設計決策」。給出恰當的設計目標——「恰當的目標應該是讓自主性層級恰如其分地對應到任務實際的風險程度和系統可靠性現況，而不是盡量追求更高的自主性層級」。
