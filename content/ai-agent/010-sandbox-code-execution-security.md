# 題目

當一個 Agent 被賦予**實際執行程式碼**這種能力時（例如讓 Agent 自己撰寫並執行一段 Python 程式碼，來完成某個數值計算或資料處理任務），為什麼這種能力需要被放在一個**「沙箱（Sandbox）」**環境裡執行，而不能直接在主系統上執行？

## 核心答案

沙箱指的是一個**經過嚴格，隔離、限制的執行環境**，讓在這個環境裡，執行的程式碼，**即使，這段程式碼，本身帶有惡意、或者因為，某種原因(不管是，模型產生幻覺、或是遭到前面(見 [[../ai-llm/023-prompt-injection.md]])已經，深入討論過的Prompt Injection攻擊，而被誘導)做出具有，破壞性的行為，這種破壞性行為所能，造成的實際損害範圍，都會被嚴格地限制在這個，隔離環境內部**，而**不會波及到執行，這個Agent的主系統、或者，主系統所能，存取到的其他敏感資源**。之所以需要這種隔離，的核心原因，在於——**大型語言模型，本質上是依照某種，機率性的判斷，和生成過程去產出程式碼它並不具備一種能夠保證百分之百正確、且絕對不會產生任何，意外或惡意行為**的機制(這，某種程度上，呼應了前面已經反覆，深入討論過的，**模型存在，幻覺的可能性、以及，容易遭受，Prompt Injection攻擊**這，兩個核心風險)，如果讓這種**本質上存在著一定機率會產出，不正確或惡意內容**的模型，所，生成的程式碼，**直接在主系統上不加任何限制地被執行**一旦，這段程式碼，真的出現，問題(不管是，無心的錯誤，還是被惡意誘導)可能會對主系統造成**難以挽回，的實際損害**(例如，刪除，重要的系統檔案、竊取，敏感資訊、或者，被用來作為進一步，攻擊其他系統的跳板)，沙箱這種隔離機制正是作為**在享受，Agent，自主，執行程式碼，這種能夠大幅提升，任務處理能力的效益的同時，把這種能力所，隱含的固有風險，控制在一個可以被，接受的範圍內**的關鍵安全防線。

## 詳細解析

**沙箱的典型技術實作方式——容器化，和，虛擬機器隔離**：實務上，實作一個**能夠提供，足夠隔離強度**的沙箱環境，常見的技術手段，包括——**(1) 容器化(Containerization)**：運用，類似，**容器**這類技術，讓，Agent，執行的程式碼，被限制在一個**擁有，獨立的檔案系統、網路，存取權限受到，嚴格控制**的隔離環境裡執行，即使，這段程式碼，嘗試去存取或修改某些檔案它實際上，能觸及到的，只是這個容器內部獨立的、和主系統，**互相隔離**的檔案系統，而**不會直接影響到**主系統，真正的檔案系統；**(2) 虛擬機器(Virtual Machine)隔離**：提供，比容器化**更徹底，一層**的隔離強度——透過，運用，完整的虛擬機器技術，讓被，執行的程式碼，運行在一個**在硬體層次就被，隔離**的獨立虛擬環境裡，這種隔離強度通常比容器化更高(因為容器化通常依然會和，主系統的作業系統核心，共享，一定程度的底層資源；而，完整的虛擬機器，則具備**自己，獨立的作業系統核心**)，但相對地，**啟動、運行的成本(運算資源和時間開銷)，也通常更高**。

**沙箱需要，限制的具體維度——不只是，檔案系統還包括，網路存取、運算資源**：一個，妥善，設計的沙箱環境，需要**同時限制多個，不同的維度**，而不是只考量，**單一個**面向——**(1) 檔案系統存取範圍**：限制，這段程式碼，只能存取某個**明確，劃定範圍**內的檔案(例如，只能存取和這一次具體任務，相關的暫存資料夾，而不能觸及主系統上其他，不相關的敏感檔案)；**(2) 網路存取權限**：這，是一個**特別需要被，重視**的維度——如果，沙箱環境完全不設限任何，對外的網路連線，一段被，執行的惡意程式碼，理論上就可能**利用這個網路連線能力**去把它在，沙箱環境裡，可能，取得的任何，敏感資訊(即使，只是這個沙箱環境本身內部相對，有限的資訊)，**外洩傳送到一個攻擊者，控制的外部伺服器**，或者被用來作為**攻擊其他，外部系統**的跳板，因此，實務上一個，**謹慎設計的沙箱**，通常會**預設完全禁止，對外的網路連線**(或者，最多只允許存取一份事先明確，列出的、經過，信任審核的特定網域清單)；**(3) 運算資源上限**：限制，這段程式碼，**能夠，使用的CPU運算量、記憶體用量、以及，最長執行時間**避免一段(不管是因為邏輯錯誤而無窮迴圈、還是被，惡意設計來，消耗大量資源)的程式碼，**無限制地，佔用系統資源**，影響整個系統或者其他正在同時，運行的其他任務。

**沙箱和，前面已經深入討論過的『權限最小化原則』之間的核心關聯**：沙箱，這個具體的技術實作，某種程度上，可以被理解成前面(見 [[../ai-llm/023-prompt-injection.md]])已經，深入討論過的**「權限最小化原則」**，在，**「執行程式碼」這個，具體能力**上，的一個,**極致展現**——**權限最小化原則**，主張**任何一個被賦予某項，能力的元件，都應該只被賦予完成它被，賦予的具體任務，所真正，必要的最小權限範圍**，而沙箱環境正是**針對,『執行程式碼』這個，能力，特別強大、風險，也，特別高的具體能力**，去**具體地落實，這個原則**——透過，把，這段被執行的程式碼，**能夠實際，存取到的範圍(檔案、網路、運算資源)，都嚴格地限縮在一個，明確、狹窄的邊界之內**，即使，這段程式碼，**因為，任何原因(無心的疏失，或者被惡意誘導)**試圖去做一些超出它，被賦予的具體任務，所真正，需要的範圍之外的事情(例如，試圖去讀取一份和這次任務完全，不相關的敏感檔案)，這種嘗試會因為**沙箱環境本身，的隔離限制**，而**根本無法，得逞**——這種，「透過，技術性的隔離手段，去**強制性地，物理層次地，落實，權限最小化這個設計原則**，而不是只依靠**期望模型自己主動克制不做，超出範圍的事情**」的做法，是沙箱這種機制之所以能夠提供**遠比單純依靠模型，自身的判斷或指令約束**，更加**可靠、值得，信賴**的安全保障的核心原因。

## 面試回答方式

先給出沙箱的核心定義——「一個經過嚴格隔離限制的執行環境，讓在裡面執行的程式碼，即使本身帶有惡意或做出破壞性行為，這種破壞性行為所能造成的實際損害範圍都會被嚴格限制在這個隔離環境內部，不會波及執行這個Agent的主系統或主系統能存取到的其他敏感資源」。詳細解釋核心原因——「大型語言模型本質上是依照機率性判斷去產出程式碼，並不具備能保證百分之百正確、絕對不會產生任何意外或惡意行為的機制，這呼應了之前反覆討論過的模型存在幻覺可能性、以及容易遭受Prompt Injection攻擊這兩個核心風險，如果讓這種本質上存在一定機率會產出不正確或惡意內容的模型所生成的程式碼直接在主系統上不加限制地執行，一旦出問題可能對主系統造成難以挽回的實際損害」。可以補充沙箱需要限制的多個維度——「不只是檔案系統存取範圍，還包括網路存取權限(避免敏感資訊外洩或被用作攻擊跳板)、以及運算資源上限(避免無限制佔用系統資源)」。可以連結到權限最小化原則收束——「沙箱可以被理解成權限最小化原則在執行程式碼這個具體能力上的極致展現，透過技術性的隔離手段強制性地落實這個原則，而不是只依靠期望模型自己主動克制，這是沙箱能提供遠比單純依靠模型自身判斷或指令約束更可靠安全保障的核心原因」，展現你對沙箱機制的技術實作、防護維度、以及背後的核心安全設計原則有完整且深入的理解。

## 常見追問

### 如果，一個Agent，被賦予「可以自己安裝，額外的第三方套件庫，再，執行程式碼」這種能力，這會比單純執行已經，寫好的程式碼，多出哪些，額外的安全考量?

**核心答案**：**會，多出一個相當關鍵、且需要被特別審慎，對待的額外風險——「供應鏈安全(Supply Chain Security)」風險**——如果，Agent，被賦予了**自主地去安裝任何它判斷，需要用到的第三方套件**這種能力，這意味著這個，Agent，**實質上具備了把，任意的、來自，外部套件庫(可能是，一個，公開的套件登錄庫)的程式碼，引入並，執行**的能力，如果其中**某一個被，安裝的第三方套件，本身就是，惡意的**(不管是，一開始就是攻擊者刻意，發布的惡意套件；還是一個原本，正常的套件，後來被攻擊者入侵、植入，惡意程式碼)，這意味著即使沙箱本身，的隔離機制，設計得再完善這個**惡意套件本身，所帶來的破壞行為**，依然**會在這個，沙箱環境的隔離範圍內**，實際地被，觸發、執行——**沙箱，能夠限制的是『這個破壞行為所能，波及、影響到的範圍』，但不能防止『這個惡意行為本身在沙箱裡，被觸發、執行』**這件事本身。

**詳細解析**：這題，要求把沙箱這個，核心安全機制，**放在一個更，完整的攻擊面**裡，去重新審視考察是否理解**沙箱雖然是一道相當，重要的防線，但它並不是唯一需要被，考量的安全維度**，而「引入，第三方套件」這件事，某種程度上，**開啟了一個沙箱本身並不直接，處理的全新攻擊面**。理解這個問題的核心在於重新釐清沙箱這個機制究竟**在保護，什麼**——沙箱，主要，處理的問題，是——**『如果，被，執行的這段程式碼，行為出現異常這種異常行為所能波及，影響的範圍，應該被限制在哪裡』**，但沙箱**並不會改變、也無法直接，防止**——**『這段，程式碼(或者，這段程式碼額外引入，使用的第三方套件)，本身的內容是善意還是，惡意』**這件事，換句話說，沙箱是一種，**『事後、圍堵型』**的防禦手段(它，假設可能會有某些異常行為發生然後，去限制這些異常行為所能，造成的實際損害範圍)；而，**「第三方套件，本身是否，帶有惡意」**這個問題，需要額外的，**『事前、預防型』**的防禦手段，去，處理——例如，**在允許一個套件被，安裝、引入之前，先對這個套件做，某種程度的安全審查或信任驗證**(例如，只允許從一份事先經過，審核、列為信任的套件清單裡，去安裝套件而不是讓，Agent，可以任意地從任何未經，審查的來源，去安裝任何套件)這種**「沙箱處理，執行時的異常行為圍堵；套件信任審查，處理引入內容，本身的安全性把關」**，是**两種性質不同、但都需要同時被妥善，考量**的安全防護層次，如果，一個Agent系統，**只仰賴，沙箱**這道防線，卻**完全不設限可以任意地從任何，未經審查的來源，去安裝、引入任何，第三方套件**，即使這個沙箱本身，的隔離機制，設計得再嚴密這個系統依然**存在被惡意套件實際，滲透、觸發攻擊行為**的風險(只是，這個惡意行為所能，波及的**外部範圍**，因為，沙箱的隔離，而被限制住，但沙箱**內部**實際上，已經遭到，這個惡意套件的實質破壞，如果，這個沙箱環境，本身內部也，儲存或處理著，某些對，這一次具體任務，而言，重要的敏感資訊，這些資訊依然可能在沙箱內部這個**已經遭到惡意套件，污染**的範圍內，被，竊取或破壞)。理解「會多出一個相當關鍵的供應鏈安全風險，如果Agent被賦予自主安裝任何第三方套件的能力，實質上具備了把任意來自外部套件庫的程式碼引入並執行的能力，如果某個被安裝的套件本身就是惡意的，即使沙箱本身設計得再完善，這個惡意套件所帶來的破壞行為依然會在沙箱環境的隔離範圍內實際被觸發執行，沙箱能限制的是這個破壞行為所能波及影響到的外部範圍，但不能防止這個惡意行為本身在沙箱裡被觸發執行，沙箱是一種事後圍堵型的防禦手段，而第三方套件本身是否帶有惡意這個問題需要額外的事前預防型防禦手段去處理，例如在允許套件被安裝前先做安全審查或信任驗證，這兩種性質不同的防護層次都需要同時被妥善考量」，展現你理解沙箱這個核心機制的實際防護邊界，並能識別出引入第三方套件這件事開啟的、沙箱本身並不直接處理的全新攻擊面。

**面試回答方式**：先給出核心答案——「會多出一個相當關鍵的供應鏈安全風險，如果Agent被賦予自主安裝任何第三方套件的能力，實質上具備了把任意來自外部套件庫的程式碼引入並執行的能力，如果某個被安裝的套件本身就是惡意的，即使沙箱設計得再完善，這個惡意套件的破壞行為依然會在沙箱環境的隔離範圍內實際被觸發執行」。釐清沙箱的實際防護邊界——「沙箱能限制的是這個破壞行為所能波及影響到的外部範圍，但不能防止這個惡意行為本身在沙箱裡被觸發執行，沙箱是一種事後圍堵型的防禦手段，而第三方套件本身是否帶有惡意需要額外的事前預防型防禦手段去處理」。給出具體因應做法——「例如只允許從一份事先經過審核、列為信任的套件清單裡安裝套件，而不是讓Agent可以任意從任何未經審查的來源安裝任何套件，沙箱處理執行時的異常行為圍堵、套件信任審查處理引入內容本身的安全性把關，這兩種性質不同的防護層次都需要同時被妥善考量」。

### 如果，沙箱的隔離做得，非常徹底是不是就可以完全不用擔心，Agent，執行程式碼，這件事，的安全風險了?

**核心答案**：**即使，沙箱的隔離做得非常徹底依然不能說『完全不用擔心任何，安全風險』**——沙箱，能夠有效地**限制，惡意或異常行為，所能，波及到的外部範圍**，但它**無法防止**幾類仍然值得被，重視的風險——**(1) 資訊，可能透過，合法、被允許的管道，洩漏**——即使，網路存取被嚴格限制如果這個沙箱環境**依然被允許透過某種，合法的管道(例如，把執行結果回傳給呼叫，這個沙箱的主系統)，去傳遞某些資訊**一個被刻意設計，的惡意程式碼，依然可能**巧妙地利用這個唯一被，允許的合法回傳管道**，去把一些**原本不應該被，洩漏的敏感資訊**，夾帶在看似，正常的執行結果裡，傳遞出去；**(2) 沙箱環境本身，可能存在，未被發現的漏洞**——沙箱，技術，本身(不管是，容器化還是虛擬機器)終究是**由人類開發者撰寫，出來的軟體**，理論上**同樣可能存在某些尚未被，發現的安全漏洞**，一旦攻擊者找到並利用這種漏洞就有可能，**『逃逸(Escape)』出，這個原本應該是，隔離的沙箱環境**，直接影響到主系統；**(3) 即使行為被限制在沙箱內也可能消耗大量運算資源形成一種，資源耗盡型的攻擊**。

**詳細解析**：這題，要求對沙箱，這個核心安全機制，做**更加誠實、不，過度誇大其防護效力**的評估，考察是否能夠避免把任何一種，**單一的安全防護手段**，錯誤地當成一個**能夠提供，絕對、萬無一失保障**的萬靈丹，而能夠理解任何一種安全機制**都有它具體能夠處理的範圍以及它無法涵蓋，的剩餘風險**。理解這個問題的核心在於逐一檢視前面提到的幾個值得，留意的剩餘風險——**「合法管道，資訊洩漏」**這個風險，觸及一個相當，**微妙**的安全設計難題——一個，完全不能和外部世界有任何，溝通的沙箱環境，實際上，**也沒有辦法把它執行任務所，得到的有用結果**，傳遞出來提供給使用者(這，某種程度上，違背了讓，Agent，執行，這段程式碼，的原始目的)，因此，**必然需要保留某種，合法的、允許，資訊從沙箱傳遞到，外部的管道**，而這個**唯一，被允許的合法管道**，本身就可能被惡意地濫用(例如把本來應該只回傳一個，簡單的計算結果，改成額外地夾帶一些這個沙箱環境內部恰好能，存取到的其他敏感資訊)，這種**「即使絕大多數管道都被嚴格封鎖只要還保留著任何一個，合法的溝通出口，這個出口本身就可能成為潛在，的資訊外洩管道」**，是一個**很難被完全，根除**的固有張力；**「沙箱本身存在漏洞」**這個風險，則觸及一個更加，根本的軟體工程真理——**任何，由人類開發、撰寫，出來的軟體(不管，設計得多麼嚴謹、經過多麼，充分的測試)，理論上都無法被保證是百分之百沒有任何漏洞的**這種**『沙箱本身，也可能存在漏洞』**的可能性，某種程度上，是一種**無法被完全消除，的殘餘風險**，只能透過**持續地更新、修補，已知的漏洞、以及，採用經過充分驗證，考驗的成熟沙箱技術**，來把這種風險控制在一個相對可以被，接受的低機率水準，而不能宣稱**已經被徹底消除**這些仔細，拆解出來的剩餘風險，帶來一個，相當重要的實務啟示——**「沙箱，是一道非常重要、且，必要的核心安全防線，但它不應該被當成唯一需要，依靠的防線」**，一個真正，成熟、審慎的Agent安全架構，應該**同時搭配，多層次、彼此，互補的防護手段**(例如，前面(見 [[../ai-llm/023-prompt-injection.md]])已經，深入討論過的『對高風險操作，額外設置人工確認』、持續的安全監控和稽核、以及，**針對被允許傳遞出，沙箱的資訊，本身也做，額外的過濾和檢查**)，來共同建構一個**具備，縱深防禦(Defense in Depth)**能力，的整體安全架構，而不是把所有，的安全期望，都寄託在**單一一道沙箱，這個防線**上。理解「即使沙箱隔離做得非常徹底，依然不能說完全不用擔心任何安全風險，沙箱能有效限制惡意或異常行為所能波及的外部範圍，但無法防止資訊透過合法被允許的管道洩漏(唯一被允許的合法溝通出口本身可能被惡意濫用)、沙箱本身作為由人類開發的軟體理論上可能存在尚未被發現的安全漏洞導致逃逸、以及即使行為被限制在沙箱內也可能形成資源耗盡型攻擊，這些剩餘風險帶來的啟示是沙箱是一道非常重要且必要的核心安全防線，但不應該被當成唯一需要依靠的防線，一個真正成熟的Agent安全架構應該同時搭配多層次彼此互補的防護手段，共同建構具備縱深防禦能力的整體安全架構」，展現你對沙箱機制的防護效力，有誠實、不過度誇大的精確評估，並理解縱深防禦這個更全面的安全設計哲學。

**面試回答方式**：先明確給出核心答案——「即使沙箱隔離做得非常徹底，依然不能說完全不用擔心任何安全風險」。逐一給出仍然存在的剩餘風險——「資訊可能透過合法被允許的管道洩漏，因為沙箱總需要保留某種合法溝通出口才能把執行結果傳回，這個出口本身可能被惡意濫用夾帶敏感資訊;沙箱本身作為由人類開發的軟體，理論上可能存在尚未被發現的安全漏洞，一旦被利用就可能逃逸出隔離環境直接影響主系統;即使行為被限制在沙箱內，也可能消耗大量運算資源形成資源耗盡型攻擊」。給出核心結論——「這些剩餘風險說明沙箱是一道非常重要且必要的核心安全防線，但不應該被當成唯一依靠的防線，一個真正成熟的Agent安全架構應該同時搭配對高風險操作的人工確認、持續安全監控稽核等多層次互補的防護手段，共同建構具備縱深防禦能力的整體安全架構」。

### 沙箱，和，之前討論過的，「權限最小化原則」以外，是不是還需要考慮「這個被，執行的程式碼，實際上，會花費多少，運算成本」這個議題?

**核心答案**：**需要，這是一個相當現實、且容易被單純聚焦於安全性而，忽略的實務考量**——即使，一段程式碼本身**完全不帶有任何惡意**單純地因為，**設計不良、或者，任務本身的性質**也可能會**消耗異常，龐大的運算資源、或者，執行異常，長的時間**(例如，一段因為，邏輯上的疏漏，而陷入，無窮迴圈的程式碼；或者一段被要求處理一份遠超乎預期，龐大的資料集，的程式碼)這種**即使沒有惡意也可能帶來失控，的資源消耗**這件事情，需要**額外地透過，前面(見 核心答案和詳細解析)已經，提到的『運算資源上限』這個維度**，去明確地設下，**具體的資源使用上限(CPU、記憶體、最長，執行時間)**一旦一段被，執行的程式碼，**超出這些事先，設定好的資源上限**，就應該被**強制終止**而不是讓它無限制地持續，消耗資源。

**詳細解析**：這題，要求把沙箱環境需要，考量的維度，從，**「安全性(是否，惡意)」**這個核心角度，額外延伸到，**「資源使用效率和穩定性(即使，不惡意是否依然可能，消耗過度資源)」**這個，同樣重要,、但容易被，忽略的面向，考察是否能夠具備**更加，全面**的沙箱設計視野，而不是只狹隘地聚焦在，**『防範惡意攻擊』**這個單一面向上。理解這個問題的核心在於，認識到——**一段，程式碼之所以可能需要被額外地加以限制原因並不只是因為它可能是,『惡意』的**——**即使，一段程式碼完全出於善意、且邏輯上也沒有任何，故意的惡意企圖**，單純地因為，**邏輯上的無心疏漏(例如，一個本來應該在滿足某個條件時，終止的迴圈，因為某個邊界情況的疏漏而永遠不會被觸發導致這個迴圈無限期地持續執行)**或者因為**任務本身的規模遠超乎預期**(例如，Agent，被要求處理一份資料量遠超出，合理範圍的巨大資料集，導致這個處理過程本身需要耗費異常，大量的記憶體或運算時間)，都可能**在完全沒有任何，惡意意圖的情況下**，依然**造成實質上讓這個系統被過度佔用資源、甚至，因此，影響其他正在同時，運行的其他任務**這種，**實質上類似一種(即使並非，故意的)『阻斷服務』**的負面效果，這種風險，某種程度上，**和，前面(見 沙箱詳細解析)已經，討論過的『惡意攻擊，導致的資源濫用』，在最終，造成的實際負面效果上，其實，是相當，類似的**(不管，是因為惡意攻擊還是，單純的無心疏漏，最終都可能導致系統資源被異常過度地佔用)，只是**成因不同**(一個是，蓄意的攻擊；另一個則，只是，無心的疏漏或超乎預期的任務規模)，因此，一個**設計得足夠，周全**的沙箱環境，不應該**只考量如何防範，蓄意的惡意行為**，也應該**同時考量如何因應即使出於善意也可能，發生的『資源使用失控』**這種情況，透過**明確地設定，具體的資源使用上限，並在超出，這個上限時，強制終止**這種**「不管這個，資源消耗過度，的成因究竟是，惡意攻擊、還是，無心疏漏都一律用同一套，明確的資源上限機制，去加以，限制」**的設計思路，某種程度上，也呼應了一個在設計**任何需要考量，穩定性和可靠性**的系統時，都值得反覆，提醒自己的核心原則——**「防禦性，的資源限制機制，不應該只針對『已知可能，發生的惡意情境』，而應該作為一種，普遍性的、不，問成因的安全網去涵蓋所有可能導致，資源被過度消耗的情況，不管這個情況，背後的原因，究竟是什麼」**。理解「需要考量這個議題，即使一段程式碼完全不帶有任何惡意，單純因為設計不良或任務本身性質，也可能消耗異常龐大的運算資源或執行異常長時間，例如陷入無窮迴圈或處理遠超預期的龐大資料集，這種即使沒有惡意也可能帶來失控資源消耗的情況，需要透過明確設定具體資源使用上限(CPU、記憶體、最長執行時間)並在超出時強制終止來因應，這種即使成因不同(惡意攻擊vs無心疏漏)最終造成的實質負面效果卻相當類似的現象，說明一個設計周全的沙箱環境不應只考量防範蓄意惡意行為，也應同時考量即使出於善意也可能發生的資源使用失控情況，這呼應了防禦性資源限制機制不應只針對已知可能發生的惡意情境，而應作為一種普遍性、不問成因的安全網，去涵蓋所有可能導致資源被過度消耗情況的核心原則」，展現你能把沙箱設計的考量視野，從單純的安全性(惡意防範)，擴展到資源使用效率和系統穩定性這個同樣重要卻容易被忽略的面向。

**面試回答方式**：先明確給出核心答案——「需要，這是一個相當現實且容易被忽略的實務考量，即使一段程式碼完全不帶有惡意，單純因為設計不良或任務本身性質，也可能消耗異常龐大的運算資源或執行異常長時間」。給出具體例子——「例如一段因為邏輯疏漏而陷入無窮迴圈的程式碼，或者被要求處理一份遠超乎預期龐大資料集的程式碼，這種即使沒有惡意也可能帶來失控資源消耗的情況，需要額外透過明確設定具體資源使用上限，並在超出上限時強制終止來因應」。給出更深的洞察——「不管資源消耗過度的成因究竟是惡意攻擊還是無心疏漏，最終造成的實質負面效果其實相當類似，都可能導致系統資源被異常佔用，一個設計周全的沙箱環境不應只考量防範蓄意惡意行為，也應同時考量即使出於善意也可能發生的資源使用失控，防禦性的資源限制機制應該作為一種普遍性、不問成因的安全網」。
