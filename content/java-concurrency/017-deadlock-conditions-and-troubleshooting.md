# 題目

死鎖產生需要滿足哪些條件？寫一個死鎖的例子。線上發生死鎖時該怎麼排查？

## 核心答案

死鎖需要同時滿足四個條件：互斥、持有並等待、不可搶佔、循環等待。最經典的例子是兩個執行緒以相反順序取得兩把鎖。排查死鎖最直接的方法是用 `jstack` 導出執行緒堆疊，JVM 會自動偵測並標示出死鎖的執行緒與鎖持有關係。

## 詳細解析

**死鎖的四個必要條件**：

1. **互斥條件**：資源（鎖）同一時間只能被一個執行緒持有。
2. **持有並等待**：執行緒已經持有至少一個資源，同時在等待取得其他被佔用的資源。
3. **不可搶佔**：資源只能由持有者主動釋放，不能被其他執行緒強行搶走。
4. **循環等待**：存在一個執行緒等待鏈，形成環狀（A 等 B、B 等 A，或更長的環）。

只要破壞其中任何一個條件，就能避免死鎖，這也是所有死鎖預防策略的理論基礎。

**經典死鎖範例**：

執行緒 1 先取得鎖 A、再嘗試取得鎖 B；執行緒 2 先取得鎖 B、再嘗試取得鎖 A。如果兩個執行緒幾乎同時開始執行，執行緒 1 拿到鎖 A 後想要鎖 B（但被執行緒 2 持有），執行緒 2 拿到鎖 B 後想要鎖 A（但被執行緒 1 持有），雙方永久互相等待，形成死鎖。

**如何預防死鎖**：

- **統一鎖的取得順序**：所有執行緒都按照相同的順序（例如依照鎖物件的 hashCode 或事先定義好的固定順序）取得多把鎖，從根本上破壞「循環等待」條件。
- **使用逾時機制**：改用 `tryLock(timeout, unit)` 代替無限期的 `lock()`，取鎖逾時就主動放棄已持有的鎖並重試或報錯，避免無限期等待。
- **一次性取得所有需要的資源**：盡量避免「先持有一部分資源，再嘗試取得其他資源」的模式。
- **縮小鎖的粒度與持有時間**：減少同時需要持有多把鎖的場景。

**線上排查步驟**：

1. 找到疑似卡死的 Java 行程 PID，執行 `jstack <pid>` 導出執行緒堆疊快照。
2. `jstack` 的輸出中，如果確實存在死鎖，會有明確的區塊標示「Found one Java-level deadlock」，並列出每個執行緒目前持有哪把鎖（`locked <地址> (a 類別名)`）、正在等待哪把鎖（`waiting to lock <地址>`），形成清楚的等待鏈。
3. 根據等待鏈找到程式碼中對應的加鎖順序，確認是哪幾段程式碼以不同順序取得了同一組鎖，修正加鎖順序或改用逾時鎖。
4. 也可以用 `jconsole`、`VisualVM` 等圖形化工具，或 Arthas 的 `thread -b` 指令直接找出阻塞的執行緒。

## 常見追問

- 除了死鎖，還有哪些類似的並行問題（活鎖 livelock、饑餓 starvation）？它們和死鎖有什麼不同？
