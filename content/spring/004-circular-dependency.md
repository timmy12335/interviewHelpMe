# 題目

什麼是循環依賴？Spring 怎麼解決循環依賴？三級快取分別是什麼？為什麼構造器注入的循環依賴解決不了？

## 核心答案

循環依賴是指兩個（或多個）Bean 互相依賴——A 依賴 B、B 又依賴 A。Spring 透過「三級快取 + 提前曝光半成品物件」來解決 setter/欄位注入的循環依賴。三級快取是——一級快取 `singletonObjects`（存完全初始化好的成品 Bean）、二級快取 `earlySingletonObjects`（存提前曝光的、還沒完全初始化的半成品 Bean）、三級快取 `singletonFactories`（存能產生半成品 Bean 的工廠 ObjectFactory，用於在需要時生成早期引用，尤其是 AOP 代理）。構造器注入的循環依賴無法解決，因為構造器注入要求「在建立物件的當下依賴就必須齊備」，而循環依賴下無法在建立時就拿到對方（對方也還沒建立）。

## 詳細解析

**循環依賴的場景**：A 的欄位依賴 B、B 的欄位依賴 A。容器建立 A 時發現要注入 B，於是去建立 B，建立 B 時又發現要注入 A——如果沒有特殊機制，就會陷入「建立 A 要先有 B、建立 B 要先有 A」的死循環。

**三級快取解決 setter/欄位注入循環依賴的流程**：

1. 建立 A：實例化 A（呼叫建構子，此時 A 是「半成品」——物件存在但欄位還沒注入），把「能獲取 A 早期引用的工廠」放入三級快取。
2. 填充 A 的屬性：發現 A 依賴 B，於是去建立 B。
3. 建立 B：實例化 B（半成品），把 B 的工廠放入三級快取。
4. 填充 B 的屬性：發現 B 依賴 A，於是去獲取 A——先查一級快取（沒有成品 A）、再查二級快取（沒有）、最後查三級快取，找到 A 的工廠，用它生成 A 的早期引用（若 A 需要 AOP，這裡生成代理），把這個早期引用放入二級快取、並注入給 B。
5. B 拿到了 A（的早期引用）、完成初始化，成為成品 B、放入一級快取。
6. 回到 A 的屬性填充：現在 B 已是成品，注入給 A，A 完成初始化，成為成品、放入一級快取。
7. 循環依賴解決。

**三級快取各自的作用**：

- **一級快取 `singletonObjects`**：存放完全初始化好的單例（成品）。正常獲取 Bean 都從這裡拿。
- **二級快取 `earlySingletonObjects`**：存放提前曝光的半成品 Bean（已實例化、未完全初始化）。避免重複透過三級快取的工廠生成早期引用。
- **三級快取 `singletonFactories`**：存放 `ObjectFactory`，能在需要時生成 Bean 的早期引用。它的關鍵作用是——如果 Bean 需要 AOP 代理，透過這個工廠生成的早期引用會是「代理物件」，保證別人注入到的是代理而非原始物件。

**為什麼構造器注入解決不了**：三級快取的機制依賴「先實例化出一個半成品物件（提前曝光），之後再填充屬性」。但構造器注入要求「依賴在呼叫建構子的當下就必須傳入」——建立 A 時建構子就要 B，可 B 還沒建立；建立 B 時建構子又要 A，可 A 還在建立中（連半成品都還沒完成，因為它的建構子沒跑完）。無法「先造出半成品再補依賴」，所以構造器循環依賴無解，Spring 會直接拋出 `BeanCurrentlyInCreationException`。

## 面試回答方式

先講清楚循環依賴是什麼（A、B 互相依賴）和它為什麼是問題（死循環）。三級快取是這題的核心，建議按「建立 A→建立 B→B 從三級快取拿到 A 的早期引用→依次完成」這個流程講一遍，比單純列舉三個快取更能展現理解。務必講清楚三級快取各自的作用，尤其「三級快取的工廠是為了 AOP——保證循環依賴時注入的也是代理物件」這個關鍵。最後解釋「構造器注入為什麼解決不了」（無法先造半成品再補依賴）。這題有深度，能完整講出流程和構造器的限制，是強力加分。

## 常見追問

### 為什麼需要三級快取？二級快取不夠嗎？

**核心答案**：如果不考慮 AOP，其實二級快取就夠了——直接在二級快取存半成品 Bean 的引用，循環依賴時從二級快取拿早期引用即可。三級快取存在的關鍵原因是「AOP 代理」——一個 Bean 如果需要被 AOP 代理，那麼別人注入到的應該是「代理物件」而非「原始物件」。三級快取存的是一個「工廠（ObjectFactory）」，只有當真正發生循環依賴、需要提前獲取這個 Bean 的早期引用時，才透過這個工廠「按需地」生成代理（提前生成代理）。如果沒有循環依賴，代理就按正常流程在初始化後期生成。三級快取讓「代理的生成時機」能靈活——正常情況正常生成，循環依賴時提前生成，且保證不管哪種情況注入出去的都是同一個代理物件。

**詳細解析**：這是三級快取設計最精妙也最容易被問的點。核心矛盾是——AOP 代理正常是在 Bean 初始化「之後」（BeanPostProcessor 後置處理）才生成的，但循環依賴時，B 需要在 A「還沒初始化完（還沒到生成代理的階段）」時就拿到 A 的引用。如果這時直接把 A 的「原始物件」給 B，那 B 持有的就是原始物件、而最終容器裡的 A 是代理物件，兩者不一致（B 用的 A 沒有 AOP 增強）。三級快取的工廠解決了這個問題——它封裝了「必要時提前生成代理」的邏輯：當 B 需要提前拿 A 時，透過 A 的工廠，如果 A 需要 AOP 就當場生成代理返回（提前把代理生成了），這樣 B 拿到的就是代理；同時這個提前生成的代理會被記錄，保證後續 A 自己初始化完成時用的也是同一個代理，全容器一致。如果只用二級快取（直接存物件而非工廠），就無法實現「只在需要時才提前生成代理」這個按需邏輯——要嘛所有 Bean 都提前生成代理（破壞了正常的生成時機、且對不需要提前的 Bean 是浪費），要嘛無法處理需要代理的循環依賴。所以三級快取的工廠是為了「優雅地處理 AOP 代理的提前生成」。

**面試回答方式**：講出「不考慮 AOP 二級快取就夠、三級快取是為了 AOP——用工廠實現『只在循環依賴需要時才提前生成代理』、保證注入的是代理且全容器一致」。能講清楚「若直接給原始物件會導致 B 拿到的 A 沒有 AOP 增強、和容器裡的代理 A 不一致」這個核心矛盾，展現你對三級快取設計動機的透徹理解，這是這題最高階的加分點。

### Spring 能解決所有循環依賴嗎？哪些情況解決不了？

**核心答案**：不能。Spring 只能解決「單例作用域 + setter/欄位注入」的循環依賴。解決不了的情況包括——「構造器注入」的循環依賴（無法先造半成品再補依賴，會拋 BeanCurrentlyInCreationException）、「原型（prototype）作用域」的循環依賴（原型 Bean 不放入快取、每次都新建，無法提前曝光，直接報錯）、以及「透過 `@Async` 等產生代理但代理生成時機衝突」的某些複雜情況。此外，Spring Boot 2.6+ 預設「禁止」循環依賴（需要顯式開啟 `spring.main.allow-circular-references=true`），因為循環依賴本身通常是設計不良的信號。

**詳細解析**：Spring 解決循環依賴是有嚴格前提的——必須是單例（才會用三級快取提前曝光）、必須是 setter/欄位注入（才能先實例化半成品再補依賴）。構造器注入解決不了（前面已述）。原型作用域解決不了，因為原型 Bean 根本不進入單例的三級快取體系（原型每次都新建、容器不快取它們），所以無法提前曝光半成品，遇到原型循環依賴 Spring 直接報錯。值得注意的是——即使 Spring 技術上能解決 setter 循環依賴，循環依賴的存在通常也是「兩個類別職責劃分不清、耦合過度」的設計壞味道，所以 Spring Boot 2.6 之後乾脆預設禁止循環依賴、逼開發者去正視和重構這個設計問題（想用還是可以開啟開關，但這個預設值傳達了「循環依賴是應該避免的」的態度）。所以最好的回答不只是「Spring 能解決哪些」，還要點出「循環依賴本身是設計問題、應該從設計上避免」。

**面試回答方式**：列出解決不了的情況（構造器注入、原型作用域），並點出「Spring Boot 2.6+ 預設禁止循環依賴」這個重要變化。最重要的是延伸出態度——「循環依賴通常是設計不良的信號、應該從設計上重構避免、而非依賴 Spring 的機制去繞過」，這種能跳出技術細節看到設計問題的回答，最能展現成熟的工程判斷。

### 循環依賴中，如果 A 需要 AOP、B 不需要，注入關係是怎樣的？

**核心答案**：A 需要 AOP 時，B 中注入的 A 會是「A 的代理物件」，而不是原始的 A——這正是三級快取工廠的作用：當 B 在循環依賴中提前獲取 A 時，透過 A 的三級快取工廠提前生成了 A 的代理，所以 B 拿到並持有的是代理。同時容器最終存入一級快取的 A 也是這同一個代理物件，保證了「B 中的 A」和「容器裡的 A」是同一個代理、全容器一致。B 不需要 AOP，所以 A 中注入的 B 就是 B 的原始物件。

**詳細解析**：這題把三級快取和 AOP 的交互具體化了。關鍵保證是「一致性」——不管 A 是在循環依賴中被 B 提前獲取、還是自己正常初始化完成，最終大家用的都是同一個 A 的代理。實現這個一致性靠的是三級快取工廠的「冪等記錄」——工廠第一次被呼叫生成代理後，會把這個代理記下來（放入二級快取），保證後續無論是 A 自己走完初始化流程、還是其他 Bean 再來獲取 A，拿到的都是這同一個已生成的代理，不會出現「B 拿到一個代理、容器裡又是另一個代理/原始物件」的分裂。而 B 不需要 AOP，它的早期曝光就是原始物件，A 注入到的就是原始 B（B 完成初始化後也還是它自己）。理解這個「需要 AOP 的 Bean 在循環依賴中提前生成代理、且保證全容器用同一個代理」的細節，展現你對三級快取和 AOP 交互的掌握達到了很深的層次。

**面試回答方式**：講出「B 中注入的是 A 的代理（三級快取工廠提前生成）、且容器裡的 A 也是同一個代理、保證一致；A 中注入的 B 是原始 B（B 不需要 AOP）」。能點出「一致性靠工廠生成代理後的記錄（放二級快取）保證後續拿到同一個代理」，展現你對這個交互細節的透徹理解，是非常深入的回答。
