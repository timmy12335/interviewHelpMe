# 題目

Spring AOP 有哪幾種通知（Advice）類型？它們的執行順序是怎樣的？多個切面的執行順序如何控制？

## 核心答案

Spring AOP 有五種通知：`@Before`（前置，方法執行前）、`@After`（後置/最終，方法執行後不管成功失敗都執行，類似 finally）、`@AfterReturning`（返回後，方法正常返回後執行）、`@AfterThrowing`（異常後，方法拋異常時執行）、`@Around`（環繞，包裹整個方法、最強大，能控制是否執行目標方法及修改參數返回值）。單個切面的執行順序是——`@Around` 前半段 → `@Before` → 目標方法 → `@Around` 後半段 → `@After` → `@AfterReturning`/`@AfterThrowing`。多個切面的順序用 `@Order` 註解或 `Ordered` 介面控制（值越小優先級越高、越先執行）。

## 詳細解析

**五種通知類型**：

- **`@Before`（前置通知）**：目標方法執行「之前」執行。常用於權限檢查、參數校驗、記錄請求。
- **`@After`（後置/最終通知）**：目標方法執行「之後」執行，不管正常返回還是拋異常都會執行（類似 finally）。常用於資源清理。
- **`@AfterReturning`（返回通知）**：目標方法「正常返回後」執行，可以拿到返回值。常用於記錄結果、對返回值做處理。
- **`@AfterThrowing`（異常通知）**：目標方法「拋出異常時」執行，可以拿到異常。常用於異常日誌、異常轉換。
- **`@Around`（環繞通知）**：最強大——它「包裹」整個目標方法，能在方法前後都執行邏輯、能決定是否呼叫目標方法（透過 `ProceedingJoinPoint.proceed()`）、能修改傳入的參數和返回值、能捕捉異常。前四種能做的它幾乎都能做。

**單個切面的執行順序**：

```
@Around 開始（proceed 之前）
  @Before
    目標方法執行
  @Around（proceed 之後）
  @After
  @AfterReturning（正常）或 @AfterThrowing（異常）
```

注意：`@After` 在 `@AfterReturning`/`@AfterThrowing` 之前執行（不同 Spring 版本細節略有差異，但 @After 類似 finally 的定位是一致的）。

**多個切面的順序控制**：用 `@Order(n)` 註解或實作 `Ordered` 介面，值越小優先級越高。對於多個切面——優先級高的切面，其「前置類」通知（@Before、@Around 前半）先執行，「後置類」通知（@After、@AfterReturning、@Around 後半）後執行，形成「洋蔥模型」（先進後出）——優先級高的包在外層，先進後出。

## 面試回答方式

先列出五種通知並簡述各自時機和用途，重點突出 `@Around` 是最強大的（能控制方法執行、改參數返回值）。執行順序是這題的核心考點——按 `@Around 前 → @Before → 方法 → @Around 後 → @After → @AfterReturning/Throwing` 講清楚。多切面順序要點出「用 @Order 控制、優先級高的在外層、洋蔥模型（先進後出）」。能講出洋蔥模型這個直觀的比喻，展現你理解多切面的巢狀執行結構而非死記順序。

## 常見追問

### @Around 環繞通知相比其他通知強在哪？使用時要注意什麼？

**核心答案**：`@Around` 強在「完全掌控目標方法的執行」——它能決定「是否執行目標方法」（可以不呼叫 `proceed()` 直接返回，等於攔截掉方法）、能「修改傳入的參數」（給 `proceed()` 傳新參數）、能「修改返回值」（改變 proceed 的返回結果）、能「捕捉和處理異常」、還能「在方法前後都插入邏輯」。使用時最要注意的是——**必須手動呼叫 `ProceedingJoinPoint.proceed()` 來執行目標方法**，如果忘了呼叫，目標方法就根本不會執行（這是最容易犯的錯）；且要正確處理 proceed 的返回值和異常（把返回值傳回去、異常適當處理或重新拋出）。

**詳細解析**：`@Around` 的強大來自它「包裹」了整個方法呼叫——它拿到的是一個 `ProceedingJoinPoint`，`proceed()` 就是「執行目標方法」這個動作的控制權在你手上。這讓它能做前四種通知做不到的事——例如快取（先檢查快取，命中就直接返回不呼叫 proceed、未命中才 proceed 並把結果存快取）、重試（在迴圈裡多次 proceed）、限流（超過限制就不 proceed 直接拋異常）、修改參數/返回值等。但這份強大也帶來責任——最經典的錯誤是「忘了呼叫 proceed()」，導致目標方法被無聲地跳過（方法沒執行但也不報錯，非常難查）；其次是「沒有正確返回 proceed 的結果」（如果目標方法有返回值，@Around 必須把 proceed 的返回值 return 出去，否則呼叫方拿到 null）；還有異常處理（如果吞掉了 proceed 拋的異常而不重新拋出，會掩蓋錯誤）。所以原則是——能用簡單通知（@Before/@AfterReturning）解決的就別用 @Around，只在真的需要控制方法執行時才用 @Around，且務必記得 proceed、正確處理返回值和異常。

**面試回答方式**：講出 @Around 的強大能力（控制是否執行、改參數返回值、處理異常、前後都能插邏輯），並用快取/重試/限流（Rate Limiting）等場景說明。重點強調注意事項——「必須手動 proceed 否則方法不執行、要正確返回結果和處理異常」。能給出「能用簡單通知就別用 @Around」的建議，展現你既懂它的強大又有正確的使用判斷。

### 多個切面作用於同一個方法時，執行順序是怎樣的（洋蔥模型）？

**核心答案**：多個切面對同一方法生效時，形成「洋蔥模型」——用 `@Order` 定義優先級（值越小優先級越高），優先級高的切面在「外層」。執行時，前置類通知（@Before、@Around 的 proceed 之前部分）按「優先級從高到低」執行（外層先進），目標方法執行後，後置類通知（@After、@AfterReturning、@Around 的 proceed 之後部分）按「優先級從低到高」執行（外層後出）。就像洋蔥——從外層剝到內層（進入時高優先級先執行），再從內層包回外層（返回時高優先級後執行），是「先進後出」的巢狀結構。

**詳細解析**：洋蔥模型是理解多切面執行順序最直觀的方式。假設切面 A（@Order(1)，高優先級）和切面 B（@Order(2)，低優先級）都作用於方法 M——執行流程是：A 的前置 → B 的前置 → M 執行 → B 的後置 → A 的後置。可以看到 A（外層）的前置最先、後置最後，B（內層）的前置後於 A、後置先於 A，形成 A 包著 B、B 包著 M 的巢狀（先進後出，像函數呼叫棧）。這個模型對於「多個橫切邏輯需要有序疊加」的場景很重要——例如你可能希望「日誌切面」在最外層（記錄整個呼叫，包括交易的開始結束），「交易切面」在內層（只包業務邏輯），這時就要讓日誌切面的 @Order 值更小（優先級更高、在外層）。實務中 Spring 的內建切面也有預設順序（如 @Transactional 有自己的 order）。理解洋蔥模型和用 @Order 控制順序，展現你能處理多個切面協同的複雜場景。

**面試回答方式**：用「洋蔥模型」這個比喻講清楚——「@Order 值小的優先級高在外層、前置類通知高優先級先執行、後置類通知高優先級後執行、先進後出的巢狀結構」。舉「日誌切面在外層包住交易切面」的例子說明實務意義。能畫出「A前→B前→方法→B後→A後」的執行序列，展現你對多切面順序的透徹理解。

### 切入點表達式（pointcut expression）常見的寫法有哪些？

**核心答案**：Spring AOP 借用 AspectJ 的切入點表達式語法，最常用的是 `execution()`——用於匹配方法執行，格式是 `execution(修飾符? 返回型別 包.類.方法(參數) 異常?)`，例如 `execution(* com.example.service.*.*(..))` 匹配 service 包下所有類別的所有方法。其他常見的還有——`@annotation(...)`（匹配標了某個註解的方法，如自訂 `@Log` 註解）、`within(...)`（匹配某個類別/包內的方法）、`@within(...)`/`@target(...)`（匹配標了某註解的類別）、`args(...)`（匹配特定參數型別）、`bean(...)`（匹配特定名稱的 Bean）。實務中最常用 `execution()`（按方法簽章匹配）和 `@annotation()`（按自訂註解匹配）。

**詳細解析**：切入點表達式是「定義哪些連接點要被織入」的方式，掌握常見寫法能讓你精確控制切面的作用範圍。`execution()` 最強大靈活——`*` 匹配任意（返回型別、方法名等）、`..` 匹配任意參數或任意層級的包，例如 `execution(public * com.example..service.*.*(..))` 匹配 example 下任意層級的 service 包裡所有 public 方法。`@annotation()` 在實務中極常用——它讓你可以「標了自訂註解的方法才被增強」，例如定義一個 `@RateLimit` 註解、寫一個 `@Around @annotation(rateLimit)` 的切面，這樣哪個方法要限流就標 `@RateLimit`，非常靈活且語意清晰（這也是很多框架如 `@Cacheable`、`@Transactional` 的實現思路——註解 + AOP）。實務中常把 `execution()`（粗粒度、按位置匹配，如「所有 service 方法」）和 `@annotation()`（細粒度、按標記匹配，如「標了 @Log 的方法」）結合使用。理解這些表達式，展現你不只知道 AOP 概念，還能實際寫出精確的切面。

**面試回答方式**：講出最常用的 `execution()`（按方法簽章、* 和 .. 通配）和 `@annotation()`（按自訂註解匹配），並舉例。特別強調 `@annotation()` 的實務價值——「自訂註解 + AOP 是很多功能（限流、日誌、快取）的實現套路、語意清晰靈活」。能連結到 @Cacheable/@Transactional 也是這個思路，展現你理解切入點表達式的實際應用。
