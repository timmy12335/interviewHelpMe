# 題目

Encoder-only、Decoder-only 與 Encoder-Decoder 差在哪？為什麼主流大模型選了 Decoder-only？

## 核心答案

差別的核心是「每個位置能看到什麼」。

**Encoder-only（BERT）**——雙向注意力，每個 token 能看到左右全部；**訓練目標是遮罩預測**；適合理解類任務（分類、抽取），但不能自然地生成。

**Decoder-only（GPT 系）**——因果遮罩讓每個位置只能看到自己與左邊；**訓練目標是預測下一個 token**；天然適合生成，而且理解任務可以用「把答案接在後面生成」來表達。

**Encoder-Decoder（T5、原始 Transformer）**——編碼器雙向讀輸入，解碼器單向生成輸出，中間用交叉注意力連接；適合明確的序列到序列任務（翻譯、摘要）。

**Decoder-only 勝出的三個理由**：**訓練效率**（一次前向就對序列裡每個位置產生了訓練信號，而遮罩預測只對 15% 的位置有信號）、**任務統一性**（所有任務都能表達成續寫，不需要為每種任務改架構）、**以及 KV Cache 讓推理高效**。

## 詳細解析

「因果遮罩讓訓練並行」是這個架構效率的關鍵。生成是逐 token 的，但訓練時不需要真的一個一個跑——把整個序列一次送進去，用一個上三角的遮罩把「未來」的注意力分數設成負無窮，於是每個位置都在「只看得到左邊」的條件下同時計算。一次前向就得到了序列長度個訓練樣本，**這是 Transformer 相對於 RNN 最大的訓練優勢**。

訓練信號密度的差距值得量化。BERT 的遮罩語言模型每個序列只有 15% 的 token 被遮住並產生損失；而自回歸的下一詞預測讓每個 token（除了第一個）都產生損失——同樣的資料量下，訓練信號差了六倍以上。在「資料是稀缺資源」的規模化時代，這個差距直接決定了誰能吃下更多資料。

「理解任務可以用生成表達」是一個關鍵的觀念轉變。分類不再需要一個分類頭——**直接讓模型生成類別的名稱**。這讓一個模型能處理任意任務而不需要為每個任務訓練一個頭，而這正是 in-context learning 與指令微調成為可能的基礎。

**但 Decoder-only 有一個真實的劣勢**：**輸入部分也只能單向讀取**。理論上雙向編碼對「理解一段長輸入」更有效——而實務上這個劣勢被規模與資料量掩蓋了。近年也有研究把因果遮罩在輸入段放寬（prefix LM），但主流仍是純因果——因為統一性帶來的工程簡化收益更大。

## 面試回答方式

先給區分的核心——**每個位置能看到什麼**，並依序說明三種架構的注意力形態、訓練目標與適用任務。給 Decoder-only 勝出的三個理由。加分點有四個：**因果遮罩讓訓練並行**——用上三角遮罩把未來的注意力設成負無窮，一次前向得到序列長度個訓練樣本，**這是相對 RNN 最大的訓練優勢**；**訓練信號密度的量化差距**——遮罩預測只有 15% 的 token 產生損失而自回歸幾乎每個都產生，差六倍以上，在資料稀缺的規模化時代直接決定誰能吃下更多資料；「理解任務可以用生成表達」是關鍵的觀念轉變，**是 in-context learning 與指令微調的基礎**；以及**公平指出它的劣勢**——輸入部分也只能單向讀取，而這個劣勢被規模掩蓋了。

## 講稿

差別的核心是每個位置能看到什麼。編碼器架構是雙向的，每個詞元能看到左右全部，適合理解類任務但不能自然生成。解碼器架構用因果遮罩，每個位置只能看到自己跟左邊，天然適合生成。

主流選解碼器架構有三個理由。訓練效率、任務統一性、還有推理時的鍵值快取。

訓練效率這點值得量化。遮罩語言模型每個序列只有一成五的詞元被遮住並產生損失，而自回歸的下一詞預測讓幾乎每個詞元都產生損失。同樣的資料量下訓練信號差了六倍以上。在資料是稀缺資源的規模化時代，這個差距直接決定誰能吃下更多資料。

還有一個觀念轉變我覺得很關鍵。理解任務可以用生成來表達，分類不再需要一個分類頭，直接讓模型生成類別的名稱就好。這讓一個模型能處理任意任務，而這正是脈絡內學習跟指令微調成為可能的基礎。

不過我也要公平地說它的劣勢。輸入部分也只能單向讀取，理論上雙向對理解長輸入更有效，只是這個劣勢被規模跟資料量掩蓋了。

## 常見追問

### 因果遮罩具體怎麼實作？

**核心答案**：在計算 softmax 之前，把「不該看到」的位置的注意力分數加上一個很大的負數（通常是 `-inf` 或 `-1e9`）——於是 softmax 之後它們的權重趨近於零。**遮罩是一個上三角矩陣**：位置 `i` 只能注意到 `j <= i`。它與 padding mask 是兩個獨立的遮罩，實務上會合併成一個。

**詳細解析**：「為什麼是加負無窮而不是直接設零」是一個好的理解檢驗：如果在 softmax 之後把權重設零，剩下的權重總和就不是 1 了，需要重新歸一化；而在 softmax 之前設負無窮，歸一化會自動只在合法的位置之間進行——**更簡潔也更數值穩定**。**實作上還有一個效率考量**：現代的注意力核心（FlashAttention）不會真的建構那個 N×N 的遮罩矩陣，而是在分塊計算時直接跳過完全在遮罩區的塊——於是因果遮罩不只不花成本，還讓計算量減半（**只需要算下三角**）。這是「數學上的性質被工程實作利用」的好例子。

**面試回答方式**：給實作方式（softmax 前加大負數、上三角遮罩、與 padding mask 合併）。加分點是回答為什麼是加負無窮而不是事後設零——事後設零需要重新歸一化，而事前加負無窮讓歸一化自動只在合法位置間進行，更簡潔也更數值穩定。核心加分點是效率考量：FlashAttention 不會真的建構 N×N 的遮罩矩陣，而是在分塊時跳過完全在遮罩區的塊，於是因果遮罩不只不花成本還讓計算量減半。

### 為什麼 Encoder-Decoder 在翻譯之外用得少了？

**核心答案**：因為「把輸入與輸出分開處理」的收益，不足以抵銷「架構複雜與不統一」的成本。Decoder-only **把輸入直接當成前綴**——同樣能表達翻譯（「把這句話翻成英文：...」），而且不需要交叉注意力這個額外的模組。在規模夠大時，前綴的方式表現不輸專門的編碼器，卻讓整個系統只需要一種架構、一套訓練流程、一種推理路徑。

**詳細解析**：「統一性的工程價值」在這裡被證明遠大於架構上的理論優勢：一個 Decoder-only 模型可以做翻譯、摘要、問答、程式碼、對話——而 Encoder-Decoder 要為不同的輸入輸出形態設計不同的處理。更關鍵的是「預訓練資料的通用性」：網路上的文本天然就是「續寫」的形式，可以直接用來訓練 Decoder-only；而 Encoder-Decoder 的預訓練需要構造成對的輸入輸出，資料的來源受限得多。這解釋了為什麼在「資料規模成為主要驅動力」之後，Decoder-only 幾乎完全取代了它。 但在某些特定場景（例如需要對超長輸入做深度理解的任務）Encoder-Decoder 仍有價值，T5 系列在學術上也仍然活躍。

**面試回答方式**：給核心理由——分開處理的收益不足以抵銷架構複雜與不統一的成本，並說明Decoder-only 把輸入當前綴同樣能表達翻譯且不需要交叉注意力。核心加分點是**預訓練資料的通用性**：網路文本天然就是續寫形式可以直接訓練，而 Encoder-Decoder 需要構造成對的輸入輸出，資料來源受限得多——這解釋了為什麼在資料規模成為主要驅動力之後它幾乎被完全取代。收在公允的補充：T5 系列在學術上仍活躍，特定場景仍有價值。

### 因果遮罩對模型能力有什麼限制？

**核心答案**：它讓模型無法「先看完全部再回答」——**每個 token 的表示只包含左側資訊**。實際的影響是：需要全局理解才能決定的事情，模型必須用「生成中間步驟」來彌補——**這正是 Chain of Thought 有效的一個原因**：它把「一次想清楚」拆成「一步步寫出來」，讓後面的 token 能看到前面的推理。

**詳細解析**：這個視角把 CoT 從「提示技巧」提升到「架構限制的補償機制」：因果模型的每個位置只有固定的計算量（一次前向）——**而困難的問題需要更多計算**。生成中間步驟等於「用序列長度換取計算深度」：每多生成一個 token，模型就多做了一次完整的前向計算，而且能讀到之前的所有輸出。這也解釋了為什麼「讓模型直接說答案」在難題上表現差——不是它不知道，而是它沒有足夠的計算步驟去推導。近年的推理模型（把思考過程大幅延長）正是把這個機制推到極致——而理解這條因果鏈，比記住「CoT 有效」有價值得多。

**面試回答方式**：給限制——每個 token 的表示只包含左側資訊，模型無法先看完全部再回答，並指出**這正是 CoT 有效的一個原因**。核心加分點是把 CoT 從提示技巧提升到**架構限制的補償機制**：因果模型每個位置只有一次前向的計算量，而生成中間步驟等於用序列長度換取計算深度——每多生成一個 token 就多做一次完整前向且能讀到之前的輸出。收在推論：「讓模型直接說答案」在難題上表現差不是因為不知道，而是沒有足夠的計算步驟去推導，而近年的推理模型正是把這個機制推到極致。
