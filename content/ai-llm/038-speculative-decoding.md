# 題目

推測解碼（speculative decoding）是什麼原理？為什麼能加速而不損失品質？

## 核心答案

**核心洞察是「驗證比生成便宜」**：解碼階段是記憶體受限的——**驗證 5 個 token 與生成 1 個 token 的時間幾乎一樣**（**都要把全部權重讀一遍，而多算幾個 token 的計算成本可以忽略**）。

**做法是兩步**。**草稿（draft）**——**用一個小得多的模型快速生成 k 個候選 token**。**驗證（verify）**——**把這 k 個 token 一次送進大模型做一次前向**，**得到每個位置的真實機率分布**，**然後用一個接受-拒絕的採樣規則逐個檢查**：**匹配就接受並繼續，第一個不匹配的位置就拒絕並用大模型的分布重新採樣一個**。

**「不損失品質」是數學上可證的**：那個接受規則經過設計，**使得最終輸出的分布與「直接用大模型逐個採樣」完全相同**——**這不是近似，而是精確等價**。

**加速比取決於「接受率」**：草稿模型與大模型越一致，接受的 token 越多，加速越明顯——**典型是 2 到 3 倍**。

## 詳細解析

**「為什麼驗證幾乎免費」是這個技術的物理基礎**。decode 階段每一步都要把整個模型的權重從顯存讀進計算單元——**這個讀取時間是固定的成本**，**而在讀進來之後，處理 1 個 token 與處理 5 個 token 的計算差異微不足道**（**因為算力本來就大量閒置**）。**所以「一次前向驗證多個位置」幾乎不增加時間**——**這正是把「串行的生成」轉換成「並行的驗證」能賺到的東西**。

**接受率決定了實際收益，而它取決於任務**。**在「容易預測」的內容上接受率很高**（程式碼的樣板、固定的格式、常見的詞組）；**在「高度不確定」的內容上接受率低**（創意寫作、罕見的專業內容）。**所以加速比在不同場景差異很大**——**評估時必須用真實的工作負載而非一個通用基準**。**而 k 的選擇也是取捨**：**k 太大則被拒絕的部分白算了草稿，k 太小則收益有限**——**通常 4 到 8 之間，並且可以動態調整（接受率高就加大）**。

**草稿模型的選擇有幾種路線**。**獨立的小模型**——同系列的小版本（例如 7B 配 70B），**需要詞表相同**。**自我推測（self-speculation）**——**用大模型自己的淺層或跳過部分層來產生草稿**，**不需要額外的模型**。**Medusa 這類方法**——**在大模型上加幾個輕量的預測頭，一次預測後面幾個位置**。**後兩者的優勢是不需要維護第二個模型，部署更簡單。**

**它與批次的互動需要注意**：**推測解碼在低批次（延遲敏感）時收益最大**——**因為那時算力最閒置**。**而在高批次（吞吐導向）時，算力已經被充分利用，額外的驗證計算不再免費**——**收益顯著下降甚至變成負的**。**所以它是一個「優化延遲」而非「優化吞吐」的技術，這個定位必須說清楚。**

## 面試回答方式

先給核心洞察——**驗證比生成便宜，因為解碼是記憶體受限的，驗證 5 個與生成 1 個的時間幾乎一樣**。給草稿與驗證兩步，並強調**「不損失品質」是數學上可證的精確等價而非近似**。加分點有四個：**解釋為什麼驗證幾乎免費**——**讀權重的時間是固定成本，讀進來之後多算幾個 token 的差異微不足道**，**這是把串行生成轉成並行驗證賺到的東西**；**接受率取決於任務**——**程式碼樣板高、創意寫作低**，**所以評估必須用真實工作負載**，並給 k 的取捨；**草稿模型的三種路線**與後兩者不需維護第二個模型的優勢；以及**它與批次的互動**——**低批次時收益最大，高批次時算力已被充分利用、額外驗證不再免費**，**所以它是優化延遲而非吞吐的技術**。

## 講稿

核心洞察是驗證比生成便宜。解碼階段是記憶體頻寬受限的，驗證五個詞元跟生成一個詞元的時間幾乎一樣，因為都要把全部權重讀一遍，而多算幾個詞元的計算成本可以忽略。

做法是兩步。先用一個小得多的模型快速生成幾個候選，再把它們一次送進大模型做一次前向，得到每個位置的真實分布，然後逐個檢查。匹配就接受並繼續，第一個不匹配的位置就拒絕並用大模型的分布重新採樣。

不損失品質這件事是數學上可證的。那個接受規則經過設計，使得最終輸出的分布跟直接用大模型逐個採樣完全相同。這不是近似，是精確等價。

加速比取決於接受率，而接受率取決於任務。程式碼的樣板、固定格式這類容易預測的內容接受率很高，創意寫作就低。所以評估時必須用真實的工作負載。

還有一個定位要說清楚。它在低批次、延遲敏感的時候收益最大，因為那時算力最閒置。高批次的時候算力已經被充分利用，額外的驗證就不再免費了。所以它是優化延遲的技術，不是優化吞吐的。

## 常見追問

### 接受-拒絕的採樣規則具體是什麼？

**核心答案**：**對每個草稿 token，比較大模型與草稿模型在該位置給它的機率**。**如果大模型的機率 `p` 大於等於草稿模型的 `q`，直接接受**；**否則以 `p/q` 的機率接受，以 `1 - p/q` 的機率拒絕**。**拒絕時，從一個「修正後的分布」`normalize(max(0, p - q))` 中重新採樣**——**這個修正確保了整體分布與直接從 `p` 採樣完全一致**。

**詳細解析**：**這個規則本質上是「拒絕採樣」的一個變體**，而它的巧妙之處在於**拒絕時不是丟掉重來，而是從差值分布中採樣**——**於是那一步仍然產出了一個 token，不會浪費**。**直觀的理解是：草稿模型高估了某個 token 的機率，我們按比例接受它；而它低估的那部分機率質量，透過差值分布被補回來**。**這個證明本身是推測解碼論文最核心的貢獻**——**因為在它之前，用小模型加速的想法早就有人提過，但都是有損的近似**。**「把一個啟發式的加速手段變成無損的精確方法」是這個工作真正的價值，而能說清楚這一點會比只描述流程更有深度。**

**面試回答方式**：給精確的規則（p ≥ q 直接接受、否則以 p/q 機率接受、拒絕時從 `normalize(max(0, p-q))` 採樣）。核心加分點是說明**巧妙之處在於拒絕時不是丟掉重來而是從差值分布採樣，那一步仍然產出一個 token 不會浪費**，並給直觀理解（**草稿高估的按比例接受，低估的那部分透過差值分布補回來**）。收在價值定位：**在它之前用小模型加速早就有人提過但都是有損近似**，**「把啟發式手段變成無損的精確方法」才是這個工作真正的貢獻**。

### 草稿模型該多大？

**核心答案**：**在「夠準」與「夠快」之間找平衡**。**草稿模型的一次前向必須遠快於大模型**——**否則生成 k 個草稿的時間就抵銷了收益**。**經驗上草稿模型是目標模型的十分之一到二十分之一參數量**（例如 7B 配 70B）。**而更重要的是「兩者的分布要接近」**——**同一個系列、同樣的訓練資料與對齊方式的模型，接受率會明顯高於隨便找一個小模型。**

**詳細解析**：**「用目標模型的輸出蒸餾草稿模型」是提升接受率最直接的方法**：讓小模型專門學習模仿大模型的分布——**它不需要自己「聰明」，只需要「猜得像」**。**這個目標比通用能力簡單得多，所以小模型可以做得相當好**。**另一個實務約束是「詞表必須相同」**——**不同詞表的模型無法直接比較 token 機率**，**這限制了跨系列的搭配**。**而自我推測（用大模型自己的淺層做草稿）繞過了這兩個問題**：**分布天然接近、詞表天然相同、也不需要維護第二個模型**——**代價是加速比通常不如專門的草稿模型**。**在部署複雜度與加速比之間，多數團隊會選擇前者。**

**面試回答方式**：給大小的經驗值並強調**更重要的是兩者的分布要接近**。核心加分點是**用目標模型的輸出蒸餾草稿模型**——**它不需要自己聰明，只需要猜得像，而這個目標比通用能力簡單得多**。給出**詞表必須相同**這個實務約束，並收在自我推測的權衡：**繞過了分布與詞表兩個問題也不需維護第二個模型，代價是加速比較低**——**而多數團隊會選擇部署簡單的那一邊**。

### 還有哪些降低生成延遲的方法？

**核心答案**：**分成三類**。**減少每步的成本**——**量化（讀更少位元組）、GQA（更小的 KV Cache）、更小的模型**。**減少步數**——**推測解碼、以及在應用層「不要讓模型生成不必要的內容」**（**簡潔的輸出格式、不要求它複述問題**）。**改善感知**——**串流輸出、先返回部分結果**。

**詳細解析**：**「不要讓模型生成不必要的內容」是應用層最容易忽略卻收益最直接的一項**：**輸出 token 是逐個生成的，每一個都花時間也花錢**——**而很多提示會讓模型輸出大量無用的鋪陳**（「好的，我來幫您分析這個問題。首先……」）。**在提示中明確要求「直接給出答案，不要解釋過程」或者要求結構化的簡短輸出，能直接把延遲砍掉一半**。**這比任何推理層的優化都便宜且立即見效**。**而反過來，如果任務確實需要推理，那些「思考」的 token 是有價值的**——**所以判斷的關鍵是「這些輸出對結果有貢獻嗎」**：**有貢獻的保留，純粹的禮貌性鋪陳去掉**。**能區分這兩者，比籠統地說「讓輸出更短」有用得多。**

**面試回答方式**：給三類方法。核心加分點是強調**「不要讓模型生成不必要的內容」是應用層最容易忽略卻收益最直接的一項**——**每個輸出 token 都花時間也花錢，而很多提示讓模型輸出大量鋪陳**，**明確要求直接給答案能直接把延遲砍掉一半，比任何推理層優化都便宜且立即見效**。收在判斷：**如果任務確實需要推理，那些思考 token 是有價值的**，**所以關鍵是問「這些輸出對結果有貢獻嗎」而不是籠統地要求更短**。
